# 0.8.56 商店容量口径修复与法师真实百关

## 本轮阻断

法师第 94 关已积累 12 种材料与 1 件装备，`inventory.length=13`。背包面板固定只渲染前 12 格，材料按获取顺序占据全部可见格，第 13 格装备不可见；在城镇点「烬誓·过渡束带」时，`buyMarksGood()` 仍用 `state.inventory.length >= 12` 判断容量，日志报 `[shop] marksBlocked {"reason":"inventoryFull","slotKey":"belt"}`，印记不扣、装备不得。

根因是 0.8.55 只修了拾取入口，没有把“装备容量”统一到商店兑换与背包渲染：材料堆叠被视为占格，且渲染顺序让材料把装备挤到不可见位置。

## 修复

1. `game/src/drops.js` 新增纯函数 `equipmentSlotCount(inventory)`，只统计 `slot !== "material"` 的装备，作为背包上限、拾取、商店兑换、UI 计数的唯一口径。
2. `game/src/main.js` 的 `collectDrops()` 与 `buyMarksGood()` 改用 `equipmentSlotCount()`；兑换失败提示改为“装备栏已满，无法兑换（材料不占格，请拆解或穿戴装备）”。
3. `game/src/render.js` 的 `renderInventory()` 先按“装备优先、材料在后”排序，再取前 12 格；计数文案改为 `N/12 装 · 材料 M 种`，无材料时保持 `N/12`。
4. E2E `snapshot().inventoryCount` 改为装备数，新增 `materialKinds`；单测新增 `equipmentSlotCount` 的 12 材料 / 12 装备 / 空值与 `null` 用例。

## 页面实测

- 加载 0.8.56 后，第 94 关背包显示 `0/12 装 · 材料 13 种`，不再把 13 种材料算成满格。
- 在城镇真实点击 800 印记的「烬誓·过渡束带」：印记 `912 → 112`，背包变为 `1/12 装 · 材料 13 种`，装备卡排在第一格并可直接点击穿戴；`equipment.belt` 变为 `marks-belt`，生命 +70、防御 +3。
- 说明商店兑换、背包可见性、实际穿戴三条链路已同时打通。

## 工具经验

Browser Use 后端在长时间试玩后返回 `CELL_RUNNER_EXIT`，随后新的 `bu.cdp` 调用会一直挂到 900 秒安全超时；页面本身仍可通过 Chrome DevTools Protocol 正常求值。为避免把“后端失灵”误判为“游戏卡死”，新增 `tools/local_cdp.py`：只发送 `Input.dispatchMouseEvent` / `Input.dispatchKeyEvent`，只读 `Runtime.evaluate` 快照，不调用战斗作弊接口。`tools/run_stages.py` 用它逐关推进并落盘检查点。
