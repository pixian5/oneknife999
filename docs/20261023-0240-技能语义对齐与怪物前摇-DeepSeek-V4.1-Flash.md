# 技能语义对齐与怪物攻击前摇（0.3.4）

- 日期：2026-10-23 02:40
- 模型：DeepSeek-V4.1-Flash
- 版本：0.3.3 → 0.3.4
- 本轮主题：**P1-1 技能语义对齐 + P1-2 怪物攻击前摇**

## 一、背景

0.3.3 的审计结论指出两处「文案承诺与实现不一致」的核心问题：

1. **技能语义虚化**：破甲斩只有伤害没有破防、震地冲是原地结算、召唤骨卫只是一次性伤害、生息法阵是一次性回血、法师雷矛不穿透。技能描述写了机制，代码却没实现，玩家感受不到职业差异。
2. **怪物出手不可预判**：`playerDamage` 每帧 `Math.random() < dt × 概率` 判定，玩家看不到任何预警，也无法靠走位规避，受击体验随机且被动。

## 二、技能语义（P1-1）

新增纯逻辑模块 `game/src/skills.js`（不依赖 DOM / 全局状态，便于单测）：

| 技能 | 规则常量 | 实现 |
|---|---|---|
| 破甲斩（战士 1） | `armorBreak`: 防御 -15% / 4 秒 | `applyArmorBreak` 刷新计时，`tickArmorBreak` 逐帧递减；`combat.computeDamage` 读 `target.armorBreakTimer` 折算防御 |
| 震地冲（战士 3） | `charge`: 140px / 0.2s 无敌 / 击退 56px | `resolveChargePoint` 计算落点（保留目标身位），`resolveKnockback` 沿外推方向推开并按地图边界夹取；突进瞬间给 0.2 秒无敌 |
| 雷矛术（法师 1） | `pierce`: 直线最多 3 目标 / 弹道宽度 44 | `pickPierceTargets` 把敌人投影到 origin→aim 射线，取投影在射程内、垂距 ≤ 弹道宽 + 半径的敌人按命中先后取前 3 |
| 召唤骨卫（道士 2） | `summon`: 12 秒 / 40% 攻击 / 冷却 0.9s / 索敌 300px | `createBoneGuard` 生成 `friendly` 实体，`main.updateSummon` 负责跟随、索敌、贴身出手与到期消散 |
| 生息法阵（道士 3） | `healZone`: 4 秒 / 每秒 8% / 半径 120 | `advanceHealZone` 单帧推进：圈内每 1 秒结算一次回血，离开立即失效，4 秒自然结束 |

**友军隔离**（骨卫是 `friendly` 实体）：

- 自动索敌 `findTarget`、范围技能 `nearestTargets`、指引箭头 `resolveGuideTarget`、点击锁定 / 悬停高亮、e2e 快照全部排除 `friendly`，避免玩家普攻指向自己的召唤物或测试脚本误把骨卫当怪物。
- 骨卫不进入怪物复活逻辑，召唤时限结束后直接从实体表移除。

**视觉反馈**：

- 生息法阵：紫色虚线回复圈 + 剩余时间刻度环，玩家在圈内时内圈加亮。
- 雷矛穿透：0.18 秒淡出的直线光束（`fx.pierce`，仅渲染）。
- 骨卫：青色虚线环标识友军，避免被误认为怪物。

## 三、怪物攻击前摇（P1-2）

`combat.js` 新增 `MONSTER_ATTACK_RULES` 与纯函数 `advanceMonsterAttack`：

- 普通怪：前摇 0.45 秒、攻击冷却 4.0 秒；首领：前摇 0.6 秒、冷却 1.7 秒。
- **冷却为什么不是设计稿的 1.2 / 0.9 秒**：旧的实现是「每帧掷骰 + 只检查最近一只怪」——普通怪 0.32 次/秒（约 3.1 秒一次）、首领 0.6 次/秒（约 1.7 秒一次），而且**被 6 只怪围住时承伤并不会翻 6 倍**（每帧只判定最近的一只）。改成固定节奏后，每只怪都独立出手且前摇必中，若照搬 1.2 / 0.9 秒，实测第 4 关沙蝎王战玩家 440 血在几秒内被清空并陷入死亡循环（1 张图 15 次死亡）。
- **最终方案：全局出手闸门 `gate` + 单前摇名额**：
  1. `player.attackGate`：任意一只怪出手后写入闸门（普通 3.1 秒 / 首领 1.7 秒），归零前任何怪都不能重新抬手；
  2. `MAX_WINDUP_ATTACKERS = 1`：同一时刻只有最近的一只怪能处于蓄力状态。
  两者合起来把「被围」的承伤速率压回旧模型（约 3.1 秒一次普通怪出手），玩家仍能享受「读蓄力环走位躲空」的收益。
- 修正后实测：沙蝎王战连续 3 次复现均存活（440 血结束时剩 53~131），不再出现死亡循环。
- 节奏：冷却结束、已接战（`aggro`）且玩家在攻击范围内 → 进入前摇（原地不动）→ 前摇归零的帧出手 → 冷却按固定值重置。
- 未接战的巡逻怪不会抬手，避免玩家路过时被一圈怪同时围攻；首领视为始终接战。
- 前摇结束若玩家已拉开距离、处于无敌或进入安全区 → **落空**（`落空` 飘字 + 挥击弧，不结算伤害）。
- 初始冷却按一个完整周期随机错开（1.2–2.9s），避免进入视野的瞬间被整群怪同时抬手；复活时清空前摇与破甲状态。
- 渲染层：红色蓄力环随前摇由外向内收拢（`entity.windup / windupTotal`），收拢到底即出手。
- 无敌期间不再进入前摇（避免空转）；中毒持续伤害与场景危险区伤害同样跳过无敌帧。

## 六、已知取舍

- 震地冲为瞬时位移 + 伤害 + 击退，不是逐帧冲刺；避免与碰撞、相机和输入预测产生耦合。
- 生息法阵以「脚下展开 + 圈内生效」实现，换图 / 复活时清空；不做跟随玩家的移动光环。
- 骨卫不复用怪物 AI（不巡逻、不仇恨、不复活），只做跟随 + 索敌 + 出手，代码更可控。
- 前摇改变承伤节奏（玩家可躲避），实际难度略降；balance-sim 是抽象模拟（不模拟前摇），因此对照数据不变，真实影响以百图 e2e 死亡数为准。
