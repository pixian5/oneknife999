# 可读性回归与复活体验（0.4.2）

- 日期：2026-10-27 01:11
- 模型：DeepSeek-V4.1-Flash
- 版本：0.4.1 → 0.4.2

## 问题

0.4.1 修好了铭牌遮挡，但留下四个尾巴：

1. **没有回归网**：定位遮挡用的「插桩 + 矩形相交」是一次性脚本，删掉后无任何用例守着「飘字 / 特效环不得压住血条」。后续新增特效（破甲层数、更多技能环）随时可能复发。
2. **铭牌无视野裁剪且每帧重建闭包**：`drawWorld` 每帧对 `state.entities` 做 `filter + map`，为每个存活实体创建 `{ y, draw: () => drawNameplate(entity) }` 再排序。百图大地图上绝大多数实体在屏外，这些分配与排序都是纯开销。
3. **飘字仍会出屏**：`textAt` 的 `vy: -26` 让 25px 的 `999` 在 1 秒内上浮 26px，靠地图边缘的怪物飘字被画布裁掉。
4. **复活把首领打回满血**：`die()` → `loadMap` → `createEntities` 重建实体表，首领一律满血。玩家一次失误就要把整条首领血条重打一遍，这也是难度探针 0/1/5 死波动的自放大来源（0.4.0 已提出待决策，0.4.1 未承接）。

## 改动

### 1. 铭牌可读性回归用例（tests/ui-nameplate.cjs）

在页面加载前通过 `page.addInitScript` 插桩 `CanvasRenderingContext2D.prototype`：

- 只记录 `#gameCanvas` 的绘制，离屏地面层（另一个 context）不参与；
- 记录 `fillText`（含 `font` / `textAlign`）、`fillRect`、`arc`、`roundRect`，并用 save/restore 层级判断是否仍在世界块内——`drawWorld` 的 `restore` 之后是屏幕坐标 HUD（连击数字等），必须排除，否则坐标系混用会产生假阳性；
- 用包装后的 `requestAnimationFrame` 分帧：每个回调开始清空日志，结束做一次相交检测。

判定规则：

- 铭牌底板 = `roundRect` 且 `radius ≈ 3`、高度为 31（怪物）或 24（玩家），同时记录其矩形；
- 铭牌自身内容不计遮挡：`Lv.` 开头的名字行、`80 / 120` 形式的血量行、位于铭牌内且高度 ≤ 6 的血条底 / 血量条；
- 其余「在铭牌之后绘制、且仍在世界块内」的绘制（飘字、粒子、特效环、技能预览）与铭牌矩形相交即记为命中。

用例自带**自检**（防止插桩失效后空跑通过）：喂一段只有铭牌内容的日志必须 0 命中；再喂人造粒子、特效环与伤害飘字必须 ≥ 1 命中。

测试过程用键盘接近最近的怪并普攻 / 技能（约 11 秒），**不用鼠标点击怪物**——hover 出的怪物 tooltip 会压住铭牌，那是既有设计（tooltip 画在最上层），不是本用例要抓的遮挡。

### 2. 铭牌视野裁剪与排序降开销（render.js）

```js
const plates = [];
for (const entity of state.entities) {
  if (!entity.alive || !nameplateVisible(entity, view, width, height)) continue;
  plates.push({ y: entity.y, entity });
}
if (playerNameplateVisible(view, width, height)) plates.push({ y: state.player.y, entity: null });
plates.sort((a, b) => a.y - b.y);
```

- 新增 `plateVisible(x, halfWidth, top, height, view, ...)` 供怪物与玩家铭牌共用；判定用铭牌矩形与视口矩形相交，**部分可见的贴边铭牌仍然绘制**，观感不变。
- 铭牌宽度抽成 `NAMEPLATE_WIDTH = { normal: 118, boss: 160 }` 与 `PLAYER_NAMEPLATE_WIDTH = 88`，裁剪与绘制共用，避免再出现「两处各写一个数字」的分叉。
- 排序条目从 `{ y, draw: 闭包 }` 改为 `{ y, entity }`，绘制时再分支，每帧省掉一次 filter + map + 每实体闭包分配。

### 3. 飘字出屏裁剪（render.js）

`drawText(text, view, viewWidth, viewHeight)` 把绘制点夹进「视口内缩 `size`」的范围：

```js
const inset = text.size;
const x = view ? clamp(text.x, view.x + inset, view.x + viewWidth - inset) : text.x;
const y = view ? clamp(text.y, view.y + inset, view.y + viewHeight - inset) : text.y;
```

只改显示位置，不动生命与上浮动效；不传 `view` 时退化为原行为，导出函数仍可单独调用。

### 4. 复活保留首领已损失生命（runtime.js / main.js）

新增纯函数（可单测）：

```js
export function restoreDamagedBoss(entities, previousEntities) {
  const damaged = (previousEntities || []).find((entity) => entity.boss && entity.alive && entity.hp < entity.maxHp);
  ...
  boss.hp = Math.max(1, Math.min(boss.maxHp, damaged.hp));
}
```

- `loadMap(mapId, spawnX, spawnY, silent, keepBossHp = false)` 先保存旧的 `state.entities`，`createEntities` 之后按需回填；
- `die()` 调用 `loadMap(..., true, true)`，即**只在该图复活时**保留；换图与首次进入仍满血刷新；
- 普通怪仍满血重置；首领**阶段**不回填，由 `updateBoss` 按新的生命比例重新判定（复活血量可能跨阶段）；
- 首领已阵亡时不参与回填（新表仍是满血首领，与 0.4.1 行为一致）。

## 经验

- 一次性排查脚本要固化成常驻用例，并给用例加**自检**：插桩失败或用例逻辑写错时，「没有命中」与「什么都没检测到」必须能区分开。
- 插桩必须区分坐标系：世界块（`drawWorld` 的 save/restore 内）与屏幕 HUD（restore 之后）混在一起会产生假阳性；离屏 Canvas（地面层）也要排除。
- 视野裁剪放在「建排序对象」之前，收益最大；同时把宽度等几何抽成常量，避免裁剪判定与绘制各写一份。
- 「复活后保留首领血量」属于**体验规则**而非数值规则，写成纯函数（`restoreDamagedBoss`）后既能单测，又不会把分支散落在 `die()` 与 `loadMap` 两处。
