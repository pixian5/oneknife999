# 地图关卡与通关规则

## 目标

本规则解决玩家进入地图后不知道“做什么、做到什么程度、打完以后去哪里”的问题。首发纵向切片的每张地图都采用相同且可预测的三段式流程：清剿普通怪、击败区域首领、前往已开启的前进出口。最终地图没有下一出口，完成前两项后直接进入明确的全流程结算。

地图探索、回城、拾取和换装可以穿插进行，但关卡主目标始终固定显示，不能被活动提示、掉落通知或战斗日志替代。

## 四张地图完成条件

| 顺序 | 地图 | 第一步：普通怪 | 第二步：区域首领 | 第三步：结束方式 |
|---:|---|---:|---|---|
| 1 | 灰烬村外 | 击败 8 只 | 裂碑领主 | 前往东侧金色出口，进入雾松林 |
| 2 | 雾松林 | 击败 10 只 | 森林巨猿 | 前往东侧金色出口，进入黑岩矿坑 |
| 3 | 黑岩矿坑 | 击败 10 只 | 坑道尸皇 | 前往东侧金色出口，进入赤砂大漠 |
| 4 | 赤砂大漠 | 击败 10 只 | 沙蝎王 | 显示“四图通关，纵向切片完成”结算 |

Boss 不计入普通怪击杀数量。玩家可以先击败 Boss 再补普通怪，两项都达成时才判定通关。每张地图首次通关发放 60 金币和 8 枚首领印记，重复进入和 Boss 刷新不重复发放。

## 原型单人节奏

当前浏览器纵向切片以单人完成四图为验收目标，不采用正式多人服的 Boss 生命池。区域首领生命依次为 900、1400、2100、3000；角色每级增加 18 点最大生命，Boss 仍保留阶段技能、危险区和首领掉落。目标是在正常使用普攻、职业技能、药水和撤离操作时，让一张地图的 Boss 战保持可读且不会因纯血量拖成不可完成的消耗战。

每次进入地图都会落在入口安全缓冲区，并补满生命与职业资源。死亡返回灰烬村后同样获得该恢复，确保玩家不会带着低血和空资源反复挑战同一目标而失去继续完成关卡的能力；生命药水仍只通过初始配给和掉落补充。

每张地图首次达成通关（普通怪与 Boss 两项完成）后，客户端会立刻将职业、当前地图、角色成长、背包、装备和四张地图的独立进度写入本机浏览器存档；自动保存发生在首领经验结算和升级检查之后。刷新页面、浏览器意外关闭或任务中断后，读取存档会回到已完成地图，已通关状态、奖励领取状态和前进出口保持不变。玩家仍可用“保存”按钮主动存档。

### 撤离与净化安全区

Boss 战不能要求玩家站桩换血。每张首发地图左下角的城镇矩形（绘制区域内缩 28 像素）都是安全区：

- 进入安全区后，普通怪、Boss 近战和已生成的危险区不会造成伤害；生命按最大生命约 10%/秒恢复，职业资源按上限约 8%/秒恢复。
- 赤砂大漠额外有三个水井，其中蝎王枯井（1980,540）是沙蝎王战的专用净化点。以井中心 70 像素为半径时具备同等安全效果，毒层约 2 层/秒下降；离开后再回到首领区域继续输出。
- 玩家应在生命低于约 65% 或毒层达到 2 层时撤离。撤离不重置当前地图击杀进度，返回 Boss 区后 Boss 当前生命仍按现场状态保留；若角色死亡，才按死亡规则回城并重置现场实体。
- 水井旁有一个赤砂蝎刷新点（1980,540），点击时应点井西侧空地，先进入安全区再用方向键或点击 Boss 重新锁定，避免把重叠怪物当成移动目标。

这套规则把“喝药/走位/撤离/回场”变成可验证的战斗循环，不通过直接降低最终 Boss 生命来掩盖生存问题。

## 状态机

```text
ENTER_MAP 进入地图
  -> CLEARING 清剿普通怪（显示当前数/要求数）
  -> BOSS_REQUIRED 普通怪达标，提示首领名称与首领区域
  -> MAP_CLEARED 普通怪与首领都完成，发放一次性奖励
  -> EXIT_READY 前三图突出显示东侧前进出口
  -> NEXT_MAP 进入下一张地图

赤砂大漠：
MAP_CLEARED
  -> PROTOTYPE_COMPLETE 显示最终完成结算，不再要求寻找出口
```

状态判断不依赖完成顺序：如果玩家先打 Boss，记录 `bossDefeated=true`，继续显示普通怪缺口；普通怪达标后立即进入 `MAP_CLEARED`。Boss 后续自然刷新只影响现场战斗情报，不撤销已获得的地图通关状态。

## 界面信息层级

### 场景右上角主目标

主目标框常驻且只显示当前唯一下一步：

- 步骤 1/3：`清剿区域怪物`，显示精确进度，例如 `6/10`；
- 步骤 2/3：`击败森林巨猿`，明确显示 Boss 名称；
- 步骤 3/3：`前往东侧出口`，明确下一地图名称；
- 最终完成：`纵向切片已通关`，说明四张地图和四名首领均完成。

目标框下方同时保留三项检查清单。完成项用绿色勾选，当前项用金色，未完成项使用空心标记。目标变化使用 `aria-live`，辅助技术可以读出新目标。

### 右侧当前关卡

当前关卡卡片显示地图名、完整通关句、普通怪/Boss 双进度、一次性通关奖励及状态标签。状态标签只有三种：`进行中`、`出口已开启`、`已通关`。

### 区域导航

每张地图额外显示 `未开始`、`进行中 n/N` 或 `已通关`。点击尚未解锁的下一地图时，不只提示出口位置，而是显示当前普通怪进度和 Boss 是否击败。

### 场景出口

- 前进出口未解锁：红色低亮边框，标签为 `未开启 · 完成当前关卡`；
- 前进出口已解锁：金色脉冲边框，标签为 `已开启 · 进入下一关`；
- 返回上一关出口：青色边框，始终可用，标签为 `返回上一关`。

玩家走入未解锁的前进出口时，会被推回安全距离，并收到精确缺口，例如：`前进出口尚未开启：再击败 3 只普通怪物，击败坑道尸皇`。返回出口不受当前地图通关状态限制，避免玩家被困。

## 快捷键规则

`T` 只指向当前地图的前进出口，不再在中间地图错误选择返回出口。前进出口未解锁时，`T` 触发与出口相同的缺口提示；赤砂大漠未通关时提示当前目标，通关后提示四图已经全部完成。

## 保存与恢复

存档按地图保存以下字段：

```json
{
  "kills": 10,
  "need": 10,
  "bossDefeated": true,
  "completed": true,
  "rewardClaimed": true,
  "completionAnnounced": true
}
```

加载旧版仅含 `quest` 的存档时，将当前地图任务迁移到对应地图进度。加载新版存档后，已通关地图、击杀数、Boss 完成状态和奖励领取状态都必须保留。现场怪物与 Boss 会重新生成，但不会重复通关奖励。

| 编号 | 操作 | 预期 |
|---|---|---|
| MC-01 | 新角色进入灰烬村外 | 显示步骤 1/3、0/8、裂碑领主未完成、东侧出口未开启 |
| MC-02 | 未击杀时走入东侧出口 | 不换图，被推回，提示还差 8 只普通怪和裂碑领主 |

| MC-04 | 先杀 Boss、后补普通怪 | Boss 状态保留；普通怪达标时正常通关 |
| MC-05 | 两项目标达成 | 奖励只发一次，目标切换为东侧出口和下一地图 |
| MC-06 | 中间地图按 T | 选择东侧前进出口，不选择西侧返回出口 |
| MC-07 | 返回上一地图 | 无论当前地图是否完成都可返回，不重置已保存的地图进度 |
| MC-08 | Boss 通关后刷新 | 现场显示 Boss 重新出现，地图仍保持已通关和出口开放 |
| MC-09 | 保存、刷新、读取 | 四张地图的独立进度和奖励领取状态保持一致 |
| MC-10 | 击败沙蝎王且普通怪达标 | 显示最终通关结算，不再提示寻找不存在的下一出口 |
| MC-11 | Boss 战低血撤回地图城镇 | 城镇安全区免伤并恢复生命/资源；回到 Boss 区可继续输出 |
| MC-12 | 沙蝎王毒层达到 2 层后进入水井 | 水井安全区净化毒层、恢复生命，尾刺危险区不造成伤害 |

| MC-15 | 每张地图通关后刷新页面 | 恢复到当前已通关地图；地图进度、奖励领取状态和出口开放状态保持 |

## 真实浏览器十次验收

命令：

```bash
ONEKNIFE_RUNS=10 NODE_PATH=/Users/x/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules \
/Users/x/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node \
tests/e2e-ten-clear-runs.cjs
```

驱动只通过选择职业、点击 Canvas、点击怪物、点击安全点、按下 `J/1/2/3/4/R/F/Q/T` 和推进浏览器时钟操作；`?e2e=1` 暴露的快照是只读观测，不提供写状态方法。每一局必须完成 8/10/10/10 只普通怪、对应四名首领、三次前进出口切换；每一关后读取本机存档并真实刷新页面，确认已通关地图恢复成功，最后检查 `#mapObjectiveTitle=纵向切片已通关`、`#mapObjectiveState=全部完成`。

## 正式服务器边界

浏览器原型由本地状态判定。正式多人版本必须由服务器权威任务服务记录击杀、首领贡献资格、地图完成和奖励幂等键；客户端只展示服务器返回状态。Boss 任务仍按有效贡献判定，不要求最后一击。奖励幂等键建议采用 `character_id + map_id + map_revision + clear_reward_version`，防止重连、跨线和重复消息造成多次发奖。
