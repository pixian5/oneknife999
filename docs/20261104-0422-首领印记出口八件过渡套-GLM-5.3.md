# 0.8.25 首领印记出口：八件绑定过渡橙装

## 背景

`docs/07-交易经济与商业化.md` 早把首领印记的出口写定为「**消耗：绑定过渡橙装**」，并给出节奏（30 天约 810 印记、约 37 天集齐八件过渡套）。但 0.8.16 之前 HUD 上那个「首领印记 X / 800」的分母只是遗留展示，玩法里**没有任何消费方**——百图通关实测单轮产出约 4300 印记（战士 4366 / 道士 4310），只进不出。本轮按文档落地真正的出口。

## 设计

- **八件套**：取八个不重复的类别槽（武器/头盔/衣服/项链/腰带/靴子/勋章/玉佩）。左右成对槽（手镯/戒指）不进套装，避免「同款两件」稀释收集感。
- **定价 800/件**（复用了遗留的 800 阈值）：单轮百图 ≈ 5 件、两轮集齐——对应文档「30 天约 810 印记」在原型回合粒度上的取整。
- **固定词缀**：每件 2 条手写词缀（攻击/生命/防御/恢复），兑换是确定收益，不做随机开箱。
- **绑定 + 每部位限兑一次**：`setId = "marks-transition"` + `bound: true`；限兑状态从背包 + 穿戴里按 setId 派生，**不新增存档字段**（`sanitizeItem` 的 `{...item}` 会保留 setId）。
- **入口**：城镇杂货商面板追加 8 行（`data-buy-marks`），与金币商品共用入城守卫（`nearTown()`）与背包 12 格上限。

## 实现

| 文件 | 改动 |
|---|---|
| `config.js` | `MARKS_SET_PRICE` + `MARKS_SET`（8 件数据） |
| `shop.js` | `marksSetItem(slot)` / `buyMarksSetItem(slot, {marks, owned})` 纯逻辑 |
| `main.js` | `buyMarksGood(slot)`：入城守卫 → 限兑/印记校验 → 背包上限 → 扣印记 + 入包 + `persistGame()` + 日志 |
| `render.js` | 商店 8 行、tip 显示印记余额、面板签名加入印记与已兑集合 |
| `input.js` | `[data-buy-marks]` 点击代理 |
| `tests/unit/shop.test.mjs` | 新用例：八槽唯一、印记门槛、限兑一次、物品契约（orange/setId/bound/≥2 词缀） |

## 验证

- `npm run verify` **201/201 全绿**（新增 1 个用例）。
- 浏览器冒烟（公网地址、真 Chromium）：
  - 种 2000 印记 + 站到镇中心 → 按 F 开店：tip「首领印记 2,000」、**8 行**、首行「800 印记」；
  - 点武器行：印记 2000→**1200**、背包 0→1、`setId=marks-transition`、按钮变「已兑换」、toast 正确；
  - **刷新后**：印记 1200 与物品都持久化，武器行禁用，其余部位仍显示「800 印记」；
  - 全程控制台 **0 错误**。

## 经济意义

- 印记从此有真实出口：单轮百图 ≈ 5 件过渡橙装，约两轮集齐八件——与设计文档的节奏对齐。
- 与金币经济正交：金币买消耗品/材料/卷轴，印记换装备，互不替代。
- 套装强度定位在「过渡」：八件合计战力约 1045 + 词缀（攻击 +94 / 生命 +480 / 防御 +16），高于章节掉落、低于终局深渊产出。

## 遗留

- 背包「材料是否占 12 格」语义仍未定案（0.8.16 只把溢出显示诚实化）；兑换受 12 格上限约束，材料多时会挤占装备位。
- 51–80 关难度塌陷与道士前中期生存（0.8.22 归因）仍未动，等待三条设计路径的决策。
