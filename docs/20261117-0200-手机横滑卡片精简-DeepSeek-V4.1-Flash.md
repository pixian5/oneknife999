# 0.8.32 手机横滑卡片精简

## 一、背景

0.8.14 的响应式改造把手机侧栏改成横滑卡片，但卡片固定 96/106px 高、内容 `overflow: hidden`。实测玩家卡内容高度 **225px**，可视仅 94px —— 升级进度条、金币/印记行、难度·图鉴行在手机上永远看不全。0.8.14 的文档把它记为「下一轮」遗留项。

## 二、测量

390×844 视口，玩家卡各行高度：

| 行 | 高度 |
|---|---|
| player-heading（头像+名字+战力） | 63 |
| hero-stats（生命/攻击/防御） | 17 |
| meter-group（升级进度） | 24 |
| 金币 / 首领印记 | 17 |
| statsLine（击杀·死亡·通关） | 15 |
| damage-estimate（普攻期望） | 15 |
| endgame-line（难度·图鉴·套装） | 15 |
| 行间距 | 约 40 |
| **合计 scrollHeight** | **225**（client 94） |

## 三、改动

纯 CSS（`game/game.css` 末尾追加媒体查询，覆盖前面 96/80px 的高度规则）：

- `.side-panel > section` → `height: 172px`；矮屏 `≤620px` 高保留 `96px`
- `.player-card` 内边距 10/12 → 8/10，头像 36px，行距 3px
- 隐藏 `#statsLine`（击杀/死亡/通关）与 `#damageEstimate`（普攻期望）
- 保留生命/攻击/防御、升级进度、金币/印记、难度·图鉴

未改 JS，未动数据与存档。

## 四、验证

| 项 | 结果 |
|---|---|
| 390×844 玩家卡 | `scrollHeight 170 = clientHeight 170`（改前 225 / 94） |
| `ui-layout` 九视口 | 全 PASS，新增「手机视口玩家卡不裁切」断言 |
| `ui-smoke` | PASS（1440 / 390 / 360） |
| `npm run check` / 单测 / Prettier | 全过（208 单测） |

九视口实测画布：桌面 1046×602、平板 432×742、手机 372×481、360 窄屏 342×287、320 矮屏 302×229。

## 五、说明

- 320×568 与 360×640 这类矮屏继续使用 96px 卡片高度，玩家卡仍会裁切 —— 这是为画布留出可玩面积的有意取舍，已在 CSS 注释中写明。
- 若后续要给矮屏也做完整玩家卡，需要把「升级进度 + 金币」折叠成一行紧凑排版，属进一步的信息密度设计。
