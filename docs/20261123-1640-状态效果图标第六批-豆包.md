# 状态效果图标第六批：12 枚状态图标与三轮补拍（0.8.74）

## 目标与背景

游戏内已有 `poison`（中毒）、`slowTimer`（减速）、`stun`（眩晕）、`blindTimer`（致盲）、`armorBreakTimer`（破甲）五类状态，但 HUD 没有独立图标：中毒靠屏幕紫色叠加，破甲在铭牌下写“⚔ 破甲 -15% · x s”，减速/眩晕/致盲没有持续提示。`game/assets` 也没有 status/buff 图标。

本轮补的是状态语义层，不是装备或怪物立绘。一次做满 12 枚，既覆盖现有五类，也为后续灼烧、流血、冰冻、护盾、治疗、狂暴、疾行留资产。

## 生产口径

- 模型：`cogview-3-flash`
- Key：用户提供的 GLM/智谱 Key，只从当前环境 `GLM_API_KEY` / `ZHIPU_API_KEY` 或仓库外 `~/.config/oneknife999/zhipu.env` 读取；不写日志、不写清单、不入库
- 尺寸：`1024×1024` JPEG，RGB，无 alpha
- 统一构图：纯黑或近黑背景，暗铁圆形徽章居中，主体约占画面 64%，四周留黑边
- 统一约束：无文字、无字母、无数字、无水印；强轮廓、强对比、金属浮雕质感
- 水印：`tools/cogview_batch.py` 下载后自动调 `tools/cogview_clean.py`，12 张全部命中右下角区域 `[837,941,1022,1017]`，方式为 `edge-interpolation`

## 补拍过程

首轮 12 张全部返回，但有 3 张不适合直接交付：

1. **03 眩晕**：首轮是战盔 + 三颗金星，但背景棕色石纹，16px 只剩头盔；`03b` 改纯星环又容易被读成“星辉”。最终 `03c` 用倾斜裂纹战盔 + 金色星轨，24–32px 能同时看到头盔与星轨。
2. **04 致盲**：首轮完全没有“盲”的语义，是睁眼红瞳 + 木板铁栅背景；`04b` 加横向布带但瞳孔仍外露，`04c` 变成红宝石铁面，`04d` 出现两个白色高光像双瞳；`04e` 用黑色皮革眼罩 + 闭眼红缝，最终采用。
3. **11 狂暴**：首轮红底光晕 + 砖墙，缩到 32px 会变成红色方块；`11b` 改纯黑底赤红兽首，最终采用；`11c` 红烟过密，16px 糊成一团。

共 9 张补拍候选，全部在 `补拍/`，取舍见 `补拍/README.md` 与 `补拍/候选小尺寸对照.jpg`。

## 尺寸与可读性

新增 `tools/art_status_preview.py`，按固定编号生成两类预览：

- `总览-12张.jpg`：4×3，每格 512px，带编号、状态名与中心符号
- `实际尺寸对照.jpg`：64/32/24/16px 四行 1:1 对照

结论：

- **24–32px 是主力**：HUD 优先按 32px 设计、24px 保底。
- **16px 下 `01/02/05/06/08/10/12` 仍能靠颜色与轮廓辨认**；`03/04/11` 偏弱，不能直接缩图交付，需单独做高对比简化版。
- `02` 与 `12` 都是靴子，靠冰蓝/银蓝与“锁链/羽翼”区分；`07` 与 `05` 都偏红，靠“匕首/盾牌”区分。
- `04` 的“闭眼红缝”是概念化表达，16px 可能被读成两只红眼；若必须 16px，需改“布带完全覆盖 + 无眼球”的符号。

## 未接入与限制

- **没有接入 `game/assets`**，也没有改 `render.js`。现 HUD 仍是中毒屏幕叠加色、破甲文字，没有状态条。
- CogView 只返回 JPEG，无透明通道；要上 HUD 需拍板“黑底方图”是否可接受，或补抠底/透明化流程。
- 12 枚里只有 5 类有现成逻辑，其余 7 枚是预留资产；接入时不要先做空槽位。
- 复杂纹理背景的水印修补仍可能轻微软化；本批 12 张均为黑底/金属，边缘插值无可见残影。
