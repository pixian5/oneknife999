# 20261029-0143 法师 / 道士难度实测（0.6.6 WorkBuddy）

## 背景

0.6.1 的难度调平（行为强度 10 项下调 + 刷怪档位分段）**只基于战士数据**，
法师与道士属验证负债：法师移速 205 / 生命 235（战士 218 / 350），
新增的减速被动（移速 ×0.68）与吸蓝被动对低血量、低防御、慢攻速职业的影响可能完全不同。

本轮目标不是改数值，而是**把这个盲区用实测数据填上**，判定是否需要在后续轮次动刀。

## 环境

沙箱为全新环境（`~/oneknife999` 不存在），按交接提示词完整重建：

| 步骤 | 结果 |
|---|---|
| `git clone`（gitcode） | 成功，`5f7a63f` / 0.6.5，`.git` 172MB |
| `npm install` | 3 个包（playwright 1.63.0 + prettier），依赖极轻 |
| `npx playwright install chromium` | **成功但耗时 25 分钟**（约 170MB，实测 90-150KB/s） |
| `npm run verify` | **159 / 159 单测全绿**，基线健康 |

### 浏览器通道的两个实测结论

1. **npmmirror 镜像救不了这个版本**：`registry.npmmirror.com/-/binary/playwright/builds/chromium/1243/`
   只同步了 `arm64` 两个包，没有 `chromium-linux.zip`（x64）；`chromium-headless-shell` 目录最高只到
   revision 1155。所以本轮无法用镜像加速，只能走官方 CDN 慢速下载。
2. **沙箱自带 Chrome 144 可以直接驱动**：`/usr/bin/chromium` 实为 Google Chrome 144，
   Playwright 1.63 通过 `channel: "chrome"` 可正常启动并读到完整 100 关 catalog。
   为不空等 25 分钟，法师 / 道士首批数据先用它跑；随后用官方 Chromium 153 复跑了波动最大的
   第 19 关做交叉验证（结论见下）。

> 环境注记：交接提示词铁律 5「无头浏览器一律走 chromium」的依据是「沙箱没有系统 Chrome」，
> 本沙箱实际自带 Chrome 144。两种通道都可用，但**探针在 chromium 153 下才是标准基线**，
> 后续轮次应统一用 `ONEKNIFE_CHANNEL=chromium`。

## 方法

```bash
npm run serve &
ONEKNIFE_PROBE_CLASS=mage   ONEKNIFE_PROBE_STAGES=15,19,45 ONEKNIFE_PROBE_RUNS=2 node tests/difficulty-probe.cjs
ONEKNIFE_PROBE_CLASS=taoist ONEKNIFE_PROBE_STAGES=15,19,45 ONEKNIFE_PROBE_RUNS=2 node tests/difficulty-probe.cjs
```

- 不携带 `?fast=1`（伤害 ×25 会让怪在前摇期被秒，数据无效）。
- 装备取本关掉落表前 4 件（`buildStageGear`），等级按主线曲线（`mainlineLevel`）。
- 判定：死亡中位数 ≤6 即 PASS；单次超限只告警，中位数超限才判失败。

## 数据

### 三职业对照（15 / 19 / 45 关，runs=2）

| 关卡 | 战士（0.6.1 基线） | 法师 | 道士 |
|---|---:|---:|---:|
| 15 | 2 死 / 64s | **3 死 / 46s**（2, 4） | **1 死 / 44s**（1, 1） |
| 19（精英档） | 1 死 / 64s | **4 死 / 52s**（5, 2） | **1 死 / 49s**（2, 0） |
| 45 | 0 死 / 63s | **3 死 / 65s**（2, 3） | **1 死 / 45s**（1, 0） |
| 合计（中位数） | 3 | **10** | **3** |

**三职业全部 PASS（≤6 死闸门）**，但难度序为 **法师 > 战士 > 道士**。

法师死亡总数是另外两职业的 3.3 倍；第 19 关出现单次 5 死，距闸门仅 1 次余量，
属波动型临界。道士三关稳定 1 死，偏轻松。

### 法师第 19 关 A/B（同 chromium 153 环境，runs=3）

| 臂 | 死亡中位数 | 耗时 | 单次序列 |
|---|---:|---:|---|
| 行为开启 | 3 | 55s | 3, 2, 3 |
| 行为关闭（`noabilities=1`） | 4 | 42s | 4, 5, 2 |

**关闭行为后死亡不降反升（3 → 4）**，与 0.6.1 第 15 关战士的结论完全同源：
压力来自**刷怪档位构成**，不是行为系统。

第 19 关是章内第 9 关，`spawnTier` 走「后 5 关」分支，9 档全开：

| 档位 | 生命 / 攻击 | 行为 | 刷位 |
|---|---|---|---:|
| tier1 苍月潮骨水鬼 | 550 / 75 | sweep + slow | 2 |
| tier2 苍月蓝鳞海妖 | 570 / 78 | normal + resourceDrain | 2 |
| tier3 苍月礁甲兽 | 590 / 80 | charge + firstHitReduce | 2 |
| tier4 苍月逐浪刀客 | 610 / 83 | multi3 | 1 |
| tier5 苍月鲨卫 | 630 / 86 | charge + enrageLowHp | 1 |
| tier6 苍月礁岩魔龟 | 650 / 89 | normal + meleeReflect | 1 |
| tier7 苍月沉渊海灵 | 670 / 92 | ranged + resourceDrain | 1 |
| tier8 苍月深海巨章 | 690 / 94 | pull + slow | 1 |

行为关闭后耗时反而缩短 13s（无护盾 / 减速 / 拖拽拖慢输出），推进更快 = 更快撞进下一波怪群，
这解释了「关掉行为反而多死一次」的反直觉结果。

### 浏览器通道交叉验证

| 通道 | 第 19 关法师死亡 |
|---|---|
| Chrome 144（`ONEKNIFE_CHANNEL=chrome`） | 5, 2 → 中位数 4 |
| Chromium 153（`ONEKNIFE_CHANNEL=chromium`） | 3, 2, 3 → 中位数 3 |

两组均落在历史波动区间（同一份代码曾测出 0-5 死），**浏览器版本对探针结果无系统性影响**。
但 chromium 153 是标准基线，两批数据合并引用，不重复跑。

## 结论

1. **闸门全过，本轮不改任何数值。** 法师最差的一次（5 死）仍在 6 死以内。
2. **法师是真难点**，根因是属性组合而非行为系统：生命 235（-33%）、防御 10（-55%）、
   攻速 0.86（-39% 出手频率），在 9 档精英怪（atk 89-94）面前几乎没有容错。
3. **道士偏轻松**，骨卫分担仇恨 + 生息法阵自愈 + 符力池大，三关稳定 1 死。
4. **刷怪档位仍是难度主轴**，与 0.6.1 结论一致；`spawnTier` 分段设计经第二次独立验证成立。

## 已知边界

- 只测 15 / 19 / 45 三关，**没有覆盖第 30 / 60 / 75 / 90 关**，中后期曲线仍可能有职业分化。
- 每关 2 次（A/B 3 次）取中位数，样本量偏小；法师第 19 关 5 死 vs 2 死说明单次波动仍大。
- 探针玩家模型是「不菜也不神」的固定策略，不模拟真实玩家的技能取舍与走位水平。
- 未测难度阶梯（烬火 / 灰烬）与无尽深层下的职业差异。
