# 细粒度行为开关与第 30 关归因（0.7.3）

- 日期：2026-10-29 11:18
- 模型：DeepSeek-V4.1-Flash
- 版本：0.7.2 → 0.7.3
- 内容：把「攻击形态 / 被动 / 亡语」拆成三个正交开关，用同种子配对复测第 30 关，定位死亡断层的真实来源

## 一、三个正交开关

`noabilities` 是 0.6.0 的总闸，只能回答「行为系统有没有影响」，回答不了「哪一类行为在杀人」。0.7.3 在 [config.js](../../game/src/config.js) 拆出三个独立开关（仅 e2e 生效，生产恒为 true）：

| 开关 | 关闭的维度 | 语义 |
|---|---|---|
| `noabishapes` | 攻击形态 | 冲锋 / 远程 / 多段 / 重击 / 横扫 / 拖拽全部回落 `normal`（近战、1 段、射程 1.0、伤害 1.0） |
| `noabipassives` | 被动 | 中毒 / 减速 / 护盾循环 / 首击减伤 / 低血减伤 / 反伤 / 致命保留 / 增伤成长等 18 条全部清空 |
| `noabideath` | 亡语 | `deathPoison`（孢子毒区）/ `deathRevive`（残星复起）清空 |
| `noabilities` | 全部 | 保持旧语义：等于上面三个同时关闭 |

接线方式：`main.js` 的 `gateAbilities()` 在 `createEntities` 生成怪时裁剪一次，**不改消费点**——结算、被动、亡语三条链路仍读同一份 `entity.abilities`，开关只是决定这份配置里有几类内容。总闸关闭时三个子开关自动失效，因此旧的消融数据仍然可比。

同时给 `snapshot().entities` 增加 `onDeath` 字段：此前只暴露 `attackShape` 与 `passives`，亡语没有任何 e2e 断言入口，等于「关了也证明不了」。

## 四、结论

1. **攻击形态是断层主因**：关掉形态后三次运行全部落在 0–2 死，中位数 8 → 1，且耗时从 ~81s 降到 ~70s。第 30 关（黑岩矿脉）的怪大量使用 `heavy`（伤害 ×1.35、前摇 ×1.6、带击退）、`charge`（突进 80px + 击退）与 `ranged`（射程 ×1.9），三者的共同点是**扩大交战窗口**：玩家必须在更远的距离或更长的前摇空档里承伤，死亡压力自然集中在这些图。
2. **被动影响中等且噪声大**：中位数 5，但逐 seed 有升有降（11↑ / 5↓ / 3↓）。单次采样波动 0–5 死是探针的已知特性，n=3 还不足以把被动判成显著因素。
3. **亡语几乎无影响**：中位数与基线相同（8 vs 8），三次运行与基线几乎重合（15 死的那次是基线同 seed 也高的噪声）。第 30 关的怪本身就不带亡语（`deathPoison` 属于雾松林与帝陵的怪），这一臂更像「对照组」，用来确认开关不会凭空改变结果。

## 五、同一个 seed 不等于可复现

0.7.2 用同样的 seed 2000/2001/2002 测基线，中位数是 10（15/10/9）；本轮同一份基线代码测出中位数 8（8/7/11）。**代码没有变**（0.7.3 只在开关上加了门控，全开时 `gateAbilities` 原样返回），差异来自帧时序：

- 探针只固定 `Math.random`（mulberry32），怪物的巡逻起点、随机游走仍随每帧 `dt` 推进；
- 主循环 `dt = Math.min(delta, 0.05)`，云电脑 2 核配额下的实际帧率随负载变化，两次运行的模拟时间线并不同步；
- 结论：**seed 能消除「随机数太野」，消不掉「帧时序漂移」**。因此跨会话的数字不可直接对比，A/B 必须同会话、同批次跑完。

这也是本轮把四臂放在同一个后台任务里串行执行的原因。

## 七、下一步

1. **每臂 n≥8**：按当前波动（0–15 死），n=3 只能证明「形态臂显著更低」，证明不了被动臂的真实贡献。计划在 2 核配额下分批跑（每批 ≤6 次）。
2. **形态再拆分**：若要继续追到 `heavy / charge / ranged` 中的具体一条，需要再加 `noshapes-heavy` 之类的开关，或直接在探针里按怪名统计「致死怪」——后者更省事，也更贴近玩家真实死因。
3. **法师对照待决策**：目前只量化战士。法师（235 血、10 防、射程 220）在第 30 关的表现是否同样集中，以及是否值得做生存补偿，需先确认方向再实现。
