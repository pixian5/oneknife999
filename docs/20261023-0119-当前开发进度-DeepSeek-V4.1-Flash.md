## 一、这轮解决的两个玩家反馈

### 1. 「打半天怪升不了级」

**现象**：第一张图连续清怪很久，等级没有任何变化。

**根因**（0.3.1 及之前）：

1. `defeat()` 里击杀经验写的是 `state.player.exp = Math.min(99, state.player.exp + reward.expGain)`——经验永远卡在 99，`applyExperience` 这种结算根本不存在。
2. 真正改等级的只有 `syncCampaignGrowth()`（通关时按累计通关图数重算），所以玩家在关卡内无论杀多少怪都不会升级。
3. HUD 却写着「升级进度」，任务卡也显示 `经验 X/100`，与实际行为不符，放大了「打半天没反应」的观感。

**修复**（0.3.2）：

- `combat.js` 新增纯函数 `applyExperience({ level, exp, nextExp, expGain, levelCap })`：支持一次经验触发连续升级，达到等级上限后经验停在满格不溢出，非法输入安全夹取。
- `main.js` 新增 `currentLevelCap()`：本关可升到的最高等级 = 主线曲线等级 + 1，终局封顶 41；新增 `gainExperience(amount)`：真实加经验、结算升级、发技能点、回满生命与职业资源、播放升级音效、写日志与 toast。
- `defeat()` 改为调用 `gainExperience(reward.expGain)`，删掉 99 截断。
- `syncCampaignGrowth()` 通关结算时保留击杀获得的等级：`earnedLevel = min(玩家等级, 主线等级 + 1)`，再取 `max(主线等级, earnedLevel)`，保证「通关不会把玩家打回低级」。
- 经验产出改为按本关目标数折算：普通怪 `ceil(100 / mapsPerLevel / kills)`，首领 `round(30 / mapsPerLevel)`；首轮进度击杀给满额，清完目标后继续刷怪给 50%，避免「打完目标后刷怪毫无反馈」，同时不让无限刷怪拉爆成长曲线。
- 首关校验：8 只进度怪 × 13 经验 + 首领 30 经验 = 134 ≥ 100，玩家在见到首领前就能升到 Lv.2。

**文档与 UI 同步**：

- 经验条副标题改为「升级进度 · 本关最高 Lv.N」，任务卡经验行改为「经验 X/100（击杀可升级，本关上限 Lv.N）」。
- 升级日志写明「本关最高可到 Lv.N」与「按 K 打开技能」。
- `game/README.md` 的「升级节奏」补充击杀经验规则。

### 2. 「普攻 J 离 1234 太远，改成 X，并支持自定义键位」

**修复**：

- 新建 `game/src/keybinds.js`：
  - `DEFAULT_KEYBINDS`：普攻 `x`、技能 1–4、药水 `q`、拾取 `f`、一刀时刻 `r`、前往出口 `t`、技能弹窗 `k`。
  - `KEYBIND_ACTIONS`：设置面板的动作清单与中文说明（唯一事实源）。
  - `RESERVED_KEYS`：WASD / 方向键 / Esc / Tab / 空格 / Enter 固定给移动与取消，不允许绑定。
  - `isBindableKey()` / `validateKeybindChange()` / `sanitizeKeybinds()`：单字母、数字、F1–F12 可绑定；冲突时提示「该键已被「技能 1」使用」；非法或重复项回退默认与候补键。
  - `loadKeybinds()` / `persistKeybinds()` / `setKeybind()` / `resetKeybinds()` / `keyLabel()` / `actionForKey()`：独立 localStorage key `oneknife999-keybinds-v1`，重置游戏不清除键位。
  - 导出运行时活引用 `keybinds`，input / render 读到的永远是最新绑定。
- `runtime.js` 新增 `keybindCapture = { action: null }`：设置面板点某个动作后进入等待按键，此时其余游戏快捷键全部屏蔽；`Esc` 取消。
- `input.js`：所有动作键改为 `actionForKey()` 查表，不再硬编码 J / 1-4 / Q / F / R / T / K；新增设置按钮、改键按钮委托、恢复默认与关闭事件。
- `render.js`：新增 `renderKeybindPanel()`；普攻角标、技能键角标、药水键、操作提示、技能弹窗提示全部改为 `keyLabel()` 动态读取，改键后立即刷新。
- `index.html` / `game.css`：右上角新增「设置」按钮与键位设置弹窗（行式列表 + 捕获态高亮脉冲 + 恢复默认）。

## 三、百图 e2e 结果

第一次全量跑（`ONEKNIFE_RUNS=1 npm run test:e2e`）在第 29 关失败：`无法把目标 boss-stage_029 移入视野`。原因是测试辅助函数 `moveEntityIntoView` 每次只按单轴、最多 30 次（约 15.6 秒模拟时间），角色从城镇走到首领再中途倒下复活回营地后，剩余次数不足以重新走完全程。这不是升级逻辑回归——前面 28 关的检查点等级与经验全部符合主线曲线（第 1 关 Lv.2、第 2 关 Lv.3 …… 第 28 关 Lv.20）。

修复（只改测试，不改游戏逻辑）：

- `moveEntityIntoView` 支持两个轴同时按住（斜向移动），尝试次数 30 → 60，给「倒下复活后重走」留出余量。
- `ui-levelup.cjs` 同步加固：击杀后目标会被清空，旧脚本只会原地按 X（无目标时按 X 不移动），改为「目标 > 250px 用键盘接近，≤ 250px 再点击并普攻」；连跑 3 次均 PASS。

修正后复跑结果（`npm run test:e2e`，战士）：

## 四、风险与取舍

1. **刷怪经验的收益边界**：本轮只允许「本关上限 = 主线 + 1」，重复刷怪不会无限升级；但清完目标后仍有 50% 经验，玩家可以在低关刷满本级经验再走。若后续要严格锁死，可把重复击杀经验改为 0 或改为只给材料。
2. **e2e 成长断言放宽**：从精确等于主线等级放宽为「主线 / 主线 + 1」，是为了容纳击杀升级；代价是断言对「等级是否会异常偏高」的敏感度下降（仍有封顶 41 与逐关检查点兜底）。
3. **键位冲突**：目前冲突只做提示不发绑定，玩家需要换一个键；没有做「互换键位」功能。
4. **移动端**：键位设置只影响键盘；触屏仍走虚拟摇杆与 HUD 按钮，没有快捷键需求。
5. **旧存档**：键位单独存 `oneknife999-keybinds-v1`，与 v4 游戏存档解耦；重置游戏不会清键位，这是有意为之（避免玩家每次重置都要重设）。
