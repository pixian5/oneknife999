## 三、F50 里程碑首领

F50 是第二个实测里程碑：

- 回响「玄烬帝尊回响」91432 HP，F49 为 36604 HP，实测 **2.498 倍**；F40 为 75431 HP，F39 为 30084 HP，实测 **2.507 倍**。两次尖峰比例几乎一致。
- 代码已明确这是设计值，不是倍率误乘：`game/src/maps.js` 中 `const bossScale = f % 10 === 0 ? 1.25 : 0.55`，里程碑层取 1.25，普通层取 0.55；再叠加深层基础成长，得到约 2.5 倍。
- 里程碑层同时是 `phases: 3`、`phase1Trigger: 0.68`、`phase2Trigger: 0.34`；普通层只有 2 阶段。F50 的三阶段都实际经历。

- F50 用时 137.5 秒，反而略低于 F40 的 146.1 秒，但死亡数从 F40 的 7 次降到 6 次。当前角色数值没有变化，差异来自战斗随机与走位。

## 五、试玩暴露的 UI 矛盾与 0.8.66 修复

F50 完成瞬间，首领情报卡仍显示：

> 已击破 · 0 秒后刷新

但本层已经 `completed`，实际不会重生。原因：`renderBoss()` 只处理「读档后没有首领实体」，没有处理「实时清层后死亡首领仍在场景数组」的情况；`bossAlert` 一直显示到下一次重载才消失。

修复：

- `game/src/render.js` 的 `renderBoss()` 新增 `abyssCleared` 判断：`map.abyssFloor` 且 `mapProgress(map.id).completed` 为真时，直接收起 `#bossAlert`，不再渲染“秒后刷新”。
- 普通百图首领保持原有倒计时逻辑，不受影响。
- 新增 `tests/ui-boss-alert-clear.cjs`：以 F2 两阶段「残星复起」首领为样本，第一次 `defeat` 只复原，第二次才真正击破；断言首领在场时情报卡可见、清层后隐藏、文案不含“秒后刷新”。
- `package.json` 的 `check` 脚本加入该文件，新增 `npm run test:ui:boss-alert`。
- 版本 0.8.65 → 0.8.66；`VERSION`、`package.json`、`package-lock.json`、`game/sw.js` 的 `CACHE_VERSION` 同步。

验证：

- `npm run verify`：250/250，Prettier 通过；日志 `/tmp/verify-0866.log`
- `ONEKNIFE_CHROMIUM_PATH=/usr/local/bin/chromium npm run test:ui:boss-alert`：PASS；日志 `/tmp/ui-boss-alert-0866.log`
- `ui-boss-victory-clear` 与 `ui-abyss-hud-gate` 同步复跑：PASS
- 浏览器强制重载 0.8.66 后，F50 完成态 `#bossAlert` 为 hidden，动态栏仍显示“本层已通关 · 首领与怪物不再重生”
