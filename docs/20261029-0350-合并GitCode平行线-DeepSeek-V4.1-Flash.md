## 三、吸收的关键内容

1. **探针确定性种子**（`tests/difficulty-probe.cjs`）：`ONEKNIFE_PROBE_SEED=1000` 时用 mulberry32 覆盖页面 `Math.random`，第 n 次运行用 `seed+n-1`；不设置则保持原随机行为。日志补 `seed=` 与 `seeds=1000~1002`。
2. **第 30 关死亡断层**：合并基线样本战士中位数 10.5 死（n=6，闸门 ≤6，FAIL）、法师 5.5（n=16，临界）、道士 3（n=10，PASS）；`noabilities` A/B 三职业关闭行为后全部 0 死，断层 100% 依赖行为系统。
3. **`blind`（致盲）被动是死代码**：`monster-abilities.js` 的 `blind: { duration, missChance }` 只在定义处出现，全代码无消费点，玩家从未被致盲。单行为消融实验因此作废。
4. **同种子不可复现**：注入 mulberry32 后同 seed 连跑两次（mage/30 关/runs=3）得到 7,11,6 与 4,8,7——帧时序 / 虚拟时钟节奏也是方差来源，种子只能部分收敛，A/B 仍须每臂 ≥8 次并报全距。
5. **三职业难度序**：法师 > 战士 > 道士（15/19/45 关全部过闸门，法师第 19 关单次 5 死为波动型临界）。

## 五、经验

- **双远程并行开发必须先比提交，不要比版本号**：两边都可能从同一个 `0.6.5` 各自升到 `0.6.6` / `0.6.7`，版本号相同不代表内容相同。`git log --oneline HEAD..gitcode/main` 才是可靠依据。
- **删除基础设施类改动（CI、脚本、部署）要单独确认**，即使对方已按用户指示删除——本线刚刚把 CI 修绿，直接 rebase 会把成果一起抹掉。
- **合并后版本号取「较大的下一号」**，不要沿用任一分支的旧号，避免与已发布的 tag / 记录撞车。
