# 0.8.12 怪物行为「配置 → 结算」契约审计：6 处死参数与语义错配修复

- 日期：2026-11-01 09:10
- 执行：WorkBuddy
- 背景：上一轮（0.8.11）结束时留了四条待办——精英系统、桌面端 HUD 分级、战士第 75 关、被动消费链全量审计。本轮判断「先修正确性，再堆内容」：精英系统会复用现有 19 种被动原语，如果原语本身有参数读不到，新系统会把缺陷成倍放大。因此先做消费链审计。

## 一、审计方法

不靠体感，也不靠「看起来能跑」。三步：

1. **数据自洽**：动态导入 `monster-abilities.js`，遍历 106 条怪物配置，校验被动 id / 攻击形态 / 亡语 id 是否都在定义表内，键名是否互为后缀（`resolveAbilities` 用 `endsWith` 匹配，互为后缀会串味），以及是否有被动定义了却没挂到任何怪。
2. **符号消费**：对 18 个被动逐个 `grep` 其纯函数与状态字段在 `game/src/*.js` 的读取点，区分「有函数封装但没调用」与「真的在用」。
3. **参数级下钻**：这一步才有收获。函数被调用了不代表参数被读了——把 `PASSIVE_PARAMS` 的 19 个参数组逐字段对照实现，找出「配置写了、代码没读」的字段。

## 二、发现

| # | 位置 | 问题 | 性质 |
|---|---|---|---|
| 1 | `rageStack` | 参数名 `attackSpeedPerStack`（攻速），实现却乘到 `damageMult`（伤害）；注释说「加快后续前摇」，但 `attackShapeConfig` 的 `windupMult` 完全没用到层数，主循环第二次调用（决定前摇）甚至没传 `rageStacks` | 语义错配 + 半死参数 |
| 2 | `enrageLowHp.speedBonus` | 配置 `+20% 移速`，`enrageMultiplier` 只读 `damageBonus`，移速分支不存在 | 死参数 |
| 3 | `packHunt.range` | 配置 `range: 260`，`main.js` 统计同类时硬编码 `<= 260`，改配置不生效 | 硬编码覆盖配置 |
| 4 | `deathPoison.duration` | 配置「持续 4 秒」，`resolveOnDeath` 返回 `life: 1.2` 硬编码；hazard 系统本身是「预警 → 引爆一次」，不存在持续伤害 | 死参数 + 文档与实现不符 |
| 5 | `resourceDrain.duration` | 配置 `duration: 3`，抽取资源是瞬时结算，没有任何计时器读它 | 死参数 |
| 6 | `shieldTimer` | 实体初始化写 `shieldTimer: 0`，实际用的是 `shieldCooldown`，全仓库零读取 | 死字段 |

顺带确认：0.6.x 记录的 `blind` 死代码**已在 0.7.1 修复**（`rollBlindMiss` 在 `resolveDamage` 里有调用点），本轮不再重复处理；状态类被动（poison / slow / stun / potionLock / skillLock / blind / resourceDrain）的写入与读取点均完整。

## 三、修复

**1. 修罗怒拆成两个参数**（`monster-abilities.js`）

```js
rageStack: { damagePerStack: 0.05, speedPerStack: 0.06, max: 5 }
```

`attackShapeConfig` 里层数同时进两个出口：`damageMult × (1 + 层数 × 0.05)`、`windupMult × max(0.5, 1 - 层数 × 0.06)`。前摇下限 0.5 是硬保护——5 层之后不能再快，否则重击形态的抬手会短到没有反应窗口。主循环决定前摇的那次调用补上了 `rageStacks`。

强度对比（5 层）：旧实现伤害 +40%、前摇不变；新实现伤害 +25%、前摇 -30%。总 DPS 接近，但压力从「一下更疼」变成「出手更密」，更符合「修罗怒」的名字。

**2. 嗜血追击真的提速**：新增纯函数 `enrageSpeedMultiplier(passives, playerHpRatio)`，与 `enrageMultiplier` 共用阈值与触发条件。`updateMonsterAI` 里只在怪确实带该被动时才计算玩家生命比，避免给全场每只怪每帧跑一遍 `playerMaxHp()`（装备加成）。

**3. 同类半径读配置**：新增 `packHuntRange(passives)`，缺省 260。当前所有怪都用默认值，所以**实际行为不变**，只是配置从此可覆盖。

**4. 毒区参数改名 `delay`**：`resolveOnDeath` 用 `p.delay ?? 1.2`。同时把 `docs/11` 的「持续 4 秒」改成「1.2 秒预警后引爆一次」——这是**改文档而不是改机制**，理由写在下面第五节。

**5. 删除 `resourceDrain.duration` 与 `shieldTimer`**：无消费点的字段直接清掉，避免下次审计再误以为它们有效。

## 四、契约测试：把消费链变成可执行断言

新增 `tests/unit/abilities-contract.test.mjs`（5 条）：

1. 行为表里的被动 / 形态 / 亡语 id 必须都在定义表内；
2. 每个被动至少被一只怪使用（亡语算 `onDeath`），键名不互为后缀；
3. 每个被动 id 必须在 `CONSUMERS` 登记表里登记「结算符号」，且该符号真的出现在结算源码（`monster-abilities.js` 纯函数区 + `main.js`）；
4. `PASSIVE_PARAMS` 每个参数组的字段清单必须与登记表**完全一致**（新增 / 删除字段却没改登记就红），且字段名能在结算源码里找到；
5. 修罗怒必须保留 `damagePerStack` / `speedPerStack`，旧的 `attackSpeedPerStack` 必须不存在（防止有人改回去）。

为什么不用「自动发现死字段」？因为 `ratio` / `max` / `chance` / `duration` 这类通用词在源码里遍地都是，纯文本扫描无法证明「本被动读的就是它」。所以真正起作用的是第 3、4 条的**登记即声明**：新增参数必须人工想清楚在哪被消费，扫描只做兜底。这个局限写进了测试文件头，不假装它能做到更多。

## 五、取舍：毒区为什么改文档而不是改机制

`docs/11` 原文写「半径 90、伤害 8、持续 4 秒」，但 hazard 系统的契约是「1.2 秒预警 → 引爆一次」，渲染（倒计时圆环按 `h.life / 1.2` 算进度）、首领危险区、探针的 `hazardStats` 全建立在这个模型上。要改成持续毒区，需要新增一条渲染分支、每跳结算、以及在探针里区分「引爆命中」与「持续命中」。

而收益侧：8 点/跳的毒伤在第 2 章（玩家血量约 200）之外几乎没有存在感，第 10 章的孢子怪更是可以忽略。为一个数值上无意义的差异去动所有首领共用的危险区契约，风险大于收益。

所以本轮把文档对齐到实现，并在 `docs/11` 写明原因。这是**唯一一处「改文档而非改代码」**，其余五项都是代码向文档靠拢。

## 六、文档同步

`docs/04-地图怪物与BOSS.md` 的行为表还停留在 0.7.5 下调前（heavy 伤害 ×1.35 / 击退 30 / 前摇 ×1.6、ranged 射程 ×1.9……），被动数量写成「19 种」（实际是 16 种被动 + 2 种亡语）。本轮按 `ATTACK_SHAPES` 实际值重写该表，并补上此前从未记录的 `gateMult`（出手后全局闸门系数）。
