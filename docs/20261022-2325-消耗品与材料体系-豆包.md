# 0.3.0 消耗品与材料体系

> 轮次：0.3.0（20261022-2325）· 版本 0.2.9 → 0.3.0
>
> 定位：把材料从「能掉、能消耗」升级为完整闭环——**来源（普通怪/首领掉落 + 拆解）→ 用途（强化消耗）→ 可见性（堆叠 ×N）→ 一致性（任务奖励可配置化）**。纯本地实现，零下载。

## 一、现状研究（改动前）

- **已有**：手工图（1-4 关）物品池有 `黑铁矿石` 等材料；生成图（5-100 关）有 `首领魂核`（slot: material）；强化已检查并消耗材料（`enhanceQuote` 检查 `inventory.some(slot==="material")`，`enhanceItem` 用 `findIndex + splice(1)` 扣 1 件）；`computePickup` 对材料走 `toInventory`（占 12 格背包）；`equipItem` 拒绝材料。
- **缺口**：
  1. 材料不堆叠——同名材料各占一格，基础材料会快速占满 12 格背包；
  2. 无拆解系统——过时装备只有「卖/换装」两种去处，docs/03 明确「拆解返还 50% 基础强化材料」；
  3. 任务奖励硬编码——`checkMapCompletion` 写死 `gold += 60; marks += 8`，任务链任务卡文案同样硬编码，改一处忘一处会漂移；
  4. 生成图普通怪会掉橙色 `首领魂核`，缺少普通怪的基础材料来源（docs/03：普通怪 -> 白/蓝、基础材料）。

## 二、实现（全部纯本地）

### 1. config.js：奖励与材料常量

- `QUEST_REWARD = { gold: 60, marks: 8 }`：通关奖励唯一事实源。`checkMapCompletion` 发放与任务链任务卡展示同源，消除硬编码漂移。
- `BASIC_MATERIAL`（黑铁矿石，blue，value 30，desc「+8 起强化消耗 1 件；可堆叠」）：拆解返还的基础材料模板，与生成图掉落的「黑铁矿石」同名同品质 → 掉落与拆解共用堆叠。

### 2. drops.js：三个纯函数（可单测）

- `stackMaterial(inventory, drop)`：拾取材料时合并同名材料 `count+1`，首件写入 `count: 1`；非材料直接追加。
- `salvageReward(item)`：装备拆解返还 `1 件 BASIC_MATERIAL + 10% 价值金币`；材料/消耗品/货币不可拆解（返回空）。
- `normalizeInventory(inventory)`：合并历史/迁移存档中重复的同名材料（旧条目无 count 视为 1 件）——**存档恢复路径也过一遍**，保证堆叠在运行时始终成立（否则只有拾取路径堆叠，旧档恢复后仍是多格）。

### 3. main.js

- 拾取：`drop.slot === "material"` 走 `stackMaterial` 并 log「材料已堆叠」；装备仍 push。
- 强化消耗：`material.count > 1 ? count-1 : splice 移除`（堆叠后 count 归零才删条目）。
- 新增 `salvageItem(itemId)`：移除装备 → 返还材料（`stackMaterial` 并入已有堆叠）+ 金币 → log + toast + 存档。
- `checkMapCompletion`：`gold += QUEST_REWARD.gold; marks += QUEST_REWARD.marks`，通关 log 文案同步常量。
- 存档恢复：`state.inventory = normalizeInventory(saved.inventory)`。

### 4. render.js / input.js / audio.js / maps.js

- `renderInventory`：材料格显示 `×N`（不显示无意义的战力 0）；装备格新增「拆」小按钮（`data-salvage-id`）；背包签名含 count（堆叠变化触发重渲染）。
- `input.js`：背包点击委托——`closest("[data-salvage-id]")` 优先拆解，否则穿戴。背包格由 `<button>` 改为 `<div>`（嵌套 button 非法 HTML）。
- `audio.js`：新增 `salvage` 音效（双音下滑）。
- `maps.js`：生成图物品池追加 `黑铁矿石`（基础强化材料，普通怪可掉）；`首领魂核` 保留为铸魂类材料（desc 已标注首领铸魂）。

## 三、验证

### 单测（69 全绿，新增 6 例）

- `stackMaterial`：同名合并 count / 首件写入 count=1 / 保留首件 id；不同名不合并、装备不写 count。
- `salvageReward`：返还 1 黑铁矿石 + 10% 价值金币；材料/消耗品/货币/null 返回空。
- `normalizeInventory`：恢复时合并重复同名材料（无 count 旧条目按 1 件计）。

### 浏览器专项验证（一次性脚本，验证后已删除）

注入存档（+7 武器 + 黑铁矿石×2 独立条目 + 旧铁剑）：
1. 恢复后材料合并为 1 格显示 `×2` ✓（normalizeInventory 生效）；
2. 点击旧铁剑「拆」→ 材料 `×3`、背包 2/12→1/12（返还材料并入已有堆叠）、金币 +12 ✓；
3. 强化武器 +7→+8（materialFromLevel=8）→ 材料 `×2`（消耗 1 件）✓。

三视口 UI 冒烟 + 渲染/输入回归全 PASS。

### 模拟器对照（balance）

本轮改动后模拟器数据与 0.2.8 逐关不同（stage_007 起）——**原因是生成图掉落池新增黑铁矿石条目改变了同种子随机映射**（`mapDrops[floor(random*len)]` 索引变化），非策略/数值问题。重新评估：
- 三职业 100 关全部通关（stage_100 三职业均在）；无单关死亡 >3（最大 2，战士第 3 关）；
- 单关总耗时持平：战士 23s / 法师 32.7s / 道士 23s（0.2.8：23s / 32s / 23s）；
- 后期（61-100 关）三职业 0 死亡；最终武器战力略增：战 247 / 法 207 / 道 251（0.2.8：212 / 192 / 236）；
- **数值平衡判定不变，不改任何游戏数值**。

## 四、调试记录与教训

1. **存档恢复路径同样需要规范化**：首版只做了拾取路径堆叠，注入「黑铁矿石×2 独立条目」的存档恢复后仍显示 ×1×1 两格——`normalizeInventory` 补齐后恢复即合并。
2. **同种子模拟器对掉落池结构敏感**：给地图物品池加条目会改变 `mapDrops` 索引映射，即使随机序列不变，掉落结果整体改变。结论：**改掉落池必须重跑模拟器对照**，不能凭「材料不占背包」推断无影响。
3. **HTML 嵌套 button 非法**：背包格原为 `<button>`，内部再放「拆」`<button>` 会被浏览器拆 DOM——改为 `<div>` 承载，事件委托用 `closest` 不受影响。
4. 存档校验要求 `classId` 字段（`readSavedGame` 检查 `CLASSES[parsed.classId]`）——浏览器注入测试存档必须带 `classId`，否则游戏按新档重开。

## 五、设计取舍

- **材料堆叠不设上限**：原型阶段基础材料占 1 格 + count 无限，简化且解决占格问题；多人版如需交易/上架再引入堆叠上限。
- **强化材料不区分等级**：黑铁矿石与首领魂核都是「1 件材料」门槛（`enhanceQuote` 不按材料质量分档）。docs/03 的「+8 起增加同区域材料」在本原型简化为统一材料门槛，铸魂系统（魂核用途）留给多人版。
- **拆解返还 10% 金币**（docs/03 是 50% 基础材料 + 少量金币）：基础材料 100% 返还 1 件（50% 语义在 1 件粒度下取整），金币按价值 10%。
