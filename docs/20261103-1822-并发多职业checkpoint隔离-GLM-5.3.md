# 0.8.21 并发多职业跑的 checkpoint 隔离

## 背景

目标：三职业 × 全部 100 关的完整验证。战士已有两次完整 PASS（0.8.19/0.8.20），法师与道士**从未跑过百图**。沙箱单次运行上限 480 分钟，两轮串行（各约 80–90 分钟）在剩余窗口内来不及 → 改为 `ONEKNIFE_CONCURRENCY=2` 并发跑法师 + 道士。

并发暴露一个断点续跑的缺陷：checkpoint 文件名为 `journey-${ONEKNIFE_RUN_INDEX || 0}.json` —— 读的是**环境变量**而非真实的 `runIndex`，并发时两个职业都写 `journey-0.json`，互相覆盖，续跑会拿错档。

## 修复

- checkpoint 文件名改为按 `runJourney(browser, runIndex)` 的实际索引生成：`stateFile(runIndex)`；
- `writeCheckpoint / readCheckpoint / clearCheckpoint` 全部带 `runIndex` 参数；
- 三个调用点（runJourney 头部读取、过图后写入、通关后清理）同步更新。

并发语义：`journey-0.json` = 第 1 个职业（mage），`journey-1.json` = 第 2 个（taoist）；某轮无 checkpoint 时该轮全新开跑，互不影响。

## 验证

- `node --check` + prettier + `npm run verify`；
- 法师 + 道士并发百图（自愈循环）双 PASS（详见轮次汇报）。
