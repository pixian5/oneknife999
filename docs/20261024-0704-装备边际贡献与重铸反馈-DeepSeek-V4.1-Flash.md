# 装备边际贡献与重铸反馈（0.4.0）

> 模型：DeepSeek-V4.1-Flash｜时间：2026-10-24 07:04

## 一、问题

0.3.8 加了角色三围（生命 / 攻击 / 防御），但玩家仍然无法在**换装前**判断一件装备值多少：

- 背包与已穿戴槽位的提示只有「有效战力 + 词缀文本」，看不出换上去之后三围会怎么变；
- 重铸是纯随机，成功后只有一行日志，面板上没有任何「刚刚变的是这件」的落点；
- 重铸面板也没标出「本件贡献」，玩家不知道该重铸哪件、值不值得花 180 金 + 1 张卷。

## 二、实现

### 1. `config.js` 新增 `equipmentTotals(equipment)`

按 12 部位一次算出 `{ power, hp, defense }`（有效战力 / 生命加成 / 防御加成），把「装备汇总」收敛为唯一入口。`runtime.js` 的 `equipmentHp()` / `equipmentDefense()` 保留原样（它们是 state 读取器），但预览与面板不再各写一套减少逻辑。

### 2. `runtime.js` 新增两个纯派生函数

```js
// 单件贡献：攻击按伤害公式的 0.9 系数折算
equipmentItemStats(item) -> { attack, hp, defense }

// 换装预览：把某件装备换到对应部位后，三围 before / after
previewEquipStats(item) -> { slotKey, before, after } | null
```

`previewEquipStats` 的 before 取当前 `state.player.equipment`，after 用 `{ ...equipment, [item.slot]: item }` 覆盖同部位，再套**与 `renderPlayer` 完全相同的公式**：

- 攻击 = `round(hero.attack + level×4 + Σ有效战力 × 0.9)`
- 生命 = `hero.hp + level×18 + Σ部位固定生命 + Σ生命词缀`
- 防御 = `hero.defense + Σ防御词缀`

### 3. 三处提示

| 位置 | 新增内容 |
|---|---|
| 已穿戴槽位 tooltip | `本件贡献：攻击 +18 · 生命 +60 · 防御 +15` |
| 背包装备 tooltip | `装备后：攻击 73→118 · 生命 446→506 · 防御 37`（同部位已穿时显示旧→新，差值 0 只显示单值） |
| 城镇杂货商重铸行 | 词缀文本下方追加 `本件贡献：…`，并保留重铸报价 |

### 4. 重铸高亮

`main.js` 的 `reforgeEquipped` 成功后写入瞬态 `state.reforgePulse = { slotKey, until: performance.now() + 2000 }`；`renderShopPanel` 把「未过期的脉冲部位」纳入脏签名，对应行加 `.pulse` 类（`game.css` 的 `reforge-flash` 动画 0.9s × 2）。到期后签名变化自动重建并移除动画类，不需要额外定时器。成功提示也改为「旧词缀 → 新词缀」（此前 Toast 只显示新词缀）。

## 三、验证

浏览器实测（战士 Lv.5，穿防御 +15 皮甲，背包放攻击 +10 / 生命 +60 铁剑）：

| 项目 | 实测 |
|---|---|
| 背包装备 tooltip | `装备后：攻击 73→118 · 生命 446→506 · 防御 37` |
| 实际穿上后三围 | 攻击 77→122、生命 446→506、防御 22（与预览差值一致，整数取整差异来自面板四舍五入） |
| 已穿戴槽位 tooltip | `本件贡献：攻击 +18 · 生命 +60 · 防御 +15` |
| 重铸成功 | 日志 `防御 +15 → 攻击 +4`；对应行 `.pulse` 出现，2.3 秒后自动消失 |
| 重铸后槽位 tooltip | 自动更新为 `攻击 +4 / 有效战力 24 / 本件贡献：攻击 +22 · 生命 +60 · 防御 +0` |

发现并修复的脏签名缺陷：`renderEquipment` 原签名只含 `id:enhance:blessing`，重铸改变词缀后标题不刷新；`renderInventory` 原签名不含已穿戴装备，换装后背包预览停留在旧对比值。两处都把词缀 / 已穿戴状态纳入签名——这是 0.3.8「签名必须覆盖所有被展示的值」的同一类问题。
