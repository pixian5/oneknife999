# 0.8.42 手工实测：装备描述与真实属性不一致

- 时间：2026-11-21 16:08 UTC（北京时间 2026-11-22 00:08）
- 模型：DeepSeek-V4.1-Flash
- 环境：CodeArts 云电脑容器（aarch64，2 核），本地 `python3 -m http.server 8080`
- 基线：**0.8.42 / `b6204df`**，`game/` 未改动（本轮只测不改）
- 方式：**手工操作**。用 Playwright 逐步驱动浏览器（不是 `tests/` 里的任何脚本），每一步操作后读页面 DOM、HUD 文本、战斗日志与存档状态，再决定下一步；其中装备属性结论同时用源码交叉验证。

## 一、结论

**游戏主流程可用，但发现一个会误导玩家的装备数值缺陷（P1）。**

- 战靴类装备描述里的「防御 +N」「移速 +N」**不产生任何实际属性**
- 背包预览把「有效战力」按 ×0.9 折算成**攻击**，于是战靴显示「攻击 41→61」
- 玩家实际得到的只有「攻击（战力折算）」与「有效战力」，防御/移速/生命都不变

其余系统（战斗、引导、掉落、技能升级、首领、通关、存档、换图、移动端、图鉴、商店）均正常，全程 **0 console error / 0 pageerror**。

## 二、缺陷证据

### 2.1 实测数据（两次独立掉落，结论一致）

装备「采药人短靴」拾取后，背包格 title 原文：

```
采药人短靴：防御 +14 · 移速 +6；有效战力 22
装备后：攻击 41→61 · 生命 386 · 防御 22
```

第二次带词缀的同名靴子：

```
采药人短靴：防御 +14 · 移速 +6；词缀：生命 +13；有效战力 22
装备后：攻击 65 · 生命 404→417 · 防御 22
```

穿戴日志与背包变化（说明穿戴动作本身成功）：

```
拾取 采药人短靴，点击背包查看属性。
穿戴 采药人短靴，有效战力 22。
```

背包 `1/12 → 0/12`，装备进入对应槽位。

**矛盾点**：

1. 描述写「防御 +14」，但预览「防御 22」不变、HUD `defenseStat` 也不变；
2. 描述写「移速 +6」，游戏内没有任何移速属性可加（全程只在怪物技能里出现「移速」字样）；
3. 描述完全没提攻击，预览却「攻击 41→61」（+20）。

### 2.2 源码根因（三处）

| 位置 | 代码事实 |
|---|---|
| `game/src/maps.js:497` | 采药人短靴定义：`{ name, slot:"boots", power:22, desc:"防御 +14 · 移速 +6" }` —— **只有 `power` 与描述文案，没有 defense/speed 字段** |
| `game/src/config.js:585,590` | `equipmentTotals().defense` 只累加 `equipmentDefenseBonus(item)`，而它只统计 `affixes` 中 `key === "defense"` 的条目；战靴的 affix（若有时）是 hp/attack，不会加防御 |
| `game/src/runtime.js:243` | 预览攻击公式：`hero.attack + level*4 + **totals.power * 0.9** + bonus.attack` —— 把装备「有效战力」直接折算进攻击 |

结论：`desc` 里的防御/移速是**纯描述字符串**，不参与结算；而 `power` 被当成了攻击加成。两个方向的误导叠加，玩家无法从 UI 判断这件装备到底加了什么。

### 2.3 影响

- 玩家按提示以为穿上战靴「变硬 + 跑得快」，实际只多了攻击（战力折算），防御与移速都没变
- 防具类（衣服/头盔/靴子）都存在同类描述的，只是本轮只真实掉落到了靴子
- 预览与实际面板一致（都按 `power*0.9` 算攻击），所以**不是显示 bug，而是数值设计/文案与结算脱节**

### 2.4 建议

1. 给 `maps.js` 的战靴/护甲补 `defense`/`speed` 字段，并让 `equipmentTotals` 纳入；或
2. 保留现状但把 `desc` 改成与结算一致（例如「战力 22 · 攻击折算 +20」）；
3. `previewEquipStats` 的攻击公式去掉 `totals.power * 0.9`，改用真实攻击字段（否则任何装备都会显示加攻击）；
4. 补单测：装备前后 `equipmentTotals().defense/speed` 与 `desc` 声称的数值一致。

## 三、次要观察（P3，单次复现，需再验）

**拾取瞬间 HUD 背包计数与 DOM 不同步**：

- 一次拾取后立刻读取：`#inventoryCount = "0/12"`，但 `#inventoryGrid.innerHTML` 已经包含该装备
- 约 1 秒后再读变为 `1/12`
- 同一轮「立刻点击背包」没有触发穿戴；放慢到 1.2 秒后点击则成功（两次掉落均成功）
- 判断：更像渲染/HUD 更新时序，而不是穿戴逻辑缺陷；快速连点的玩家可能丢掉一次点击，建议在拾取后统一走一次 `renderAll()` 或先更新计数再渲染格子
