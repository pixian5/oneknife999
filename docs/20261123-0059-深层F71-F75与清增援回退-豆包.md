## 一、0.8.68 的两项工具改动

### 1. 清增援 A/B：结论是“更差”，已回退

F70 的 19 死里有 16 次来自首领召唤增援，原计划在首领阶段先清最近增援。第一次实现“增援 ≥2 就清”，F71 实测首领 HP 长时间停在 18456，因为“清一只、召一只”把 boss 输出饿死。随后改为“清一只增援后立刻回头打一轮 boss”，boss 血量能正常下降，但 A/B 数据仍明显差于只打 boss：

| 层 | 清增援策略 | 只打 boss | 差异 |
|---|---:|---:|---:|
| F71 | 185.9s，死亡 196→205（+9） | 122.1s，死亡 196→201（+5） | 慢 63.8s（+52.3%），多死 4 |
| F72 | 192.9s，死亡 205→216（+11） | 179.1s，死亡 201→210（+9） | 慢 13.8s（+7.7%），多死 2 |

前两层合计：清增援 378.8s / +20 死，只打 boss 301.2s / +14 死；清增援慢 20.5%、多死 30%。最终把 `run_abyss.py` 回退到只锁 boss，未提交清增援代码。

结论：**“真人会先清增援”不等于“自动脚本追着单只增援点杀”更优**。脚本每次切目标都要重新走位、点击、吃一轮技能；而 `combo` 已经包含 4/3/2/1 四个范围技能，锁 boss 时范围技能仍会扫到近身增援。当前角色的正确打法应是“锁 boss + 范围技能顺带清”，而不是逐个点杀。

### 2. 单实例锁

此前同时启动了 `run_abyss` 的多个进程，两个 bot 同时操作同一页面，键盘/鼠标事件互相打断，日志重复、层数据失真。0.8.68 在 `tools/run_abyss.py` 增加 `saves/.run_abyss.lock`：

- 启动时写入当前 PID；发现锁内 PID 仍存活则拒绝启动。
- 进程退出时用 `atexit` 删除自己持有的锁，避免误删后来实例的锁。
- 实测第二个进程立即报“已有 run_abyss 在运行（PID 2255），拒绝重复启动”；本轮全程只有 1 个 bot，结束后锁文件自动消失。
- `.gitignore` 已加入 `saves/.run_abyss.lock`。
- `python3 -m py_compile tools/run_abyss.py` 通过；`npm run verify` 250/250、Prettier PASS。

## 三、同章节十年对照：HP 只涨 14%，时间和死亡涨得更凶

F71–F75 与 F61–F65 都落在第 1–5 章，可直接对比：

| 层对 | HP 倍率 | 用时 | 死亡 |
|---|---:|---:|---:|
| F71 / F61 | 1.147 | 122.1s / 68.4s | +5 / +2 |
| F72 / F62 | 1.145 | 179.1s / 80.0s | +9 / +3 |
| F73 / F63 | 1.143 | 120.7s / 105.4s | +5 / +5 |
| F74 / F64 | 1.141 | 105.1s / 108.5s | +6 / +4 |
| F75 / F65 | 1.139 | 223.6s / 106.3s | +13 / +4 |

- HP 倍率稳定在 **1.139–1.147**，与 `abyssMultipliers(f).hp = 1 + f*0.14` 的十年 +14% 一致。
- 但五层总用时 750.6s 对 468.6s，**+60.2%**；死亡 +38 对 +18，**+111%**。
- 攻击倍率 `1 + f*0.07` 也从 F61 的 5.27 涨到 F71 的 5.97，十年 +13.3%；玩家仍是 41 级、1583 HP、909 攻击、26 防御，没有同步成长。
- 单看 F73/F74 仍接近上一轮（120.7s 对 105.4s、105.1s 对 108.5s），F71/F72/F75 的尖峰更像“高伤首领 + 无药水 + 死亡回跑”的叠加，而不是全局线性变慢。**不能只用五层平均就下“深层失控”结论。**

## 四、被忽略的补给箱：五层 `resourceClaimed` 全是 false

每层完成 JSON 都有：

```json
{"completed": true, "resourceClaimed": false, "siteClaimed": false}
```

`run_abyss.py` 只打小怪和首领，从不按 F 搜索秘藏补给箱。0.8.65 的深层补给箱 +2 瓶药水因此从未被脚本拿到；F75 结束只有 1 瓶，是沿途掉落。深层地图明确提示“F 搜索秘藏补给箱”，真人会顺路开箱，脚本不会。

这使 F71–F75 成为“**无补给箱口径**”：药水长期 0–1，死亡后只能回营地重跑，死亡与用时都会被放大。下结论前必须先把开箱纳入工具，否则无法区分“数值太难”与“脚本不补给”。
