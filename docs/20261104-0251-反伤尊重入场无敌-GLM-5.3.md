# 0.8.23 反伤尊重入场无敌 + 击杀者归属

## 根因（0.8.22 遗留问题的最终答案）

0.8.22 定性「烬火章 41-50 是全职业入场爆发墙，首死 1s、Boss 满血 P1、击杀者大量『未知』」。本轮继续深挖发现两层真相：

1. **入场保护早已存在**：`loadMap` 主路径无条件 `state.player.invulnerable = 3`（还回满血、压住仇恨获取）。此前设想的「新增入场保护」根本不需要。
2. **反伤绕过无敌**：近战反伤的扣血路径（`main.js` 反伤结算）不检查 `invulnerable`，也不写 `lastKiller`、不进承伤记账。玩家在 3 秒保护窗口内攻击带 `meleeReflect` 的怪，会被自己伤害的 25% 弹死——配合探针 `?fast=1` 的 25 倍伤害放大，一巴掌拍死自己。这就是：
   - 「首死 1s」：无敌窗口期内死（保护形同虚设）
   - 「击杀者未知」：反伤路径不写 `lastKiller`
   - 「法师也死」：`meleeHit` 按**攻击种类**判定（普通/破甲/冲锋），三职业的普攻都是「普通」，机器人主用普攻 → 全员吃反伤

## 修复（规则一致性，非数值调整）

1. `reflectDamage(passives, damage, { invulnerable })`：无敌窗口内返回 0——保护窗口的语义就是「这段时间不掉血」。纯函数，新增两条单测断言。
2. 反伤调用点：传入 `state.player.invulnerable`；`recordDamage("反伤", ...)` 单独记账（探针的来源统计从此能看见反伤）；致死时 `lastKiller = ${target.name}·反伤`。

## 对难度的预期（待探针复测）

无敌窗口内的自杀消失；窗口结束后机器人仍会贴脸拍反伤怪，预期死亡中位下降但不清零。真实玩家（无 fast 放大、会看 `-N` 飘字换目标）受影响远小于机器人。复测：战士/道士 @41 探针 n=3 对比 0.8.22 基线（4 / 6）。

## 验证

- `npm run verify` 200/200 全绿（含新断言）。

## 复测结果（n=3，修正后）

| 探针 | 修正前 | 修正后 | 变化 |
|---|---|---|---|
| 战士@41 | 4 死 / 承伤 4713 / 首死 1s | **3 死 / 4813 / 首死 1s** | 死 -1 |
| 道士@41 | 6 死 / 承伤 12314 / 首死 1s | **2 死 / 3370 / 首死 5s** | 死 -4，承伤 -73% |

- 击杀者归属生效：`killers=烬火熔岩奴·反伤x2 / 烬火烬甲巨虫·反伤x1`——「未知」彻底消失，反伤成为可读死因。
- 道士改善最明显（6→2，承伤 -73%，首死 1s→5s 越过了 3 秒保护窗）。
- 战士仍死 2–3 次：**无敌窗口结束后贴脸拍反伤怪**的正当惩罚（荆棘机制的设计意图），机器人不会“看到 -N 就换目标”。真实玩家可规避；若要进一步降低，方向是改进探针躲避逻辑，而不是削弱荆棘。

## 结论

0.8.22 的三个谜团（首死 1s / 未知击杀 / 法师也死）由「反伤绕过入场无敌 + 无击杀者归属 + fast ×25 放大」统一解释；本轮规则一致性修复后，机器人层面的 41 关死亡中位 4/6 → 3/2。
