# 产品总纲

> 当前浏览器原型的可玩范围已扩展为 10 章、100 张连续关卡地图，具体可达目录、成长曲线和实测证据以 [14-百图关卡与成长曲线.md](14-百图关卡与成长曲线.md) 为准。本文件中早期的 16 张地图是正式多人版本的区域概念基线，不代表当前原型的关卡数量。

## 产品定位

《一刀999》不是独立副本制 ARPG，而是持续存在的传奇类 MMORPG。一个服务器中的玩家共享地图资源、BOSS 刷新、装备市场、敌友关系和王城历史。装备价值来自稀缺、流派用途、可交易性和争夺故事。

## 核心玩家

第一核心人群是喜欢刷怪爆装、战法道、行会战争的成熟玩家；第二人群是喜欢交易、收集和经营装备的轻战斗玩家；第三人群是每天 20~60 分钟、周末愿意参与组织活动的移动端玩家。

不以重度副本背板、卡牌构筑或赛季清档玩家为主要目标。

## 核心循环

### 60 秒

找到刷怪点 -> 判断怪物与敌对玩家 -> 击杀 -> 查看地面掉落 -> 拾取或争夺 -> 决定继续深入还是回城。

### 30 分钟

完成一个明确目标 -> 获得技能、装备或材料进度 -> 参与一次精英/BOSS/遭遇战 -> 整理和交易 -> 设置下一件装备追求。

### 一周

提升等级与装备 -> 加入行会并参与据点 -> 准备王城物资 -> 周三资格战 -> 周六王城战 -> 分红和重设敌对目标。

## 独有卖点

### 一刀时刻

玩家完成职业职责积累破势槽，槽满后强化下一次核心技能。第一次剧情触发固定显示 999，之后全部使用真实伤害。战士表现为单次斩击，法师把多段法术压缩成一次爆发，道士引爆毒并联动召唤物。

一刀时刻不影响 BOSS 最后一击归属，不绕过 PvP 控制递减，不在商城出售独占词缀。

### 服务器历史

九章主线和王城结果共同写入服务器年表。结果影响事件、NPC、王城设施和外观，不删除玩家资产或封锁地图。

## 内容支柱

1. 野外刷怪与精英巡逻。
2. 地图 BOSS 和固定世界 BOSS。
3. 三职业组队与职业技能书追求。
4. PK、红名、悬赏和死亡爆装。
5. 行会据点、资格战和王城战。
6. 玩家摆摊、拍卖和装备生产消费。

## 首发范围

- 1~100 级和 1 转入口。
- 战士、法师、道士三个职业。
- 16 张地图、14 个区域 BOSS、1 个终局 BOSS；灰烬村没有 BOSS。
- 300 件装备、6 套套装、12 个装备部位。
- 单服目标同时在线 800 人；王城和世界 BOSS 实例上限 240 人。
- 移动端优先；团队达到 18 人以上时双端同步首发，否则 PC 延后。

## 不做事项

- 不直接出售顶级装备、技能书、强化材料、等级、转生和 PvP 属性。
- 不用赛季清空核心资产。
- 不做无风险无限挂机产出高级装备。
- 不让城主封锁普通玩家主线、基础职业技能和交易所。
- 不复制既有传奇产品的专有名称、地图、美术、怪物、技能和音效。

## 规格使用说明

本卷回答“做什么、给谁做、什么不能做”。技能帧、装备词缀、掉落权重等可直接执行的数值，以
[11-数值配置基线.md](/Users/x/code/oneknife999/docs/11-数值配置基线.md) 为唯一事实源；本卷中的
示例只用于说明验收口径。产品、程序、美术、运营和 QA 发现冲突时，必须先记录冲突编号，不能在
客户端或活动配置中临时覆盖。

### 决策优先级

1. 资产安全高于即时爽感：装备、金币、交易和死亡掉落必须可追溯、可回滚。
2. 传奇核心高于泛化 MMO：野外刷怪、地面爆装、自由 PK、行会战争必须在首发可玩。
3. 选择有代价但不锁死内容：剧情选择改变路线和外观，不永久剥夺职业、地图和核心交易。
4. 付费只买便利和表达：任何付费功能都不能改变 PvP 胜率、BOSS 归属或高阶装备上限。
5. 低端设备可读优先：特效可以降级，敌我、危险、掉落品质和倒计时不能消失。

## 产品目标与非目标

### 12 个月目标

| 目标编号 | 目标 | 可观测指标 | 验收窗口 |
|---|---|---|---|
| G-01 | 让新玩家在首日理解“刷怪、爆装、变强、交易、争夺” | 首日完成五类行为的账号比例 >= 55% | 开服第14天 |
| G-02 | 让成长有下一件明确追求 | 20级以上玩家装备详情页次日回访 >= 35% | 每周 |
| G-03 | 让野外冲突可恢复 | 首次死亡后10分钟内再次离开安全区 >= 65% | 每周 |
| G-04 | 让行会战争成为社交高潮 | 周六王城报名席位使用率 >= 80%，重复参战率 >= 60% | 每月 |
| G-05 | 让经济形成真实价格 | 紫装、橙装在拍卖行每周至少有三次有效成交区间 | 每周 |
| G-06 | 让服务器历史可被记住 | 30天内至少查看一次年表的活跃账号 >= 25% | 每月 |

### 明确非目标

- 不以首月充值额作为唯一成功标准；要同时看免费玩家留存、资源集中度和举报成立率。
- 不追求所有地图随时满人；低峰期应通过动态开线和任务目标维持可见的玩家密度。
- 不把挂机时间当成在线时长；自动战斗应帮助碎片时间玩家完成基础产出，但不能替代 BOSS、王城和交易判断。
- 不保证每次死亡都公平地返还装备；需要保证规则事先可见、掉落可审计、误判可申诉。

## 玩家分层与任务清单

### 四类首发用户

| 类型 | 每次时长 | 首要动机 | 首周必须完成 | 主要风险 |
|---|---:|---|---|---|
| 爆装型 | 60~120分钟 | 看光柱、抢稀有词缀 | 击杀区域 BOSS 3次、卖出1件装备 | 掉率失望后流失 |
| 战争型 | 90~180分钟 | 组织、指挥、夺城 | 加入行会、参加资格战和王城演练 | 人数不足或强会垄断 |
| 经营型 | 20~60分钟 | 找价差、做装备、摆摊 | 完成一次重铸、一次成交、一次委托 | 市场深度不足 |
| 碎片型 | 10~30分钟 | 每天有确定进度 | 完成日常、获得印记、提升一件装备 | 被长流程和 PK 吓退 |

### 玩家任务与系统责任

每一项玩家任务都必须能归属到一个系统责任人：

| 玩家问题 | 系统回答 | 责任模块 | 失败兜底 |
|---|---|---|---|
| “我现在该去哪？” | 地图目标、推荐等级、危险标签 | 地图导航 | 回城后恢复最近目标，不强制自动寻路 |
| “这件装备值不值得留？” | 对比面板、套装缺口、成交区间 | 背包/交易 | 可锁定、可收藏、7天历史记录 |
| “为什么我打不过？” | 战斗回放中的命中、减免、控制原因 | 战斗日志 | 显示最近10秒摘要，不暴露反作弊阈值 |
| “死了会掉什么？” | 当前名字状态、区域表、掉落格数 | PK/死亡 | 死亡结算页列出规则和流水 ID |
| “行会贡献算不算我？” | 个人贡献分和奖励资格实时进度 | 行会/活动 | 断线重连后按服务器流水补算 |

## 核心循环规格

### 60 秒循环的可测状态机

```text
进入地图
  -> 选择目标(普通怪/精英/玩家/BOSS)
  -> 锁定或取消锁定
  -> 走位与技能起手
  -> 服务器判定命中、仇恨、控制
  -> 目标死亡/玩家撤退/玩家死亡
  -> 生成或争夺地面物
  -> 拾取保护检查
  -> 继续深入、回城整理或发起交易
```

每个状态都需要可观测事件：`map_enter`、`target_lock`、`skill_cast_start`、`damage_resolved`、
`entity_dead`、`drop_spawn`、`loot_attempt`、`loot_resolved`、`town_return`。客户端只负责发送
输入和展示状态，不能自行补发 `loot_resolved` 或修改 `damage_resolved`。

### 30 分钟目标模板

系统在玩家进入地图后生成一个短目标、一个中目标和一个风险目标：

| 目标 | 示例 | 完成奖励 | 取消条件 |
|---|---|---|---|
| 短目标(5~8分钟) | 击杀30只推荐等级怪 | 金币、药材、经验 | 退出地图不取消，次日重置 |
| 中目标(15~25分钟) | 击杀精英并鉴定一件蓝/紫装 | 强化材料、印记进度 | 目标 BOSS 被其他队伍击杀时转换为助攻任务 |
| 风险目标(5~15分钟) | 深入危险区夺取资源点 | 稀有材料、荣誉 | 主动离开或死亡，奖励按阶段结算 |

目标生成不能要求“最后一击”或“必须杀死某名玩家”，以免把组队支援变成负收益。

### 一周循环的资源锁

- 每日确定产出：个人首领、行会任务、前两次地图 BOSS、活跃任务；具体数值见基线。
- 每周高峰产出：世界 BOSS、资格战、王城战、周常委托。
- 每月叙事产出：年表事件、章节选择、限时外观；不删除核心资产。
- 失败不会清空已获得的印记、技能书和装备，只改变下一次活动的路线或竞争对象。

## 功能优先级与验收口径

### P0 首发阻断功能

| 功能 | 最小可玩范围 | 通过条件 | 阻断缺陷 |
|---|---|---|---|
| 移动与普攻 | 三职业、三张地图 | 服务器权威、断线可恢复 | 客户端可伪造伤害 |
| 掉落与拾取 | 白到橙、地面光柱 | 并发拾取只归属一人 | 重复物品或凭空消失 |
| 装备成长 | 强化、鉴定、交易 | 流水可追溯 | 回滚丢失强化或绑定状态 |
| PK 与死亡 | 白/黄/红名、三类区域 | 规则与掉落一致 | 锁定绕过掉落、死亡不结算 |
| 行会与王城 | 资格战、240人王城 | 结算幂等 | 断线导致重复奖励 |
| 商业化 | 外观、仓库、通行证 | 无战斗属性注入 | 付费影响伤害或掉率 |

### P1 首发后 90 天

新增皇州支线、锻造委托、训练场回放、更多外观和跨服观战。P1 不得在 P0 资产流水尚未通过审计时上线。

## 关键体验指标定义

指标必须同时记录分母、时间窗和过滤条件，避免只报一个漂亮比例：

| 指标 | 分母 | 事件 | 合格线 |
|---|---|---|---:|
| 一刀识别率 | 看过第一次教学的账号 | `oneknife_prompt_shown` 后点击或释放 | >=80% |
| 掉装理解率 | 首次死亡账号 | 死亡页展开掉落规则 | >=75% |
| 交易信任度 | 完成交易账号 | 交易后未立即举报且7日未申诉 | >=97% |
| 目标可达性 | 接受30分钟目标账号 | 30分钟内完成短目标 | >=70% |
| 归因公平度 | BOSS 参与账号 | 贡献明细打开且排名无投诉 | >=90% |

## 运营和版本边界

### 版本号与配置兼容

每个配置包包含 `content_version`、`rules_version`、`rollback_version`。数值热更只允许在维护窗口
发布；影响掉落、PK、税率和王城奖励的配置必须双人审核并保留旧包 30 天。客户端版本落后时可以
继续登录和战斗，但涉及资产写入的接口必须由网关拒绝。

### 事件优先级

1. 资产安全事件：暂停发奖和交易，保留战斗实例。
2. 规则不一致事件：关闭相关活动入口，公告当前生效版本。
3. 性能事件：降级非关键特效和世界广播，不降低拾取、伤害和结算可靠性。
4. 内容质量事件：标记问题任务并给出可替代目标，不删除玩家已有奖励。

## 详细埋点协议

公共字段：`event_id`、`server_id`、`shard_id`、`account_id_hash`、`role_id`、`character_level`、
`class_id`、`map_id`、`rules_version`、`client_version`、`timestamp_utc`。事件字段不得包含支付卡号、
通讯录或设备原始指纹。

| 事件 | 必填字段 | 触发时机 | 用途 |
|---|---|---|---|
| `product_loop_enter` | 入口、推荐目标、风险级 | 进入地图或城镇 | 判断循环断点 |
| `goal_generated` | 目标 ID、类型、预计时长 | 生成30分钟目标 | 校准目标难度 |
| `goal_completed` | 目标 ID、用时、奖励流水 | 目标结算 | 检查奖励可靠性 |
| `drop_viewed` | 物品模板、品质、停留时长 | 玩家打开掉落详情 | 评估稀有物价值认知 |
| `trade_compare` | 物品 ID、对比来源、价格 | 打开交易对比 | 优化经营型体验 |
| `death_rules_opened` | 区域、名字状态、可掉数量 | 展开死亡规则 | 验证风险透明度 |
| `guild_war_intent` | 报名、出战、缺席原因 | 活动报名或退出 | 评估组织摩擦 |
| `store_item_viewed` | SKU、免费/付费、关闭方式 | 查看商城物品 | 验证非强迫商业化 |

## 首发完成定义

当且仅当以下条件全部满足，产品总纲可以标记为“首发可交付”：

1. 12 个分卷中的字段命名和数值引用通过自动检查。
2. P0 功能全部有成功、失败、断线、重复请求和回滚用例。
3. 100、160、240 人战争压力档均通过，且 P95 低于基线。
4. 经济模拟 180 天未出现不可逆通胀、装备复制或单联盟永久垄断。
5. 免费玩家可在不购买任何 SKU 的情况下获得三职业核心技能、进入所有首发地图并参与王城。
6. 客服能根据事件 ID 找到战斗、掉落、交易和死亡规则的完整链路。

本卷版本：`0.0.7-draft`；任何新增系统先在本卷登记，再进入对应分卷的实现队列。

## 玩家旅程脚本

### 第一次会话

1. **进入灰烬村**：镜头只展示三件事：职业、角色、村外目标；背景叙事留到玩家主动打开日志后展示。
2. **完成第一次击杀**：在目标死亡的同一秒出现掉落光柱、拾取按钮和装备对比；不弹商城。
3. **第一次受伤**：药水按钮短暂高亮，解释“生命低于阈值才自动提示”，不自动替玩家喝稀有药。
4. **第一次组队邀请**：显示队伍人数、贡献共享和离开方式；拒绝不会降低后续匹配。
5. **第一次精英**：在地面显示前摇形状，玩家可打断或绕行；失败只少材料，不丢核心任务。
6. **第一次 BOSS**：先显示阶段、贡献类别和复活路线，再显示一刀教学；一刀不会改变掉落归属。
7. **回城整理**：装备页默认突出当前缺口和可交易状态，批量操作默认安全。

### 第一次死亡

死亡是一次解释型事件而不是惩罚弹窗：先展示“发生了什么”，再展示“损失了什么”，最后展示“现在能
做什么”。若玩家在10秒内关闭死亡页，回城后仍可从战斗记录入口查看；若玩家连续三次死亡，系统提供
地图推荐、组队入口和非强制的低风险目标，不自动赠送顶级装备。

## 产品状态字典

| 状态 | 进入条件 | 可做 | 不可做 | 离开条件 |
|---|---|---|---|---|
| `town_safe` | 进入安全区 | 交易、仓库、组队、任务 | 主动攻击 | 离开安全区 |
| `map_normal` | 普通地图 | 刷怪、普通 PK | 王城器械 | 切图/回城 |
| `map_danger` | 危险入口确认 | 高收益、PK、BOSS | 强制保护 | 死亡/撤离 |
| `map_desolate` | 绝地入口确认 | 高收益、红名争夺 | 普通保险覆盖 | 死亡/撤离 |
| `boss_instance` | 前厅开放/报名 | 贡献、拾取、复活 | 退出后重新占贡献 | BOSS结算 |
| `castle_war` | 名单锁定 | 阵营目标、战斗 | 改盟、交易、改名 | 结算/强制退出 |
| `asset_pending` | 资产服延迟 | 查看战斗、回城 | 交易、分解、强化 | 结算或安全失败 |

产品、UI 和客服必须使用相同状态名。文案可以本地化，状态 ID 不可随语言包改变。

## 开服首周观察清单

每天固定四个时间点导出：在线峰值、地图分布、BOSS参与、掉落品质、死亡与再出城、交易价格、金币比、

贡献和王城胜负的热修必须公告生效时间和规则版本，历史事件按原版本结算。

## 玩法组合验收

每周至少安排一次包含以下四类行为的真实测试：单人刷怪、组队 BOSS、玩家交易、行会目标。测试者必须
从地图入口开始，记录目标选择、风险判断、拾取、整理、冲突、回城和下一目标。若任何一步必须依赖策划
口头解释才能完成，产品说明和 UI 仍不合格。

### 组合用例

| 用例 | 行为链 | 期待感受 | 观察点 |
|---|---|---|---|
| 追装备 | 刷怪 -> 紫装 -> 对比 -> 委托/交易 | “再打一轮就能补齐” | 详情页和价格样本 |
| 抢 BOSS | 预告 -> 集合 -> 贡献 -> 地面争夺 | “我有贡献而非只看最后一击” | 贡献可读性、拾取延迟 |
| 复仇 | 被杀 -> 查看规则 -> 悬赏/组队 -> 返回 | “损失可理解，能继续玩” | 再出城率、举报 |
| 组织 | 行会任务 -> 据点 -> 资格 -> 王城 | “个人也有位置” | 个人档位、外围目标 |
| 经营 | 分解 -> 委托 -> 摆摊 -> 成交 | “旧装备有去处” | 退出率、税和价格 |

## 内容密度预算

首发内容不是把数值堆满，而是确保每个等级段有可重复的组合：

| 等级段 | 地图 | 区域首领 | 技能/装备目标 | 组织内容 |
|---|---:|---:|---|---|
| 1~20 | 3 | 2 | 3基础技能、蓝装 | 组队教学 |
| 21~40 | 3 | 3 | 第一橙、强化+5 | 行会、据点演练 |
| 41~60 | 3 | 3 | 三件套、技能书 | BOSS、资格战 |
| 61~80 | 3 | 3 | 红碎片、五件套 | 绝地、联盟 |
| 81~100 | 3 | 3 | 八件套、转生 | 天阙、王城 |
| 1转 | 1 | 0/终局 | 金装、主宰碎片 | 皇城终战 |

每个等级段至少有一个安全目标、一个风险目标和一个社交目标。缺少任一目标时，不用重复同一种怪物，
而是增加路线、机制、交易或公共事件。

## 设计冻结规则

冻结后的技能、掉落、PK、税率和王城奖励只能通过新规则版本变更；剧情、UI和外观可以小步更新，但不得
改变已经开始活动的结算。冻结清单每周生成 hash，发布包和客服工具读取同一 hash。发现文档与配置不一致
时，以服务器实际规则和本基线为准，立即补充冲突记录并通知玩家。

## 产品完成定义的反向检查

完成不是“文档写完”，而是玩家、服务器、资产和运营都能从同一规则完成闭环：玩家可在无付费条件下创建
职业、学技能、刷怪、看到品质、穿戴、交易、死亡后读懂风险、加入行会、参与 BOSS和王城；服务端能为每一步
提供 request/event/ledger；QA能用正常、失败、断线、重复和回滚用例重现；运营能通过面板看见异常并在不改
历史资产的情况下暂停或回滚；客服能用事件 ID解释玩家问题。

若任一链路只有客户端画面、口头规则、手工数据库修复或未版本化的热更，产品状态降回“概念/开发中”，不
能标记为商业候选。本卷二次扩展版本：`0.0.7-draft-r5`。

## 最小可玩闭环验收

测试者从1级开始，在不看外部说明的情况下完成“出城 -> 击杀 -> 看到地面品质 -> 拾取 -> 穿戴 -> 回城 ->
强化/交易 -> 设定下一目标”。随后完成一次组队 BOSS、一次死亡规则查看和一次行会报名。流程中不得出现
资产复制、隐藏付费战力、只能最后一击完成的任务或无法理解的错误状态；结果必须可从事件和流水重建。

此闭环的验收数据同时写入 `P0_PRODUCT_LOOP` 快照，作为首发候选的最低证据。

快照还要记录测试角色、客户端版本、规则版本、地图、队伍、资产流水和失败原因，便于跨版本回放。

若闭环在任一设备、网络或职业上失败，团队先修复对应系统与提示，再重新跑完整链路；不能只跳过失败步骤、
手工补发装备或把该账号从统计分母中删除。产品结论必须保留失败样本、修复版本和复测结果。

闭环通过后由产品、资产和 QA 共同签字。

签字记录进入版本包。

版本包永久保存。

并可回放。

产品负责人每月复核上述证据仍可读取、可复现、可追责；证据失效即重新验收。
