# 《一刀999》设计文档索引

## 文档规则

本目录是游戏设计的单一事实源。发生冲突时按以下优先级处理：

1. `11-数值配置基线.md` 中的公式、上限和时间。
2. 对应系统分卷中的规则。
3. `00-产品总纲.md` 中的方向性描述。
4. 历史备份仅供追溯，不参与实现。

任何规则修改必须同步修改验收用例。任何新增货币、装备品质、PK 状态或付费商品都需要更新经济压力测试。

## 可运行原型

第一版浏览器纵向切片位于 [`../game/index.html`](../game/index.html)，覆盖三职业选择、移动、职业技能、首领战、地面掉落、装备穿戴、升级、首领印记和本地保存。它是前端模拟，不代表正式服务器的资产权威实现；启动命令、控制方式和当前边界见 [`../game/README.md`](../game/README.md)。当前地图节点事实源为 `18-地图场景交互节点打磨记录.md`；`17` 仅保留上一版本的两节点设计和回归记录。

## 术语

- **玄烬大陆**：游戏世界。
- **九州**：边、沙、毒、雪、雷、海、幽、天、皇九个区域。
- **烬阳城**：行会争夺的王城，不是普通主城。
- **一刀时刻**：三职业共享的高光强化机制，并非固定伤害作弊。
- **公开装备**：BOSS 掉在地面、带保护期、保护结束后可被争夺的装备。
- **绑定过渡装**：确定性兑换装备，不交易、不掉落，属性上限低于同阶公开装备。

## 如何使用分卷

### 策划阅读路径

先读 `00` 了解产品边界，再读 `01` 和 `04`理解世界线、地图和事件，然后读 `02`、`03`确认战斗和成长，
最后读 `05`~`08`确认风险、组织、经济和界面。任何新系统先在 `00`登记目标和非目标，再在对应分卷写
状态、字段、数值引用、异常和 QA；不允许直接在活动公告或客户端文案中创造一套临时规则。

### 程序阅读路径

先读 `11` 的字段、公式、版本和单位，再读 `09` 的服务边界、命令、事件和幂等，按功能读取 `02`~`08`。
资产相关功能必须同时打开 `03`、`05`、`07` 和 `09`，因为装备的绑定、死亡、交易、销毁和流水是一个
完整链路。战场功能必须同时打开 `04`、`06`、`09` 和 `11`，不能只实现客户端积分条。

### QA 阅读路径

先用 `10` 建立测试矩阵和缺陷等级，再按用例前缀查找：`C`战斗、`M`地图、`G`成长、`K`PK、`W`行会、
`E`经济、`U`UI、`S`服务器、`L`剧情、`P`产品、`B`基线。每条用例都要验证服务器流水、重复请求、断线和
回滚，不仅验证画面文字。

## 文档变更流程

1. 建立变更编号，描述用户问题、目标、非目标和受影响分卷；
2. 先改 `11` 或确认无需改数值，再改系统分卷和 UI/QA；
3. 更新状态机、字段、异常、埋点和回滚；
4. 运行 Markdown 链接、术语、数值和占位检查；
5. 生成版本差异和备份，更新根入口和 `VERSION`；
6. 由产品、系统/数值、服务端、QA和经济（涉及交易时）签字。

### 不允许的变更

- 在客户端描述中把锁定写成死亡免疫；
- 在商城增加装备、技能、强化、掉率、等级、转生、复活、王城器械或 PvP属性；
- 在 BOSS任务中要求最后一击作为唯一完成条件；
- 用赛季清档删除等级、装备、行会和交易资产；
- 用客户端动画、浮字或本地时间作为资产和战斗结算依据；
- 在没有新规则版本和模拟的情况下静默修改掉率、税率、死亡概率、贡献和王城奖励。

## 交付物模板

每个分卷新增功能至少提交：

```text
功能卡：目标、非目标、负责人、依赖、版本
流程图：正常、失败、断线、重复、回滚
配置：字段、类型、范围、默认、规则版本
数值：引用11的键、示例、模拟结果
UI：页面、按钮、风险、错误码、无障碍
埋点：公共字段、事件、分母、时间窗
QA：成功、边界、异常、性能、灾备
运维：开关、告警、公告、客服查询、回滚
```

没有这八类交付物的内容只能标记为“概念草案”，不能进入制作排期和外部承诺。
