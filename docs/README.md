# 《一刀999》设计文档索引

## 文档规则

本目录是游戏设计的单一事实源。发生冲突时按以下优先级处理：

1. `11-数值配置基线.md` 中的公式、上限和时间。
2. 对应系统分卷中的规则。
3. `00-产品总纲.md` 中的方向性描述。
4. 历史备份仅供追溯，不参与实现。

任何规则修改必须同步修改验收用例。任何新增货币、装备品质、PK 状态或付费商品都需要更新经济压力测试。

## 可运行原型

第一版浏览器纵向切片位于 [`../game/index.html`](../game/index.html)，覆盖三职业选择、移动、职业技能、首领战、地面掉落、装备穿戴、升级、首领印记和本地保存。它是前端模拟，不代表正式服务器的资产权威实现；启动命令、控制方式和当前边界见 [`../game/README.md`](../game/README.md)。当前地图节点事实源为 `18-地图场景交互节点打磨记录.md`；`17` 仅保留上一版本的两节点设计和回归记录。

## 术语

- **玄烬大陆**：游戏世界。
- **九州**：边、沙、毒、雪、雷、海、幽、天、皇九个区域。
- **烬阳城**：行会争夺的王城，不是普通主城。
- **一刀时刻**：三职业共享的高光强化机制，并非固定伤害作弊。
- **公开装备**：BOSS 掉在地面、带保护期、保护结束后可被争夺的装备。
- **绑定过渡装**：确定性兑换装备，不交易、不掉落，属性上限低于同阶公开装备。

## 如何使用分卷

### 策划阅读路径

先读 `00` 了解产品边界，再读 `01` 和 `04`理解世界线、地图和事件，然后读 `02`、`03`确认战斗和成长，
最后读 `05`~`08`确认风险、组织、经济和界面。任何新系统先在 `00`登记目标和非目标，再在对应分卷写
状态、字段、数值引用、异常和 QA；不允许直接在活动公告或客户端文案中创造一套临时规则。

### 程序阅读路径

先读 `11` 的字段、公式、版本和单位，再读 `09` 的服务边界、命令、事件和幂等，按功能读取 `02`~`08`。
资产相关功能必须同时打开 `03`、`05`、`07` 和 `09`，因为装备的绑定、死亡、交易、销毁和流水是一个
完整链路。战场功能必须同时打开 `04`、`06`、`09` 和 `11`，不能只实现客户端积分条。

### QA 阅读路径

先用 `10` 建立测试矩阵和缺陷等级，再按用例前缀查找：`C`战斗、`M`地图、`G`成长、`K`PK、`W`行会、
`E`经济、`U`UI、`S`服务器、`L`剧情、`P`产品、`B`基线。每条用例都要验证服务器流水、重复请求、断线和
回滚，不仅验证画面文字。

## 文档变更流程

1. 建立变更编号，描述用户问题、目标、非目标和受影响分卷；
2. 先改 `11` 或确认无需改数值，再改系统分卷和 UI/QA；
3. 更新状态机、字段、异常、埋点和回滚；
4. 运行 Markdown 链接、术语、数值和占位检查；
5. 生成版本差异和备份，更新根入口和 `VERSION`；
6. 由产品、系统/数值、服务端、QA和经济（涉及交易时）签字。

### 不允许的变更

- 在客户端描述中把锁定写成死亡免疫；
- 在商城增加装备、技能、强化、掉率、等级、转生、复活、王城器械或 PvP属性；
- 在 BOSS任务中要求最后一击作为唯一完成条件；
- 用赛季清档删除等级、装备、行会和交易资产；
- 用客户端动画、浮字或本地时间作为资产和战斗结算依据；
- 在没有新规则版本和模拟的情况下静默修改掉率、税率、死亡概率、贡献和王城奖励。

## 交付物模板

每个分卷新增功能至少提交：

```text
功能卡：目标、非目标、负责人、依赖、版本
流程图：正常、失败、断线、重复、回滚
配置：字段、类型、范围、默认、规则版本
数值：引用11的键、示例、模拟结果
UI：页面、按钮、风险、错误码、无障碍
埋点：公共字段、事件、分母、时间窗
QA：成功、边界、异常、性能、灾备
运维：开关、告警、公告、客服查询、回滚
```

没有这八类交付物的内容只能标记为“概念草案”，不能进入制作排期和外部承诺。

### 0.3.8 角色面板三围状态

角色卡片此前只有一个综合「战力」数字，玩家在杂货商重铸出「防御 +15」后看不到承伤变低，生命词缀也只剩血条上限的细微差异。本轮在头像 / 战力下方新增一行 **生命 / 攻击 / 防御**（复用已有 `.stat-row`），三项全部与战斗结算同源：攻击 = `hero.attack + level×4 + 装备有效战力×0.9`（与 `computeDamage` 的 `base` 一致）、生命 = `playerMaxHp()`（含部位基础与生命词缀）、防御 = `playerDefense()`（职业基础 + 防御词缀，与 0.3.7 承伤同源）。HUD 脏签名纳入三个新值，避免「只改防御 / 生命词缀时战力不变 → 面板不刷新」。实测战士 Lv.1 裸装 368 / 37 / 22（战力 81），加一件 power 40、防御 +15、生命 +60、攻击 +10 的护甲后 488 / 82 / 37（战力 131），与公式完全吻合。验证：105 单测全绿、三视口冒烟 / 升级专项 / 渲染回归 PASS、perf 平均 5475.25 fps / p95 0.5ms / p99 0.8ms / 最差帧 4.1ms / 零长帧、难度探针战士第 5 关 0 死 / 52s、第 15 关 5 死 / 251s（PASS，接近 6 死闸门；本轮只改 HUD，差异来自探针操作模型波动）、战士百图 e2e 100/100（Lv.41、1 次死亡、终局金币 226695）。详见 [20261024-0538-角色面板三围展示-DeepSeek-V4.1-Flash.md](20261024-0538-角色面板三围展示-DeepSeek-V4.1-Flash.md)。

### 0.3.9 难度探针稳定性状态

0.3.6 的探针在同一套战斗数值下测出过第 15 关 0 死 / 75s、1 死 / 138s、5 死 / 251s，差异来自探针自身正反馈：玩家死亡会让首领**满血重置**，而喝药阈值 55% 偏低（往往到「下一次重击就死」的区间才喝），一次失误就把整场首领战拖长。本轮新增 `ONEKNIFE_PROBE_RUNS`（默认 **3**）：每关重复 3 次、每次新建 context + page，取死亡数与耗时**中位数**；判定改为中位数闸门（`deaths > 6` 才失败），单次超限只打印 `PROBE WARN`，耗时仍单次严格判定；喝药阈值 **55% → 65%**、检查频率每 4 循环 → 每 3 循环；`PROBE START` / `PROBE RESULT` 增加 `run=1/3`。实测三次均为 0 死：第 5 关 38s（50 / 38 / 38）、第 15 关 52s（52 / 53 / 36），说明 0.3.8 的 5 死 / 251s 是探针自放大而非关卡难度变化。验证：105 单测全绿、三视口冒烟 / 升级专项 / 渲染回归 PASS、perf 平均 5631.24 fps / p95 0.4ms / p99 0.7ms / 最差帧 5.5ms / 零长帧、战士百图 e2e 100/100（Lv.41、0 次死亡、100 个检查点 SAVED+RESTORED、终局金币 227870；fast 模式死亡数不参与难度判定）。详见 [20261024-0634-难度探针稳定性-DeepSeek-V4.1-Flash.md](20261024-0634-难度探针稳定性-DeepSeek-V4.1-Flash.md)。
