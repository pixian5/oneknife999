# 真实战斗状态验证（0.8.76）

- 日期：2026-11-23 20:41
- 模型：豆包
- 版本：0.8.76
- 相关回归：`tests/ui-status-real-combat.cjs`、`npm run test:ui:status-real`

## 背景

0.8.75 把中毒、减速、眩晕、致盲、破甲接进了 HUD，但回归 `tests/ui-status-icons.cjs` 是**直接写 `state.player`** 再检查 DOM。这只能证明 `renderStatusIcons()` 会读字段，不能证明：

1. 真实怪物命中玩家后，`applyOnHitPassives` 真的会写入这些字段；
2. 真实命中与 HUD 渲染在同一条战斗循环里能对齐；
3. 0.5 秒眩晕这种短状态在截图与断言前不会先自然结束；
4. 破甲是真实技能 `castSkill(0)` 的结果，不是测试手工挂上去的。

本轮补的是这条链路，不改状态数值，也不扩大 HUD 范围。

## 测试设计

### 真实来源

- 中毒：`black_rock_mine` 的**腐毒僵尸**（`poison + resourceDrain`）。腐毒僵尸只带毒，不像林皮蛛会同时带减速；一次真实命中后断言 `poison === 1`、HUD `×1`。
- 眩晕：`black_rock_mine` 的**矿脉蝙蝠**（`stun`，0.5 秒）。命中后立即暂停冻结，避免 0.5 秒窗口在截图前结束。
- 减速：冰封地图的**霜牙狼**（`slow + packHunt`）。一次真实命中后断言 `slowTimer > 0`，HUD 角标按 `ceil` 显示秒数。
- 致盲：冰封地图的**雪原猎手**（`blind`，2 秒、失手率 0.3）。断言 `blindMissChance === 0.3`。
- 破甲：真实调用战士 `castSkill(0)`（破甲斩），目标选该图首领（血量足够高，不会被一次技能击杀）；断言目标 `armorBreakTimer > 0`、玩家怒气下降、技能进入冷却、目标确实掉血。

### 怎么避免“测试自己写状态”

- 测试只做三件准备：`loadMap()` 载入真实地图、把玩家与目标摆到攻击距离内、设置 `aggro=true` / `attackCooldown=0`。
- 状态字段本身不写，全部由 `playerDamage()` → `applyOnHitPassives()` 产生。
- `Math.random = () => 0` 只用于让 35%/40%/25%/30% 的随机判定在本次用例中必中；这是确定性控制，不是状态注入。后续待办里专门补真实概率的统计回归。
- 为了隔离，其余怪只做 `aggro=false / attackCooldown=999`，不修改它们的被动或伤害。

### 截图与冻结

- 命中后在同一 `page.evaluate` 内调用 `setPaused(true)`，再 `renderAll()`；状态计时不再递减，0.5 秒眩晕可以被稳定截图。
- 截图前隐藏 `#guideBanner`、`#toast`、`#pauseOverlay`，只保留 HUD 与世界画面。
- 桌面 1440×900 截 5 张：中毒、眩晕、减速、致盲、破甲。
- 移动 390×844 用**林皮蛛**一次真实命中同时产生中毒+减速，验证两枚真实图标在窄屏状态条内不被 `overflow` 裁切。

## 代码改动

1. 新增 `tests/ui-status-real-combat.cjs`：
   - `prepareMonster()`：真实地图 + 真实怪 + 攻击距离布置；
   - `waitForStatus()`：20ms 轮询真实状态字段，命中即暂停；
   - `castRealArmorBreak()`：真实 `castSkill(0)` 链路；
   - `readHud()`：复用 0.8.75 的 `overflow` 祖先裁切检查；
   - 桌面 5 例 + 移动 1 例。
2. `game/src/main.js` 在 `TEST_MODE` 下新增 `testApi`：
   ```js
   testApi: { loadMap, setPaused, castSkill, renderAll, state: () => state }
   ```
   让回归复用页面已经载入的生产模块实例，不再二次 `import("/src/main.js")`。
3. `package.json` 新增 `test:ui:status-real`，并把新文件加入 `check`。

## 遇到的问题

- **macOS Chrome 二次动态 import 抖动**：页面主模块已经成功加载、`snapshot()` 可用，但测试再 `await import("/src/main.js")` 会报 `Failed to fetch dynamically imported module`。同一页面手动脚本却正常，属于本机 Chrome/Playwright 的模块图边界问题。改为在 TEST_MODE 暴露 `testApi`，直接复用已载入的实例，问题消失。
- **测试里 `page.locator(...).click()` 偶发 30 秒超时**：职业选择只是准备步骤，改成等待 DOM 后直接 `element.click()`；同时给首屏加载加了最多 3 次重试。业务断言没有重试。
- **0.5 秒眩晕的截图窗口**：如果不暂停，断言 + 截图往返经常超过 0.5 秒；现在命中检测和暂停在同一个 evaluate 内完成，之后计时冻结。
- **破甲目标选择**：最初想用 `冰川巨兽`，但实际冰封地图是 `stage_031`，该图没有这个怪；改用该图首领，既保证血量足够，也保住“真实实体”的前提。

```text
真实战斗状态回归通过
```

复跑时发现一件事：**不能拿“玩家生命下降”当命中判据**。安全区每秒回复 10% 最大生命，若目标刷新点靠篝火/水井，致盲状态已经写入、生命却被回满，`hp < maxHp` 会假失败。现在四个被动用例统一改为断言 `player.lastKiller === 目标名`：`lastKiller` 只在 `playerDamage()` 真实结算命中时写入，比生命差值更稳，也不会被回血掩盖。修完后连续跑两次均通过。

另外，`ui-status-icons` / `ui-smoke` / `ui-layout` 在 macOS Chrome 上都踩到同一个首屏职业卡 `locator.click()` 30 秒超时。新增 `tests/game-entry.cjs` 统一入口：只重试“加载页面 + 选职业”，直接 DOM click，业务断言不重试；三个用例改用它后，状态图标四视口、smoke 三视口、layout 九视口全部通过。`package.json` 的 `check` 已纳入该文件。
