## 一、数值断崖修复（P0，玩家可感知）

**关 4 → 关 5 难度与装备双断层已消除。** 生成图数值曲线整体重写为「以第 4 关（赤砂大漠）为锚点线性增长」：

| 维度 | 旧曲线（关4 → 关5 → 关100） | 新曲线（关4 → 关5 → 关100） |
|---|---|---|
| 怪物攻击 | 70–92 → **16–22（跌 75%）** → 122 | 70–92 → **70–92（无缝衔接）** → 123 |
| 怪物生命 | 480–620 → 103–180 → 1197 | 480–620 → **485–626** → 1198 |
| Boss 攻/血 | 112/3000 → 30/1200 → 152/9560 | 112/3000 → **112/3068** → 152/9480 |
| 武器 power | 56 → **20（跌 64%）** → 210 | 56 → **58** → 210 |
| 项链/战靴 | 48/36 → 13/11 → 108/106 | 48/36 → **49/45** → 112/108 |

- 实现在 `game/src/maps.js` 的 `generatedMap`：`anchored(base, slope)` 辅助函数，第 5 关起与关 4 衔接、第 100 关峰值与旧设计一致；怪物/装备/金币/Boss 全部数值同批归一。
- 前期（关 1–4 手工图）内部陡爬坡不变；关 5–100 成为长缓坡。全 100 关节奏模拟：清肉怪 3–10 刀、Boss 战 22–58 刀、被杀所需 hits 从关 1 的 22 缓降到关 100 的 9——难度高原而非断崖。

## 二、承伤公式对齐设计基线（P1）

- 新增纯函数 `computeIncomingDamage({ attack, attackerLevel, defense })`（combat.js）：`减免 = 防御/(防御+100+攻击者等级×5)`，与 `docs/11-数值配置基线.md` 完全一致（输入输出同一公式）。
- `main.js` 怪物攻击（原公式缺失攻击者等级项、玩家减伤恒封顶）与地面危险区伤害（`spawnHazard` 现携带 `attackerLevel`）全部改走该函数。
- 效果：后期 Boss/怪攻不再被固定减伤稀释，难度曲线与设计分卷可对账。
