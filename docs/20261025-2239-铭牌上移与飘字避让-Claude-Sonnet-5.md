# 城堡铭牌上移与飘字避让（0.4.1）

- 日期：2026-10-25 22:39
- 模型：Claude Sonnet 5
- 版本：0.4.0 → 0.4.1

## 问题

玩家反馈「人物、野怪的血条、名字被遮挡了一点」。

在浏览器里逐帧插桩 `CanvasRenderingContext2D`（记录每次 `fillText` / `fillRect` / `arc` / `roundRect` 及绘制顺序），对每一帧做矩形相交检测，定位到两个独立成因：

1. **伤害飘字压在铭牌上**。`resolveDamage` 在 `target.y - target.radius - 12` 处画伤害数字，而铭牌三行（名字 `top+11`、血量 `top+21`、血条 `top+25..29`，`top = y - radius - 39`）正好覆盖 `y-radius-39 … y-radius-8`。飘字中心 `y-radius-12` 落在血条与血量之间，13px 字号直接盖住血条；暴击 18px、一刀时刻 25px 覆盖更大。
2. **铭牌离实体太近，特效环伸进血条**。小怪铭牌底边距轮廓只有 8px、首领 14px，而首领红色饰环半径是 `radius*1.22+8/14`、攻击前摇环最大 `radius+36`、玩家中毒 28 / 破势 30。插桩统计 60 帧：描边环命中铭牌 89 次、实心圆 59 次、飘字 82 次、其他铭牌 78 次。

此外铭牌原先在 `drawEntity` 内部绘制（在实体循环里），之后的 `drawSkillRangePreview`、`drawPlayer`、`drawParticles`、`drawTexts` 全部画在它上面——**任何后绘制的世界元素都能盖住血条**，这是结构性问题，不只是数字偏移。

## 改动

### 1. 铭牌几何集中为常量（render.js）

新增三个导出，铭牌与飘字共用同一套纵向几何，避免两处各写一份数字后走偏：

```js
const NAMEPLATE_HEIGHT = 31;
const NAMEPLATE_GAP = { normal: 20, boss: 26 };   // 原 8 / 14
export function nameplateTop(entity) { ... }       // 底边 = y - r*(boss?1.22:1) - gap - 高度
export function floatYAboveNameplate(entity, offset = 4) { ... }
```

- 间隙 `normal` 8 → **20**、`boss` 14 → **26**，铭牌整体上移 12px，首领饰环（`r*1.22+14`）与中毒 / 破势环不再伸进血条。
- `entity.radius * (boss ? 1.22 : 1)`：`drawEntity` 里首领本体按 1.22 缩放，此前铭牌只减去 `entity.radius`，对首领实际少让了约 25% 的半径。

### 2. 铭牌改为场景最上层统一绘制（drawWorld）

从 `drawEntity` 移除 `drawNameplate(entity)` 调用，改在 `drawWorld` 的粒子与飘字之后集中绘制，并按 `y` 升序（远→近）排序，重叠时让更靠近镜头的角色铭牌压在上面：

```js
const nameplates = state.entities.filter((e) => e.alive).map((e) => ({ y: e.y, draw: () => drawNameplate(e) }));
nameplates.push({ y: state.player.y, draw: drawPlayerNameplate });
nameplates.sort((a, b) => a.y - b.y).forEach((entry) => entry.draw());
```

玩家铭牌同样从 `drawPlayer` 拆出为独立的 `drawPlayerNameplate()`（本体绘制保持不动），一并参与排序。玩家有效轮廓按 30 计（中毒光环 28 / 破势环 30），`PLAYER_NAMEPLATE_HEIGHT = 24`。

### 3. 世界内飘字统一避让铭牌（main.js）

伤害、落空、`999` 剧情飘字改用 `floatYAboveNameplate`；玩家受伤 / 中毒 / 治疗 / 升级 / 连击 / 恢复点 / 重铸提示改用 `floatYAbovePlayer`，全部画在铭牌上方而不是压在血条上。

## 经验

- Canvas 的绘制顺序就是层级。把「信息类 HUD（铭牌）」和「演出类元素（飘字 / 粒子 / 特效环）」放在同一个 `drawEntity` 里按实体顺序画，任何后绘制的内容都会盖住信息。信息层应统一收口到最后一次性绘制。
- 用 `CanvasRenderingContext2D.prototype` 插桩 + 逐帧矩形相交检测，可以在没有截图能力时精确定位「谁盖住了谁」，比肉眼比对像素更可靠。
- 几何数字一旦在被两个模块引用（铭牌与飘字），就必须抽成共享函数；本项目已出现同源数字分叉导致遮挡的先例。
