## 一、为什么写这份手册

用户明确要求「容器内数据不持久，所以尽可能把数据放进代码库里，包括历史轨迹」。本轮实测印证了这一点：

- 部署完成后不久，**`/opt/oneknife999`、8080 服务进程、`/var/log/oneknife.log`、`/var/log/tunnel.log` 以及 `/opt/oneknife-start.sh` 全部消失**（`/opt` 只剩 `cloud / google / libreoffice26.8 / mcp`）；
- 同时，装到 `/opt/cloud/devTools/nodejs/v22` 下的 **instabox CLI 也消失**（该 prefix 位于平台只读快照层，写入不持久）。

结论：**任何只存在于容器里的部署状态都等于不存在**。凡是要留下来的东西，必须满足其一：
1. 已 push 到远端仓库（文档、脚本、版本号）；
2. 落在外部长期平台（instabox 实例、Hugging Face Space、自有服务器）；
3. 能由上述两者用一条命令重建。

## 三、部署步骤（本轮实际执行）

### 3.1 在 instabox 实例上把线上拉到 0.8.39

```bash
# 依赖：npm i -g instabox（必须装到可写 prefix，见 5.3）
IB=/usr/local/bin/instabox
$IB exec m_agqxoy6u363jxgfufg2onqxbm4 -- \
  'cd /data/home/oneknife999 && \
   git fetch https://atomgit.com/laotongtian/oneknife999.git main && \
   git reset --hard FETCH_HEAD && git clean -fdq game/ && cat VERSION'
```

- 更新前：`VERSION=0.8.38`、commit `1124cd5`、线上 `src/maps.js` md5 `833e1018…`（旧版）。
- 更新后：`VERSION=0.8.39`、commit `7d2616c`、`src/maps.js` md5 `e84f8d95…`（与仓库一致）。
- `serve.py` 读文件系统，git 更新即生效，**不需要重启服务**。
- 用公开 URL `git fetch`（仓库公开），不把带令牌 URL 写进实例 `.git/config`，也不出现在命令行历史。
- 实例上的 `node_modules` 在 `.gitignore` 内，`git clean -fdq game/` 只清 `game/` 未跟踪文件，不影响依赖。

## 五、环境坑（下次接手直接照做，别重走）

### 5.1 装不了 nginx

`yum install nginx` 失败：`Couldn't resolve host name for https://prod-rpm.cloudartifact.szv.dragon.tools.huawei.com/...`，`base` 源整体不可用。容器内**没有 nginx、没有 docker**，静态服务只能走 Python 标准库（3.7+ 的 `http.server` 已是多线程）。

### 5.2 平台沙箱（华为云 DevKit）没走通

`huaweicloud_sandbox_connect` 多次 60 s 超时（`MCP error -32001`），偶发连上后 `exec` 报 `APIGW.0301 Incorrect IAM authentication information: Unauthorized`。**不要在这条路上反复重试**，本轮最终改用「容器本地服务 + external 隧道 / instabox」。

### 5.3 npm 全局安装位置不可靠

`npm config get prefix` 指向 `/opt/cloud/devTools/nodejs/v22`（平台只读快照层）。在该 prefix 下 `npm i -g instabox` 当次可用，**下一次会话即消失**。正确做法：

```bash
npm i -g --prefix /usr/local instabox
/usr/local/bin/instabox --version
```

### 5.4 隧道选型实测矩阵（按「浏览器能否直接打开」判定）

| 服务 | 结果 | 结论 |
|---|---|---|
| localhost.run（`ssh -R 80:localhost:8080 nokey@localhost.run`） | HTTPS 可用，四项通过，浏览器复测通过；但免费 burst 会耗尽并降速 | **可用，仅应急** |
| pinggy（`ssh -p 443 -R0:localhost:8080 a.pinggy.io`） | `Connection reset by ... port 443` | 不可用 |
| serveo.net（`ssh -R 80:localhost:8080 serveo.net`） | curl 正常，浏览器被导向 “Serveo - Warning” 页 | 不可用 |
| cloudflared quick tunnel | GitHub Release 下载被限速到约 0.3 KB/s（38 MB 无法完成） | 不可用 |
| instabox 实例自带 `serve.py` | 四项 + 浏览器全通过，带宽稳定 | **主公网入口** |

判据：**HTTP 层 200 不等于浏览器能用**。serveo/pinggy 都是 curl 绿、浏览器红；必须用真实 Chromium 打开一次、确认 `#classModal` 与 console。

### 5.5 容器重置是常态

本轮至少发生一次全量清空（仓库、进程、日志、全局包同时消失）。所以：部署完立刻把结论写回仓库，别指望容器里的 `README.sh`、日志或 shell history。

### 5.6 硬对齐会吃掉未提交改动

`container-deploy.sh` 第一版直接 `git fetch && git reset --hard FETCH_HEAD`，在「刚写完文档、还没提交」时执行，把 README / 文档索引 / 经验三处改动整批冲掉（`untracked` 的新文档和新脚本反而保住了）。现在脚本先查 `git status --porcelain`，非空即中止；要丢弃必须显式 `FORCE=1`。同类脚本（自动部署、自动同步）都该做这个保护。

## 六、下次接手的固定动作（8 步）

1. `cat VERSION` 与 `git log --oneline -1`，确认当前基线；若仓库落后先 `git fetch && git reset --hard FETCH_HEAD`。
2. 校验三处版本一致：`VERSION` / `game/sw.js` / `game/src/main.js`（不同步先按 0.8.36 纪律修正）。
3. `bash scripts/container-deploy.sh` 重建容器本地服务与验证（`TUNNEL=none` 可跳过隧道）；脚本检测到未提交改动会中止，先提交或确认无用再加 `FORCE=1`。
4. `npm i -g --prefix /usr/local instabox`（若 `/usr/local/bin/instabox` 不存在）。
5. 用 `instabox exec` 把实例对齐到 `main`（命令见 3.1），核对 `VERSION` 与 `src/maps.js` md5。
6. 跑四项验收（3.3）+ 公网浏览器冒烟（`#classModal` 可见、console 0 error）。
7. 需要更新 HF Space 时用 `scripts/deploy-hf.py`（**禁止手工 upload_folder**，会覆盖 Space 根 README 导致 CONFIG_ERROR）。
8. 有代码或配置类改动才提交推送；纯部署轮不改版本号、不产生空提交。

### 推送认证（2026-11-18 实测）

两种方式都能把提交推上 `atomgit.com/laotongtian/oneknife999` 的 `main`，**令牌只从环境变量注入，不写进任何被 git 跟踪的文件，也不进 `.git/config` / remote URL**。

方式 A：先登录 `ag`（本容器已验证可访问仓库）：

```bash
printf '%s' "$GITCODE_TOKEN" | ag auth login --with-token
ag auth status                      # ✓ Logged in to atomgit.com as laotongtian
ag repo view laotongtian/oneknife999
```

方式 B：直接 `git push`，用一次性 credential helper 传令牌：

```bash
git -c 'credential.helper=!f() { echo username=oauth2; echo "password=$GITCODE_TOKEN"; }; f' push origin main
git ls-remote origin -h refs/heads/main     # 核对远端 HEAD 与本地一致
```

反面教材（都踩过）：

- `ag auth login --with-token --force` → `unknown flag: --force`。`ag` **不支持** `--force`，要重新登录直接再执行一次 `--with-token`。
- `cat <<EOF | ag auth login ...` 的 heredoc 结尾容易被 shell 吞掉，报 `here-document delimited by end-of-file`，令牌还会被粘到报错里；用 `printf '%s'` 更稳。
- 容器不持久：`/root/.config/ag-cli/token.json` 下次会话会消失，接手时重新登录即可，不用改任何仓库文件。
