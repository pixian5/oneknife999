## 零、与 0.2.1 的合并说明

0.2.1 与 0.2.2 是同一时间段内并行的两轮修改：0.2.1 修复了首领刷新读秒、HUD 每帧重建与按键大小写三个缺陷（单文件版本），0.2.2 完成模块化与工程化。合并方式是把 0.2.1 的全部修复并入 `game/src/` 模块：

- 首领读秒改为读取实体 `respawn`，彻底删除 `state.boss` 状态副本（`runtime.js` / `main.js` / `render.js`）；
- HUD 脏检查统一为 `setText / setHtml / setStyle / setClass` 写入缓存（覆盖 0.2.1 的六处面板签名）；
- 键盘 keydown / keyup、移动判定与屏幕方向按钮统一小写键名；
- `tests/ui-render-input-regression.cjs` 纳入 npm 脚本与 CI；测试中「拾取后背包固定为 3/12」的断言改为「至少一类资产增加」，因为掉落内容随机且一次 F 可拾取多件（材料/药水/金币/印记碎片），原断言会偶发失败（本机复现 2/5 次）。

## 一、本轮完成内容

### 1. 单文件拆分为 ES Modules

`game/game.js`（2159 行、148KB、最长单行 1661 字符）拆分为 `game/src/` 下 8 个模块，入口改为 `game/index.html` + `<script type="module" src="src/main.js">`：

| 模块 | 行数 | 职责 | 是否依赖 DOM |
|---|---:|---|---|
| `src/main.js` | 约 720 | 入口与主逻辑：地图流程、战斗、掉落、输入、主循环、E2E 接口 | 是 |
| `src/maps.js` | 约 630 | 4 张手工地图 + 96 张确定性生成地图、关卡顺序与通关规则 | 否 |
| `src/config.js` | 约 145 | 职业、怪物资料、掉落池、运行环境标记 | 否（`typeof window` 保护后可在 Node 引用） |
| `src/render.js` | 约 630 | Canvas 世界绘制、HUD DOM 渲染、屏幕反馈 | 是 |
| `src/runtime.js` | 约 80 | 运行时状态容器（state / setState / keys / pointer / moveTarget） | 否 |
| `src/geometry.js` | 66 | 确定性随机、贝塞尔采样、路径计算（纯函数） | 否 |
| `src/persist.js` | 28 | localStorage 存档读写、v2 → v3 迁移判定 | 否 |
| `src/util.js` | 20 | DOM 查询与数学辅助（纯函数） | 否 |

跨模块可变状态通过 `runtime.js` 的 `state` / `moveTarget` 活绑定与 `setState` / `setMoveTarget` 收敛，避免了散落的全局赋值。`seed开发方案.md` 中「把现有 game.js 拆分为 ES 模块」的检查项在本轮完成。

### 2. 测试本地化

- 新增 `package.json`（`type: module`）与 `package-lock.json`，Playwright 作为 devDependency（不下载浏览器二进制）。
- 两个浏览器测试脚本不再硬编码 `NODE_PATH=/Users/x/.cache/codex-runtimes/...`，改为 `npm run test:ui` / `npm run test:ui:regression` / `npm run test:e2e`；新增 `tests/browser-options.cjs`，默认驱动本机已安装的 Google Chrome（`ONEKNIFE_CHANNEL` 可切换为 `chromium` 供 CI 使用）。
- 脚本收敛为：`npm run serve`（本地服务）、`npm run check`（语法检查）、`npm run verify`（check + 单测）、`npm run test:ui`、`npm run test:ui:regression`、`npm run test:e2e`。

### 3. 单元测试与 CI

- 新增 `tests/unit/geometry.test.mjs` 与 `tests/unit/maps.test.mjs`，共 13 个用例：几何纯函数、地图目录契约（100 图 / 每图 3 节点 / 12+ 刷怪点 / Boss 阶段）、成长曲线基线（100 图 Lv.41）、生成确定性（含 stage_005 坐标金值）。

- 新增 `.github/workflows/e2e.yml`：手动或每周触发百图 e2e（耗时较长，不阻塞 push）。

### 4. 渲染性能优化（行为不变）

1. **HUD 脏检查**：`render.js` 新增 `setText / setHtml / setStyle / setClass` 写入缓存（WeakMap），内容未变化时跳过 DOM 写入。此前 `renderRegion / renderEquipment / renderInventory / renderLog / renderMapHeader / renderMapObjective / renderPlayer` 每帧无条件重建 DOM（60fps 下每秒数十次 innerHTML 解析），现在只在数据变化时更新；0.2.1 的六处面板签名缓存被统一进这套机制。
2. **事件委托**：背包点击（`inventoryGrid`）与区域导航点击（`regionList`）从「每次重建后重新绑定监听器」改为「启动时绑定一次」，同时解除渲染层对主逻辑 `equipItem` 的反向依赖。
3. **静态地图层离屏缓存**：地形、道路、城镇/战区、路线标记、战区装饰、水道、网格、地标改为切换地图时绘制一次到 2400×1500 离屏画布，每帧只做一次 `drawImage`；动态层（战术节点、出口、危险区、掉落、实体、飘字、玩家）绘制顺序不变。
4. **实测纠偏**：此前分析怀疑的「96 图启动生成拖慢冷启动」经实测不成立——100 张地图生成约 11ms，因此未做懒加载改造。
