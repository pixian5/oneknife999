# 0.8.81 深层终局与回响 B 方案

- 版本：0.8.81
- 日期：2026-11-24 03:45
- 模型：豆包
- 范围：F90 回响通关顺序、深层入口补给、死亡保留普通怪已损生命 A/B、深层成长文案、F91–F95 实测

## 1. 为什么改

0.8.80 的 F90 仍有两个结构性漏洞：

1. **首领击杀顺序不受控**。`defeat()` 对任何首领死亡都无条件 `bossDefeated = true`，并清空首领 260px 内普通怪。玩家用 AOE 先杀回响时，系统会把“普通怪没清完”这件事直接抹掉，F90 变成“先杀大怪就通关”。
2. **死亡把普通怪全部重置为满血，但首领却保留已损生命**。F90–F95 的实际死亡循环是：玩家磨掉回响 30% 生命 → 被小怪耗死 → 回响保持 30% 已损，普通怪全部满血。玩家每死一次，就要重新磨一遍小怪，容错极低。

另外，深层 UI 写着“深层成长 +14% 生命 / +7% 攻击”，但 `abyssMultipliers()` 是相对**基础值**的加法，不是每层复利；F80→F90 的实际相对生命增幅约 +11.5%。这句话会误导玩家按 +140% 预估 F90。

## 2. F90 回响 B 方案

### 2.1 规则

- 只在 `abyss-F90` 生效，`buildAbyssMap(90).echoVictoryRule = "clear-first"`；F10–F80 保持 `legacy`，不做全局重写。
- 回响死亡当帧检查 `state.quest.kills < state.quest.need`：
  - 是：判定“提前击破”。`bossDefeated` 不置 true，`echoEarlyDefeated` 置 true，回响 42 秒后重生；**不清空周边普通怪**。
  - 否：正常最终击破，`bossDefeated = true`，走原有的余波清怪与通关结算。
- `checkMapCompletion()` 仍只认 `kills >= need && bossDefeated`；提前击破不会把 `completed` 写成 true。
- 最终击破后 `echoEarlyDefeated = false`，避免下一轮判定残留。

### 2.2 奖励与印记

- `computeKillReward()` 增加 `echoEarlyDefeated` 分支：
  - 提前击破：`firstProgressKill = false`，经验按 50%；不发首领印记。
  - 最终击破：按首次首领击破发满额经验与 35 印记。
- 新增 `bossMarksAwarded`，只在 F90 的 `clear-first` 规则下置 true，保证一次 F90 只发一次印记；普通图 / 旧整十层继续保留“重复击杀仍发印记”的旧行为。
- 这样不会出现“提前击破拿 35，最终击破再拿 35”的双发。

### 2.3 祖父保留

- 旧档 F90 `completed = true` 时，`mapProgress()` 仍按 `kills + bossDefeated` 派生 completed。
- `loadMap()` 在深层 completed 时继续只保留 friendly/npc，不会生成回响。
- `enterAbyss()` 仍按 `completed` 放行 F91；不改 `abyssBest`，不会把已完成 F90 打回。
- 新增 UI 用例在完成态刷新后断言“无回响 + 可按 T 进 F91”。

## 3. 深层入口补给

- 在 `loadMap()` 写入 `visitedMaps[mapId] = true` 之前判断首访：
  - `abyss-F*` 且非 `keepBossHp`（死亡复活）且 `visitedMaps[mapId]` 为假 → `+1` 生命药水。
- 用 `visitedMaps` 做持久标记，死亡重进、刷新、重新读档都不会重复领；每层只发一次。
- 不加上限：当前药水没有硬上限，补给来源是“每层首访 +1”和秘藏箱，深层必须逐层推进，不能反复刷同一层。
- 与秘藏补给箱叠加：F91 首访 +1，开箱再按既有规则 +2（F31+），仍只够一次容错，不会变成无限药。

## 4. 死亡保留普通怪已损生命 A/B

- 新增纯函数 `preservedAbyssNormalHp(maxHp, hp, ratio)`：
  - `ratio = 0`：满血重建（旧行为，A 组）。
  - `ratio = 0.5`：新血量 = 新上限 - 已损生命 × 0.5，即保留一半伤害；下限 1。
- 新增 `restoreDamagedAbyssMonsters()`，只处理“上一场存活且受伤”的普通怪，跳过 Boss / 友军 / NPC / 召唤物 / 已死怪，按 `entity.id` 对齐。
- 开关默认 **开 B 组**：`?abyssPreserve=0` 或 `localStorage.oneknife999-abyss-preserve=0` 回退 A 组。最初依据：F91 A=10 死/185.2s、B=6 死/140.6s；F92 A=9 死/154.4s、B=6 死/114.4s。**但 F91–F95 全量重跑后 B=+52 死、A=+47 死，B 总死亡反而多 5；默认 B 转为待复核，不再宣称“稳定少 33–40%”。**
- `die()` 仍走 `loadMap(..., keepBossHp = true)`；首领继续走 `restoreDamagedBoss()`，普通怪只有 B 组才回填。

## 5. 深层成长文案

- `endgame.js` 新增 `abyssGrowthText()`：`同章每层 +14% 基础生命 / +7% 基础攻击，10 层换章`。
- `abyssRelativeHpGain(80, 90)` 返回约 `11.47%`，单测锁定 11.4–11.6 区间。
- `render.js` 的区域导航从硬编码“深层成长 +14% 生命 / +7% 攻击”改为 `abyssGrowthText()`，并加 `title`：`深层倍率按基础值加法，不是每层复利`。

## 8. 实测与边界

- 0.8.81 未改变 F10–F80 的回响顺序，避免一把改掉旧整十层的复玩节奏。
- 提前击破仍给经验（半额），但不给印记；这是有意设计：提前击杀不是“无效操作”，但无法跳过通关条件。
- 默认 B 是初步实测结论，不是拍脑袋；但全量 F91–F95 出现反转，且 F93/F95 的死亡受“首领阶段残留额外普通怪”污染，必须先用“清完额外小怪”的对照复测再决定是否保留。A 组仍可用 `?abyssPreserve=0` 复验。
- 入口补给不补满药水，只 +1；如果后续实测 F91–F95 仍然药水荒，再考虑改 F31+ 秘藏箱或首访补给数量，而不是无限叠。
