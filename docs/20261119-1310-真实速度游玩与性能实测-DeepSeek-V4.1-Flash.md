## 六、发现缺陷：换图后不落盘（P2，未修）

### 证据

- 三关连跑进入第 4 关 `red_sand_desert` 后 `page.reload()`：快照回到 `black_rock_mine`（stage 3，已完成状态），金币/等级保留，但第 4 关内 `kills 0/10` 的进度归零
- 两关连跑同样复现：进第 3 关后刷新 → 回到第 2 关
- 两次运行 100% 复现，不是偶发

### 根因

`game/src/main.js:1916 doTravel()` 只做 `loadMap(exit.target, ...)`，**没有 `persistGame()`**。落盘点只挂在通关、升级、拾取、喝药、强化等事件上，因此「刚进新图、还没触发任何事件」这段时间完全没落盘。

### 影响

玩家进入新图后切后台 / 手机被系统杀进程 / 主动刷新 → 回到上一图的出口（已完成状态），需要再按一次 `T`；如果在新图已经打了几只怪但没升级/没拾取，这部分进度也会丢。

### 建议修法

1. `doTravel()` 末尾补 `persistGame()`（与 0.8.6 修「选完职业立即落盘」同类空窗）；
2. 补一条回归断言：进入新图 → `reload()` → 仍在当前图，且 `currentMapId` 等于新图；
3. 顺带检查 `tryTravel()` 的确认弹层分支（低等级进入高压图）是否也需要落盘。

### 为什么百图 e2e 没发现

`tests/e2e-100-shots.cjs` 每关都在「通关结算点」落盘并 `SAVED+RESTORED` 校验，然后才走出口——正好绕开「进图到首次事件」这段空窗。**这类缺陷只能用真实速度 + 主动刷新才能暴露**，这也是本篇与 fast 验收并存的价值。

## 七、测试方法（未入库的临时脚本）

- 用 Playwright `chromium.launch({ executablePath })` + 自写循环，不依赖 `tests/` 里的 fast 模式
- 每 130–200 ms 读一次 `window.__ONEKNIFE_E2E__.snapshot()`：取最近怪/首领坐标，按 `W A S D` 靠近，距离 <62 px 时按住 `X` 普攻、每 1.8 s 按 `1`，首领按 `R`
- 血量 <50% 且 900 ms 内未喝药时按 `Q`；掉落 85 px 内按 `F`；通关后按 `T` 并点 `[data-travel-ok]`
- 性能用 `requestAnimationFrame` 自采样 8 s / 5 s；移动端用 `viewport 390×844 + isMobile + hasTouch`，用 `mouse.down/move/up` 模拟摇杆拖拽（游戏接受 pointer 事件）
- 脚本只在本机 `/tmp` 使用，不入库（属于一次性验证工具）
