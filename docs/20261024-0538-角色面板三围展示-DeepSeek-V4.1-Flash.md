# 0.3.8 角色面板三围展示（生命 / 攻击 / 防御）

## 问题

0.3.7 让装备防御词缀真正参与承伤，但界面只显示一个综合「战力」数字：

- 玩家在杂货商花 120+ 金币重铸出「防御 +15」，战力可能只涨一点点，**看不到承伤变低**；
- 生命词缀同理，改动装备前后只能看到血条上限的细微差异；
- 战力公式里防御按 `×2` 折算权重，属于综合评分，不是可对照的属性值。

结果是「变强」缺少可验证的反馈，玩家无法判断重铸值不值。

## 实现

### 1. `game/index.html`

在角色卡片头部（头像 / 名字 / 战力）下方、经验条上方插入一行三围：

```html
<div class="stat-row hero-stats">
  <span>生命 <b id="hpStat">0</b></span>
  <span>攻击 <b id="attackStat">0</b></span>
  <span>防御 <b id="defenseStat">0</b></span>
</div>
```

复用已有 `.stat-row`（flex + 两侧分布 + 11px），不需要新 CSS。

### 2. `game/src/render.js` `renderPlayer()`

把原本一次性的战力求和抽成 `equippedPower`，再按「与战斗结算同源」的方式计算三项：

```js
const equippedPower = Object.values(state.player.equipment)
  .reduce((sum, item) => sum + (item ? effectiveItemPower(item) : 0), 0);
const power = hero.attack + state.player.level * 4 + equippedPower + hero.defense * 2;
const attackStat = Math.round(hero.attack + state.player.level * 4 + equippedPower * 0.9);
const hpStat = playerMaxHp();
const defenseStat = playerDefense();
```

- **攻击**：与 `computeDamage` 的 `base` 公式完全一致（装备战力 `×0.9`），
  不是简单相加——否则面板数字会比实际伤害高 11%。
- **生命**：`playerMaxHp()`（职业基础 + 等级×18 + 部位基础 + 生命词缀）。
- **防御**：`playerDefense()`（职业基础 + 防御词缀），与 0.3.7 承伤结算同源。

面板签名（`panelChanged`）加入三个新值，否则只改防御 / 生命词缀时签名不变，HUD 不会刷新——战力在那两种情况下可能完全不变。

## 实测（系统 Chrome，1440×900）

| 状态 | 生命 | 攻击 | 防御 | 战力 |
| --- | --- | --- | --- | --- |
| 战士 Lv.1 裸装 | 368 | 37 | 22 | 81 |
| 同上 + 法力重铠（power 40 / 防御 +15 / 生命 +60 / 攻击 +10） | 488 | 82 | 37 | 131 |

对照公式：生命 350+18=368，加护甲部位 60 + 生命词缀 60 = 488；
攻击 33+4=37，装备有效战力 50×0.9=45 → 82；防御 22+15=37。全部吻合。

## 探针波动（需要关注）

同一套探针代码在本轮之前分别测出过第 15 关 0 死 / 75s、1 死 / 138s，本轮 5 死 / 251s。本轮改动只涉及 HUD 展示（`renderPlayer`），不触碰战斗逻辑，因此差异来自探针自身的不确定性：

- 首领战「一刀一撤」依赖固定 320ms 的后撤窗口，虚拟时钟推进与网络/渲染无关，但**玩家死亡会导致首领回血重置**，一次失误就让整场拉锯延长约 40s，并放大后续被毒 / 危险区磨死的概率；
- 探针的喝药节奏是「每 4 个循环且血量 < 55%」，接近阈值时不喝药，容易在 60% 附近来回。

结论：单次结果不能作为数值结论，只能作为「有没有卡死 / 是否超闸门」的门禁。若要把探针升级为数值回归，需要多次取中位数（见下一步待实现 P1）。
