# 工程门禁与素材瘦身（0.8.78）

- 版本：0.8.78
- 时间：2026-11-23 22:28
- 模型：豆包
- 范围：工程门禁、CI 触发、素材清理与压缩；不改动战斗数值和玩法逻辑。

## 一、为什么先做这一批

0.8.77 合并后，项目仍有三个会持续放大的问题：

1. `npm run check` 是手工文件清单，新模块可能漏检；`game/sw.js` 的 `SHELL` 也是手工清单，新增 ES 模块忘加会导致离线启动缺模块。
2. CI 只监听 `main`，`work` 分支的提交要等合并后才跑；14 项 UI 回归没有覆盖最近补的状态、移动端、HUD、死亡存档。
3. `game/assets` 约 114MB、812 个文件；其中 55 个旧 `monster-*.png` 约 41.3MB 已不被运行时引用，`ui-divider.jpg` 单张 2.07MB，移动端缓存和首次加载都没有体积门禁。

这一批先把“不会越改越乱”和“不会越加越重”补上，再进 0.8.79 的地图差异。

## 二、工程门禁

新增：

- `tools/check-syntax.mjs`：扫描 `game/src/**/*.js`、`game/sw.js`、`tests/**/*.{cjs,mjs}`、`tools/**/*.mjs`，共 100 个文件；不再维护手工清单。
- `tools/check-version.mjs`：校验 `VERSION`、`package.json`、`package-lock.json`、`CURRENT_APP_VERSION`、`sw.js` 的 `CACHE_VERSION` 一致；同时校验 `SHELL` 覆盖 `game/src/*.js` 且不引用不存在的文件。
- `tools/asset-budget.mjs`：素材总量 ≤60MB、地图底图 ≤450KB、单张非地图 ≤500KB、禁止 0 字节；本批瘦身后 29.3MB / 757 个文件通过，合并美术线第三批后 35.6MB / 941 个文件仍通过。
- `tools/asset-audit.mjs`：补 `resolvedWithMissing` / `noOwnArt` 的失败退出码，素材缺失不再只是打印。

`package.json`：

- `check` 改为 `node tools/check-syntax.mjs && node tools/check-version.mjs`。
- `format` / `format:check` 增加 `tools/**/*.mjs`。
- `verify` = `check + format:check + test:unit + test:assets`。
- 新增 `test:assets` = `asset-audit --json` + `asset-budget`。

CI：

- push / PR 分支从 `[main]` 扩为 `[main, work]`，`work` 的提交不再等合并才暴露。
- UI matrix 从 14 项扩到 19 项，新增 `ui:status`、`ui:status-real`、`ui:touch`、`ui:hud-health`、`ui:death-save`。
- `verify` 现在会跑版本、素材、格式与 250 个单测。

### 3.2 按实际显示尺寸压缩

使用 ImageMagick 离线处理，不引入运行时依赖：

| 类别 | 处理 | 代表结果 |
|---|---|---|
| `monster-full-*` | 保留 160×160，PNG 调色板 128 色 | 藤蔓缚妖 idle 35KB → 7.7KB |
| `boss-full-*` | 保留尺寸，调色板 128 色 | 裂碑领主 109KB → 32KB |
| `player-*` | 最大 256，调色板 128 色 | 战士 458KB → 46KB |
| `equip-*` | 最大 256，调色板 256 色 | 武器 296KB → 33KB |

结果：

- 本批自身压缩结果：`game/assets` 约 114MB / 812 个文件 → **29.3MB / 757 个文件**，体积约 **-74%**。
- 合并美术线第三批（46 只独立原画派生 184 张四帧）后：**35.6MB / 941 个文件**，仍低于 60MB 总预算。
- 当前最大单图 `bg-battlefield.jpg` 451KB，所有地图底图 ≤376KB。
- 941 个文件全部通过 `identify` 解码检查；合并后 `asset-audit` 为 106/106 四帧解析成功、**137 个独立动作帧物种、0 个别名复用、0 个仅静态原画、0 个完全无自有素材**。

### 3.3 合并美术线第三批（46 只独立四帧）

- GitCode `work` 的 `1249467`（提交者 DeepSeek-V4.1-Flash）为本轮并入了 46 只“只有静态原画”的怪：按同源派生 160×160 RGBA 四帧，共 184 张；`idle` 归一化，`walk/attack/hit` 用小幅旋转/位移，属程序化占位。
- 同批修复 `resolveMonsterSpriteName` 的优先级：自身白名单优先，别名仅在“无自有帧”时回退；此前别名优先会让新增白名单完全不生效（第 7 关 `loadedFrames=[]`）。
- 合并后 `asset-audit`：106/106 四帧解析成功、137 个独立动作帧物种、0 个别名复用、0 个仅静态原画、0 个完全无自有素材。
- 这批 184 张不进调色板压缩，保持 RGBA；静态原画仍是“派生动作”的源头，不是真实逐帧动作原画。

## 五、边界与风险

- 调色板压缩是**有损**的；当前证据是桌面/移动截图与 941 文件解码，不代表所有原画在极端放大下都无损。后续新原画仍走 GLM/CogView，不拿本次压缩结果当美术源。
- 46 个“仅静态原画”在合并前存在；美术线第三批已用静态图派生 184 张 160×160 RGBA 四帧（idle 归一化，walk/attack/hit 小幅旋转位移），并把 `resolveMonsterSpriteName` 改为“自身白名单优先、别名仅无自有帧时回退”。这解决的是**运行时不再借别人帧**，不是真实动作原画；`walk/attack/hit` 仍是程序化占位，真实动作原画到位后覆盖同名文件。
- 184 张派生帧没有走本批调色板压缩，保留 RGBA；这是 29.3MB → 35.6MB 的主要增量，换来透明边缘与动作姿态可用。
- F90 进度、回响 A/B、深层数值都没有改动；本批不碰玩法判定。
- `game/sw.js` 的 `CACHE_VERSION` 已随 0.8.78 更新；旧缓存会在 activate 时清掉，首次打开会重新拉取压缩后的素材。
- `art-source/monster-legacy/` 不入库；如果换机器且需要旧原图，从上面的 tar 备份或 Git 历史恢复。
