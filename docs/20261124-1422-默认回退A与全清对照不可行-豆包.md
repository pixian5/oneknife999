# 0.8.82：死亡保留默认回退 A，全清对照不可行
> 0.8.83 后记：B 组的“保留一半已损生命”已改成“死亡后最高 50% 最大生命且只降不升”，修复了普通怪越死越回血。本文的 B=5716/7145 与旧 B 长跑数据仅代表 0.8.82；新 B 需重跑。


- 日期：2026-11-24 14:22
- 版本：0.8.81 → 0.8.82
- 结论：F91–F95 全量样本没有证明 B 组（保留一半已损生命）优于 A 组；把“清完额外普通怪”作为对照在 F91 让两组都陷入死亡循环，该路线不成立。默认改回 A，B 保留为显式实验开关。

## 1. 触发原因

0.8.81 最初按 F91/F92 小样本把默认设为 B：F91 A=10 死/185.2s、B=6 死/140.6s；F92 A=9 死/154.4s、B=6 死/114.4s。随后 F91–F95 全量真实键鼠跑完：

| 层 | A 死亡 | B 死亡 |
|---|---:|---:|
| F91 | +10 | +8 |
| F92 | +9 | +5 |
| F93 | +6 | +17 |
| F94 | +11 | +8 |
| F95 | +11 | +14 |
| **合计** | **+47** | **+52** |

B 在 F91/F92/F94 更好，但 F93/F95 反弹；全量 B 多 5 死（约 +10.6%）。F93/F95 的死亡有大量发生在首领阶段，场上有未计入 5 只任务的额外普通怪，因此不能把 +5 全部归因于“保留一半生命”。

## 2. 尝试“清完额外普通怪”的对照

为了排除额外怪污染，写了一个**临时脚本** `/tmp/clean_abyss.py`，不修改仓库源码：

- 复用 `tools/run_abyss.py` 的真实键鼠移动/点击/连招；
- 普通怪阶段不再在 `kills >= 5` 停止，而是循环到 `alive` 普通怪为 0；
- 低血量按 Q 喝药（真实键盘事件），A/B 一致；
- 从 F90 完成档载入，按 T 进入 F91，只测 F91。

结果：

- A 组：4 分钟内死亡 473→490（**+17**），场上仍有 10–11 只普通怪，未清完。
- B 组：约 2 分钟内死亡 473→477（**+4**），场上仍有 10–11 只普通怪，未清完。

两组的“清完”都没有完成，且观察时长不同，不能拿这两段数据做严格 A/B；但足以说明：**F91 的 12 只普通怪全清不是当前角色能稳定完成的路线**。深层设计只要求 5 只，额外怪是可选风险，不是必须清的空场。用“全清”做对照会把测试变成另一种玩法，不能用来判定死亡保留机制。

因此**停止“清完额外普通怪”的对照**，不把该逻辑写进 `run_abyss.py`，避免后续长跑被拖死。
