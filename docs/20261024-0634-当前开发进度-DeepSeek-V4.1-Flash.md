## 一、本轮完成

**难度探针稳定性**：让 `npm run test:difficulty` 从「只能看是否卡死」升级为「可作为数值回归参考」。

- 新增 `ONEKNIFE_PROBE_RUNS`（默认 **3**）：每关重复 N 次、每次新建 context + page，取死亡数与耗时**中位数**。
- 判定改为**中位数闸门**（`deaths > 6` 才失败），单次超限只打印 `PROBE WARN`；耗时仍单次严格判定（代表关卡能否推进）。
- 喝药阈值 **55% → 65%**，检查频率 每 4 循环 → 每 3 循环。原因：55% 时已在「下一次重击可能致死」区间，而死亡会让首领满血重置，形成越打越久的自放大。
- `PROBE START` / `PROBE RESULT` 增加 `run=1/3` 标记。

## 四、本轮发现的问题（未修，待决策）

1. **探针只测战士**：法师 / 道士的基线装备、射程、资源循环都没被「多次中位数」覆盖过。扩面需要先确认这两个职业在本关掉落表下的生存能力。
2. **探针不模拟防御词缀收益**：基线装备 `affixes: []`，无法量化 0.3.7 接入的防御词缀价值。可加 `ONEKNIFE_PROBE_DEFENSE_AFFIX` 对照组。
3. **`balance-sim` 仍未模拟前摇 / 全局闸门**：数值调整只能靠浏览器探针验证，模拟器结论与实测之间仍有落差。
