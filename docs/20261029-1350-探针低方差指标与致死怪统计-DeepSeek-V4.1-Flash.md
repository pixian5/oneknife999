# 探针低方差指标与致死怪统计（0.7.6）

- 日期：2026-10-29 13:50
- 模型：DeepSeek-V4.1-Flash
- 版本：0.7.5 → 0.7.6
- 内容：给难度探针补上「首次死亡时间 / 每百秒承伤 / 致死来源」三个低方差指标，并复测第 30 关

## 一、为什么要换指标

0.7.5 的教训很直接：同一份代码，n=3 测出中位 9 死，补到 n=8 变成中位 6 死。死亡数不是「难度的刻度」，而是「失误次数 + 正反馈放大」的混合体：

- 玩家死亡会被送回城镇重生，普通怪满血刷新、必须重新清一遍（首领生命自 0.4.2 起保留），一次失误就把「清怪 + 走位」的完整成本再付一次；
- 死亡数是**离散且阶梯式**的，一次调参 10%–20% 往往连一个整死都挪不动；
- 种子只锁 `Math.random`，锁不住帧时序（`dt = Math.min(delta, 0.05)` 随负载变化），跨会话中位就能差 2 死。

要判定小步调参，需要**连续、单调**的量。本轮给探针加三个：

| 指标 | 含义 | 为什么单调 |
|---|---|---|
| `damage100` | 每 100 秒模拟时间的**净生命损失**（只累加 hp 下降，喝药 / 复活回血不计） | 承伤速率直接反映怪物输出的持续强度，削系数必然下降 |
| `firstDeath` | 首次死亡发生的模拟秒数（未死亡记 -1） | 输出越低，第一次死得越晚 |
| `killers` | 致死来源计数（怪物名 / 中毒 / 地面危险区） | 用于定位「谁在杀人」，避免继续整体削系数 |

## 二、实现

### 探针侧（[tests/difficulty-probe.cjs](../../tests/difficulty-probe.cjs)）

新增 `sampleCombat(stats, snap, atMs)`，在 `defeatEntity` 的每一轮循环采样一次快照：

- `hp` 比上一拍低就累加差值，升高（喝药 / 升级回血 / 复活满血）一律不计——只算「承伤」，不算「回复」；
- `player.deaths` 增加时，把当前模拟毫秒记进 `deathTimes`，并按 `player.lastKiller` 累加致死来源；
- 采样跨「清怪 + 首领战」全程累计，`damage100` 用全程耗时归一化，避免两段节奏差异影响可比性。

输出格式（每次运行一行）：

```
PROBE RESULT stage 30 stage_030 run=1/8 arm=baseline class=warrior Lv.21 deaths=… seconds=… firstDeath=…s damage100=… killers=…
```

汇总行追加中位数：`首死中位=…s 承伤中位=…/百秒`。首死中位数只统计「确实死亡过」的运行，全部未死时保持 -1。

### 游戏侧（[main.js](../../game/src/main.js)）

探针拿不到「谁打死了我」，因此新增诊断字段 `state.player.lastKiller`：每次怪物命中写入攻击者名字，中毒 / 地面危险区致死时写入对应来源，`snapshot().player.lastKiller` 暴露给测试。

该字段**只用于诊断**：不参与结算、不写存档、不进 HUD，生产环境行为与 0.7.5 完全一致。

## 三、验证

- 小样本冒烟（第 15 关战士，2 次）：新字段全部出现，且能抓到真实死因——`run=2` 的 2 次死亡记为 `killers=地面危险区x2`（首领二阶段地面危险区），说明「非怪物」来源也能被区分。
- `npm run verify`：161 单测全绿、格式与语法检查通过。

### 4.1 低方差指标读出了什么

- **承伤速率高度稳定**：8 次落在 4861–6881，中位 5741，逐次波动约 ±17%；而死亡数在 2–10 之间跳（5 倍差）。同一份代码、同一个种子组，`damage100` 比死亡数稳定得多。
- **首死中位 33s**：说明压力从入场就存在（首死 25–52s），不是「打首领才崩」。
- 跨会话仍不可比：0.7.5 那一批同代码 n=8 中位 6 死，本轮中位 7 死——两批数字不能相加，能跨批比较的是 `damage100` 这类速率量（但本轮才有，旧批没有历史值）。

### 4.2 谁在杀人：没有「单一凶手」

53 次死亡按来源归类：

| 来源 | 次数 | 占比 | 形态 |
|---|---:|---:|---|
| 龙脉沙魂亡灵 | 8 | 15% | `ranged` |
| 地宫龙君（首领） | 7 | 13% | boss |
| 龙脉地宫炎蝠 | 7 | 13% | `charge` |
| 龙脉石俑卫 / 寻宝恶徒 / 矿毒邪蛛 | 5 / 5 / 5 | 28% | `sweep` / `ranged` / `normal` |
| 矿道巨虫 / 石甲巨像 / 地面危险区 | 4 / 4 / 4 | 23% | `charge` / `sweep` / hazard |
| 龙脉毒虫 | 2 | 4% | `normal` |

按形态汇总：**ranged 13（25%）、charge 11（21%）、sweep 9（17%）**，三类「扩大交战窗口」的形态合计 62%；首领 13%、普通近战 13%、地面危险区 8%；`heavy` / `multi` / `multi3` / `pull` 在本关没有致死人。

这解释了为什么 0.7.5 整体收系数能把中位从 8 压到 6–7，但压不到更低：凶手分散在三种形态、九个怪身上，**整体下调是钝刀**；下一步要动的是 `ranged` 与 `charge`（合计 46%），而且要在承伤速率上看到下降，才算改动生效。

## 五、结论与下一步

1. **本轮不改数值**：0.7.6 只加可观测性，行为与 0.7.5 完全一致（`lastKiller` 只读不写、不参与结算）。战士第 30 关仍在中位 6–7 死之间，与 0.7.5 的结论一致：压线，没有余量。
2. **判定口径换轨**：后续调参以 `damage100`（本轮基线中位 **5741**/百秒）与 `firstDeath`（中位 **33s**）为主指标，要求下调 ≥10% 才算生效；死亡数只作闸门（中位 ≤6）。
3. **定向下调的对象**：`ranged`（射程 1.6 倍，致死人最多）与 `charge`（突进 64px + 击退 24）优先；不建议再整体削 `heavy`——它在本关零致死人，继续削只会牺牲手感。
4. **补三职业**：法师本轮没有跑，`damage100` 基线缺一组；下一步按同样 n=8 补法师，再比较「同承伤速率下谁更脆」。
