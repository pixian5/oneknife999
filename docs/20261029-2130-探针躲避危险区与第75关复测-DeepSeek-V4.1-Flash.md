# 探针躲避危险区与中毒，第 75 关复测（0.8.0）

- 日期：2026-10-29 21:30
- 模型：DeepSeek-V4.1-Flash
- 版本：0.7.9 → 0.8.0
- 内容：修掉探针对「脱手伤害」的盲区（看不到危险区、中毒阈值过高），复测第 75 关判断峰值是否真实

## 一、问题：探针看不见危险区

0.7.9 测出第 75 关中位 4 死，死因里「地面危险区 6 + 中毒 4」占 45%。但排查发现**这是探针自身的盲区**，不完全是关卡问题：

1. `snapshot()` 只暴露 `hazardsSpawned`（累计生成数），**没有任何危险区的实时位置**。探针无法走位躲红圈，只能站着挨打；
2. 探针的中毒撤退阈值是 `poison >= 3`。而中毒伤害是「层数 × 4 点 / 每 1.2 秒」，3 层时已在半血区；带 `poisonStacks` 的首领（第 75 关正是）会持续叠层，等到 3 层往往来不及撤。

真玩家看到红圈会走开、中毒 2 层就会想去净化——探针做不到，所以数字系统性偏悲观。

## 二、改动

### 2.1 游戏侧：暴露危险区

[main.js](../../game/src/main.js) 的 `snapshot()` 新增：

```js
hazards: (state.hazards || [])
  .filter((hazard) => !hazard.snap)
  .map((hazard) => ({ x: hazard.x, y: hazard.y, r: hazard.r, life: hazard.life })),
```

只暴露「还没引爆」的危险区（`snap === false`），给测试用；不参与任何游戏逻辑。

### 2.2 探针侧：两条躲避规则

[tests/difficulty-probe.cjs](../../tests/difficulty-probe.cjs)：

**① 脚下有红圈就走开**（每次循环开头判定）：

```js
const dangerUnderfoot = (snap.hazards || []).find(
  (hazard) => Math.hypot(hazard.x - snap.player.x, hazard.y - snap.player.y) < hazard.r + 18
);
if (dangerUnderfoot) {
  // 朝背离圈心的方向走 90px，再等 260ms
  await moveToPoint(page, target, mapId, 26);
  await spend(260);
  continue;
}
```

**② 中毒阈值 3 → 2 层**：`needsRecovery` 从 `poison >= 3` 改为 `poison >= 2`，让探针在毒还没叠满时就回营地。

### 3.1 结果解读

1. **死亡中位 4 → 2，总承伤 4378 → 3908（−11%）**：确认 0.7.9 的数字确实被高估了一部分，探针的躲避盲区是真实原因之一。
2. **但峰值没有消失**：中位 2 死、全距 1–4，仍是三关里最高的（第 60 关 0 死、第 90 关 0 死）。总承伤 3908 也比第 60 关（2904）高 35%。
3. **危险区依旧是第一杀手**（8 次共 13 次死亡里，危险区 8 次、中毒 3 次、猎杀者 4 次），躲避只是让探针少挨了几下，机制本身仍在持续施压。

### 3.2 一个重要的方法学收获

**同一份关卡代码，探针的操作水平能让死亡中位数差 2 倍**（4 → 2）。这意味着：

- 之前所有"探针测出的死亡数"都带着"这个探针不会躲红圈"的系统偏差；
- 对**纯输出型关卡**（第 30 关）影响小，因为挨打不可避免；
- 对**脱手伤害型关卡**（第 75 关）影响大，因为躲避是主要应对手段。

后续再判「某关是否超标」，必须先确认探针在这个机制上不是瞎的。

## 四、第 75 关到底要不要修

修完躲避后仍有中位 2 死（未超闸门 ≤6），但它是 60 / 75 / 90 三关里唯一有死亡的，且总承伤高 35%。三个选择：

| 选项 | 说明 |
|---|---|
| **不修** | 中位 2 死仍在闸门内，且第 75 关是百图里少数有「毒首领 + 最短特殊间隔」的关卡，属于设计上的难点，保留它有辨识度 |
| **只降危险区伤害** | 给修正表加 `hazardMult`，只影响该关的脱手伤害，不动怪物正面输出 |
| **拉长特殊间隔** | 加 `specialIntervalMult`，把 4.63s 拉回 5.0s（与第 60 关持平），会缓和阶段战节奏 |

本轮**不改数值**：先有准确的测量，再决定改不改，避免又回到"凭一次数字调参"的老路。
