# 界面性能与首领倒计时修复记录（U-PERF-01）

> 合并说明：本文记录 0.2.1 的修复。0.2.2 工程化补强把同一批修复并入 `game/src/` ES Modules——首领读秒取实体（`render.js` 区域动态）、键名小写归一化（`main.js` 输入与移动判定）、HUD 脏检查统一为 `setText / setHtml / setStyle / setClass` 写入缓存（`render.js`），并把 `tests/ui-render-input-regression.cjs` 纳入 `npm run test:ui:regression` 与 CI。行为与验证口径保持不变。

## 1. 本轮目标

0.2.1 修复三个影响原型可信度与性能的缺陷：首领刷新倒计时固定显示 0 秒、主循环每帧重建 HUD 面板、按键大小写在 Shift / CapsLock 状态下失效。本轮只改动前端渲染与输入处理，不改变关卡规则、数值配置与存档结构（仍为 `oneknife999-prototype-save-v3`）。

本轮范围：

- 把首领刷新状态从"状态副本"改为"实体单一事实源"；
- 六个 HUD 面板改为内容签名驱动的按需渲染；
- 键盘输入统一小写归一化；
- 为上述三项补充可重复执行的浏览器验证。

非目标：不改动伤害、掉落、通关条件、地图生成与自动保存流程；不引入新的 HUD 内容。

## 2. 问题与根因

| 编号 | 现象 | 根因 | 风险 |
|---|---|---|---|
| U-PERF-01-A | 首领被击破后区域动态与首领情报条固定显示"0s 后刷新"，与真实 42 秒刷新脱节 | `state.boss` 是与实体并列的状态副本，只在初始化时写入，之后没有任何地方更新它；真实刷新由实体 `entity.respawn` 递减驱动 | 玩家无法判断首领刷新时机；副本还会继续扩大，未来 BOSS 读条、阶段、贡献等都可能读到旧值 |
| U-PERF-01-B | 每帧重建背包、装备、区域导航、战场日志、关卡卡与区域动态的 DOM；背包按钮每帧重复绑定点击监听 | `update()` 每帧调用 `renderAll()`，各面板直接 `innerHTML = ...` 整体重写 | 60fps 下持续 GC 抖动与样式重算；监听器随帧累积；移动端点按存在失效风险 |
| U-PERF-01-C | Shift / CapsLock 按住时 WASD 与方向键失效或"卡键" | 按下时按 `event.key` 原样记录（大写存为 `keys.W`），移动判定却读取小写 `keys.w`；keyup 同样大小写不匹配 | 特定输入状态下无法移动，移动端按钮写入的键名也需要与桌面保持一致 |

## 3. 修复内容

### 3.1 首领状态改为单一事实源（A）

- 删除 `state.boss` 副本：创建角色、进入地图、击破首领、首领复活四处写入全部移除；
- 区域动态与首领情报条的刷新读秒改为直接读取首领实体的 `respawn`；
- 首领状态只保留两个事实源：实体 `alive`（当前是否在场）与关卡进度 `bossDefeated`（本关是否完成击杀目标）。

### 3.2 渲染改为"内容变化才写 DOM"（B）

- 区域动态、关卡卡、区域导航、装备栏、背包、战场日志六处增加内容签名；签名未变化时直接返回，不重写 DOM、不重复绑定监听；
- 签名初值为 `null`，把"空内容"与"尚未渲染"区分开。这是本轮实际踩到的缺陷：背包为空时签名与初始空字符串相同，导致首次渲染被跳过、背包格为空，已修复并加入回归用例；
- 内容真正变化时（拾取、穿戴、击杀、通关、切图、首领击破与刷新）仍然立即重建，交互路径与保存行为完全不变。

### 3.3 按键统一小写归一化（C）

- keydown / keyup 与移动判定统一使用 `event.key.toLowerCase()`；
- 屏幕方向按钮写入的键名同步小写，桌面键盘与移动端按钮共用同一套键名。

## 4. 验收证据

新增常驻回归测试 `tests/ui-render-input-regression.cjs`（Playwright，桌面 1440×900，真实键盘事件与真实拾取路径）全部通过，关键结果：

| 用例 | 结果 |
|---|---|
| 首领被击破后区域动态与情报条读秒 | 42s → 39s 逐秒递减（修复前固定 0s） |
| 技能/背包/装备/导航/日志/目标卡 1.6 秒元素身份 | 六处面板均不被重建，且元素存在 |
| 大写 W / 大写 ArrowDown 移动 | y 780 → 638 → 747，大小写均可移动 |
| 背包 12 格渲染 | 预置 2 件物品显示 2/12，首格非空（覆盖空签名缺陷） |
| 真实拾取 | 按 F 拾取后 2/12 → 3/12，药水 3 → 4，日志同步更新 |
| 首领击破后的目标卡刷新 | 关卡卡出现首领 ✓，任务文案显示"Boss 已击败" |
| 页面运行错误 | 无 |

项目自带测试：

- `tests/ui-smoke.cjs`：桌面 1440×900 与移动 390×844 无纵向滚动、Canvas 非空、技能悬停与范围预览全部通过；
- `tests/e2e-ten-clear-runs.cjs`（`ONEKNIFE_RUNS=1`）：战士单账号 100 图真实鼠标键盘长跑回归（每关清怪、验证首领阶段与危险技能、自动存档、刷新恢复后走出口进入下一关），运行命令与结果记录见 [game/README.md](../game/README.md) 与 [通关测试记录](13-通关测试记录.md)。

## 5. 边界与后续

- 本轮是前端原型内的性能与一致性修复，HUD 仍是本地模拟；接入正式服务端（`09-服务器技术与反作弊.md`）时，首领状态、刷新计时与关卡进度都必须改为服务端权威并按相同幂等口径回放。
- 签名缓存只解决"重复写同一内容"的问题；若后续 HUD 面板增加更高频的动态数据（如实时排行、伤害统计），应改为增量更新而不是扩大签名范围。
