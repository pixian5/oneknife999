# 《一刀999》0.8.7 详细测试计划

- **被测基线**：`atomgit.com/laotongtian/oneknife999` `main` @ `a0a3a5e`（0.8.7）
- **被测形态**：纯前端 Canvas 百图原型（十章 100 图），静态部署 + 浏览器运行
- **计划版本**：2026-10-31
- **适用范围**：发布前回归、版本验收、线上部署验收、缺陷复现
- **编写依据**：本轮已完成的真机测试数据（1–3 关全流程、百图 56/43 关）、仓库现有测试资产（167 单测、6 项浏览器回归、e2e/perf/balance/difficulty 探针）

> 注意：当前工作区 `HEAD` 停在 `3700649`（0.8.5），暂存区存在合并中的变更；本计划以远端 `main`（`a0a3a5e`）为准，执行前请先 `git fetch origin && git reset --hard origin/main`。

---

## 1. 测试目标与范围

### 1.1 目标

1. 验证 100 图主线闭环：清怪 → 首领 → 掉落 → 拾取 → 穿戴/强化/重铸 → 升级加点 → 存档 → 出口 → 下一图。
2. 验证三职业的差异化战斗（近战/远程/召唤+治疗）与技能资源、冷却、范围校验。
3. 验证存档正确性：落盘时机、刷新恢复、v2/v3/v4 迁移、损坏回退、导入导出、重置。
4. 验证 UI 在桌面/平板/手机的可用性，特别是顶栏、商店、重铸、技能面板、背包 12 格。
5. 验证性能与数值曲线：60 FPS、HUD 不重建、难度峰值可控、经济不失控。
6. 验证部署形态：公网 HTTPS、静态资源、隧道/守护、缓存与 Range。

### 1.2 范围内

- `game/` 下全部前端模块与素材
- `tests/` 下全部单测、UI 回归、e2e、perf、balance、difficulty 探针
- 部署脚本（`serve.py`、`keepalive.sh`、instabox 端口发布）
- 移动端仿真（Chromium `is_mobile` + `has_touch`）

### 1.3 范围外（本轮不测）

- 服务端权威逻辑（原型为纯前端模拟）
- 真实 iOS/Android 设备、Safari/微信内置浏览器（另列兼容性专项）
- 行会据点、王城战、交易/拍卖等尚未落地系统
- 付费与计费链路

## 2. 测试策略与分层

| 层级 | 内容 | 工具 | 触发频率 | 门禁 |
|---|---|---|---|---|
| L0 静态 | 语法、格式 | `node --check`、Prettier | 每次提交 | 必须 |
| L1 单测 | 纯函数、迁移、经济、战斗公式 | `node --test`（167 例） | 每次提交 | 必须 |
| L2 浏览器 UI | 三视口冒烟、渲染稳定性、铭牌、升级、致盲、行为开关 | Playwright（6 个脚本） | 合并前 | 必须 |
| L3 真机全流程 | 真实键鼠/触屏跑核心闭环并截图 | Playwright 手动脚本 | 版本验收 | 必须 |
| L4 百图 e2e | 自动通关 100 图（分段） | `e2e-ten-clear-runs.cjs` | 版本验收 | 必须 |
| L5 性能/数值 | 帧率、HUD 重建、难度探针、经济模拟 | `perf-probe`、`balance-sim`、`difficulty-probe` | 版本验收 | 参考阈值 |
| L6 部署 | 公网访问、资源完整性、守护与恢复 | curl + 浏览器 | 每次部署 | 必须 |

**执行顺序**：L0 → L1 → L2 → L6（部署就绪）→ L3 → L4 → L5。

### 3.4 观测与证据规范

- 每个用例记录：用例 ID、开始时间、结果、关键数值、截图路径、Console 错误、非 2xx 请求

## 6. 执行计划

### 6.1 轮次与时间盒

| 轮次 | 内容 | 用例 | 预计时长 | 产出 |
|---|---|---|---|---|
| R0 冒烟 | A/B 选职业与落盘、F-01 首关 | A-01~03、B-01~03、F-01 | 30 min | 冒烟结果 |

| R3 性能数值 | L-01~05、perf/balance/difficulty | 5 条 | 40 min | 性能与数值报告 |
| R4 部署 | M 全量 + E2 真机全流程 | 8 条 | 1 h | 部署验收单 |
| R5 兼容 | N 专项（人工/真机） | 4 条 | 2 h | 兼容性矩阵 |

### 6.2 并发与资源

- L2/L3 浏览器用例并发 ≤ 3（单机 4 vCPU / 8 GiB）
- L4 百图**禁止单页跑满 100 关**：每 25 关重建 context（保留 storageState），否则 Chromium 在虚拟时钟快进下会 `Target closed`（本轮已复现：56 关、24 关、10 关、2 关不等）
- 每次长跑前清理残留 `chromium --headless` 进程

### 6.3 百图分段策略（关键）

```
段1: 1–25   段2: 26–50   段3: 51–75   段4: 76–100
每段：新建 browser → 导入上一段 storageState → 跑 25 关 → 保存 storageState → 截图 3 张
```

### 6.4 每轮必跑门禁

```bash
npm run verify          # check + format + 167 单测
npm run test:ui         # 三视口冒烟（含顶栏可命中、选职业落盘断言）
```

## 7. 缺陷管理

### 7.1 级别

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 无法开始/无法通关/存档丢失/白屏崩溃 | 立即修复，阻塞发布 |
| P1 | 主流程受阻但有绕行、关键数值错误、移动端不可用 | 本版本必修 |
| P2 | 体验明显受损（按钮不可点、布局溢出、提示错误） | 本版本修复或明确排期 |
| P3 | 轻微体验/文案/边界 | 排期处理 |
| P4 | 观感建议 | 记录 |

### 7.2 准入标准

- L0/L1/L2 全绿
- 无 P0/P1 未关闭
- 资源非 2xx = 0
- 移动端三视口可用

### 7.3 准出标准

- L3 核心闭环 1 轮通过（三职业至少各 1 次开局）
- L4 百图分段 4 段全部到达 checkpoint，最终文案正确
- L5 帧率与数值在阈值内
- 缺陷单 P0/P1 清零，P2 有结论

## 8. 风险与应对

| 风险 | 影响 | 概率 | 应对 |
|---|---|---|---|
| Chromium 长时间虚拟时钟崩溃 | 百图跑不完 | 高 | 每 25 关重建 context；分 4 段；清理残留进程 |
| 资源 404（新地图/新 Boss） | 立绘空白 | 中 | 每次新增地图跑资源清单比对 + 生产形态 404 断言 |
| 存档结构变更未迁移 | 老玩家丢档 | 中 | 每次改 schema 必加迁移用例与单测 |
| 移动端顶栏/面板溢出 | 手机不可用 | 中 | 三视口断言常态化（已加入 `ui-smoke`） |
| 难度峰值（41–46 关） | 玩家流失 | 中 | `difficulty-probe` 分段采样，>4 死触发复核 |
| 经济通胀 | 商店/重铸失衡 | 低 | `balance-sim` 与金币基线断言 |
| 部署自动暂停 | 公网 503 | 中 | 守护 + 唤醒重试 + 监控告警 |
