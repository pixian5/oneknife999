# 第 75 关危险区伤害下调与命中率诊断（0.8.3 / 0.8.4）

- 日期：2026-10-29 23:47（0.8.3）/ 2026-10-30 02:10（0.8.4 追加）
- 模型：DeepSeek-V4.1-Flash
- 版本：0.8.2 → 0.8.3 → 0.8.4
- 内容：按方案 A 给关卡修正表加 `hazardMult` 只降第 75 关危险区伤害；随后用危险区命中率统计验证并修正了成因判断

## 一、为什么选方案 A

0.7.9 与 0.8.2 两轮数据把第 75 关的问题定位得很清楚：

- **两职业致死来源都指向危险区**：战士 8/13（62%）、法师 6/15（40%）；
- 它是四关里**唯一两职业共同指向同一机制**的关卡（第 30 关是正面输出、第 60/90 关零死亡）；
- 法师的死因更能说明问题：`sting` 红圈直接落在玩家脚下、不看距离，**惩罚的恰恰是远程职业「停在射程边缘」这个正确打法**——法师中位 3 死 > 战士 2 死，就是「站位悖论」的直接体现。

三个候选方案里：

| 方案 | 影响面 | 为什么不选 |
|---|---|---|
| A. 只降危险区伤害 | 只动脱手伤害 | **选中** |
| B. 拉长特殊间隔 | 会改变阶段战节奏设计 | 4.63s 是百图最短，是刻意的设计点，动了会破坏节奏辨识度 |
| C. 关掉叠加毒 | 会损失「毒首领」机制 | 第 75 关是百图少数有毒首领的关卡 |

方案 A 最精准：只削「惩罚固定站位」的那部分伤害，怪物正面输出与首领节奏都不变。

## 二、改动

### 2.0 0.8.4 追加：危险区命中率诊断

在验证 0.8.3 的过程中发现推断缺少证据，于是补了可观测性：

- [main.js](../../game/src/main.js) 的 `loadMap` 初始化 `state.hazardStats = { detonated, hit }`，危险区引爆时累加 `detonated`、命中玩家时累加 `hit`；
- **只在 `!keepBossHp`（真正进入新场景）时重置**——初版无条件清零，导致死亡复活后计数归零，算出 6% 的假命中率（33 次引爆却死 3 次，数据自相矛盾）；
- `snapshot()` 输出 `hazardStats`；探针每次运行打印 `hazard=命中/引爆(命中率)`。

### 2.1 修正表拆成两个正交系数

[maps.js](../../game/src/maps.js)：

```js
export const MAP_DIFFICULTY_OVERRIDES = {
  30: { attackMult: 0.88, reason: "..." },
  75: { hazardMult: 0.75, reason: "两职业致死来源均以地面危险区为主（战士 8/13、法师 6/15）" }
};

export function mapDifficultyOverride(stageNumber) {
  return MAP_DIFFICULTY_OVERRIDES[stageNumber] || null;
}
```

`attackMult` 管普通怪与首领本体（0.7.7 已有），`hazardMult` 只管首领技能生成的危险区（本轮新增）。两者**正交**：第 30 关只登记 `attackMult`、第 75 关只登记 `hazardMult`，互不牵连。

关卡对象同步带上两个字段：

```js
difficulty: { attackMult, hazardMult, reason }
```

### 2.2 危险区伤害读取该系数

[main.js](../../game/src/main.js) 的 `spawnHazard()`：

```js
const hazardMult = map.difficulty?.hazardMult || 1;
const damage = Math.round(boss.attack * 1.4 * hazardMult);
```

手工地图（前 4 关）没有 `difficulty` 字段，`?.` 缺省为 1，行为完全不变。

### 2.3 为什么取 0.75

危险区伤害 = `boss.attack × 1.4`，0.75 倍后相当于从 1.4 降到 1.05 倍首领攻击。

目标是把「危险区致死」从主因降到次要：战士 62% → 期望 40% 左右、法师 40% → 期望 25% 左右。没有直接取 0.5 是因为：

- 危险区是首领阶段战的核心压迫机制，砍半会让二阶段变得没有存在感；
- 0.75 已能让「被红圈打中一次」从「接近半血」变成「掉三分之一」，给玩家留出「吃一次还能补」的容错。

（0.8.4 复测后确认这个幅度对法师足够、对战士不够，但不够的原因不是幅度大小，而是危险区在战士承伤里只占 28%——见 4.3 节。继续下调的边际收益都在法师身上，所以维持 0.75。）

## 三、单测守卫

同一个用例扩展为双系数校验：

1. 每个登记项的 `attackMult` 在 (0.8, 1)、`hazardMult` 在 (0.5, 1)，且必须写明 `reason`；
2. 未登记关两个系数都必须是 1.0；前 4 张手工图不带 `difficulty`；
3. **第 75 关的 `attackMult` 必须为 1**（不能被牵连）、`hazardMult` 必须 <1；
4. `mapDifficultyOverride(74) / (76)` 必须为 `null`。

`npm run verify`：162 单测全绿。

## 四、复测（两职业，第 75 关，n=8，seed 2000–2007）

### 4.1 法师：明显改善

| 指标 | 0.8.2（hazardMult=1） | 0.8.3（hazardMult=0.75） |
|---|---:|---:|
| 死亡中位 | 3 | **1** |
| 全距 | 0–5 | **1–4** |
| 总承伤中位 | 3191 | 3438 |
| 首死中位 | 35s | 28s |

逐次：3 / 1 / 1 / 1 / 1 / 1 / 4 / 4。

法师的致死来源从「危险区为主」（6/15 = 40%）变成「禁区猎杀者为主」（5/17）。这正是预期的效果：危险区不再是他最大的死因。

### 4.2 战士：没有改善，反而略升

| 指标 | 0.8.0（hazardMult=1） | 0.8.3（hazardMult=0.75） |
|---|---:|---:|
| 死亡中位 | 2 | **3** |
| 全距 | 1–4 | **1–5** |
| 总承伤中位 | 3908 | 4074 |
| 首死中位 | 34s | 32s |

逐次：4 / 5 / 3 / 4 / 3 / 3 / 2 / 1。

### 4.3 这个分化说明了什么（0.8.4 已用数据修正）

初版推断是「战士贴脸 70px，本来就站在圈里，问题不是打得太疼而是躲不掉」。**0.8.4 加了危险区命中率统计后，这个推断被数据推翻了。**

新增诊断 `hazardStats`（`detonated` / `hit`）并让探针输出 `hazard=命中/引爆(命中率)` 后，两职业各跑 n=6：

| 职业 | 命中 / 引爆 | 命中率 | 每趟引爆 | 每趟命中 | 平均总承伤 |
|---|---|---:|---:|---:|---:|
| 战士 | 52 / 330 | **15.8%** | 55.0 | 8.7 | 3779 |
| 法师 | 69 / 221 | **31.2%** | 36.8 | 11.5 | 2620 |

**战士反而更会躲**（15.8% vs 31.2%，不到法师的一半）。他不是「走不出去」——恰恰相反，他的「一刀一撤」后撤节奏比法师站桩更有效地躲开了红圈。

那为什么降伤害对战士无效？因为**危险区在两人承伤里的占比差了一倍**：

| 职业 | 危险区单次伤害 | 每趟命中 | 危险区承伤合计 | 占总承伤 |
|---|---:|---:|---:|---:|
| 战士 | 123 | 8.7 | ~1070 | **28%** |
| 法师 | 132 | 11.5 | ~1518 | **58%** |

（单次伤害取 `computeIncomingDamage` 按各自防御折算，`hazardMult=0.75` 后的值。）

- 法师 **58% 的承伤来自危险区** → 降 25% 等于总承伤降 14.5%，死亡中位 3 → 1，效果显著；
- 战士只有 **28%** → 降 25% 只削掉他总承伤的 7%，落在 ±17% 的采样波动里，看不到。

**结论修正**：0.8.3 的判定（保留 0.75）依然正确，但理由从「战士躲不掉」改成「**危险区只占战士承伤的 28%，这一刀砍不到他的痛点上**」。战士的痛点是**引爆频率**（每趟 55 次，是法师的 1.5 倍）与其余 72% 的正面输出，不是危险区的单次伤害。

这也解释了为什么战士的总承伤（3779）比法师（2620）高 44%：他挨的危险区次数更多，且其余部分的正面承伤也更重（贴脸必然吃更多普攻）。

### 4.4 判定：保留 0.75，但承认它只解决了一半问题

- **对法师**：这是一次成功的修正（中位 3 → 1，危险区不再是主因）；
- **对战士**：无效但不有害（中位 2 → 3 在全距 1–5 的噪声内，两批数据的区间高度重叠）；
- 两职业都在 ≤6 闸门内，没有出现「改坏了」的迹象。

**不建议为了战士继续降 hazardMult**：0.75 → 0.5 也许能把战士再拉低一点，但那会让危险区对法师变成「几乎无威胁」，二阶段的存在感被抹掉。战士的问题需要另一种解法。

### 4.5 战士的下一个方向：引爆频率，不是单次伤害

数据（0.8.4）显示战士每趟要挨 **55 次引爆**、命中 8.7 次，危险区占他承伤 28%。所以对他有效的是**减少引爆次数**，而不是继续削每次的伤害：

| 选项 | 说明 | 预期对战士 |
|---|---|---|
| 拉长特殊间隔 | `specialInterval` 4.63s → 5.2s，引爆次数约降 11% | 直接减少 55 次 → 49 次 |
| 缩短红圈半径 | 55px → 45px，让命中率从 15.8% 再降 | 他本来就躲得开，收益小 |
| 延长引爆倒计时 | `life` 1.2s → 1.6s | 同上，收益小 |
| **不动** | 战士中位 3 死仍在 ≤6 闸门内 | 成本最低 |

注意：前两条会同时影响法师。**如果要动 `specialInterval`，必须两职业一起复测**——法师现在中位 1 死，再降可能变得过于轻松。

> 初版文档曾把「缩半径 / 延长引爆 / 预警后不跟随」列为战士的主要方向，那是基于「战士躲不掉」的错误假设。命中率数据表明他躲得比法师好，这三条对他的收益都有限。

## 五、0.8.4 的命中率实测（n=6，seed 2000–2005）

原始数据（每次运行的「命中 / 引爆」）：

| 职业 | 逐次 | 命中率合计 |
|---|---|---|
| 战士 | 14/59(24%)、4/53(8%)、13/84(15%)、4/49(8%)、11/56(20%)、6/29(21%) | 52/330 = **15.8%** |
| 法师 | 14/50(28%)、10/26(38%)、11/48(23%)、11/16(69%)、12/43(28%)、11/38(29%) | 69/221 = **31.2%** |

同批的死亡与承伤：

| 职业 | 死亡中位 | 平均总承伤 | 每趟引爆 | 每趟命中 |
|---|---:|---:|---:|---:|
| 战士 | 3（4/1/3/2/3/3） | 3779 | 55.0 | 8.7 |
| 法师 | 2（2/2/2/2/3/3） | 2620 | 36.8 | 11.5 |

读法：

1. **战士命中率只有法师的一半**——他更会躲，「贴脸就躲不掉」的假设不成立；
2. 但战士**每趟挨的引爆次数多 50%**（55 vs 37），把「躲得好」的优势吃掉了：8.7 次命中 vs 11.5 次，绝对次数只低 24%，而他每趟承受的正面输出也更重，所以总承伤反而高 44%；
3. 法师命中率高但总引爆次数少，加上这次 `hazardMult` 砍掉 25% 危险区伤害，两头叠加才把中位压到 1 死。

**唯一还没解释的**：为什么法师的命中率（31.2%）比战士（15.8%）高这么多？一个合理推测是「法师站桩输出、红圈落下时正在施法前摇里不便中断」，而战士本来就在持续走位（一刀一撤）。这条尚未单独验证，如后续要动红圈机制，应先确认。

## 六、这套修正表的用法（更新）

- **`attackMult`**：用于「怪物正面输出过高」型峰值（如第 30 关）；
- **`hazardMult`**：用于「脱手伤害过高」型峰值（如第 75 关）；
- **判定某个系数有没有用，先算「被修的那部分伤害占总承伤多少」**：占比低于 30% 时，即使系数砍 25%，总承伤也只降 7%，落在采样噪声里——这不是「修错了」，而是「这一刀砍不到痛点上」。0.8.3 的战士就是这种情况（危险区占 28%）、法师则占 58%（效果显著）。
- 先看 `killers` 的构成决定登记哪个系数，再用 `totalDamage` 与死亡中位数验证；
- 一次只登记一个系数，**不要两个一起加**——否则无法归因是哪一项起作用；
- **同一个修正对不同职业的收益可能完全不同**，必须两职业都复测才能下结论。
