# 0.8.40 A 块第一批：10 种普通怪补全三帧并在本容器完成落地

## 背景

A 块目标是给「有静态单帧、但无 walk/attack/hit 动作帧」的普通怪补齐三帧。上一阶段在 instabox 沙箱批量生成时，沙箱进入免费档 `machine_cooldown`（提示可唤醒时间 2026-11-19T17:26:38Z），导致已生成的结果图只停留豆包 CDN 短链（`https://aka.doubaocdn.com/s/xxx`），无法落进仓库 assets。

## 关键决策：改在本容器（vm）落地，不再等沙箱

实测本容器具备全部条件，因此把「落地」环节整体迁回本地容器：

| 能力 | 实测结论 |
|---|---|
| 落地脚本 | `/home/user/instabox-cli/cutout.py` 本地就有（只调用，不读源码、不改算法） |
| 图像库 | Python 3.12.11 + Pillow 13.0.0 |
| 网络 | CDN 短链 302 → 可下载 2048×2048 JPEG 原图；github.com 返回 200 |
| Git | 2.34.1，可直连双远端 |
| 参考图 | `refs-in/` 111 张黑底 JPG 完整保留 |

派生的两条纪律：

1. **沙箱只承担「生成中继」**，落地、校验、提交、推送一律在本容器完成，避免再被冷却卡死。
2. **短链必须尽快消费**。短链指向带签名与 `x-expires` 的字节 CDN 地址，过期即 404；此前已整批过期过一次，靠 `refs-in/` 重新上传参考图才恢复。

## 代码改动

- `game/src/assets.js`：`ACTION_MONSTERS` 追加上述 10 个名字（带 0.8.40 注释）。
- 配套把每种的静态单帧 `monster-full-{名}.png` 复制为 `monster-full-{名}-idle.png`。

**为什么必须复制 idle**：`resolveMonsterSpriteName` 对白名单物种恒拼 `monster-full-${name}-${action}.png`，`idle` 也不例外；普通怪分支没有「动作帧 → 静态单帧」的逐级回退（该回退只做在 Boss / 精英分支）。若只有 walk/attack/hit 而没有 `-idle.png`，静止状态的怪会直接 404、退回几何图形——这正是 0.6.0 踩过的坑（见 assets.js 顶部注释）。

## 失败归因（9 张）

沿用此前规律：发光、半透明、火焰/烟雾周身的生物，背景无法在任一阈值档清干净。本轮失败集中在火焰邪蝠（3/3）、灰烬蜈蚣（3/3）、沙盗斥候-hit、潮汐幽灵-hit、灰鬃狼-attack。
