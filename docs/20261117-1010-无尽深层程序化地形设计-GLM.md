> 关联分卷：[21-终局与长线系统.md](21-终局与长线系统.md)（其「已知偏差」一节明确本项为待实现）。

## 一、现状与问题

当前 `enterAbyss()`（game/src/main.js）按 `MAP_ORDER[(floor × 37) % 100]` **复用百图已有地形**。
三个具体缺陷：

1. **布局重复感**：100 层以后必然重走来时的图，「无尽」名不副实；
2. **怪物表错位**：深层层数与被复用图的 stageNumber 无关，第 57 层可能套着第 3 关的
   低级图名与剧情文案（`map.story` 是百图剧情），沉浸断裂；
3. **隐藏雷区（实现时必须处理）**：`isForwardExit()` 用 `MAP_ORDER.indexOf()` 判定方向，
   深层地图 id 不在 `MAP_ORDER` 里时 `indexOf = -1`，**任何出口都会被判为「前进出口」**
   ——若生成的深层图带 exits，会出现「完成当前关卡」的错乱提示。现状复用的百图图自带
   exits 指向百图邻图，玩家在深层踩到东侧出口会**直接传送回百图**（带走深层增益），
   这是现存行为缺陷，程序化地形方案必须一并修掉。

## 二、目标与非目标

**目标**

- 每层布局（营地/道路/首领位/战术节点/刷怪点）由层数确定性生成：同层同布局（可复现、
  可回归），不同层布局不同；
- 深层地图与百图完全隔离：id、出口、进度计数互不污染；
- 刷新/重进后停留在原层（存档兼容零新增字段）。

**非目标（本轮不做）**

- 深层专属怪物美术与新物种（复用十章 monsterTypes + 既有素材，专属内容留给 P2）；
- 无限大地形/滚动地图（仍为 2400×1500 固定画布，与百图一致）；
- 深层排行（需服务器）。

## 三、方案总览：运行时注册，不改静态表

`MAPS` / `MAP_ORDER` / `MAP_CLEAR_RULES` 在模块加载时静态构建，渲染、任务链、区域导航、
通关计数全部依赖它们。**方案是不修改这三张静态表的结构**，新增一个运行时注册层：

```text
game/src/maps.js 新增：
  ABYSS_MAP_PREFIX = "abyss-F"
  buildAbyssMap(floor)            // 纯函数：层数 → 完整 map 对象（布局/怪/boss/无 exits）
  ensureAbyssMap(floor)           // 幂等注册：MAPS[id] 已存在则返回，否则注册并写入
                                   //   MAP_CLEAR_RULES[id] = { kills: 0, boss, next: null,
                                   //   exit: "无出口（按 T 深入）", stageNumber: 100 + floor, ... }
  abyssMapId(floor)               // "abyss-F57"
```

要点：

- **id 命名 `abyss-F{n}`**：与百图 id（`stage_XXX` / 手工图名）无碰撞；`MAP_ORDER` 不收录，
  因此 `MAP_ORDER.filter(completed).length`（通关计数、难度解锁、`primaryExit`）天然忽略深层，
  `chapterStats` / `regionList` / 任务链也不会把深层当作百图关卡渲染；
- **exits = []**：深层图不设任何出口，彻底规避 `isForwardExit` 的 `indexOf = -1` 雷区；
  下层唯一途径是按 T（Boss 层击败首领后解锁，见第五节）；
- **注册是幂等且记忆化的**：同一层重复进入（刷新恢复/来回切层）复用同一对象，
  保证「同层同布局」与 `loadMap` 缓存（`groundLayer` 按 `map.id`）正常工作。

## 四、布局生成器 `generatedAbyssLayout(floor)`

复用百图 `generatedLayout` 的组件（`SITE_LAYOUTS` / 战术节点放置 / 路径采样全部现成），
只换三样：

| 项 | 百图 | 深层 |
|---|---|---|
| 种子 | `seededRandom(stageNumber × 982451653 + 104729)` | `seededRandom(floor × 2654435761 + 977)`（**独立种子空间**，杜绝与百图某关撞布局） |
| 章节主题 | `CHAPTERS[(stageNumber-1)/10]` | `CHAPTERS[(floor-1) % 10]` 轮换（调色盘/怪物表/底图沿用十章素材） |
| 营地纵向位 | `[180,565,950][stageNumber % 3]` | `[180,565,950][floor % 3]`，且 `townRect` 加宽 40px（深层补给更慷慨，对抗成长压力） |

地图名与文案：`深层·${chapter.short}${["裂隙","回廊","蚀窟","寒渊","熔道","冥河","浮台","残骸","战场","帝寝"][递增主题]}`,
`story` 给一段通用深层文案（`beatTitle: 深层 F{floor}`），不引用百图剧情，消除错位感。

## 五、怪物、Boss 与推进流程

- **怪物**：每层从主题章 `monsterTypes`（9 种）取种子洗牌后的 5~7 种，档位全开
  （深层没有「章内前 5 关保护」，压力由 `abyssMultipliers(floor)` 全权调节——该倍率
  已在 `createEntities` 接好，本方案零改动）；刷怪点 12~16 个由布局生成器产出。
- **Boss**：每图必有 boss 结构（`loadMap`/任务展示依赖），分两类：
  - **首领层**（`isAbyssBossFloor`，每 10 层）：主题章 boss，血量额外 ×1.35；
  - **普通层**：主题章 boss 作「守门者」，血量 ×0.55、击杀可选（不锁层）。
- **推进规则改造**（`enterAbyss` 与 input.js 的 T 键）：
  - 普通层：按 T 任意深入（维持现状自由度）；
  - 首领层：**击败本层首领才允许深入**（`enterAbyss` 检查 `mapProgress[abyssId].bossDefeated`），
    防止无限跳层刷低层数值；提示文案区分两种状态。
- **掉落**：沿用该图 drops 表（带 setKey，深层可补套装）＋ `abyssQualityBonus(floor)` 品质
  提档（已实现，零改动）。

## 六、存档兼容（零新增字段）

现有字段 `abyssFloor` / `abyssBest`（v4 存档，0.6.0 引入）足够，**存档版本不升级**。三个场景：

| 场景 | 行为 |
|---|---|
| 百图未通关的旧档 | `abyssFloor=0`，`enterAbyss` 被解锁检查拦住，不触任何深层代码路径 |
| 0.8.x 及以前「在深层（复用百图 id）刷新」的旧档 | `currentMapId` 是百图 id，`loadGame` 现有逻辑直接恢复，行为与旧版一致 |
| **新方案下在深层刷新** | `currentMapId = "abyss-F57"`。`loadGame` 第 2259 行现有检查 `MAPS[saved.currentMapId]` 会 miss → 回退灰烬村（丢层体验）。**改造点**：识别 `abyss-F` 前缀时先 `ensureAbyssMap(floor)` 注册再恢复；层数取自 `state.abyssFloor`（存档已有），坐标缺失时回该层营地 |

附带影响（可接受，文档明示）：`state.mapProgress` 会写入 `abyss-F{n}` 条目——通关计数只数
`MAP_ORDER` 内的 id，深层条目不影响任何判定，仅让 mapProgress 对象随层数缓慢增长
（每层一条、几百字节级）；如在意，P2 可在 `persistGame` 时剥离 `abyss-F*` 键。

## 七、回归清单（实施完成的验收门）

**单测（tests/unit/，新增 abyss-terrain.test.mjs）**

1. 种子确定性：`buildAbyssMap(57)` 两次调用 deep-equal（布局/刷怪点/boss 位完全一致）；
2. 布局差异：F1~F30 两两的 boss 坐标与路径折点序列至少一项不同（抽样 10 对）；
3. id 与静态表隔离：`MAP_ORDER` 不含任何 `abyss-F*`；`MAP_CLEAR_RULES["abyss-F1"].next === null`；
4. `exits` 恒为空数组（防 `isForwardExit` 雷区回归）；
5. 数值衔接：F1 怪物 hp/attack = 主题章第 1 档 × `abyssMultipliers(1)`（乘法链与百图一致）；
6. Boss 层标记：`buildAbyssMap(10)` 的 boss 血量含 ×1.35、`buildAbyssMap(3)` 含 ×0.55；
7. 幂等注册：`ensureAbyssMap(5)` 两次返回同一引用，`MAPS` 中该 id 仅一份。

**UI 回归（扩展 tests/ui-abyss（现有 `test:ui:abyss`）**

8. 通关百图档注入 → T 进入 F1：地图标题含「深层」、`exits` 为空（画布无出口高亮）；
9. 深层内刷新页面 → 仍停留在 `abyss-F1`（标题不变、`abyssFloor=1`）；
10. 首领层（注入 F10 档）未杀 boss 按 T → 提示「击败首领后才能深入」；杀完 → 进入 F11。

**手动/性能**

11. F1 / F10 / F30 三层截图目检（主题轮换可见、铭牌/贴图正常）；
12. `npm run perf` 不回退（地图生成每层一次、非每帧，预期无影响，仍需跑门禁确认）。

## 九、风险与开放问题

1. **`ensureAbyssMap` 的运行时写入违反「MAPS 只读」的隐含约定**——所有遍历 `MAPS` 的
   代码（`Object.values(MAPS)` 在图鉴/怪物归并里出现过）会看到深层条目。已核对两处
   现有遍历：`collectChapterGroups`（按 `MAP_ORDER` 遍历，安全）与 `bestiaryStats`
   （名单来自 `MAP_ORDER`，安全）；实施时需再全量 grep `Object.values(MAPS)` 复核。
2. 首领层锁层对「卡关玩家」的体验——若 boss 打不过将无法继续，是否给「回到 F(n-1)
   自由层补给」的引导（P1 用日志提示，够用）。
3. 深层主题轮换用十章素材，第 100+ 层后会再次轮换重复——可接受（数值仍在成长），
   P2 再谈专属主题。
