你将接手《一刀999》项目的开发。这是一个浏览器单机原型：传奇类 MMORPG 的玩法验证载体，
纯前端 Canvas 实现，十章 100 关、三职业、106 种带独立行为的怪物、装备强化/重铸/套装、
难度阶梯与无尽深层。159 个单元测试全绿，完整 CI。

你不是来「了解项目」的——直接按下面的指令开工。

## 第一步：只做一件事——法师/道士难度实测

这是上一轮遗留的**验证负债**：0.6.1 的难度调平只基于战士数据。新增的减速被动（移速 ×0.68）
对法师（移速 205、血量 235，战士是 218/350）的影响可能完全不同，不测就无法确认调平是全局有效
还是战士专属。

```bash
npm run serve &          # 4174 端口，探针依赖
ONEKNIFE_PROBE_CLASS=mage ONEKNIFE_PROBE_STAGES=15,19,45 ONEKNIFE_PROBE_RUNS=2 node tests/difficulty-probe.cjs
ONEKNIFE_PROBE_CLASS=taoist ONEKNIFE_PROBE_STAGES=15,19,45 ONEKNIFE_PROBE_RUNS=2 node tests/difficulty-probe.cjs
```

判定：死亡中位数 ≤6 即 PASS。若法师超闸门，**不要直接砍行为数值**——先用
`ONEKNIFE_URL="http://127.0.0.1:4174/?e2e=1&noabilities=1"` 跑 A/B 对照，分清是行为系统
还是刷怪构成的问题（上一轮就是这么定位真因的，详见 docs/20261028-1816 文档）。
测完把结果记入 docs/11 数值基线的探针表，然后进入日常循环。

## 日常循环（每个开发轮次）

1. **选任务**：优先级见 docs/20261028-1906-下一步待实现-GLM.md（按投入产出比排序，
   当前顺序：法师道士实测 → 精英系统 → 深层程序化地形 → 图鉴奖励 → balance-sim 经济模型）。
2. **动手前**：读对应分卷设计（docs/00-21 是事实源，11 号数值基线优先级最高）；
   若实现与设计冲突，如实标注偏差并记录「待对齐」，不要静默偏离。
3. **实现**：代码中文注释；纯逻辑下沉到独立模块（combat/skills/drops/endgame 的风格），
   随机数必须可注入以便单测；渲染层改动画前先看铭牌回归的硬指标。
4. **验证（缺一不可）**：
   - `npm run verify` —— 语法 + Prettier + 159 单测，任何红都不得提交
   - 改了渲染 → `npm run test:ui:nameplate`（9534 铭牌零遮挡是硬指标）
   - 改了数值/行为 → 非快进探针实测（见上），并用 noabilities 做 A/B
   - 大改 → `npm run test:ui` + `npm run perf`（GATE：p99 ≤4ms、零 20ms+ 长帧）
5. **文档**：①`docs/年月日-时分-标题-GLM.md` 技术记录；②规则类改动写入对应**分卷**
   （04 怪物/03 装备/21 终局/11 数值），只写快照不写分卷是违规；③README 的
   当前开发进度/下一步待实现；④文档索引登记。
6. **版本**：+0.0.1，满十进一（VERSION + package.json + README 三处同步）。
7. **提交**：中文 commit message，写清动机与验证结果。推送 `gitcode` 与 `origin` 两个远程
   （用户有 WiFi 时推送；没有就只提交本地并说明）。

## 铁律（违反会真实翻车）

1. **不要用 fast 模式测行为与难度**。`?fast=1` 伤害 ×25，怪被秒杀，被动来不及触发，
   探针数据无效。难度数据只能来自非快进探针。
2. **不要凭感觉调难度数值**。必须 A/B 对照（noabilities 开关）分清真因——
   0.6.1 时「第 15 关 5 死」曾差点错怪行为系统，真因是刷怪档位。
3. **不要动 spawnTier 分段**（maps.js：章内前 5 关用档位 0-5、后 5 关 0-8）。
   取满 9 档会让第 15 关死亡中位数从 1 涨到 5，这是实测过的。改它必须重跑探针。
4. **不要跳过 Prettier**。批量正则改写代码后 `npm run verify` 必挂——上一轮就误伤过
   `ENHANCE_RULES.rates`（同为单行数组）。改完先格式化再单测。
5. **不要在没跑探针的情况下宣称难度没问题**。159 个单测只覆盖逻辑正确性，
   难度影响只能靠非快进探针。
6. **无头浏览器必须** `chromium.launch({ headless: true, channel: "chrome" })`——
   默认 chromium 二进制在本机不存在（项目测试统一走系统 Chrome）。
7. **不要重写 git 历史**。`.git` 已 226MB（171MB 素材），瘦身需 `git filter-repo`，
   属破坏性操作，必须用户单独确认。
8. **不要把设计承诺当成已实现**。docs/04 的精英八词缀、docs/03 的 3/5/8 件套装
   都是设计、不是代码。接手时先读「当前开发进度」里的能力边界清单，那里诚实列了
   所有没做的事。

## 项目速查

- 架构：`game/src/` 18 个 ES Module。纯逻辑层（combat/skills/drops/shop/feedback/
  monster-abilities/endgame，随机可注入、可单测）与状态层（main/runtime/render/input）分离。
- 状态机：`runtime.js` 的 `state` 是唯一全局；存档 v4（`persist.js`，迁移表驱动）。
- 行为系统：`monster-abilities.js`——8 攻击形态 + 19 被动 + 2 亡语，
  `resolveAbilities` 按 suffix 匹配章节前缀名，106 种怪零遗漏（单测守着）。
- e2e 接口：`window.__ONEKNIFE_E2E__`（快照含 attackShape/passives/shield/guideStep/
  difficulty/bestiaryCount），URL 参数：`?e2e=1` 测试模式、`&fast=1` 快进、`&noabilities=1` 行为开关。
- 素材：`game/assets/` 543 个文件 171MB。动作帧命名 `monster-full-{名}-{idle|walk|attack|hit}.png`、
  `player-full-{class}-{action}.png`，渲染层三级回退（动作帧→静态立绘→几何图形）。
- 文档：`docs/README.md` 是分卷索引与冲突优先级；`文档索引.md` 是全量索引；
  新文件命名 `年月日-时分-标题-模型名.md`。
- 远程：`origin`（GitHub）与 `gitcode` 双推送；推送前确认用户网络。
