# 主角新增四动作帧（run / guard / lowhp / victory）

- 版本：0.8.25 → **0.8.26**
- 模型：豆包 Seedream 5.0 Flash（image_edit 图生图）+ 纯 PIL 抠图
- 日期：2026-11-06

## 一、需求
用户要求「增加主角更多动作」。原有主角只有 6 个动作帧（idle / walk / attack / cast / hit / death），三职业 × 6 = 18 张，游戏内表现偏单调（战斗里几乎只有站桩与挥砍两个姿态）。

## 二、新增动作与触发规则

| 动作 | 文件 | 触发条件 | 优先级 |
|---|---|---|---|
| run 奔跑 | `player-full-{class}-run.png` | `player.moving` 且 `runTimer > 0.7s`（连续移动计时，停下即清零） | 高于 walk |
| guard 格挡 | `player-full-{class}-guard.png` | `guardTimer > 0`（受击瞬间置 0.35 秒） | 低于 hit |
| lowhp 重伤 | `player-full-{class}-lowhp.png` | `hp / maxHp <= 0.25` 且静止（移动时仍用 walk/run，避免卡死虚弱姿态） | 最低（仅高于 idle） |
| victory 胜利 | `player-full-{class}-victory.png` | `victoryTimer > 0`（击败 Boss 时置 3 秒） | 仅次于 death |

完整优先级：`death > victory > hit > cast > attack > guard > run/walk > lowhp > idle`。

## 三、代码改动

1. `game/src/render.js` — `playerSpriteAction()` 扩展四个分支；缺图时仍自动回退到无后缀静态立绘（`player-full-{class}.png`），不会出现空白人物。
2. `game/src/render.js` — `drawPlayer()` 内维护 `runTimer`（按帧 1/60 累加，移动中断即归零）。
3. `game/src/main.js` — `update(dt)` 每帧同步 `state.player.maxHp = playerMaxHp()`（供 lowhp 判定，等级/装备变化即时生效），并递减 `guardTimer` / `victoryTimer`。
4. `game/src/main.js` — `defeat(target)` 中判定 `target.boss` 后置 `victoryTimer = 3`。
5. `game/src/main.js` — 玩家受击处（hitFlash 赋值点）同时置 `guardTimer = 0.35`。

## 四、素材生产

- 参考图：取三职业 idle 帧（160×200 RGBA）放大到 512×640、铺纯黑底，上传 CDN 后作为 image_edit 的参考图。
- 生成：12 次 image_edit（4 动作 × 3 职业），prompt 统一约束「保持外观/轮廓/配色/装备与画风完全不变，仅改姿态」+「纯黑背景、主体完全照亮、居中构图、无文字无字母无水印」。尺寸 819×1024（4:5，与原贴图同比例）。
- 落地：纯 PIL 抠图 → bbox 裁剪 → 等比缩放进 160×200 → **底部对齐**（脚踩底边，保证脚底锚点与旧帧一致）。

实际贴合尺寸：

| 职业 | run | guard | lowhp | victory |
|---|---|---|---|---|
| 战士 warrior | 160×172 | 160×181 | 160×157 | 160×194 |
| 法师 mage | 160×179 | 160×182 | 160×197 | 137×200 |
| 道士 taoist | 160×193 | 160×196 | 159×200 | 130×200 |

## 五、抠图策略修正（本轮最大坑）

首版沿用旧参数（**高阈值起步 + 纯边缘泛洪**），结果三职业贴图被抠成**空心骨架**——深色铠甲的鳞片缝隙与背景亮度接近，泛洪顺着缝隙钻进躯干，把本体吃成透明。用户明确最反感这种效果。

最终策略（已写回 `cutout.py`）：

1. **阈值阶梯倒序**：从最低的 18/10 起步（最保守，先保证主体实心），背景没清干净再依次升到 28/16、45/28。
2. **退化检测**：抠图后若 bbox 面积 > 整幅 92%，判定「背景没清干净」，该档作废。
3. **闭运算填缝**：alpha 先 MaxFilter(7)+MinFilter(7)，封住铠甲鳞片的窄孔。
4. **洞填充**：从四边把外部背景泛洪标成 128，剩余仍为 0 的即被主体包围的内部空洞，回填成不透明。
5. 战士 run / victory 因肢体大开、缝隙更多，单独提高到 MaxFilter(15)/MinFilter(15)。

修正后法师、道士全部实心，战士 guard/lowhp 实心，run/victory 仍有少量破碎——但游戏内贴图仅 112px 高且是瞬时动作帧，观感可接受，记录为已知限制。

## 六、验证

- `npm run verify`：**201/201 全绿**（含 playerSpriteAction 相关既有单测）。
- 绿底拼图目检：15 格（3 职业 × 5 动作，含原 idle 对照），确认无空心、无黑底残留、脚部统一贴底。
- 未做浏览器实机（本轮为素材+纯函数改动，动作切换依赖运行时状态，留待下一轮真机验证）。

## 七、已知限制 / 下一步

1. warrior 的 run / victory 边缘仍有破碎，可考虑重生成原图（更亮的主体光照）再抠。
2. victory 仅在击败 Boss 时触发，精英/关卡通关未接入，可按需扩展到 `defeat(elite)`。
3. guard 目前是「受击瞬间」表现，真正的格挡机制（减伤）尚未实现，动作先行于玩法。
