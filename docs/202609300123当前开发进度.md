## 二、存档 schema 版本化（P1-2）

[src/persist.js](../game/src/persist.js) 由「硬编码 v2 → v3」改为「版本号 + 迁移函数表」：

- `CURRENT_SAVE_VERSION = 3`；`SAVE_MIGRATIONS` 表：键 = 源版本号，值 = 把存档升到「键版本 + 1」的纯函数（当前仅 `2: v2 → v3`，写入 `migrationLevelFloor` 等级下限）。
- 新增纯函数 `migrateSave(saved)`：逐级迁移到当前版本，返回 `{ saved, migrated, fromVersion }`；版本高于当前（拒绝降级）或缺少迁移路径时返回 `null`。
- 版本缺失视为 v2（v2 存档不写 `saveVersion` 字段），`readSavedGame` 改为调用 `migrateSave`，读取顺序与「不删除 v2 原件」策略不变。
- 新增 `tests/unit/persist.test.mjs` 6 例：v2 旧档迁移与等级下限、缺等级回退 1、同版本归一、拒绝更高版本、非法输入返回 null、迁移结果可安全序列化。
- 后续新增存档版本只需：`CURRENT_SAVE_VERSION +1` 并在迁移表补一个纯函数，不再改动读取主流程。

## 六、帧率探测（P1-4）

新增 [tests/perf-probe.cjs](../tests/perf-probe.cjs)（`npm run perf`）：无头 Chrome + `--disable-frame-rate-limit --disable-gpu-vsync`，独立 rAF 循环采样 8 秒真实操作（方向移动 + 普攻 + 技能轮换），结果写入 `.test-artifacts/perf-probe.json`。

实测（MacBook M5，1440×900，战士）：

| 指标 | 数值 |
|---|---:|
| 采样规模 | 39680 帧 / 8538ms |
| 平均帧率 | 约 4647 fps（无垂直同步，等效单帧开销约 0.2ms） |
| p95 帧 / p99 帧 | 0.6ms（约 1666 fps） / 0.9ms（约 1111 fps） |
| 最差帧 | 8.3ms |
| 长帧（>20ms / >33ms） | 0 / 0 |

结论：当前 CPU 侧渲染与逻辑单帧开销远低于 60fps 的 16.7ms 预算，**暂不实施怪物/掉落分层缓存**（`202609300017下一步待实现.md` P1-4 的可选项）；后续新增渲染内容后再跑 `npm run perf` 复测。注意该数据来自桌面无头环境，不代表低端移动真机表现。
