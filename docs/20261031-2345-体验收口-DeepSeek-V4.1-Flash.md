# 0.8.9 体验与健壮性收口

本轮处理上一轮真机测试与项目分析中登记的 4 个待修项：导入数值无上限、toast 互相覆盖、召唤骨卫需先锁目标、重铸空提示贴边。

## 一、导入存档数值钳制（P3）

**问题**：`sanitizeSavedGame` 只净化物品字符串与颜色，玩家字段完全放行。实测把 `player.gold` 改成 123456 后导入，金币原样生效，与「服务器权威」叙事冲突。

**修复**（`game/src/persist.js`）：

```js
const SAVE_LIMITS = {
  gold: 9999999,
  level: 60,
  exp: 9999999,
  hp: 999999,
  marks: 999999,
  potion: 999,
  reforgeScroll: 999,
  skillPoints: 99
};
```

- 逐字段 `clampField`，**仅在字段存在时钳制**，避免把缺失的 `maxHp`/`potion` 补成 0 破坏老档
- `skillLevels` 截断到 4 项，每项 ≤99
- 顶层 `equipment` 与 12 槽位白名单逻辑保持不变

**验证**：新增 2 条单测（超上限全面钳制、缺失字段不被补值），单测总数 167 → 169。

## 二、toast 队列化（P3）

**问题**：`showToast` 单例覆盖。实测买药水扣款成功，但提示被紧随其后的「附近没有可攻击目标」覆盖。

**修复**（`game/src/render.js`）：改为 5 条队列，每条 1.8s，相邻重复消息合并；队列空时清理定时器。

**验证**：`test:ui`、`test:ui:regression`、`test:ui:timeline` 均通过，提示不再瞬时覆盖。

## 三、召唤骨卫口径对齐（P3）

**问题**：无目标按 2 提示「先锁定一个目标」，与 README「在身边召唤骨卫协同作战」不一致。

**修复**（`game/src/main.js`）：把召唤分支提前到目标校验之前，无需锁定目标，在玩家脚下召唤；保留符力扣除、冷却、施法帧与 12 秒存活。

**验证**：新增 `npm run test:ui:summon`，断言「无目标 → 符力 160→126 → 时间线出现『骨卫在场景中现身』」；`SUMMON PASS`。

## 四、重铸空提示留白（P4）
