# 0.8.79 地图阵容差异化与威胁标签

## 背景

0.8.78 之前，第 2–10 章的 90 张生成图虽然每张都有 9 种 `monsterTypes`，但实际刷怪只用了其中 5–8 种贴图；106 个地图怪名最终只产生 65 个不同贴图，深层试玩后最明显的问题从“缺功能”变成“每张图看起来都一样”。

0.8.79 只处理**每张图实际出场阵容**，不改地图布局、怪名表、数值表、精英与召唤逻辑，避免把内容问题和数值问题混在一起。

## 实现

### 1. 确定性阵容生成

`game/src/maps.js` 新增：

- `shuffledIndices(seed, source)`：用现有 `seededRandom` 做种子洗牌，保证同关卡每次生成一致。
- `generatedMonsterRoster(stageNumber)`：返回本图实际出场的 4–6 个 `typeIndex` 数组。
  - 每章第一张生成图（第 5、11、21……关）从本章 9 种怪里洗牌取 4–6 种。
  - 后续图保留上一图 `min(floor(本图阵容/2), floor(上一图阵容/2))` 种，其余只从“上一图完全没有的物种”中取。
  - 这样同章相邻两图的重叠不超过较小阵容的一半，不会出现只换一只怪的伪差异。
- `generatedMap()` 返回 `monsterRoster`。`monsterTypes` 仍保留完整 9 种，供精英、召唤、图鉴与数值表共用，不直接裁剪。

实际分布：4 种 29 张、5 种 38 张、6 种 29 张；每章 10 张图有 5–6 种不同组合。

### 2. 实体创建映射

`game/src/main.js` 的 `createEntities()`：

```js
const roster = map.monsterRoster;
const typeIndex = roster ? roster[spawn[2] % roster.length] : spawn[2];
const baseType = map.monsterTypes[typeIndex];
```

`spawn[2]` 仍是布局档位（0..8），继续用于等级差 `levelMin + spawn[2] * 2 + index % 3`；只有贴图/怪名映射到本图阵容。这样不会因为裁剪阵容而改变关卡等级曲线。

### 3. 地图威胁标签

新增 `MAP_THREATS` 五类：矿尘、灼热、腐雾、雷暴、潮汐；`mapThreatFor(stageNumber)` 同章每两张图轮换一个威胁，避免 100 张图只有一种环境提示。

`generatedMap()` 增加 `threat` 字段；`render.js` 的目标卡文案追加“（地图威胁：xx）”。当前只做**可读标签**，还没有接伤害、视野、恢复等实际机制。

### 4. 版本与构建版本

- `VERSION`、`package.json`、`package-lock.json`、`CURRENT_APP_VERSION`、`CACHE_VERSION` 全部升到 0.8.79。
- `BUILD_VERSION` 之前停留在 0.8.7，本轮改为 `const BUILD_VERSION = CURRENT_APP_VERSION;`，避免诊断接口与发布版本各说各话。

## 验证

### 单元测试

`npm run verify`：语法 100 文件、版本一致性、Prettier、**252/252 单测**、素材审计与预算 35.6MB / 940 文件全部通过。

新增两组契约测试：

- 每张生成图阵容 4–6 种、无重复、所有阵容物种都实际出场、相邻重叠 ≤ 较小阵容一半、每章至少 5 种组合。
- 每张生成图带 `threat`，id 在池内，且与 `mapThreatFor(stage)` 一致；同章前五组威胁至少 3 种。

## 边界与未做

- 威胁只有标签，没有实际效果；下一步再接矿尘降视野、灼热持续伤害、腐雾压低恢复、雷暴随机落点、潮汐减速等机制。
- 每章 2–3 张地图专属精英尚未实现；当前精英仍按 `rollElite` 的通用词缀规则生成。
- 不改地图布局、刷怪点数量、9 档数值、深层逻辑；阵容只影响实际出场的怪名/贴图。
- `generatedMonsterRoster(4)` 会被 `Math.max(5, …)` 夹到第 5 关；手工第 4 关不消费该函数，本轮只检查生成图之间的相邻关系。
