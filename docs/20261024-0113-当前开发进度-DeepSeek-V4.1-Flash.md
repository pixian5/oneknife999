## 一、本轮完成：非快进难度探针

0.3.5 的百图 e2e 死亡数从 0 次变成 18 次（两轮都没改战斗数值），说明快进模式下的死亡数已经没有参考价值。本轮补上「按正式数值结算」的难度闸门。

### 1. 新增 `tests/difficulty-probe.cjs`（`npm run test:difficulty`）

- **只快进虚拟时间**：`page.clock` 推进游戏时间，但 URL 不带 `fast`，伤害与怪物前摇 / 全局出手闸门全部按正式数值结算。
- **玩家基线**：主线等级曲线、技能点均分到 4 个技能、穿戴本关掉落表前 4 件装备（Node 动态 import `maps.js` 读取）、6 瓶药水 / 4000 金币。
- **操作模型**：近战贴脸、远程停在射程边缘；普攻与技能交替；血量 < 55% 喝药、< 60% 或中毒 3 层回安全点；打首领「一刀一撤」拉开到首领 104px 攻击距离外，让 0.6s 蓄力环落空。
- **判定**：单关死亡 ≤ 6 次（`ONEKNIFE_PROBE_MAX_DEATHS`）、模拟耗时 ≤ 900s（`ONEKNIFE_PROBE_MAX_SECONDS`）、该关必须 `completed`；每 50 个战斗循环打印目标 / 玩家血量与死亡数。
- **隔离**：每关新建 context + page（同页连跑会让第 15 关死亡数从 2 次暴涨到 17 次）。

### 2. `snapshot()` 补 `player.maxHp`

探针原先自己算 `职业基础 + 等级×18`，漏掉装备生命加成（第 15 关基线装备 +135 HP），导致「半血」被当成「满血」、撤退逻辑失效。现由游戏侧提供含装备加成的真实上限，百图 e2e 也能复用。

## 四、本轮发现的问题（未修，待决策）

**防御词缀没有实际效果。** `config.js` 的 `equipmentDefenseBonus()` 与 `runtime.js` 的 `equipmentDefense()` 都只是导出，**没有任何调用点**；玩家承伤 `computeIncomingDamage({ defense: activeHero().defense })`（`main.js` 的两处怪物出手）只取职业基础防御。结果是 0.3.5 词缀重铸出的「防御」词缀完全不影响承伤，只有生命 / 攻击词缀有效。修复方式很小（把 `activeHero().defense + equipmentDefense()` 传进承伤公式），但会整体降低后期承伤、需要重测数值，因此本轮只记录不修改，等待决定。
