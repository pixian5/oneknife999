# 致盲被动接线与被动消费链审计（0.7.1）

- 日期：2026-10-29 04:10
- 模型：DeepSeek-V4.1-Flash
- 版本：0.7.0 → 0.7.1
- 来源：GitCode 平行线的 0.6.7 实测发现 `blind`（致盲）被动是死代码，本轮把它接上消费点并做全量审计

## 一、问题

`game/src/monster-abilities.js` 的 `PASSIVE_PARAMS.blind = { duration: 2, missChance: 0.3 }` 定义完整，23 种怪（雪原猎手 / 摄魂鬼 / 虚空影 / 沙魂亡灵 / 暴雪鹰王 / 幽冥鬼鸮 / 雾隐蛟 / 灰烬影狼 / 灰烬魔影 / 虚影刺客等）也挂了 `passives: ["blind"]`，但全代码没有任何地方读取它——致盲从未生效，玩家命中率从未被影响。

后果不只是「少一个特效」：GitCode 侧的难度断层调查原本要用**单行为消融**定位第 30 关的 10.5 死，而致盲是死的，导致消融实验测的是一个不存在的效果。

## 二、被动消费链审计（18 条全部有消费点）

| 被动 | 消费点 | 形态 |
|---|---|---|
| poison / slow / stun | `main.js` `applyOnHitPassives` → 玩家 `poison` / `slowTimer` / `attackTimer` | 命中时写入 |
| resourceDrain / potionLock / skillLock | 同上 → `resource` / `potionLock` / `skillLock` | 命中时写入 |
| **blind** | 同上 → `blindTimer` + `blindMissChance`（0.7.1 新增） | 命中时写入 |
| rageStack | `applyOnHitPassives` 自增 `rageStacks`；`attackShapeConfig` 读攻速 | 命中时 + 出手术 |
| shieldCycle | `main.js` 周期护盾（`shieldValue`） | 逐帧 |
| firstHitReduce / lowHpReduce | `applyDefensePassives`（承伤修正） | 受击时 |
| meleeReflect | `reflectDamage` → 玩家承伤 | 受击时 |
| lethalSave | `resolveLethalSave`（残军意志） | 受击时 |
| enrageLowHp | `enrageMultiplier`（玩家低血增伤） | 出手术 |
| packHunt | `packHuntMultiplier`（同类数量） | 出手术 |
| lowHpDamageUp | `lowHpDamageMultiplier` | 出手术 |
| deathPoison / deathRevive | `resolveOnDeath`（毒区 / 复原） | 死亡时 |
| 攻击形态（normal/multi/heavy/ranged/charge/sweep/pull） | `attackShapeConfig` → 前摇 / 段数 / 范围 / 击退 | 出手术 |

结论：`blind` 是唯一断链的参数，其余 17 条均可追踪到具体读写位置。

## 三、实现

1. `monster-abilities.js` 新增纯函数：

```js
export function rollBlindMiss({ blindTimer = 0, missChance = 0 } = {}, random = Math.random) {
  if (blindTimer <= 0 || missChance <= 0) return false;
  return random() < missChance;
}
```

2. `applyOnHitPassives` 写入致盲：`blindTimer = max(现有, duration)`、`blindMissChance = params.missChance ?? 0.3`，飘字「致盲」。
3. `resolveDamage` 结算前判定：落空则飘字「未命中」（灰蓝色）、写战斗日志「…落空：目标隐于雾中」，返回 0 且不结算伤害（技能 / 普攻 / 一刀时刻 / 召唤物同路径）。
4. 主循环逐帧递减 `blindTimer`，归零时清 `blindMissChance`（与减速 / 药水封锁 / 技能封锁同一段）。
5. 存档不特殊处理：`persist.js` 落整份 `state.player`，与既有 `slowTimer` / `potionLock` 一致。

## 五、经验

- **配置有定义 ≠ 生效**：被动表、参数表都是「声明」，必须能指出具体读写位置；新增原语时同步补一条纯函数 + 单测，否则会长期静默失效。
- **消融实验前先确认行为真的生效**：对一个死代码做 A/B，得到的是「无差别」，会被误读成「该行为无害」。
- 消费链审计用「`grep 参数名` 跑一遍全部源码」最直接：只有出现次数 = 1（就在定义处）时才是可疑项。
