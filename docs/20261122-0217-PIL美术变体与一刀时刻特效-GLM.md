## 一、能力边界的诚实说明（为什么不是 AI 位图生成）

用户上轮授权"你来解决"，我彻底排查后确认：

1. **内置 `image_gen` 工具不在本会话环境**——imagegen 技能是为 Codex 环境写的，那个环境有内置生成工具；本 GLM 通道环境没有。两次 LocalToolSearch 全量检索证实（返回的全是会话管理类工具）。
2. **CLI 回退需要 `OPENAI_API_KEY`**——环境变量与全局配置（AGENTS.md）均无此 key，按技能规则不擅自走该通道、也不索要完整密钥。
3. `image_search` MCP 注册但连接失败（"coding plan is required"，平台订阅限制）。

**解锁路径**：提供 OpenAI 平台 API key（环境变量设置，勿贴对话）即可走 CLI 模式生成全新立绘；或继续豆包管线。本轮用 **PIL 程序化变体**交付——从现有素材确定性生成，风格 100% 一致、零外部依赖。

- **生成**：以 `fx-skill-inferno`（地狱火涡流）做 HSV 色相偏移 +36°（红橙→金），叠加 `fx-skill-holy` 光晕与中心径向白光（GaussianBlur 6），128×128 透明 PNG，38KB。

### 2. abyss-bg-01/02.jpg（深层专属底图）

- **生成**：chapter-01/06 底图 → 亮度 0.5 → 饱和 0.65 → 紫调(58,34,82)/青调(30,62,78) 28% 混合 → 大半径暗角。1600×900、126/117KB（与章节底图同规格）。

## 四、过程坑（两次，均已当场修）

1. **Playwright evaluate 的闭包变量不跨上下文**：回调里引用 Node 侧常量 `SAVE` 报 `ReferenceError`——必须作为参数显式传入，且 **Playwright 限制 evaluate 只收 1 个函数参数**，多个值要包成单对象（`{ v, key }`）。之前 0.8.29 时代写过正确写法但忘了为什么，本轮重新踩明。
2. **python 补丁脚本重建 import 块时格式损坏**（PASSIVE_FX 后缺逗号）——又是"多段替换+格式重排"坑，最终用精确坏文本替换修复。教训已入经验目录候选：正则重建代码块不如精确字符串替换稳。
