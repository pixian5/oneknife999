# 服务器技术与反作弊

## 架构边界

- 网关：鉴权、限流、版本校验。
- 大厅：角色、行会、聊天、组队。
- 地图服：移动、怪物、战斗、PK。
- 战场服：世界 BOSS、资格战、王城。
- 资产服：装备、货币、仓库、交易。
- 结算服：掉落、贡献、任务、邮件。
- 日志与风控：事件流水、关联图、报警。

资产服是装备和货币单一事实源。地图服不能直接写背包，只能提交带幂等键的结算请求。

## 装备实例

字段：`item_instance_id`、模板、品质、词缀、强化、耐久、绑定、锁定、所有者、生成来源、规则版本、创建时间、最后流水 ID。

生成、拾取、强化、重铸、交易、掉落、铸魂和销毁均写不可变流水。物品删除必须有业务原因和对应材料结果。

## 掉落原子性

```text
boss_dead(event_id)
  -> acquire idempotency lock
  -> create drop seed and items once
  -> persist drop ledger
  -> publish ground entities
  -> update contribution rewards
```

两个玩家同时拾取使用比较并交换所有者；只有一个成功。客户端光效不是资产凭证。

## 交易原子性

上架冻结物品，购买冻结金币，结算在同一事务中转移物品、金币和税。任何一步失败全部回滚。重复支付回调和重复购买请求使用订单 ID 幂等。

## 战斗同步

服务器权威；客户端预测移动和表现。输入缓冲 120ms，位置误差 0.8 米平滑纠正、2 米立即纠正。攻击间隔、施法距离和控制由服务器判定。

普通地图每线 80~120 人。首发单服 800 CCU；战场服 240 人上限。扩容到 2,000 CCU 前必须完成地图迁移、聊天分片和资产服压力测试。

## 断线

断线 90 秒内允许重连。危险区角色保留 15 秒，防止拔线逃战；15 秒后若未受攻击则安全下线。王城重连恢复阵营、位置、冷却和贡献，不重复发奖励。

## 反作弊信号

- 移动速度、加速度和穿墙。
- 攻击间隔、技能冷却、无目标施法。
- 拾取距离和同一物品并发请求。
- 自动路径重复度、在线时长、输入熵。
- 多账号金币环流、异常高价交易。
- BOSS 贡献刷治疗、刷承伤和无效目标。

异常账号先限制交易和排名，不立即删除装备。人工确认后基于流水回滚。申诉提供事件 ID，不公开检测阈值。

## 多开和工作室

同设备最多 2 个账号；世界 BOSS 和王城同设备只有一个角色获得贡献奖励。账号可信度根据注册时间、正常任务、设备稳定性和交易行为逐步提高，不以充值提高。

## 数据与隐私

聊天原文按法规保留，支付信息不进入战斗日志。埋点使用账号内部 ID，不上传通讯录和无关设备文件。玩家可查看近 30 天登录、交易和消费记录。

## 灾备

- 资产数据库跨可用区同步。
- 每 6 小时快照，流水持续备份。
- 回滚工具按事件范围，不做全服粗暴回档。
- 发布前验证旧客户端被网关拒绝写资产。

## 技术验收

- 100 万次拾取并发无重复所有者。
- 10 万次支付重复回调只到账一次。
- 240 人王城 P95 战斗事件确认低于 180ms。
- 地图服崩溃后已结算装备不丢、不重复。
- 资产服短暂不可用时地图停止发奖但战斗可安全结束。

## 技术规格说明

本卷是逻辑服、资产服、战场服、日志和风控的接口边界。设计原则是“战斗可以短暂降级，资产不能模糊
结算”：地图服负责实时位置和战斗事件，资产服负责装备、货币和仓库唯一事实，结算服负责把贡献、掉落、
任务和邮件写成幂等结果。任何服务不得直接修改另一个服务的私有存储。

## 服务职责与调用方向

```text
客户端
  -> 网关(鉴权/限流/版本)
     -> 大厅(角色/行会/聊天/组队)
     -> 地图服(移动/怪物/战斗/PK)
     -> 战场服(BOSS/资格/王城)
     -> 资产服(装备/货币/仓库/交易)
     -> 结算服(掉落/贡献/任务/邮件)
     -> 日志与风控(事件流水/关联图/告警)
```

调用采用明确的命令和事件：命令由一个服务负责校验和幂等，成功后发布事件；订阅者只更新自己的读模型。
资产服不能订阅客户端动画事件作为扣款依据，地图服不能因为客户端“看见光柱”就生成物品。

### 服务契约

| 服务 | 写入权限 | 依赖 | SLA 目标 | 降级方式 |
|---|---|---|---|---|
| 网关 | 会话、限流 | 配置中心 | P99 100ms | 拒绝旧版本资产写入 |
| 大厅 | 角色、行会、聊天 | 账号、资产读模型 | P95 200ms | 聊天降级，角色只读 |
| 地图服 | 战斗实例状态 | 导航、配置、结算命令 | P95 150ms | 降飘字，不降判定 |
| 战场服 | 240人实例状态 | 地图、贡献 | P95 180ms | 降非关键广播 |
| 资产服 | 装备、货币、交易 | 数据库、流水 | P95 300ms | 停止资产写入 |
| 结算服 | 奖励和邮件 | 资产命令、事件总线 | P95 300ms | 队列重试 |
| 风控 | 风险状态和告警 | 全量事件 | 15分钟内告警 | 延迟处置，不改战斗 |

## 通用事件和幂等键

事件公共字段：`event_id`、`event_type`、`aggregate_id`、`producer_service`、`schema_version`、
`rules_version`、`occurred_at_utc`、`sequence`、`correlation_id`、`payload_hash`。同一个 `event_id` 在任何
消费者中只应用一次；事件顺序按 `aggregate_id + sequence` 检查，乱序进入重排队列。

命令公共字段：`request_id`、操作者、客户端版本、会话、超时、签名摘要。服务以 `request_id` 返回第一次
结果，重复请求不能重新扣费、生成或发奖。幂等记录保留至少180天，便于客服和灾备重放。

## 装备和货币一致性

### 物品实例状态机

```text
generated -> ground -> inventory -> equipped
inventory/equipped -> frozen(listing/trade/enhance)
frozen -> inventory/equipped | transferred | destroyed
equipped -> dropped -> ground -> picked
```

状态迁移必须通过资产服事务；同一实例不可同时属于角色、摊位、邮件和地面实体。删除只允许迁移到
`destroyed` 并关联原因和返还流水，禁止物理删除作为常规业务。

### 掉落原子性

```text
boss_dead(event_id)
  -> acquire idempotency lock
  -> create drop seed and item instances once
  -> persist drop ledger
  -> publish ground entities
  -> calculate contribution
  -> issue personal rewards
```

贡献计算失败时保留 BOSS 死亡和物品实例在待结算状态，不能重新生成第二套；重试只消费同一 `drop_seed`。
若资产服不可用，地图服可以继续到战斗结束，但停止拾取和奖励写入并通知玩家“结算延迟”。

### 交易原子性

上架冻结物品，购买冻结金币，结算事务写物品转移、金币转移、成交税、王城分成和订单状态。任一步失败
回滚全部数据库变更并释放锁；跨服务通知采用 outbox，避免数据库成功但消息丢失。

## 战斗同步和时间

服务器使用单调时钟计算技能冷却、位置误差和 BOSS 阶段；UTC 墙上时间只用于活动排期和年表。客户端
时间漂移超过5分钟时仍可战斗，但不能决定 BOSS 刷新、罪恶值下降、活动结算或邮件到期。

输入缓冲120ms；同会话输入序号递增，倒序和重复拒绝。位置误差0.8米平滑、2米立即校正；冲锋、击退、
传送和复活均写授权位移事件。地图线容量80~120，战场240，扩容到2000 CCU前必须完成地图迁移、聊天
分片、资产压测和故障演练。

## 断线、重连与状态快照

断线90秒内允许重连；危险区角色保留15秒，若未受攻击才安全下线。快照字段包括地图、线、位置、战斗
状态、HP/资源、技能冷却、PK模式、名字状态、队伍/行会、贡献和 `snapshot_id`。重连流程先鉴权，再读取
快照与未确认事件，按序重放，最后推送客户端；客户端本地缓存不能覆盖服务器快照。

王城和世界 BOSS 断线重连恢复阵营、位置、冷却和个人贡献；若角色在快照期间已死亡，优先应用死亡流水，
不能既复活又领取死亡后奖励。重连超过90秒视为正常重新进入，不能带出战斗保护和 READY 一刀状态。

## 反作弊分层

### 客户端层

只做完整性、版本、输入节流和崩溃报告，不把安全判断放在客户端。客户端可以检测篡改并上报摘要，但不
直接封禁或删除资产，避免误报造成不可逆损失。

### 服务器层

验证速度、加速度、路径碰撞、攻击间隔、技能冷却、无目标施法、拾取距离、目标可见性、重复请求、BOSS
贡献和交易价格。阈值配置不下发客户端；所有处置引用事件 ID和规则版本。

### 风控层

输入序列异常、在线时长、自动路径重复度、输入熵、同设备/网络/支付关系、环形转账和死亡后资产回流
形成风险图。风险分只分桶保存，原始设备指纹不进入玩家公开数据；高风险先限制交易和排名，再人工复核。

## 多开、工作室与误伤保护

同设备最多2个账号；世界 BOSS 和王城同设备只允许一个角色获得贡献奖励，其他角色可以观战或外围补给。
账号可信度由注册时长、正常任务、设备稳定性和合法交易逐步提高，不以充值提高。新账号高价值交易采用
冷却和人工抽查，不自动没收合法装备。

处置状态：`observe -> trade_restricted -> ranking_restricted -> manual_review -> rollback/ban`。任何
封禁必须关联资产图、事件链和人工审批；回滚只按异常流水范围，不能通过全服回档掩盖审计缺口。

## 数据隐私与访问控制

聊天原文按法规保留，支付信息不进入战斗日志；埋点使用内部账号哈希，不上传通讯录、相册或无关设备文件。
玩家可查看近30天登录、交易和消费记录；删除请求按法规脱敏而非破坏资产审计链。客服按最小权限访问：普通
客服读死亡摘要，资深客服读流水，资产管理员执行双人审批的补偿命令。

## 备份与灾备演练

- 资产数据库跨可用区同步，流水持续备份；每6小时生成快照并校验恢复。
- 事件总线保留180天，关键 BOSS 和王城事件保留365天。
- 发布前演练地图服崩溃、战场服崩溃、资产服只读、消息重复、数据库主从切换和配置回滚。
- 回滚工具按事件范围运行，预览受影响角色和资产数量；执行前需要二人确认和公告。
- 旧客户端可以被网关拒绝写资产，但不能读取不存在的字段或显示错误掉落概率。

## 运维指标与告警

| 指标 | 目标 | 告警 | 处理 |
|---|---:|---:|---|
| 地图事件 P95 | <=150ms | 连续5分钟>180ms | 降普通广播 |
| 王城事件 P95 | <=180ms | 连续3分钟>220ms | 降特效和非关键同步 |
| 资产写入 P95 | <=300ms | 连续3分钟>500ms | 停止新资产写入 |
| 重复事件率 | 0 | 任一重复到账 | 立即冻结相关订单 |
| 掉落待结算队列 | <1000 | >5000持续2分钟 | 扩容结算消费者 |
| 位置校正率 | <0.5% | 单地图>2% | 检查导航和攻击脚本 |
| 风控告警延迟 | <15分钟 | >30分钟 | 降级高风险交易 |

## 接口交付清单

服务器上线包必须包含服务依赖图、命令/事件 schema、幂等策略、状态机、快照字段、监控面板、灾备 runbook、
数据保留表、S-001~S-010 自动化和压测报告。任何新增资产操作若没有 `request_id`、`rules_version`、
`ledger_id` 和回滚路径，不得开放给客户端。

本卷扩展版目标版本：`0.0.7-draft`。

## API 契约样例

### 拾取命令

```json
{
  "request_id": "LOOT-20260810-0001",
  "event_id": "DROP-88FA",
  "ground_entity_id": "GE-123",
  "role_id": "R-1001",
  "client_seq": 8841,
  "map_id": "MAP_BLACK_ROCK_MINE",
  "rules_version": "0.0.7"
}
```

响应枚举：`accepted`、`already_picked`、`not_owner`、`expired`、`out_of_range`、`asset_pending`、
`invalid_session`。无论成功还是重复请求，都返回同一 `ground_entity_id` 的最终所有者和 `ledger_id`；
客户端不能以“光柱存在”推断仍可拾取。

### 强化命令

```json
{
  "request_id": "ENH-001",
  "item_instance_id": "I-9F5A",
  "material_instance_ids": ["MAT-01", "MAT-02"],
  "client_snapshot_hash": "sha256:...",
  "rules_version": "0.0.7"
}
```

资产服先锁装备和材料，再由结算服按服务器种子结算；快照哈希过期时拒绝提交并要求刷新。重复 request_id
只返回第一次成功/失败和 `enhance_ledger_id`，不能再扣材料。

## 数据存储分层

| 数据 | 主库 | 读模型 | 保留 | 一致性 |
|---|---|---|---:|---|
| 角色/装备/货币 | 资产数据库 | 大厅/背包缓存 | 永久/法规 | 强一致事务 |
| 战斗事件 | 战斗事件库 | 回放索引 | 10分钟/活动7天 | 有序事件 |
| 掉落/贡献 | 结算库 | BOSS面板 | 180天 | 幂等命令 |
| 聊天 | 合规日志库 | 频道缓存 | 按法规 | 可查询 |
| 风控关联图 | 风控库 | 告警面板 | 180天 | 最终一致 |
| 年表 | 世界状态库 | 客户端缓存 | 永久 | 版本化 |

缓存只用于读取和界面加速，资产写入不能依赖缓存成功。缓存失效时显示加载中或只读，不把默认值当作0金币、
无掉落或和平模式。所有读模型保存来源事件序列，落后时可重建。

## 事件总线和重试

事件采用至少一次投递；消费者使用 `event_id` 幂等表。处理失败分为可重试、需排序、数据错误和人工审核：

| 类型 | 重试 | 处理 |
|---|---:|---|
| 数据库超时 | 5次指数退避 | 仍失败进入待处理 |
| 事件乱序 | 排序窗口5秒 | 等待前序 |
| schema不兼容 | 0 | 隔离队列、报警 |
| 资产冲突 | 0 | 返回原结果/人工复核 |
| 风控慢 | 异步 | 不阻塞合法战斗结算 |

待处理队列有容量和年龄告警；队列恢复时按事件序列消费，不按重试到达顺序乱序发奖。人工处理不能直接
修改队列内容，只能提交补偿或重新投递命令。

## 战斗服与资产服故障边界

| 故障 | 可继续 | 暂停 | 玩家提示 |
|---|---|---|---|
| 资产服只读 | 移动、已开始战斗 | 交易、拾取、强化 | 资产结算延迟 |
| 结算队列堆积 | 战斗、地图移动 | 发奖、邮件领取 | 奖励排队中 |
| 聊天服故障 | 刷怪、PK、BOSS | 世界/队伍聊天 | 聊天暂不可用 |
| 战场服故障 | 普通地图 | 王城/资格报名和结算 | 活动暂停 |
| 配置中心故障 | 当前版本战斗 | 新活动、热更 | 使用已锁版本 |
| 日志库故障 | 安全战斗 | 高价值客服操作 | 审计暂不可用 |

任何故障提示都必须给出事件 ID或查询入口；不显示“请重新购买/重新强化”这类可能造成重复资产操作的文案。

## 网络和连接策略

连接分为登录、地图、战斗、交易和语音/聊天通道；交易和资产命令使用独立序列与重放保护。移动端切后台
时，地图保留15秒危险区状态和90秒重连窗口；客户端恢复后先同步服务器快照，再恢复输入。高延迟时减少
普通广播和动画预测，不提高技能命中容差。

服务端按区域、线路和战场分片；跨线迁移使用迁移令牌，包含角色、队伍、PK、快照和未确认事件序列。
迁移失败回原线，令牌只能使用一次，防止重复角色出现在两条线。

## 安全和密钥边界

客户端只持有短期会话令牌；资产命令使用网关签名和服务间 mTLS，规则配置以签名包下发。私密密钥、支付
凭据、风控阈值和数据库连接不进入客户端、Markdown文档或日志。测试环境使用合成账号和假支付回调，不
连接生产资产。

## 反作弊特征工程

每个风险特征记录窗口、来源事件和置信等级：

| 特征 | 窗口 | 例子 | 误伤控制 |
|---|---:|---|---|
| 速度越界 | 10s | 服务器位移超过导航 | 检查技能授权位移 |
| 攻击周期 | 60s | 间隔低于技能最小值 | 按延迟分位数校准 |
| 路径重复 | 24h | 95%路线相同 | 与自动战斗白名单区分 |
| 输入熵 | 10m | 方向/技能过于固定 | 不单独作为封禁证据 |
| 拾取冲突 | 1h | 大量同物品并发 | 先拦重复请求 |
| 资产环流 | 7d | 多账号互转高价 | 允许真实稀有成交复核 |
| 贡献刷分 | BOSS实例 | 满血治疗/无效承伤 | 使用有效值和衰减 |

风险模型输出分桶和原因类别，不把完整模型参数返回玩家。封禁前至少需要两类独立信号或人工证据，避免
单一低输入熵、网络抖动或辅助设备导致误封。

## 监控面板

每个服务面板固定显示吞吐、P50/P95/P99延迟、错误码、重试、队列年龄、活跃实例、内存、CPU、网络、
数据库连接和规则版本。资产面板额外显示余额负数、双所有者、重复订单、待结算装备、人工补偿和回滚量。

告警必须包含服务、区域、版本、关联事件、开始时间、当前影响角色数和建议 runbook；不能只发“系统异常”。
告警恢复后保留完整事件，不删除噪声以掩盖波动。

## 服务接口错误码

| 错误码 | 服务 | 含义 | 客户端动作 | 是否重试 |
|---|---|---|---|---|
| `AUTH_VERSION_OLD` | 网关 | 客户端不能写资产 | 提示升级 | 否 |
| `IDEMPOTENT_REPLAY` | 任意 | 请求已处理 | 显示原结果 | 查询 |
| `ASSET_FROZEN` | 资产 | 物品/货币被锁 | 显示来源 | 否 |
| `RULE_VERSION_MISMATCH` | 资产/战斗 | 配置过期 | 刷新配置 | 否 |
| `GROUND_NOT_OWNER` | 掉落 | 无归属或保护 | 显示剩余时间 | 否 |
| `COMBAT_TARGET_INVALID` | 地图 | 目标不合法 | 取消技能 | 否 |
| `SETTLEMENT_PENDING` | 结算 | 奖励排队 | 显示查询 | 是/查询 |

## 数据库事务边界

资产事务一次只处理一个聚合根：装备、货币、订单、行会金库或奖励。跨聚合操作通过事务表和 outbox 连接，
不能在一个长事务里锁整张玩家表。事务提交前写意图，提交后写结果；服务崩溃时由后台扫描未完成意图，
使用 request_id 重试或标记人工处理。

### 资产事务样例

```text
BEGIN
  lock item I-9F5A
  lock gold account R-2002
  verify owner, price, binding, rules_version
  append item_transfer ledger
  append gold_transfer ledger
  append tax ledger
  update order=settled
  append outbox notification
COMMIT
```

任何锁等待超过配置上限返回 `ASSET_BUSY`，不强行杀事务；客户端查询 request_id，不能再次发起新订单。

## 事件重放和历史兼容

历史事件由事件自己的 `schema_version` 和 `rules_version` 解析。新增字段向后兼容，删除字段只能在读模型
迁移后进行；历史掉落、死亡、强化和王城不能使用当前规则重新计算。回放工具必须能重建：角色位置、技能、
伤害、控制、掉落、订单、金币、行会贡献和年表结果。

重放结果不直接写生产资产；先生成差异报告，显示实例 ID、余额、所有者、订单状态和奖励差异，由双人审批
后执行补偿或修复命令。重放失败进入隔离队列，不静默跳过。

## 服务器配置发布

配置包包含签名、依赖版本、灰度比例、生效 UTC、回滚版本和 schema hash。网关、地图、战场、资产和结算
服务在同一活动中读取一致的锁定版本；新活动可以使用新版本，已开始活动继续用旧版本。配置中心故障时
使用当前已签名版本，不加载半包或本地未验证文件。

## 聊天和隐私边界

聊天服务按频道、区服和语言分片；消息包含发送角色、频道、文本哈希、时间和举报 ID。原文按法规保留，
战斗日志只引用聊天事件 ID，不复制全文。屏蔽、举报和频道限流在服务器执行，切换客户端或修改本地时间
不能绕过。

## 反作弊复核流程

```text
特征异常 -> 关联至少两类证据 -> 风险分桶
         -> 低风险观察 / 中风险交易限制 / 高风险人工复核
         -> 合法释放 / 异常回滚 / 封禁
```

人工复核先看事件链和资产图，再看设备/网络关联；设备关联不是单独定罪证据，网络抖动不是速度作弊证据。
封禁通知给事件范围、规则类别、申诉入口和申诉期限，不公开阈值和模型权重。申诉期间合法装备不自动删除，
异常高价值资产可以冻结至复核完成。

## 资产状态一致性检查

每小时对资产库、读模型、事件队列和邮件执行抽样核对：装备实例数量、所有者、绑定/锁定、强化、货币余额、
订单状态、地面实体、死亡邮件和行会仓库。发现差异先冻结相关实例和交易，不直接修正读模型；通过流水
重算后生成修复命令。抽样结果保留 `consistency_check_id`、差异数量、起止序列和处理人。

## 事件保留和脱敏

战斗回放只保留最近10分钟，BOSS/王城活动事件保留180~365天，资产流水永久或按法规保留。日志中的账号、
角色和设备字段使用内部 ID/哈希；支付和聊天原文只在合规服务存储。生产日志禁止写入会话令牌、私钥、支付
卡号和完整 IP；调试日志上线前必须经过脱敏检查。

## 技术与玩法边界摘要

地图服只负责实时战斗和位置，资产服只负责装备/货币/交易，结算服只负责奖励/任务/贡献，战场服只负责

BOSS/死亡/活动、重复请求重新扣费或无流水人工改物，均为 P0 架构违规。

## 数据迁移要求

schema 迁移先在备份和影子读模型上运行，校验装备数量、所有者、余额、订单、行会仓库、年表和事件序列；
支持旧字段读取和新字段双写观察。迁移失败立即停止新写入并回滚应用版本，不把半迁移数据暴露给客户端。
删除字段需要至少一个完整版本的弃用期和历史回放验证。

## 安全事件响应

发现攻击、密钥泄露、批量作弊、资产复制或支付异常时，建立安全事件 ID，限定受影响服务、账号、资产和
时间窗；吊销短期令牌、冻结高风险写入、保留日志和快照，再进行修复和回滚。公告不公开检测阈值和密钥，
但要说明玩家可见影响、资产保护、预计恢复和申诉入口。事后新增监控、回归和最小权限规则。

## 技术文档完成定义

每个服务有责任边界、API/事件 schema、状态机、幂等、存储、缓存、权限、隐私、监控、容量、故障降级、
备份恢复和测试；每个资产操作能由流水重建，每个客户端错误能关联 request/event，每个高风险处置能由人工
审批和申诉。缺任一项时服务不进入生产写入权限。

## 生产演练顺序

1. 用合成账号创建三职业、装备、金币、行会和活动快照；
2. 正常完成刷怪、BOSS、拾取、强化、交易、死亡、邮件和王城；
3. 在每个资产提交前后分别重启地图、结算、资产和战场服务；
4. 注入重复、乱序、延迟、数据库只读、队列堆积、缓存失效和旧客户端；
5. 验证玩家提示、服务降级、幂等结果、资产差异、告警、客服查询和恢复；
6. 使用快照和事件在隔离环境恢复，再与原资产、余额、订单、贡献和年表逐项比较。

演练结果必须满足100万拾取无双所有者、10万支付回调只到账一次、240人王城P95低于180ms、资产写入P95
低于300ms、重连不覆盖死亡、旧客户端不能写资产。失败项进入发布阻断而不是降低测试规模。

## 数据治理清单

玩家可见数据、运营分析、客服查询、风控证据和生产日志使用不同权限；内部 ID可以关联事件，但公共页面不

订单，结算确认掉落/任务/邮件，安全确认反作弊/权限/隐私，运维确认监控/备份/回滚，QA确认故障演练。
所有签字引用同一构建和规则版本；其中任一服务更换构建后，相关签字和测试失效并重跑。

本卷最终规格版本：`0.0.7`。

生产运行期间每周恢复一个只读快照、每月完成一次跨可用区演练、每季度完成一次全链路灾备；演练失败进入
发布阻断和整改，不能只记录告警。恢复数据与生产数据按实例、余额、订单、贡献和年表逐项对账。

对账报告保存快照时间、流水终点、事件缺口、差异实例和修复命令；差异不为零时恢复环境不得承接生产写入。
灾备完成后复核密钥、权限、监控、告警和客服查询，防止数据恢复但安全边界失效。

所有演练结论进入下一次容量、故障和安全测试基线，未关闭整改项不得以新版本覆盖或归档。

## 服务降级优先级

故障时首先保护资产唯一性与战斗权威，其次保证玩家可退出高风险区域，最后才是聊天、推荐、排行榜和表现。资产库无法确认提交时，拾取、交易、强化、死亡掉落和支付进入只读或待确认，不返回伪成功；地图服仍提供安全撤离和状态查询。排行榜、年表和推荐可延迟刷新，但延迟必须显示数据时间，不能拿缓存结果触发奖励。

降级开关按服务、区域、活动和规则版本设定范围，包含操作者、审批、原因、生效、过期和回滚条件。客户端从网关读取当前能力矩阵，禁用不可用操作并保留查询入口。恢复写入前先消费积压事件、校验幂等键、对账资产差异，再逐区灰度；不能因进程健康就直接全量开放。

### 反作弊证据链

检测信号只用于风险评分，处罚必须关联可复核证据：输入时间序列、移动轨迹、技能事件、资源变化、设备关联和规则版本。单次高伤、高手速或高收益不能独立构成永久封禁。自动系统可限制交易、匹配或高价值拾取并触发人工复核，但须告知玩家限制类别、申诉入口和预计复核时间，不公开可被规避的具体阈值。

证据按最小必要原则保存并设到期策略；客服只能查看解释所需摘要，安全人员访问原始设备与关联数据要有审批。模型或规则更新用已裁定样本回放，分别观察漏判、误判和不同设备/网络群体差异。灰度期间只告警不处罚，达到审核阈值后再逐步开启可逆限制，永久处罚始终保留人工签字。
