# 深入代码分析与数值断层（2026-10-11 13:35）

> 记录时间：2026-10-11 13:35 · 基于版本：0.2.3（纯分析轮，无功能改动）
> 分析方式：三路并行深审（渲染层 / 地图生成器 / 测试体系）+ Node 导入真实游戏模块做全 100 关数值模拟 + `npm run verify` 基线（39 单测全绿）。
> 所有结论均经代码行号或运行验证，非泛泛推断。

## TL;DR

工程骨架（分层、单测、CI、文档治理）在同类项目中属高水平，但深查确认了 **1 个真实数值断层（P0）**、**1 处实现与设计基线的公式偏离**、**3 个"改坏了没有任何测试能抓住"的测试盲区**，以及一批已定位到行号的具体缺陷。中期修复成本都低，但数值断层直接影响玩家可感知的节奏。

## 一、数值断层：关 4 → 关 5 难度与装备双倒退（P0）

手工图（1–4）与生成图（5–100）是两套数值体系，enrichment 循环（maps.js:1305-1366）只覆盖了等级，没覆盖怪物/装备数值，形成断崖：

| 关 | 怪物攻击 | Boss 攻/血 | 可获武器 power |
|---|---|---|---|
| 4 赤砂大漠（手工） | 70–92 | 112 / 3000 | 56 |
| 5 边境祭坛（生成） | **16–22（跌 75%）** | 30 / 1200 | **20（跌 64%）** |

- **关 4 本身是隐藏难度墙**：Boss 一击对战士 92 伤害（maxHp 约 467，5 击死；法师 3 击死），站桩承伤约 55 hp/s，Boss 战约 30 秒——不拉扯/不借助安全区几乎必死；紧接着的关 5 却是全程最轻松的关卡之一。
- **装备倒退持续几十关**：生成武器 `10+2s` 追平手工图 4 的 56 需到 s=23，战靴 s=30，项链 s=40。玩家在关 5–22 拿到的新装备全面劣于关 4 旧装备。
- **根因**：生成公式 `scale = 1 + stageNumber*0.085` 从 s=5 才起算，未与手工图数值衔接。
- **建议**：让生成缩放曲线在 s=5 处插值锚定手工图 4 的数值（或把手工图数值改为同一公式派生），一次修改同时抹平难度与装备两条断层。
- **后期节奏经模拟确认健康**：清怪稳定 2.5–3.4 秒、Boss 战 12–19 秒、威胁缓慢上升（被杀所需 hits 从 22 降到 11），第 100 关站桩打 Boss 必死（承伤 1442 vs maxHp 1115）迫使走位——这是合理设计。

## 二、玩家承伤公式偏离设计基线

`docs/11-数值配置基线.md` 与 `docs/02-战斗与职业.md` 的统一公式为：`防御减免 = 防御/(防御+100+攻击者等级×5)`。

- 出口端 `combat.js:12` 与基线一致 ✓
- **入口端 `main.js:464`（怪物攻击）与 `main.js:480`（地面危险区）缺失"攻击者等级"项**：玩家减伤恒为固定上限（战士 18%、道士 14%、法师 9%），永不随关卡衰减，怪攻线性增长直接全额透传。
- 后果：后期法师被 Boss 一击约 138（maxHp 1000 的 14%），承伤 DPS 约 83——数值失衡风险全押在这条未按基线实现的路径上，且与基线的偏离无任何文档说明。
- **建议**：入口端改用与基线一致的公式（攻击者等级可取实体 level），并补玩家承伤单测。

## 三、测试体系：三大盲区（深审结论）

测试骨架健康——单测断言精确到公式、e2e 真实键鼠驱动 + 虚拟时钟通关百图、catalog 契约扫描厚实。但盲区方向一致：**玩家"挨打侧"与经济侧几乎零断言**。

| 改坏什么 | 哪层测试能抓住 |
|---|---|
| 某图怪物攻击 ×10 | **没有一层**（fast 模式死亡免费、无死亡计数，照常通关） |
| 存档 gold/marks 字段改名 | **没有一层**（跨刷新静默清零） |
| level/exp 恢复改坏 | e2e checkpoint（main.js:302）✓ |
| 装备/背包恢复改坏 | e2e + 界面回归 ✓ |
| 地图几何/节点改坏 | maps 单测 + e2e catalog 双层（守护最强）✓ |

关键缺口与修复建议：

1. **snapshot 接口字段不全**（main.js:992-1005）：缺 `gold/marks/inventory/equipment`，e2e 的刷新恢复断言想查也查不到。补字段 + 断言，是堵经济盲区的最低成本路径。
2. **fast 模式对难度失明**：玩家伤害 ×25、死亡免费复活（main.js:516-528），e2e 全程零死亡断言。建议至少记录并断言死亡次数为有限值。
3. **默认仅战士跑 e2e**（`ONEKNIFE_RUNS=1` → warrior），mage/taoist 只有手动并发才覆盖；测试内 BASE_HP/attackRange 表是 config 手抄镜像，config 改动不会报警。
4. **perf-probe 是探针不是门禁**：无垂直同步下测的是 CPU 吞吐，"平均 4647 fps"不回答"60Hz 下会不会掉帧"，且无阈值无基线对比。建议改测"帧时间 p99 < 16.7ms"并设失败阈值。
5. **纯函数单测缺口**：`weightedPick`（已实测：空数组抛 TypeError、全零权重静默返回首项、负权重结果错乱）、`monsterProfile`、`pathTurnCount` 直接测试缺失；无损坏/截断存档用例（`loadGame` 在 main.js:773 静默吞错）。
6. 脆弱点：ui-smoke 用真实时钟 `waitForTimeout` 硬等待（慢机器偶发 flake）；e2e 重新实现了游戏相机（镜像耦合）；Boss phase 靠快照采样，快进下可能跳相位误报。

## 四、渲染层与移动端 UI（已验证的关键项）

- **render.js:534 死三元**：`entity.boss ? entity.color : entity.color`，两分支相同（已实测确认），应为笔误。
- **脏检查止步于写入层**：`renderAll` 每帧无差别跑 12 个 HUD 渲染器，省了 DOM 写、省不掉每帧的字符串/数组构建（renderLog 的 slice+reverse+map+join、renderRegion 整段 HTML 串等）。建议升级为"计算层签名"：签名不变则跳过构建。
- **技能栏冷却每跨一秒整段 innerHTML 重建**（render.js:957-977）：键盘焦点每秒丢失一次（可访问性 bug）。
- **移动端三件套缺失**：无 `env(safe-area-inset-*)`（Home 条压按钮）、`#gameCanvas` 无 `touch-action: none`（双击缩放/长按干扰）、761–767px 视口区间药水按钮被 `overflow:hidden` 裁掉（action-bar 最小宽约 768px vs 折行断点 760px）。
- class-modal 无 `role="dialog"`/焦点陷阱；resize 直绑无防抖（iOS 工具栏收展会事件风暴）；bossAlert 的 aria-live 每秒播报倒计时。

## 五、地图生成器（maps.js）

**确定性确认可靠**：种子 `stageNumber*982451653+104729`（maps.js:791），982451653 与 2^32 互素、关号映射单射，无种子碰撞；每关固定消耗 54 次 random，同关严格一致 ✓。`mapLayoutSignature` 含全部关键坐标，可作重复检测 ✓。

问题：

1. **手工图数据被无差别覆盖**（maps.js:1311-1312、1365）：pine_forest 手写 levelMin 8–18 被覆盖为 2–3（已实测确认），出口路牌读到覆盖前旧值，路牌与地图自述矛盾；四张手工图手写 exits 被整体丢弃。
2. **freePoint 回退梯死代码**（maps.js:997-1000）：`safeFallback` 谓词与 `valid` 等价、永不可达；真兜底放弃间距约束可贴怪刷新；末级 `throw`（maps.js:1002）在模块 import 期执行且无 try/catch，一旦触发全游戏白屏。
3. **encounterBands 元数据与实际 spawn 脱节**（maps.js:861-862 vs 930-934）：approach 带声明 3 只实为 4 只，rally 带声明 5 只实为 4 只；Boss 区回拉循环进一步偏离。仅影响渲染标注。
4. **结构性重复**：site 母题 `(s-1)%10`、城镇行 `s%3`，周期 30——s、s+30、s+60、s+90 共享母题+城镇行；radial 与 fork 几何生成完全同构；10 种母题实际只有 4 种路网拓扑。
5. **数据有、AI 无**：spawn 的 route/progress 分带契约（警戒带→压迫带→集结）只被渲染标注消费，`createEntities` 只读 x/y/type，怪物是静态点+wander——"分段叙事"目前是纯装饰。
6. **死数据**：96 张生成图怪物与 Boss `exp: 0`（maps.js:1085、1140，已确认），`computeKillReward` 根本不读实体 exp；手工图 exp 字段同样无人消费。
7. 文案：`chapter.short + 怪名` 产出"龙脉龙脉毒虫"类 stutter；十章主 Boss（灰烬霸主…玄烬帝尊）无 MONSTER_FLAVOR，终局 Boss 反而没文本。

## 六、经检查确认没有问题的方面

- 离屏缓存失效条件（仅按 map.id）、save/restore 全部成对、measureText 不在热路径。
- 种子确定性、campaignGrowth 分段边界无 off-by-one（10/11→Lv11、30/31→Lv21、60/61→Lv31 连续）、MAP_CLEAR_RULES 100 关 next 链闭环、kills 需求全部 ≤ 图内怪数。
- e2e 是真玩（无 evaluate 直改状态、虚拟时钟非硬等待）、并发用独立 browser context 隔离 localStorage 正确。
- 迁移表单测、快进 Boss 18% 承伤上限、drops 权重带边界测试质量高。
