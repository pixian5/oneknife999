# PK、红名与死亡爆装

## PK 模式

和平、组队、行会、阵营、全体五种模式。切换全体需要二次确认和 3 秒准备；进入战斗后 15 秒不能切回和平。安全区强制和平。

20 级前不能主动攻击玩家。高等级攻击低等级触发等级保护，差距超过 10 级时伤害递减并提高罪恶值。

## 名字状态

| 状态 | 罪恶值 | 权限 | 死亡风险 |
|---|---:|---|---|
| 白名 | 0 | 全部正常功能 | 低 |
| 黄名 | 1~299 | 部分传送费用增加 | 中 |
| 红名 | 300 以上 | 主城仓库禁用，只进红名村 | 高 |

主动击杀白名 +100；击杀最近 60 秒主动攻击过自己的玩家不增加；击杀红名获得正义值。罪恶值只在危险区杀怪或在线活动中下降，安全区挂机不下降。

## 死亡掉落表

| 状态 | 普通区 | 危险区 | 绝地 |
|---|---|---|---|
| 白名 | 背包 0~1 格 | 背包 1 格 | 背包 1~2 格，不掉穿戴 |
| 黄名 | 背包 1 格 | 背包 1~2 格 | 背包 2 格，5% 掉 1 件未绑定穿戴 |
| 红名 | 背包 2 格 | 背包 2~3 格，10% 掉穿戴 | 背包 3 格，20% 掉穿戴 |

每次死亡最多掉一件穿戴装备。先判定是否触发，再从未绑定穿戴装备中等概率选择。绑定装、任务物品和付费外观永不掉落。

装备锁定只防误卖、分解和交易，不保护死亡掉落。玩家捡到的可交易装备不能主动绑定，避免顶级装备全部退出爆装风险。

## 保护和保险

金币保险只抵消白名或黄名的一格背包掉落，不保护穿戴装备、不覆盖红名。进入危险区、绝地和切换全体模式前显示当前精确概率。

复生特性触发时不视为死亡，不产生掉落；王城每场只能触发一次。原地复活后有 3 秒只能移动的保护，主动施法立即结束。

## PvP 数值

最终 PvE 伤害乘 0.65，吸血上限 5%，召唤伤害乘 0.70。同类控制在 8 秒内按 100%、50%、25%、免疫递减。

职业修正限定 0.90~1.10，必须写在公开版本说明中。等级差保护只帮助撤离，不让低级玩家反杀高阶成为最佳刷荣誉方式。

## 仇敌和悬赏

死亡后可加入仇敌列表，只显示最近出现地图和最后活跃时间，不显示实时坐标。发布悬赏时系统冻结金币；首次符合条件的击杀领取。

同设备、同网络长期关联、同支付关系和高频互杀进入反刷审计。悬赏目标在竞技场、切磋和王城复活点被杀不计完成。

## 复活点和堵门

复活点周围 12 米为禁止攻击缓冲区。离开后获得 5 秒撤离加速，但攻击会立即取消。地图至少有两条离开复活区的路径；行会不能用碰撞体完全堵住出口。

## PK 指标

- 新玩家首次被杀后 10 分钟内再次出城比例。
- 白名误伤变黄名比例。
- 红名平均持续时间和装备掉落价值。
- 同一玩家 24 小时被同一行会击杀次数。
- 保险购买率和实际触发率。

若首次被杀后退出率超过 25%，先调整复活路线、提示和等级保护，不直接取消野外 PK。

## PK 设计规格

本卷定义自由 PK 的可预期边界：玩家可以主动承担风险、争夺刷怪点和复仇，但任何规则都不能被用来
强迫新玩家永久离开成长路线。名字状态、区域类型、等级保护、死亡掉落和悬赏是五个独立判定，客户端
只展示结果，不能把“锁定”“保险”当作死亡免疫。

## PK 状态字段与状态机

```yaml
pk_state:
  mode: peace|party|guild|faction|all
  name_state: white|yellow|red
  crime_value: integer
  justice_value: integer
  combat_lock_until_utc: timestamp
  protection_until_utc: timestamp
  last_attacker_ids: [role_id]
  last_victim_ids: [role_id]
  rules_version: 0.0.7
```

模式迁移：

```text
和平 ->(长按确认3秒)-> 全体 ->(进入战斗)-> 战斗锁定15秒 -> 和平
和平 -> 组队/行会/阵营 -> 只对规则允许目标生效
任意模式 -> 安全区 -> 强制和平
死亡 -> 复活保护3秒 -> 移动或施法 -> 保护结束
```

服务器每次模式变化写 `pk_mode_changed`，包含前后模式、原因、地图、输入序号和规则版本。客户端断线
重连读取服务器状态；本地显示的全体按钮不代表已经生效。

## 目标合法性判定

攻击请求按以下顺序检查：

1. 攻击者和目标是否存在于同一战斗实例和可攻击地图。
2. 攻击者模式是否允许该目标，目标是否处于复活/安全/切磋保护。
3. 是否触发队伍、行会、阵营和最近攻击者豁免。
4. 距离、角度、视线、技能目标过滤器是否通过。
5. 等级差保护、PvP系数和控制递减是否准备完成。
6. 写入攻击事件，再计算伤害、罪恶值和荣誉。

目标合法但伤害为0仍可能触发“主动攻击”记录；打到无敌目标、自己召唤物或安全区目标不增加罪恶值，
但连续发送无效攻击会进入反作弊审计。

## 罪恶值与名字状态计算

| 行为 | 罪恶值变化 | 荣誉变化 | 说明 |
|---|---:|---:|---|
| 主动击杀白名 | +100 | 0 | 受害者最近60秒主动攻击过则不加 |
| 主动击杀黄名 | +60 | 0 | 若对方先开全体，按白名规则 |
| 击杀红名 | 0 | +20 | 只在危险区和绝地有效 |
| 协助击杀白名 | +30 | 0 | 按有效伤害/控制参与比例 |
| 误伤队友 | 0 | 0 | 伤害被过滤，连续误触只提示 |
| 保护区攻击 | 0 | 0 | 事件记录但无伤害 |

罪恶值在危险区击杀怪物或参加活动时每5分钟下降一档，安全区挂机不下降。红名状态进入红名村，
主城仓库禁用但可访问角色信息、任务和不可交易的基础商店；不可用“付费洗白”直接清除罪恶值。
净化任务、正义活动和在线时间是唯一主要清除路径。

### 等级保护示例

攻击者60级、目标35级，差距25级：

- PvP伤害先乘0.65，再乘等级保护系数；
- 不获得荣誉，罪恶值按白名击杀加倍；
- 目标在复活后获得撤离加速，不增加反杀伤害；
- 低等级主动攻击高等级时，双方可正常战斗，但不能通过组队小号刷荣誉。

## 死亡掉落算法

### 判定顺序

```text
角色死亡
 -> 读取死亡时的 map_id、zone_type、name_state
 -> 读取背包可掉物和穿戴未绑定物
 -> 计算背包格数范围与穿戴触发概率
 -> 生成随机种子并抽取实例
 -> 锁定掉落物、创建地面实体和保护时间
 -> 写死亡结算流水
 -> 广播死亡摘要
```

同一死亡事件使用一个 `death_event_id` 和 `drop_seed`；重连、重复请求、客服查询都只能读取该结果。先
判定格数再抽实例，背包不足时将候选物按品质从低到高排序并把未能生成的物品保留在死亡邮件，不悄悄
改变抽样结果。

### 具体边界

- 背包掉落只从死亡瞬间处于可交易、未绑定、非任务锁定的物品中抽取。
- 穿戴掉落每次最多一件；触发后从所有未绑定穿戴物等概率抽取，不按价格和战力暗中偏置。
- 绑定装备、任务物品、付费外观、正在铸魂锁定的消耗品不掉落，但锁定普通可交易装备仍可掉落。
- 背包满不改变格数判定；无法生成的候选进入死亡邮件，邮件有7天领取期。
- 地面实体保护期结束后任何符合拾取规则的玩家均可拾取；死亡者本人不能通过立即复活绕过保护。

### 算法示例

红名进入绝地死亡，规则为背包3格、穿戴20%：

```text
可掉背包池 = [药水堆、蓝戒、黑铁、未绑定紫靴、普通材料]
抽取格数 = 3
穿戴试验 = random(0,1) < 0.20
若穿戴试验成功，从未绑定穿戴列表等概率抽1件
若死亡事件重放，必须使用同一个 drop_seed 得到同一结果
```

系统公告不公开具体掉落实例，只显示区域和品质范围；死亡者本人显示实例 ID 后六位、拾取者、地图、
规则版本和战斗记录 ID。

## 保险与复生

金币保险是有限风险缓冲：只抵消白名或黄名一格背包掉落，进入危险区前按本次有效期冻结金币；死亡后
若触发则返还该格物品的系统估值上限，不能返还实际市场价、穿戴装备或红名掉落。保险不影响掉落抽样，
也不影响击杀者看到的地面实体；系统返还和玩家拾取不能同时发生。

复生特性在死亡结算前判定，成功时不创建死亡掉落、不增加罪恶值，王城每场最多一次。原地复活3秒内
只能移动，主动施法立即取消保护；被推回安全区不产生额外复生次数。

## 反堵门与反骚扰

1. 复活点12米缓冲区禁止攻击，至少两条出口，碰撞体不能完全封锁。
2. 同一攻击者对同一低等级目标连续击杀超过阈值时，悬赏和荣誉不再增加，罪恶值仍按规则计算。
3. 被同一行会24小时内击杀达到阈值的玩家收到“撤离路线”和求援提示，不自动传送或强制免战。
4. 行会据点和王城复活点的器械伤害有目标上限，不能以无敌复活点刷击杀积分。
5. 举报成立后可以限制攻击者进入特定公共活动，但不静默删除已合法掉落物；资产回滚必须有流水证据。

## 仇敌与悬赏生命周期

```text
死亡 -> 加入仇敌(可选) -> 发布悬赏(冻结金币)
 -> 候选击杀事件 -> 规则过滤(切磋/竞技场/复活点/同设备)
 -> 首个有效击杀结算 -> 解冻或扣除金币 -> 记录7天
```

仇敌列表最多保存100人，显示最近出现地图和最后活跃时间，不显示实时坐标。悬赏金额在发布时冻结，
目标改名、转职和换行会不改变目标角色 ID。击杀者与目标长期设备、网络、支付关系进入风险图，命中
时先进入人工复核，不自动发放悬赏。

## PK 申诉与客服证据

玩家可在死亡页申请：掉落规则解释、拾取争议、异常伤害复核、悬赏未结算。客服读取：

- `death_event_id`、区域与名字状态快照；
- 伤害事件前后10秒、控制递减和复活保护；
- 掉落种子哈希、候选池、实际地面实体；
- 拾取请求序列和最终资产流水；
- 举报、悬赏和设备关联只返回“是否进入审核”，不返回阈值。

申诉不能直接改变罪恶值、复活次数或已合法交易的装备；发现规则执行错误时按同一规则补偿所有受影响
玩家，不能只给投诉者一件顶装。

公共字段追加 `pk_mode`、`name_state`、`crime_value_before/after`、`zone_type`、`death_event_id`、
`drop_count`、`equipment_drop_triggered`、`insurance_state`、`attacker_role_id`。

| 事件 | 关键字段 | 用途 |

| `pk_mode_changed` | 前后模式、确认时长 | 检查误触和切换摩擦 |

| `crime_resolved` | 击杀来源、增减值 | 罪恶值经济和反刷 |
| `death_resolved` | 死亡类型、规则版本 | 复盘玩家损失 |

| `pk_report_submitted` | 类别、证据 ID | 举报处理时效 |

## 发布门槛

1. K-001~K-010 自动化通过，100万次死亡抽样无重复、无绑定泄露、无锁定免疫。
2. 首次死亡后10分钟再出城率达到指标；若退出率超过25%，先调提示、路线和等级保护。
3. 任何死亡页显示的区域、名字状态、掉落格数和保险结果都能从流水重建。
4. 红名不能访问主城仓库但不能被永久困死；净化任务、红名村和基础交易必须可用。

本卷扩展版目标版本：`0.0.7-draft`。

## PK 场景设计卡

### 场景A：效率点偶遇

两队在危险地图同一刷怪点相遇。默认模式只允许攻击规则允许目标；切全体需长按3秒，攻击后15秒不能
切回和平。玩家可以争夺怪物、绕行或发起战斗。若一方死亡，死亡页显示区域掉落格数和可撤离路线；公共
任务将未完成击杀转换为助攻，不因为被击杀失去所有主线进度。

### 场景B：红名回城

红名角色不能使用主城仓库，但可回红名村修理、净化、领取邮件和访问基础商店。红名状态下降只在危险区
在线活动或净化任务中发生，安全区挂机不下降。红名玩家被击杀后，正义值和悬赏规则按合法击杀判定，不能
通过小号互杀刷洗白。

### 场景C：BOSS前厅混战

BOSS前厅沿用地图 PK 标签；个人贡献与 PK 击杀是两套分数。最后一击只公告、不决定个人包。玩家可以
打断敌对队伍、抢场地目标或绕行，满血治疗、无效承伤和无敌伤害不计贡献。BOSS死亡后锁定贡献表，再生成
地面包，避免战斗继续改变已经结算的奖励。

### 场景D：王城复活点

复活点12米为禁攻缓冲，至少两条出口；3秒移动保护中施法立即取消。王城击杀可以影响个人分，但同一目标
60秒内重复击杀递减，复活点对刷不能取代城门、能源塔和王座目标。低特效仍显示阵营、阶段和高危技能。

## PK 模式详细权限

| 模式 | 可攻击 | 不可攻击 | 进入方式 | 退出限制 |
|---|---|---|---|---|
| 和平 | 受攻击者反击 | 普通玩家 | 默认 | 战斗锁定15秒 |
| 组队 | 非队伍玩家 | 队友 | 组队后自动 | 离队后刷新 |
| 行会 | 非本会玩家 | 本会 | 行会模式 | 战斗锁定 |
| 阵营 | 敌对阵营 | 同阵营 | 活动/章节 | 活动结束 |
| 全体 | 合法 PvP目标 | 安全/保护目标 | 长按3秒确认 | 进入战斗15秒 |

模式判断不能由客户端颜色代替；服务端返回 `can_attack`、拒绝原因和下一次可切换时间。切换请求超时或
重复时只返回第一次结果，不叠加3秒准备和15秒锁定。

## 名字状态和罪恶值边界

罪恶值、正义值、红名持续和传送费使用独立字段，名字颜色只是展示。主动击杀白名+100，协助+30，击杀
红名正义+20；目标最近60秒主动攻击过自己时，白名击杀不增加罪恶值。系统按照击杀事件和目标状态快照
计算，不能因目标在死亡后改名改变结果。

红名村提供四类服务：修理、净化任务、绑定金币基础消费和邮件领取；不提供拍卖高价值取货绕过风险。红名
可通过净化声望、危险区在线和击杀指定魔物下降罪恶值，速度有每日上限，不能买通系统直接清零。

## 掉落候选池边界

### 背包候选排序

抽到格数后，从可掉池中使用服务器种子等概率抽取；候选物按实例而不是模板区分。不可掉物包括任务物品、
绑定装备、付费外观、当前任务保护物和客服冻结物。锁定普通可交易装备仍可掉落，死亡页明确这一差异。

### 背包满和邮件

死亡掉落生成时若地面空间不足，候选进入“死亡保管邮件”而非删除；邮件7天可领取，领取后物品保持原
绑定和死亡来源。击杀者看到的地面实体可能少于死亡者候选数，避免地图拥挤；双方都能看到实际流水摘要。

### 多人同死

同一服务器 tick 多名玩家死亡，各自使用独立 `death_event_id` 和 `drop_seed`；死亡事件排序只用于广播，
不能让先广播的玩家获得更低掉落。复活、保险、红名和穿戴判定按每个死亡快照独立完成。

## 保险、复生与风险提示矩阵

| 保护 | 覆盖 | 不覆盖 | 触发时机 | 失败原因 |
|---|---|---|---|---|
| 金币保险 | 白/黄名一格背包 | 红名、穿戴、实际市场价 | 死亡结算后 | 额度不足/状态不符 |
| 复生特性 | 一次死亡转复生 | 掉落、罪恶值、王城多次 | 死亡前 | 本场已用/被禁用 |
| 复活保护 | 3秒移动撤离 | 施法后、再次受击 | 原地复活 | 主动施法 |
| 地面保护 | 20/15秒归属 | 保护结束后的公共争夺 | 物品生成 | 事件过期 |

风险面板必须显示“当前快照时间”，如果服务器返回配置过期或资产服延迟，按钮显示只读和查询中，不使用
旧数值让玩家误入绝地。

## 反骚扰阈值的业务逻辑

同一攻击者对同一低等级目标24小时内重复击杀达到阈值时：

1. 后续击杀仍按死亡和罪恶值规则结算，但荣誉和悬赏不再增加；
2. 目标收到撤离路线、求援和黑名单提示，不强制传送；
3. 攻击者进入观察状态，风险图记录关联账号、地图和时间；
4. 若目标主动反击，不取消其自卫豁免，避免被动站着挨打；
5. 若系统误判，客服按事件链批量修复荣誉和悬赏，不直接发高阶装备。

阈值本身不下发客户端，不在公告中公开具体次数；玩家只看到“重复击杀奖励递减”的规则类别。

## PK 前中后流程检查

### 进入风险区前

客户端读取服务器快照并依次展示：地图和线路、推荐等级、名字状态、背包掉落格数、穿戴触发概率、保险
是否覆盖、复生是否可用、最近撤离点和队伍状态。玩家确认后才提交 `zone_enter_request`；请求过期或快照
超过5秒，按钮变为刷新。进入后记录 `risk_acknowledged`，死亡页可以引用这次确认而不是推测玩家是否知情。

### 战斗中

每次合法攻击记录攻击者、目标、模式、地图、等级保护、技能和规则版本；拒绝攻击也记录原因但不增加罪恶值。
模式切换、队伍/行会变化、进入复活保护和红名状态变化都即时广播给相关玩家。客户端显示的名字颜色、
通缉图标和声音必须由同一状态快照产生，不能出现红色名字但服务器仍为白名的窗口。

### 死亡后

死亡结算先锁定掉落和罪恶值，再发复活按钮、死亡摘要和拾取通知。复活按钮不能在掉落结算完成前使用；
若资产服延迟，显示“正在保护资产”，允许查看战斗但不允许再次进入交易、强化或分解。死亡页关闭后，
角色可从邮件、战斗记录和仇敌页再次打开同一 `death_event_id`。

## 自卫和助攻边界

玩家在最近60秒被某角色主动攻击，反击和协助反击不增加罪恶值，但仍受区域和模式合法性检查。系统按
攻击事件序列记录“先攻者”，不能因伤害被护盾吸收、控制未命中或目标瞬移而丢失先攻记录。助攻要求对目标
造成有效伤害、有效控制、净化敌方增益或承受目标关键技能之一；只在附近挂机不计助攻。

| 行为 | 自卫豁免 | 助攻计分 | 荣誉/罪恶 |
|---|---|---|---|
| 被攻击后击杀攻击者 | 是 | 是 | 不加罪恶 |
| 先手控制后队友击杀 | 否 | 是 | 先手者按罪恶 |
| 满血治疗队友 | 否 | 否 | 不计贡献 |
| 净化队友真实控制 | 否 | 是 | 不计罪恶 |
| 复活点攻击 | 无 | 无 | 记录并限制 |

## 装备掉落选择器伪代码

```text
resolve_death(victim, death_event):
  snapshot = freeze(victim, map, name_state, bind_state)
  bag_slots = roll(death_event.drop_seed, table(snapshot.zone, snapshot.name))
  bag_pool = eligible_inventory(snapshot, exclude=[bound, quest, support_hold, premium_cosmetic])
  bag_items = sample_without_replacement(bag_pool, bag_slots)
  if roll(death_event.drop_seed, "equipped") < equipment_probability(snapshot):
      equip_pool = eligible_equipped(snapshot, exclude=[bound, locked_by_service])
      equip_item = sample_without_replacement(equip_pool, 1)
  create_ground_or_mail(bag_items + equip_item, death_event)
  write_death_ledger(snapshot, bag_items, equip_item)
```

伪代码的 `locked_by_service` 只表示客服冻结或活动锁，不是玩家普通锁定；普通锁定装备仍在 `eligible_equipped`。
实现必须按实例 ID抽样，不能按模板数量抽完再复制实例。死亡事件重放时只读取已生成结果，不重新执行抽样。

## PK 争议案例

| 案例 | 事实 | 处理 |
|---|---|---|
| 玩家锁定紫靴后死亡 | 锁定仅防误操作 | 合法掉落，死亡页解释 |
| 白名被红名击杀 | 普通区/危险区规则 | 白名按区域掉落，红名罪恶增加 |
| 双方同帧死亡 | 两个独立死亡事件 | 各自独立抽样，广播顺序不影响 |
| 保险购买后立即切绝地 | 保险不覆盖绝地 | 进入前提示失效，不能退费绕过 |
| 复生触发后被再次击杀 | 同场已用复生 | 第二次正常死亡掉落 |
| 悬赏目标在王城复活点死亡 | 复活点刷分 | 不计悬赏，仍可合法战斗结算 |
| 关联小号拾取掉落 | 风险图命中 | 先限制高价值转移，人工复核 |
| 服务器重启后死亡邮件重复 | 同一 death_event | 幂等返回原邮件，不能重复领取 |

## PK 区域设计标准

普通区至少提供两条刷怪路线和一个可见回城点；危险区提供三条路线、一个 BOSS前厅和一个撤离捷径；
绝地提供两条撤离路线、较高收益和明确穿戴掉落风险。地图外框不应让玩家在无敌复活点附近被迫穿过单点
死亡门；高收益点与唯一出口距离至少留出一条可观察、可转身和可使用位移的空间。

## PK 规则公告模板

每次活动或地图公告采用固定顺序：

```text
区域：名称、推荐等级、线路
模式：可攻击目标、全体切换方式、复活保护
死亡：背包格数、穿戴概率、绑定/锁定差异
奖励：荣誉、悬赏、BOSS贡献是否独立
```

不使用“高风险高回报”作为唯一说明；必须给出精确概率或明确区间。规则变更时公告旧版本和新版本，

### 边界用例补充

1. 目标在攻击请求到达前进入安全区：请求拒绝，不能产生罪恶值；
2. 攻击者切换行会后仍在战斗锁定：15秒内保持原模式，不能以退会绕过；
3. 目标同帧触发复生和服务器重启：复生结果先写入死亡流水，重启只重放一次；
4. 死亡前装备刚被交易冻结：交易事务先锁定，死亡候选读取最终所有权，不能同时属于双方；
5. 保险在进入区域后余额不足：进入请求失败或显示未覆盖，不能死亡后负余额理赔；
6. 悬赏目标改名：按角色 ID继续追踪，昵称变化不改变悬赏；
7. 地面保护结束瞬间两人拾取：资产比较并交换只成功一个，另一人看到已拾取；
8. 红名在主城入口断线：危险区角色保留15秒，安全区入口仍按服务器位置，不能拔线免死；
9. 客服冻结装备期间死亡：冻结原因写入候选排除，普通玩家锁定不享受同样排除；
10. PK规则版本切换：已进入区域按入口快照，新进入读取新版本，死亡页显示实际版本。

所有边界用例都要有事件链、页面截图、流水 diff 和重连结果；只做“看起来掉了/没掉”的手工测试不算通过。

## PK 完成定义

玩家在出城前能读懂风险，战斗中能辨认合法目标、红名与保护，死亡后能看见损失、规则、拾取者和下一步；
服务器能从先攻、自卫、击杀、罪恶、死亡、掉落到悬赏完整回放；客服能在10分钟内用事件 ID解释；QA能在
断线、重启和并发条件下复现唯一结果。四项全部满足后，PK系统才可进入首发。

首发后每日抽查白、黄、红名死亡各100例，确认候选池、绑定、锁定、保险、穿戴上限和最终所有者；异常率
不为零时暂停对应高风险规则并建立事件范围，不以平均概率掩盖个案资产错误。

抽查报告由 PK、资产和 QA 共同签字并保存规则版本、随机种子和修复记录。

签字后纳入发布归档与下次回归基线。

## 争议事件裁定边界

网络延迟、低帧率或玩家未看提示本身不撤销合法死亡；只有服务器权威事件缺失、区域规则错误、保护状态误判、同件装备双所有者或系统不可用造成的异常才进入资产修复。裁定必须引用死亡前后事件、规则版本和最终所有者，客服无权仅凭截图复制装备。多人争抢掉落时以资产服务成功提交的首个拾取请求为准，失败者收到已被拾取的明确结果。

未成年人保护、封禁、维护和支付退款不改变既有死亡归属；需返还时走带审批的反向流水，并从错误持有者处冻结同一实例，不能克隆替代品制造双所有权。
