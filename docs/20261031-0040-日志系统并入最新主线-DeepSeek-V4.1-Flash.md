# 日志系统并入最新主线（0.8.15）

- 日期：2026-10-31
- 模型：DeepSeek-V4.1-Flash
- 版本：0.8.14 → 0.8.15
- 目标：把本地 0.8.6 承伤诊断 + 0.8.7 全项目结构化日志，合并进远端最新主线 0.8.14（响应式布局 / 精英系统 / 终局）。

## 背景：两条互不相关的历史

远端 `origin/main` 停在 **0.8.14**，但它的提交是浅克隆产生的 grafted 根提交（`3b2042e`），与本地日志分支的提交历史**没有共同祖先**。直接 merge 会把 0.8.14 的响应式、精英、终局等新功能全部回退，因此必须先选基线再定向移植。

决定：**以 0.8.14 为唯一代码基线**，只把诊断与日志能力叠加上去；本地旧分支保留为存档，不参与主线。

## 移植顺序

1. 从 `origin/main` 0.8.14 创建 `0.8.15-logging-on-main`。
2. cherry-pick `bdf90c1`（0.8.6 承伤归因：`diagnostics` / `recordDamage` / 探针字段）。
3. cherry-pick `f8bba1a`（0.8.7 结构化日志：`logger.js` / 埋点 / E2E 入口）。
4. 解决冲突，原则：**保留 0.8.14 新功能，叠加日志与诊断**。

先移植诊断再移植日志的原因：日志提交的 `main.js` 已经调用 `recordDamage("monster"/"hazard"/"poison")`，如果跳过 0.8.6，会留下一批未定义函数，游戏一进战斗就抛错。

## 保留的诊断能力

- `state.diagnostics`：伤害来源（怪 / 危险区 / 中毒）、危险区 spawned/detonated/hit/damage、死亡上下文最多 20 条。
- 探针输出 `sources=`、`hazardKinds=`、`deathCtx=`，用于回答「血是谁打掉的」。
- `logger.js`：debug/info/warn/error 四级、19 个类别、600 条环形缓冲、`logThrottled` / `logSample`、全局上下文、异常钩子、`__ONEKNIFE_LOG__` 与 `__ONEKNIFE_E2E__.logs/logsText`。
- `?log=debug` 详细日志 + 控制台镜像；`?e2e=1` 自动 debug 但不镜像，避免探针被 console I/O 拖慢。
- 探针失败时 dump 最近 120 条浏览器日志；启动即崩溃时提示页面没有 `__ONEKNIFE_LOG__`。

## 经验

- **跨历史合并先选基线，不要先 merge**：grafted 浅克隆的远端与本地是两棵独立树，`git merge` 会把「更新的一侧」当成冲突源，容易把新功能回退。正确顺序是：选最新线为基线 → 逐提交 cherry-pick → 按「保留新功能 + 叠加旧能力」解冲突。
- **cherry-pick 要看依赖顺序**：日志提交引用了上一个诊断提交的函数，单独 pick 会留下未定义符号；先 pick 依赖提交，冲突数量和运行风险都更小。
- **冲突解决后必须跑全量门禁**：`verify` 只能证明语法与纯函数，浏览器回归才能发现「模块能加载但主循环没跑」这类集成问题。
- 下载依赖与浏览器一律走镜像源：npm 用 `--registry=https://registry.npmmirror.com`，Chrome for Testing 用同一镜像路径；直连 Playwright CDN 在云电脑只有 50–150 KB/s。
