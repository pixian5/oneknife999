# 任务链状态机（2026-10-22 22:54）

> 记录时间：2026-10-22 22:54 · 版本：0.2.9
> 依据 [08-新手任务社交与UI.md](08-新手任务社交与UI.md)（任务卡状态机设计）与 [15-百图剧情与任务线.md](15-百图剧情与任务线.md)（每关剧情节点）在原型内落地最小可用版本。

## 目标与范围

原任务链 UI（0.2.5）只展示「当前章 10 个剧情节点是否完成」，无任务状态概念、无任务卡、无奖励可见性。本轮落地两级状态机（关级三态 + 章级进度），**不改变通关奖励发放行为**（仍在 checkMapCompletion 自动发放 60 金币 + 8 首领印记），全部为展示层与派生逻辑增量。

## 状态机定义

### 关级三态（runtime.js `questStatus(mapId)`，由 mapProgress 派生）

| 状态 | 条件 | UI 标记 |
| --- | --- | --- |
| `available` | 非当前关 且 未完成 | ○ |
| `active` | 当前关 且 未完成 | ◉（琥珀色高亮） |
| `completed` | 已通关（奖励自动发放，含 rewardClaimed） | ✓（青色） |

> 原型内任务自动接受（进图即 active），奖励通关自动发放，故 docs/08 的 `accepted` / `completed_pending_claim` / `claimed` 等中间态在纯前端原型中不产生独立 UI 状态；`completed` 已含 claimed。

### 章级进度（runtime.js `chapterStats(chapterIndex)`）

- 当前章 10 关完成数统计（标题右侧 `N/10 完成`）。
- `complete = done >= 10` 时任务链底部显示章末承接：`第 X+1 章已解锁`（或十章全完成的终态文案）。

## UI 变更（render.js `renderQuestChain` / game.css / index.html）

1. 任务链标题改为 `第X章 · 章名 · 任务链`，右侧进度 `N/10 完成`。
2. 节点列表上方新增**当前任务卡**（`.quest-current`）：当前关剧情节点标题、清怪/Boss 目标与状态、**通关奖励摘要**（60 金币 + 8 首领印记 + 领取状态）、**经验进度** `X/100（等级由通关数决定）`。
3. 节点三态标记：`✓ 001 · 异兆`（完成）/ `◉ 011 · 异兆`（当前）/ `○ 002 · 遗痕`（未到），悬停保留剧情摘要。
4. 章末承接文案 `.qc-chapter-done`。
5. `index.html` 给 `quest-chain-tip` 补 `id="questChainTip"`（原为纯 class，0.2.9 起用 setText 更新）。

## exp 双轨语义（顺带梳理，不改代码）

- **exp**（0-99，杀怪累积，nextExp 恒 100）= 单图内进度展示条，不是升级经验。
- **等级** = 由通关数驱动（campaignGrowth：1-10 关每关一级，之后递减）。
- 任务卡明确标注「经验 X/100（等级由通关数决定）」，消除双轨误解；任务奖励与 exp 无耦合。
