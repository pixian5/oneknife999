# 0.8.19 百图 e2e 断点续跑（P0-2）

## 背景

`e2e-100-shots.cjs` 内部已有"每 25 关重建 context（storageState）"的进程内分段（0.8.8），但**进程一旦被环境杀死（云沙箱被平台反复挂起），只能从第 1 关重来**——实测两次完整尝试分别死于 18/45 关，百图全流程从未一次性跑完。本轮补上跨进程断点续跑。

## 方案

`tests/e2e-100-shots.cjs` 新增 checkpoint 机制（环境变量开关，默认关闭、行为不变）：

- **写档**：每关"通关并确认进入下一图"后，把 `{mapIndex, storageState, stage, classId}` 写到 `ONEKNIFE_STATE_DIR`（默认 `/tmp/oneknife-e2e-state/journey-N.json`）。选这个时机是因为此刻存档 `currentMapId` 已确定指向下一关，恢复时的快照校验才有唯一期望值。
- **续跑**（`ONEKNIFE_RESUME=1`）：首个 context 直接带 `storageState` 创建；跳过选职业、首图预检（秘藏补给箱/场景节点/出口拦截）与三个存档预检（迁移/资产/损坏回退）；地图循环 `continue` 掉已完成关卡；恢复后立刻校验 `currentMapId === MAP_ORDER[startMapIndex]`，不符即抛错（防止拿错档续跑）。
- **清档**：通关（最终文案 + Lv.41 + 第 100 关校验全过）后删除 checkpoint。

## 使用

```bash
# 全新开跑（与原来完全一致）
ONEKNIFE_URL="http://127.0.0.1:8080/?e2e=1&fast=1" node tests/e2e-100-shots.cjs
# 进程被杀后，从最近 checkpoint 继续
ONEKNIFE_RESUME=1 ONEKNIFE_URL=... node tests/e2e-100-shots.cjs
```

## 验证

- `node --check` + prettier + `npm run verify`（200 单测）全绿。
- 机制实测：全新跑至第 4 关 kill 进程 → checkpoint 落盘 → `ONEKNIFE_RESUME=1` 重启打出 `RESUME stage 4/100` 并从第 4 关继续推进（详见轮次汇报）。

## 边界与说明

- `STAGE STATS` 汇总只含续跑段落的关卡（跳过段不补录）——断点续跑优先保证"走完"，统计完整性让位。
- checkpoint 里的 storageState 含游戏存档，只存在沙箱 `/tmp`，不进仓库。
- 并发跑（ONEKNIFE_RUNS>1）时各 run 用 `ONEKNIFE_RUN_INDEX` 区分 checkpoint 文件。

## 顺带修复：断言对齐 0.8.15 logger 语义

首次验证即暴露一个**合并遗留断裂**：0.8.15 把告警改走结构化 logger（e2e 模式不镜像 console.warn），而 `assertCorruptedSaveFallback` 还在等 `console.warn`，导致 e2e 在 0.8.15 合并后的树上从未能真正起步（此后无人重跑过百图 e2e，CI 也刻意不含它）。修复：断言改为优先读 `__ONEKNIFE_E2E__.logs()` 日志缓冲（匹配 `save:readFailed/readRejected`），无 logger 的旧时代回退 console.warn。

## 实现过程中顺带修掉的四个问题（含两个上游遗留）

1. **e2e 在 0.8.15 合并后从未能起步**（上游遗留）：`assertCorruptedSaveFallback` 等 `console.warn`，而 0.8.15 logger 在 e2e 模式不镜像 console。断言改为读 `__ONEKNIFE_E2E__.logs()` 日志缓冲（匹配 `readFailed/readRejected` 事件名），旧时代回退 console.warn。
2. **stage_005 必崩**（上游遗留）：0.8.14 响应式改造后换图瞬间画布短暂隐藏，`canvasGeometry` 的 `boundingBox()` 返回 null 直接 TypeError。加重试（最多约 2 秒虚拟时间等画布可见）。
3. **重复预检调用**（本人在本轮引入后又修正）：`if (!RESUME)` 块替换时残留两行旧调用，RESUME 模式下预检仍会跑。
4. **恢复起点差一关**：过图不立即落盘（内存已进下一图、localStorage 还在上一图），checkpoint 的 mapIndex hint 比实际快一关。恢复改为**以存档快照为准**：读 `currentMapId` 定位起点，落在「已通关未过图」的图上先按 T 过图再进循环。

## 机制实测记录

全新跑至第 6 关 kill 进程 → checkpoint 落盘 `mapIndex=6` → `ONEKNIFE_RESUME=1` 重启打出 `RESUME mode：跳过预检` + `RESUME at stage 7/100 (stage_007)` → 连过 7/8/9 关 checkpoint 推进到 9。杀→续循环验证通过。
