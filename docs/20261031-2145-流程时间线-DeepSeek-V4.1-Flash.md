# 0.8.8 流程时间线：用事件日志替代逐帧截图核对

## 一、为什么要改

真机测试阶段累积了 60+ 张截图，但截图有两个硬伤：

1. 执行测试的模型无法直接读图，视觉判断要靠额外的图像模型与像素统计，成本高且不稳定；
2. 截图只能证明「某个瞬间渲染正常」，无法回答「第 N 关到底缺了哪一环」——击杀、掉落、升级、存档、换图是否都发生过。

因此把游戏内事件日志升级为可断言的数据源：`log()` 同时写入内存环形缓冲，e2e 可直接拉取完整时间线。

## 二、实现

- `game/src/render.js`
  - 新增 `eventTrace`（上限 800 条）与 `traceEvents(limit)` / `clearTraceEvents()`
  - `log()` 追加 `{ t, type, text }`，`text` 剥离 `<b>` 等标签
  - 仅内存数组，不写 localStorage、不打 console、不增加 DOM 节点
- `game/src/main.js`
  - 仅在 `?e2e=1` 下暴露 `window.__ONEKNIFE_E2E__.timeline(limit)` 与 `clearTimeline()`
- `tests/ui-flow-timeline.cjs` + `npm run test:ui:timeline`
  - 真实键盘打通首关，读取时间线并断言关键事件齐全
- `tests/e2e-100-shots.cjs`
  - 每关 checkpoint 后读取时间线，输出 `kills / loot / deaths / saves`
  - 缺少保存事件、或击杀数少于「普通怪 + 1 首领」时打印 `WARN`
  - 每 25 关重建 context（保留 `storageState`），结束时打印 `STAGE STATS` 汇总

## 三、实测

首关（`?e2e=1&fast=1`，战士）：

```
FLOW TIMELINE {"total":54,"kills":9,"loot":15,"levelUp":2,"save":1}
  20243ms [loot] 首领击破：裂碑领主 倒下，个人获得 35 首领印记。
  20243ms [loot] 裂碑领主 掉落 散落金币袋，走近后自动拾取。
  20244ms [loot] 灰烬村外通关：60 金币、8 首领印记已发放。前往东侧出口进入雾松林。
  20244ms [loot] 灰烬村外通关进度已自动保存：刷新或任务中断后会从当前地图恢复。
FLOW TIMELINE PASSED
```

`kills=9` 恰为 8 只普通怪 + 1 只首领，说明事件口径可用于关卡级核对。

## 四、后续用法

- 百图分段跑完后，用 `STAGE STATS` 直接看每关：击杀数是否达标、有无存档、死亡出现在哪些关
- 出现 `WARN stage N 击杀事件不足` 时，说明该关少杀了怪或事件未记录，可单独复跑该关
- 截图保留为视觉证据（人工复核与视觉回归），流程判断全部以时间线为准
