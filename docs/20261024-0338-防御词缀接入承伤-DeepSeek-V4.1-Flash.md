# 0.3.7 防御词缀接入承伤（修复死代码）

## 问题

0.3.6 排查难度探针时发现：装备的「防御」词缀从 0.3.5 词缀重铸上线起就**从未生效**。

- `config.js` 的 `equipmentDefenseBonus(item)` 只累加 `affixes[].key === "defense"`，本身正确。
- `runtime.js` 的 `equipmentDefense()` 也正确汇总 12 个部位的防御词缀。
- 但两者**没有任何调用点**：`main.js` 的两处玩家承伤（怪物出手、首领危险区）都写 `defense: activeHero().defense`，只取职业基础防御。

后果：玩家在杂货商花金币重铸出「防御 +N」，HUD / 装备描述显示有，实际承伤一点不降。这是典型的「定义 → 汇总 → 传入结算」链路只接通前两段。

## 修复

1. `runtime.js` 新增 `playerDefense()`：

```js
// 玩家总防御（0.3.7）：职业基础防御 + 装备防御词缀。
export function playerDefense() {
  return activeHero().defense + equipmentDefense();
}
```

2. `main.js` 两处承伤改为 `defense: playerDefense()`
   - 怪物出手结算（`playerDamage` 内 `step.strike` 分支）
   - 首领危险区结算（同一函数的 `state.hazards` 循环）

统一走一个入口，避免以后新增承伤点再漏算装备。

3. `snapshot()` 的敌人条目补 `maxHp`
   实测探针日志出现 `hp=152/NaN`：`__ONEKNIFE_E2E__.snapshot()` 的实体映射此前只有 `hp`，没有 `maxHp`，任何按上限算百分比的脚本都会得到 `NaN`。补上该字段（不影响游戏逻辑）。

4. 单测 `tests/unit/equipment.test.mjs` 新增 `playerDefense` 用例：
   - 两个部位各带防御词缀 → 累加正确；
   - 未穿装备 → 退回职业基础防御，不出现 `undefined` / `NaN`；
   - 攻击 / 生命词缀不参与防御。

## 影响面（为什么必须重跑全量）

承伤降低会同时影响：

- **难度**：后期防御词缀越多，玩家越硬。第 15 关基线装备若重铸出防御，承伤明显下降。
- **百图 e2e**：`fast` 模式下玩家伤害 ×25，死亡数本来就不代表难度，但仍要确认流程不因承伤变化而卡关。
- **难度探针**：本轮基线装备 `affixes` 为空，所以理论上承伤不变；实测第 5 关 0 死 / 51s、第 15 关 1 死 / 138s（同配置前一次为 0 死 / 75s，探针操作节奏与 RNG 会带来波动，均远低于「死亡 ≤ 6」闸门）。
