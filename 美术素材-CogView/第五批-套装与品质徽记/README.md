# 第五批：六套套装徽记 + 六档品质纹章 12 张

生成日期：2026-11-23 14:56

模型：内置 `image_gen`（`seedream_5.5`），非 CogView-3-Flash。目录名延续 `美术素材-CogView/` 只表示同一套概念稿系列；本批运行环境没有注入 `ZHIPU_API_KEY`，因此改用豆包内置模型。

性质：概念稿，**未接入 `game/assets`**。全部为 JPEG、RGB、无透明通道，但本批没有右下角“AI生成”水印。

## 目标

第四批已把 12 个装备槽与 4 个物品做满，继续补单件装备会重复。本批改为补齐两个已有系统但尚无专属视觉的对象：

- 6 套套装：`game/src/endgame.js` 的 `SET_BONUSES`（边境、苍月、龙脉、冰封、烬火、帝陵）；
- 6 档品质：`docs/03-成长与装备.md` 的白、蓝、紫、橙、红、金。

套装用**不同外轮廓**拉开识别，品质用**同一套八芒星环 + 不同颜色宝石**表达“同一槽位、不同档位”。这比 12 张都做圆形徽章更利于 16–32px 下的区分。

## 实际尺寸质检

本批没有现成 UI 槽位，**64 / 32 / 16px 是按预期用途设定的参考，不是页面实测**。`实际尺寸对照.jpg` 按 1:1 贴图，不用放大图判断。

- 64px：12 张全部成立；01 盾形、03 竖椭圆、04 六边形、05 心形、06 八角形，外轮廓彼此不同。
- 32px：12 张都能读出主体；07 白晶与 09 紫晶补拍后明显改善。
- 16px：01 狼头、05 红心、07 白晶、09 紫晶、11 红石、12 金冠最稳；02 蓝月偏冷偏暗，03 青龙只剩绿色竖条，06 帝玺的紫纹与黑金边容易糊在一起，08 蓝宝石仍可辨。

结论：若接入，套装徽记建议不小于 32px；16px 只适合品质色点，不适合承载套装语义。

## 质量与限制

- 12 张最终图均为 1024×1024 JPEG，质量 92，243–317 KB；原图实际为 1536×1536，已统一缩放到系列口径。
- 没有“AI生成”水印；全部无 alpha 通道，不能直接当透明徽章。
- 模型会在“帝玺”印面生成抽象纹路，远看像篆刻，近看不是可读汉字；本批按装饰纹接受，没有把它当文字资产。
- 05 的“心形熔铁”语义直接，但在传奇装备语境里也可能被误读为生命/回血图标；若要接入套装栏，需配合“烬火”文字或套装色。
- 本批未做“边境内阁/苍月”等设计文档中的正式套装名映射，只对齐代码里的 6 个 `setKey`。

## 复现

本批由内置 `image_gen` 逐张生成，没有可用的 CogView 批量命令行。生成后统一执行：

```bash
python3 tools/art_emblem_preview.py
```

预览脚本只读取 12 个固定编号文件，生成总览和 64/32/16px 对照；不会改动原图。
