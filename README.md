# 《一刀999》

原创传奇类 MMORPG 的可玩浏览器原型 + 完整设计文档体系。

- **可玩原型**：十章 100 张连续关卡、三职业、首领阶段战、掉落装备、自动保存；纯前端 Canvas 实现，代码位于 [game/](game/)。
- **设计文档**：[docs/](docs/) 是设计事实源（产品、战斗、成长、地图、PK、行会、经济、服务器、QA、数值基线），治理规则见 [docs/README.md](docs/README.md)。
- **当前版本**：0.4.3（见 [VERSION](VERSION)）

## 快速开始

```bash
npm install
npm run serve      # 打开 http://127.0.0.1:4174
```

操作方式、关卡结构与验收命令见 [game/README.md](game/README.md)。

## 测试

```bash
npm run verify                # 语法检查 + 代码格式检查 + 纯函数单元测试（无需浏览器）
npm run test:ui               # 桌面 / 移动视口冒烟测试（含虚拟摇杆，需先 npm run serve）
npm run test:ui:regression    # 界面渲染与输入回归（需先 npm run serve）
npm run test:e2e              # 真实浏览器百图通关回归（需先 npm run serve）
npm run perf                  # 帧率探测，结果写入 .test-artifacts/（需先 npm run serve）
npm run balance               # 真实速度数值模拟（三职业百图，输出 tests/balance-out.csv）
```

持续集成：[ci.yml](.github/workflows/ci.yml) 在每次 push 运行校验；[e2e.yml](.github/workflows/e2e.yml) 手动或每周运行百图回归。

## 目录结构

```text
game/           可玩原型（index.html + src/ ES Modules + game.css）
tests/          浏览器回归（Playwright）与纯函数单元测试
docs/           设计文档事实源（00–20 分卷 + 历史备份 + 开发进度记录）
设计.md          设计总入口与阅读顺序
```

0.3.7 修复防御词缀死代码：0.3.5 上线词缀重铸后，「防御」词缀一直**完全不生效**——`config.js` 的 `equipmentDefenseBonus()` 与 `runtime.js` 的 `equipmentDefense()` 写得都对，但两处玩家承伤（怪物出手、首领危险区）写的是 `activeHero().defense`，只取职业基础防御，装备防御从未参与结算。本轮新增 `runtime.playerDefense()` = 职业基础防御 + 装备防御词缀，两处承伤统一改用它，以后新增承伤点也不会再漏算。同时 `snapshot()` 的敌人条目补 `maxHp`，修复难度探针日志 `hp=152/NaN`（按上限算百分比需要该字段）。单测新增 `playerDefense` 用例（词缀累加 / 空装备回退 / 攻击与生命词缀不参与），104 → 105。验证：105 个单测全绿、三视口冒烟 / 升级专项 / 渲染回归 PASS、perf 平均 5080.62 fps / p95 0.5ms / p99 0.8ms / 最差帧 4.8ms / 零长帧、难度探针战士第 5 关 0 死 / 51s、第 15 关 1 死 / 138s（探针有 RNG 波动，同配置前一次为 0 死 / 75s，均在闸门内）、战士百图 e2e **100/100（Lv.41、100 个检查点 SAVED+RESTORED、终局金币 229636、4 次死亡；fast 模式死亡数不代表真实难度）**。

0.3.8 完成角色面板三围展示：此前角色卡片只有一个综合「战力」，玩家在杂货商重铸出「防御 +15」后看不到承伤变低、生命词缀也只剩血条上限的细微差异，「变强」缺少可验证的反馈。本轮在头像 / 战力下方新增一行 **生命 / 攻击 / 防御**，三项全部与战斗结算同源：攻击 = `hero.attack + level×4 + 装备有效战力×0.9`（与 `computeDamage` 的 base 完全一致，不是简单相加）、生命 = `playerMaxHp()`（含部位基础与生命词缀）、防御 = `playerDefense()`（职业基础 + 防御词缀）。HUD 脏签名纳入三个新值，避免只改防御 / 生命词缀时战力不变导致面板不刷新。实测战士 Lv.1 裸装 368 / 37 / 22（战力 81），加一件 power 40、防御 +15、生命 +60、攻击 +10 的护甲后 488 / 82 / 37（战力 131），与公式完全吻合。验证：105 个单测全绿、三视口冒烟 / 升级专项 / 渲染回归 PASS、perf 平均 5475.25 fps / p95 0.5ms / p99 0.8ms / 最差帧 4.1ms / 零长帧、难度探针战士第 5 关 0 死 / 52s、第 15 关 5 死 / 251s（PASS，接近 6 死闸门；本轮只改 HUD，差异来自探针操作模型波动）、战士百图 e2e **100/100（Lv.41、100 个检查点 SAVED+RESTORED、终局金币 226695、1 次死亡；fast 模式死亡数不代表真实难度）**。

0.3.9 完成难度探针稳定性：0.3.6 的探针在同一套战斗数值下测出过第 15 关 0 死 / 75s、1 死 / 138s、5 死 / 251s，差异来自探针自身正反馈——玩家死亡会让首领**满血重置**，而喝药阈值 55% 偏低（往往到「下一次重击就死」的区间才喝），一次失误就把整场首领战拖长。本轮新增 `ONEKNIFE_PROBE_RUNS`（默认 3）：每关重复 3 次、每次新建 context + page，取死亡数与耗时**中位数**；判定改为中位数闸门（`deaths > 6` 才失败），单次超限只打印 `PROBE WARN`，耗时仍单次严格判定；喝药阈值 55% → 65%、检查频率每 4 循环 → 每 3 循环；`PROBE START` / `PROBE RESULT` 增加 `run=1/3`。实测三次均为 0 死：第 5 关 38s（50/38/38）、第 15 关 52s（52/53/36），说明 0.3.8 的 5 死 / 251s 是探针自放大而非关卡难度变化。验证：105 个单测全绿、三视口冒烟 / 升级专项 / 渲染回归 PASS、perf 平均 5631.24 fps / p95 0.4ms / p99 0.7ms / 最差帧 5.5ms / 零长帧、战士百图 e2e 100/100（Lv.41、0 次死亡、100 个检查点 SAVED+RESTORED、终局金币 227870；fast 模式死亡数不代表真实难度）。
