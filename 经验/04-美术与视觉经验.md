# 美术与视觉经验

> 从 docs 与开发过程提炼的 AI 生成素材 + 游戏 UI 接入经验（持续补充）。

## AI 生图素材接入游戏 UI

1. **小尺寸展示别用整张构图图**：带金龙/祥云环绕的 LOGO 整图缩到 38–200px 后，装饰元素喧宾夺主、文字不可读（OCR 都识别不出"一刀999"）。解法：用 PIL 裁出文字主体区（如 x 20%–80%）再接入，`object-fit: contain` + `object-position: left center` 控制。
2. **生成图通常带多余文字/水印**：seedream 会在 Logo 上方自作主张加 "LOGO" 英文字。生成后先放大核对 OCR，多余区域裁掉再进仓库（参考 `docs/20261025-0618-美术素材-豆包.md`）。
3. **无透明通道**：`image_gen` 出的是实底图（白/黑底），做透明立绘需另用抠图工具；卡片内用 `overflow:hidden` + 通栏裁边即可达到"贴图"效果。
4. **比例决定用法**：立绘用 3:4 竖版（`object-fit: cover; object-position: center 14%` 取上半身）、背景 16:9、Logo 宽幅 2:1+、饰条 4:1。生成时按用途定宽高，避免后期硬拉变形。
5. **体积控制**：4K 级 JPG（如 4096×1024 饰条 2.1MB）会胀大仓库；可先压缩到 <500KB 再提交。本轮 7.5MB 已入仓，后续瘦身。
6. **游戏内嵌图与文字名要一致**：首领立绘自带书法字"裂碑领主"，需与 `maps.js` / `config.js` 的 Boss 名核对一致；截图 OCR 可能误读（"裂碑"→"裂碎"），以源码为准。
7. **云电脑验证**：无 node_modules 时不下载 Playwright（流量），用系统 Chromium 无头截图验证 UI：`chromium --headless=new --screenshot=out.png --window-size=1440,900 URL`；注入存档用同源 `localStorage` 跳转页绕过选职业弹窗。
8. **云电脑 Playwright 三坑**（0.4.2 补齐）：
   - 环境变量 `PLAYWRIGHT_BROWSERS_PATH=/opt/vm/preinstall/ms-playwright` 无写权限 → 安装/运行都需覆盖为 `PLAYWRIGHT_BROWSERS_PATH=/home/user/.cache/ms-playwright`；
   - 云电脑只有系统 chromium 无 Google Chrome → 测试用 `ONEKNIFE_CHANNEL=chromium` + `npx playwright install chromium`（浏览器装用户目录）；
   - 注入页 `import` 用文件绝对路径会 404，必须用相对路径（`./src/runtime.js`）。
9. **图标生成后处理**：seedream 图标常带金框/白边/多余装饰（侧栏小图标、四角骷髅、随机文字），小尺寸显示前统一 `crop` 外圈 4% 并按需裁中央；带字图标（如"诅咒""追魂签"）在 20px 级不可读、不影响。
10. **小按钮图标位**：62×56px 技能按钮塞 23px 图标用 `padding-top: 30px` 给图标留位（绝对定位左上），文字 `justify-content: flex-end` 沉底，避免重叠。
11. **动态立绘文件名要与代码拼接规则完全一致**：`renderBoss` 用 `assets/boss-${boss.name}.jpg` 拼接，文件名（含中文）必须与 `boss.name` 逐字一致；旧资产名不符会触发 `onerror` 兜底，截图里只看到 alt 文本。解法：为旧资产补一份中文名副本，`onerror` 仅作真正缺失时的兜底。
12. **image_gen 短链下载偶发 RemoteDisconnected**：批量下载用 urllib + 4 次重试 + sleep 2s，重试后全部成功；不要把偶发断连误判为素材失败。
13. **批量同系列素材的命名规则先定再生成**：章节图 `chapter-NN.jpg`、Boss `boss-{名}.jpg`、装备 `equip-{key}.png` 在生成前先定，接入时零改写；左右对称部位（手镯/戒指）共用一张图，用映射函数收敛。
14. **弹层背景用 CSS 变量 + 渐变遮罩**：`background: linear-gradient(180deg, rgba(...)), var(--travel-bg) center/cover`——JS 只设变量不拼样式串，图片天然叠暗色渐变保证文字可读，主题切换零重排。
15. **headless 无法交互时用静态测试页验证弹层**：复制弹层 DOM + 内联设 CSS 变量即可验证背景渲染，测完删除；测试页 OCR 乱码是 headless 缺 CJK 字体，与正式游戏无关。
16. **AI 对「环形饰品」类别区分度有限**：双环绞丝手镯 prompt 会生成成戒指形态；手镯/戒指同为环形、小尺寸展示差异不明显，可先接受，追求区分度再单独重生成。
17. **UI 有美术 ≠ 战斗有美术**：立绘必须接到渲染循环的实体绘制层（drawPlayer / drawEntity），只放选人卡/情报条等静态界面，战斗画面仍是几何图形——用户会以为美术没做。
18. **战斗贴图用异步缓存 + 就绪回退**：`loadSprite`（Map 缓存 Image）+ `spriteReady(img)`（`complete && naturalWidth>0`）判断就绪，未就绪回退原几何绘制；游戏每帧重绘，加载完成自动切换，无回调无闪烁。
19. **怪物名以代码为准**：生成图复用 `maps.js` 的 `monsterTypes` 同名类型，16 张立绘即可全覆盖，不必做设计文档里的 40 怪（那只是世界观草案）。
20. **image_gen 批量批次不稳**：4 张/3 张批次出现 `Length mismatch`（content 比 request_list 少 1），2 张一批稳定；「腐败/尸体/腐烂」等词触发审核误拦截，换「岩甲重卫/菌肤/灵体」等中性描述通过。
21. **Boss 状态圈保留在贴图之上**：Boss 红圈 / phase 环 / 攻击前摇环是战斗信息，贴图分支后继续绘制；眼睛点这类「形象特征」只在无贴图时画，避免贴图上叠黑点。
22. **全身立绘比头像更有「人物感」**：48px 圆形头像在战斗中观感仍是圆圈；全身透明立绘（脚底锚定）配合动作动画才达到页游精灵效果。脚底锚点：贴图底部对齐实体 y + radius×0.5~0.9。
23. **PIL 四角种子抠图够用**：BFS 从四角扩散（邻接色差 34 + 种子色差 70 双阈值）对暗色渐变背景立绘效果好；主体与背景同色系（红犬+暗红底）需降到 edge_tol=20；Boss 立绘自带书法字会残留（小尺寸可接受）。
24. **classId 挂在 state 顶层**：本项目 `state.classId`（persist.js 同构），渲染层勿用 `state.player.classId`（undefined → 贴图 404 静默回退几何形，看起来「美术没生效」）。修复后 0.4.4 截图里「火焰特效头像」实为回退几何圆，需以像素级/元素级截图复核。
25. **canvas 元素非全屏**：游戏画布在页面 (25,149) 尺寸 1046×603，用页面坐标做 OCR 换算全错；验证战斗画面用 `locator('canvas').screenshot()` 拿元素本体，再按元素内坐标裁切。
26. **headless 截图用真实等待**：`--virtual-time-budget` 下异步图片可能未加载完就截图；Playwright `waitForTimeout(3000+)` 后再截，并监听 404 响应排查。
27. **程序化动作动画可行**：单张立绘 + Canvas 变换（浮动 sin、前倾 rotate、前扑 translate、受击高频抖动、攻击刀光弧）即可模拟多动作感，无需多帧精灵表（image_gen 多帧一致性差、工作量大）。
