# 美术与视觉经验

> 从 docs 与开发过程提炼的 AI 生成素材 + 游戏 UI 接入经验（持续补充）。

## AI 生图素材接入游戏 UI

1. **小尺寸展示别用整张构图图**：带金龙/祥云环绕的 LOGO 整图缩到 38–200px 后，装饰元素喧宾夺主、文字不可读（OCR 都识别不出"一刀999"）。解法：用 PIL 裁出文字主体区（如 x 20%–80%）再接入，`object-fit: contain` + `object-position: left center` 控制。
2. **生成图通常带多余文字/水印**：seedream 会在 Logo 上方自作主张加 "LOGO" 英文字。生成后先放大核对 OCR，多余区域裁掉再进仓库（参考 `docs/20261025-0618-美术素材-豆包.md`）。
3. **无透明通道**：`image_gen` 出的是实底图（白/黑底），做透明立绘需另用抠图工具；卡片内用 `overflow:hidden` + 通栏裁边即可达到"贴图"效果。
4. **比例决定用法**：立绘用 3:4 竖版（`object-fit: cover; object-position: center 14%` 取上半身）、背景 16:9、Logo 宽幅 2:1+、饰条 4:1。生成时按用途定宽高，避免后期硬拉变形。
5. **体积控制**：4K 级 JPG（如 4096×1024 饰条 2.1MB）会胀大仓库；可先压缩到 <500KB 再提交。本轮 7.5MB 已入仓，后续瘦身。
6. **游戏内嵌图与文字名要一致**：首领立绘自带书法字"裂碑领主"，需与 `maps.js` / `config.js` 的 Boss 名核对一致；截图 OCR 可能误读（"裂碑"→"裂碎"），以源码为准。
7. **云电脑验证**：无 node_modules 时不下载 Playwright（流量），用系统 Chromium 无头截图验证 UI：`chromium --headless=new --screenshot=out.png --window-size=1440,900 URL`；注入存档用同源 `localStorage` 跳转页绕过选职业弹窗。
8. **云电脑 Playwright 三坑**（0.4.2 补齐）：
   - 环境变量 `PLAYWRIGHT_BROWSERS_PATH=/opt/vm/preinstall/ms-playwright` 无写权限 → 安装/运行都需覆盖为 `PLAYWRIGHT_BROWSERS_PATH=/home/user/.cache/ms-playwright`；
   - 云电脑只有系统 chromium 无 Google Chrome → 测试用 `ONEKNIFE_CHANNEL=chromium` + `npx playwright install chromium`（浏览器装用户目录）；
   - 注入页 `import` 用文件绝对路径会 404，必须用相对路径（`./src/runtime.js`）。
9. **图标生成后处理**：seedream 图标常带金框/白边/多余装饰（侧栏小图标、四角骷髅、随机文字），小尺寸显示前统一 `crop` 外圈 4% 并按需裁中央；带字图标（如"诅咒""追魂签"）在 20px 级不可读、不影响。
10. **小按钮图标位**：62×56px 技能按钮塞 23px 图标用 `padding-top: 30px` 给图标留位（绝对定位左上），文字 `justify-content: flex-end` 沉底，避免重叠。
11. **动态立绘文件名要与代码拼接规则完全一致**：`renderBoss` 用 `assets/boss-${boss.name}.jpg` 拼接，文件名（含中文）必须与 `boss.name` 逐字一致；旧资产名不符会触发 `onerror` 兜底，截图里只看到 alt 文本。解法：为旧资产补一份中文名副本，`onerror` 仅作真正缺失时的兜底。
12. **image_gen 短链下载偶发 RemoteDisconnected**：批量下载用 urllib + 4 次重试 + sleep 2s，重试后全部成功；不要把偶发断连误判为素材失败。
13. **批量同系列素材的命名规则先定再生成**：章节图 `chapter-NN.jpg`、Boss `boss-{名}.jpg`、装备 `equip-{key}.png` 在生成前先定，接入时零改写；左右对称部位（手镯/戒指）共用一张图，用映射函数收敛。
14. **弹层背景用 CSS 变量 + 渐变遮罩**：`background: linear-gradient(180deg, rgba(...)), var(--travel-bg) center/cover`——JS 只设变量不拼样式串，图片天然叠暗色渐变保证文字可读，主题切换零重排。
15. **headless 无法交互时用静态测试页验证弹层**：复制弹层 DOM + 内联设 CSS 变量即可验证背景渲染，测完删除；测试页 OCR 乱码是 headless 缺 CJK 字体，与正式游戏无关。
16. **AI 对「环形饰品」类别区分度有限**：双环绞丝手镯 prompt 会生成成戒指形态；手镯/戒指同为环形、小尺寸展示差异不明显，可先接受，追求区分度再单独重生成。
17. **UI 有美术 ≠ 战斗有美术**：立绘必须接到渲染循环的实体绘制层（drawPlayer / drawEntity），只放选人卡/情报条等静态界面，战斗画面仍是几何图形——用户会以为美术没做。
18. **战斗贴图用异步缓存 + 就绪回退**：`loadSprite`（Map 缓存 Image）+ `spriteReady(img)`（`complete && naturalWidth>0`）判断就绪，未就绪回退原几何绘制；游戏每帧重绘，加载完成自动切换，无回调无闪烁。
19. **怪物名以代码为准**：生成图复用 `maps.js` 的 `monsterTypes` 同名类型，16 张立绘即可全覆盖，不必做设计文档里的 40 怪（那只是世界观草案）。
20. **image_gen 批量批次不稳**：4 张/3 张批次出现 `Length mismatch`（content 比 request_list 少 1），2 张一批稳定；「腐败/尸体/腐烂」等词触发审核误拦截，换「岩甲重卫/菌肤/灵体」等中性描述通过。
21. **Boss 状态圈保留在贴图之上**：Boss 红圈 / phase 环 / 攻击前摇环是战斗信息，贴图分支后继续绘制；眼睛点这类「形象特征」只在无贴图时画，避免贴图上叠黑点。
22. **全身立绘比头像更有「人物感」**：48px 圆形头像在战斗中观感仍是圆圈；全身透明立绘（脚底锚定）配合动作动画才达到页游精灵效果。脚底锚点：贴图底部对齐实体 y + radius×0.5~0.9。
23. **【已证伪】PIL 背景色差抠图不可用于暗色系立绘**：BFS 四角种子（邻接色差 34 + 种子色差 70）对与背景同色调的怪物（暗绿僵尸/暗灰侦察者/红犬暗红底）会沿渐变穿透主体内部（**空心**）或整图吞主体（主体占比掉到 1.5%–6%）；种子色差放大、梯度墙（Sobel>110）变体均失败——AI 生成立绘的背景含岩石/烟雾纹理，非均匀渐变。**唯一稳定路径是显著性检测**：`pip install rembg onnxruntime` + u2net 模型（176MB，约 7s/张 CPU），主体占比提升到 49%–86%，绿底合成全部实心完整。bria-rmbg 2.0（1GB）更大更重，且沙箱/环境重置会丢已下载模型，u2net 足够。**
24. **classId 挂在 state 顶层**：本项目 `state.classId`（persist.js 同构），渲染层勿用 `state.player.classId`（undefined → 贴图 404 静默回退几何形，看起来「美术没生效」）。修复后 0.4.4 截图里「火焰特效头像」实为回退几何圆，需以像素级/元素级截图复核。
25. **canvas 元素非全屏**：游戏画布在页面 (25,149) 尺寸 1046×603，用页面坐标做 OCR 换算全错；验证战斗画面用 `locator('canvas').screenshot()` 拿元素本体，再按元素内坐标裁切。
26. **headless 截图用真实等待**：`--virtual-time-budget` 下异步图片可能未加载完就截图；Playwright `waitForTimeout(3000+)` 后再截，并监听 404 响应排查。
27. **程序化动作动画可行**：单张立绘 + Canvas 变换（浮动 sin、前倾 rotate、前扑 translate、受击高频抖动、攻击刀光弧）即可模拟多动作感，无需多帧精灵表（image_gen 多帧一致性差、工作量大）。
28. **静态离屏缓存要感知异步资源**：背景层等静态绘制缓存（groundLayer）若包含异步图片，缓存键必须带就绪态（bgReady），图片加载完成自动重建，否则永远画无背景版本。
29. **氛围图 cover 铺底 + 压暗遮罩**：16:9 氛围图铺任意矩形地图用 `max(mw/iw, mh/ih)` 等比居中裁切；统一压暗 0.6-0.7 让道路/网格/名牌等信息层优先，纯色背景回退保底。
30. **复用既有特效系统**：Boss 换阶段震屏只需赋值 `fx.shake/shakePower`（render 层已做 translate 抖动）+ `spark` 炸点，不新增机制，改动最小。
31. **血条/名牌锚定「脚底 - 贴图高 - 间距」**：贴图脚底 = 实体 y + radius×系数（怪物 0.55 / Boss 0.9 / 玩家 24px）；血条 top = 脚底 - 贴图高 - 间距，名牌与血条整体悬在头顶，绝不压身体。新增实体（骨卫、友军）沿用同一公式。
32. **立绘抠完必须绿底抽查主体占比**：抠图是否正确以「绿底合成 + 主体像素占比」为准（实心怪 49%–86%）；只看文件存在/透明无意义——色差算法可能把主体整个抠没。
33. **UI 小尺寸图标后处理用「亮度裁边 + 方形适配」**：128px 以下图标先按亮度阈值裁掉黑色边角（缩略图黑底很常见），再按短边方形适配中心；比按固定 px 裁切稳。
34. **image_gen 生成 UI 图标最稳 2 张/批**：3-4 张/批出现 Length mismatch 与审核拦截概率升高；「腐败/尸体」等词会触发拦截，描述里避开（本批用「火焰/矿石/卷轴」等效表达）。
35. **顶栏按钮生成易带装饰行**：btn-skill/settings 首次生成带「一排小功能图标」顶部装饰条，PIL `crop_center(0.62)` 裁中央 62% 去装饰条，保留圆徽章主体。
36. **特效黑底用亮度抠图转透明**：fx 类贴图 AI 常给黑底（渲染方便），PIL 按 RGB 三通道和 < 95 置透明 + SMOOTH_MORE 羽化；全发光光柱类（fx-beam）主体占比 100% 属正常，透明化不丢内容。
37. **特效贴图接入走「贴图优先 + 程序回退」**：`loadSprite` + `spriteReady` 判空，贴图就绪画贴图，否则画原程序化图形——首帧不空白，加载后自动升级，零风险。
38. **文字字形 UI 是最后缺口**：审计「还有哪里没美术」直接 grep 代码里 `glyph`、`setText`、`<i class=`、`fillRect/fillText` 程序化绘制，一一对应替换为贴图；玩家头像这类「图已生成但没接入」最容易被漏掉。
39. **只用豆包模型做素材**：用户明确要求生成美术不用第三方模型——image_gen(seedream_5.0_flash) 生成 + 纯 PIL 算法处理（亮度抠图/缩放），全程不下载 rembg/u2net 等开源模型；暗色怪黑底分离用阈值 45（95 会切穿黑壳/黑羽暗部），绿底合成目检 + 主体占比双保险。
40. **云电脑内存 3.9G 限制大规模推理**：onnxruntime 载 176MB u2net 模型推理 2048 输入会 OOM（exit 137）；限制输入 1024 + 单线程 + 关内存模板才可跑（该方案已被"纯 PIL 无模型"取代，仅记坑）。
41. **舒展造型占比天然偏低**：展翅/烟雾/触须类怪物抠图后主体占比低（如 20.7%）属固有形态，先绿底目检确认主体完整，再如实记录，别当质量问题重做。
42. **占比 <30% 的护栏**：亮度抠图不达标（暗甲/细肢被阈值切除）就保留带背景全图（黑底 1024²）落 `monster-{名}.png`，宁留全图不强行透明，清单标注「未透明化」待后续处理。
43. **批量素材库命名与规格先行**：大规模预生成前先定死命名表（10 章 × 10 种、map-cXX-XX）、目标尺寸（160²/1600×900）、风格基线（暗黑厚涂+暖金暗红+发光眼），子代理才可并行且产物可直接入库。
44. **manifest 是素材库交付物**：150 张批量生成最后落一份含文件名/章节/短链/尺寸/占比/状态的 manifest（存 docs 与 .creative-design），接入游戏时按清单映射即可。

45. **Instabox 云沙箱 SDK 连接与坑**：`require('@insforge/instabox-sdk')` 的 `Sandbox.connect(沙箱id,{apiKey})`，跑命令用 `sb.commands.run(cmd,{timeoutMs})`（返回 exitCode/stdout/stderr），写文件用 `sb.files.write(path,str)`；**Shell 每次重置**——cd/环境变量不跨调用保留，一律绝对路径、把 `cd /data/home/oneknife999 && ...` 串在同一条里；PIL/numpy 需提前 `pip --user --break-system-packages` 装好，沙箱打印的 workspace 提示无害可忽略。
46. **纯 PIL 多动作帧流程=亮度阈值+SMOOTH_MORE 羽化+contain 居中**：黑底厚涂立绘分离无需第三方模型——numpy 算 RGB 三通道和 <45 → alpha=0（背景），再 `ImageFilter.SMOOTH_MORE` 羽化 alpha 一次后把 alpha<8 置 0（别把主体羽没）；按内容 bbox 裁紧，contain 等比缩放进目标盒后居中贴透明画布（玩家 160×200、怪物 160×160）。本轮 28 张占比 33.6%–69.3% 全部达标，宽幅 attack/cast 动作也能完整容纳不切主体。
47. **暗色细肢造型占比天然偏低要留护栏**：余烬傀儡/机关傀儡/烬心猎手一类暗色、细长肢体造型，亮度阈值 45 下细肢暗甲被切，主体占比 22%–25% 天然低于 30%——先绿底目检确认主体是否完整，再如实保留黑底全图兜底（去 -full 命名、1024²），别当质量问题反复重抠；后续换局部亮度归一/分区阈值或人工重生成。
48. **同物种多动作帧用「idle 基准 + image_edit 变体」两段式**：先 `image_gen` 出 1 张 idle 基准，再以 idle 返回短链作为 `image_edit` 的 `image_reference_url_list` 参考图生成 walk/attack/hit，prompt 强调「保持完全相同的物种外观、只改姿态」——跨帧外观一致性远好于逐帧独立生成；变体按 2 张/批合并调用，减少调用次数与限流风险。
49. **多动作帧命名规范**：`monster-full-{中文名}-{action}.png`，action 用小写 `idle/walk/attack/hit` 后缀，与无动作后缀的旧素材（`monster-full-{名}.png`）并存不冲突；每物种 4 帧一份清单，接入时按后缀映射动画状态机即可。
50. **200 张批量分片经验**：50 物种 × 4 帧拆 4 个并行执行者各 12 种，每片内部串行（idle → walk/attack/hit 有参考图依赖），跨片互不依赖；统一 prompt 模板 + 统一处理脚本（亮度抠图阈值 45 + SMOOTH_MORE 羽化 + 160×160 居中缩放）+ 统一命名与「绿底占比 ≥30%」护栏，最后服务器端全量校验 200 文件，合并零冲突。

## 背景纯净度决定抠图成败（0.8.28 实测）

- **症状**：`cutout.py` 报「所有阈值档背景都未清干净」。根因是生成图背景里有地面阴影 / 火星 / 水花 / 雾气，泛洪要么顺着缝隙钻进主体（抠成空心骨架），要么 bbox 退化成整幅（>92% 判废）。
- **解法**：prompt 必须写死「背景为均匀纯黑**无任何粒子与地面**」；参考图优先用**同角色已成功落地的帧**，不要用原始带雾图。
- **反直觉点**：描述攻击特效（火焰暴涨、水花四溅、碎石飞散）会直接毁掉背景纯净度，宁可只描述姿态。
- **仍未解决**：近纯黑铠甲本体（幽冥鬼将、黑岩魔像）在低阈值下仍可能被穿透成空心。修的方向应是**生成时把主体打亮**，不是继续调抠图阈值（阈值调高会吃空暗部，用户明确反感空心）。

## 0.8.x 增补（2026-11，GLM 补记）

- **素材批次接入的映射表模式**（0.8.26-0.8.29）：技能特效/节点贴图/地标全收敛到 `assets.js` 的映射表（SKILL_FX/TACTICAL_PROP/LANDMARK_PROP），新批次只加映射行；渲染层三级回退（动作帧→静态立绘→几何）保证缺图不影响可玩。
- **生成图怪名带章前缀**（0.8.5 教训）：代码拼 `monster-full-${name}` 时素材库无前缀，5-100 关动作帧全 404——`assets.js` 的 resolve 层负责剥前缀+别名映射。
- **治疗/召唤分支不走 resolveDamage**（0.8.30）：给多分支技能施放加统一视觉时，枚举所有提前 return 的分支，漏挂=特效永远放不出来（单测全绿也发现不了，靠实机截图）。
- **四角 alpha 检查透明化**：`PIL` 读 (0,0)/(w,0)/(0,h)/(w,h) 四角均值 <30 判透明合格——视觉发黑≠黑底（火球特效四角真透明）。

## 落地环境与产物校验（0.8.40）

- **沙箱冷却不该堵死落地**：instabox 免费档会因久无活动进入 `machine_cooldown`（可数天），期间无法写文件、跑脚本。但豆包 CDN 短链在任意能联网的容器都能下载，落地脚本本身也是纯 Python+Pillow——**落地一律在本容器做**，沙箱只当生成中继；反复 `Sandbox.connect` 重试没有意义。
- **短链是会过期的中转品**：`aka.doubaocdn.com/s/xxx` 302 跳到字节 CDN 的带签名地址（含 `x-expires`）。生成后必须当轮消费落地，否则整批 404；参考图过期就回 `refs-in/` 黑底 JPG 重新上传。
- **普通怪动作帧必须有 idle 副本**：`resolveMonsterSpriteName` 对白名单物种恒拼 `monster-full-${name}-${action}.png`（idle 也不例外），而**普通怪分支没有「动作帧→静态单帧」回退**（该回退只在 Boss/精英分支）。加入 `ACTION_MONSTERS` 前必须把 `monster-full-{名}.png` 复制成 `-idle.png`，否则静止状态直接 404 退成几何图形。
- **缺一帧就不要进白名单**：动作帧是状态机整体切换，只有 walk 没有 hit 会让受击瞬间掉回几何图形；凑齐 walk/attack/hit + idle 再追加。
- **落地脚本单批别超 25 张**：本地实测约 12s/张，52 张一批会在 280s 处被超时截断（已写文件不回滚）。分批 10–20 张，或后台跑 + 按「清单里哪些文件已存在」补齐。
- **产物校验用数值不用眼**：160×160、`RGBA`、alpha 不透明像素 > 200、半透明占比 < 25%——三条同时满足才算没空心、没漏抠。
- **双远端可能不对称**：GitCode 侧可能比 GitHub 多若干提交，开工前先 `git fetch` 两个远端比对 `HEAD..远端/main`，在**较新的那个**基线上落地改动，否则推送必被拒；版本号也要按对方已占用的号顺延。

## 贴图内存（0.8.41）

- **大图素材必须按显示尺寸降采样后再缓存**：2048×2048 动作帧单张解码 16MB，一关 4 怪 × 4 帧 ≈ 256MB；永久缓存必 OOM，4GB 机器 4–5 关就崩。缓存前按用途给最大边（UI 128 / 战斗 256 / 首领 512 / 章节 1280 / 底图 2048），原 Image 用完即弃。
- **贴图缓存要有字节预算与 LRU**：只按条数限不住（尺寸差异极大），按 `字节` 计预算 + 命中移到队尾、超预算清队首，canvas 淘汰时 `width/height=0` 才真释放。
- **`img.src=""` 会再触发一次 `onerror`**：加载结算要用 `finished` 标记保证只减一次 `inFlight`，清空前先解绑回调，计数用 `Math.max(0, …)` 兜底。
- **`performance.memory` 不可信/不可用**：页面里常是 undefined 或量化值，堆要看 CDP `Performance.getMetrics.JSHeapUsedSize`，进程内存要看 `/proc/<pid>/status` 的 VmRSS。
- **排查顺序**：先证伪 JS 堆泄漏（连跑两关堆应持平），再查渲染层缓存与素材解码，最后才怀疑环境内存。

## CogView 技能图标第三批：23px 才是验收尺寸（0.8.62）
- **先定缩放尺寸再定画风**：技能栏图标桌面只有 23×23px、移动端 19×19px。原图 1024 看着精细，缩下去只剩剪影；必须“单主体、粗轮廓、2–3 色、避免细碎纹理”，复杂盔甲纹和背景会糊成噪点。
- **做 1:1 按钮预览，不要只做原图总览**：把图标按 23/19px 贴进 44/38px 的深色金边按钮，才能看出真实可读性；92px 只作 4× 放大参考，不算验收尺寸。
- **提示词要防“加戏”**：写“雷矛术”容易生成施法者 + 方形画框；开头强写“画面只有一个物体，绝不能出现人形、人脸、身体、手、法师、法阵、边框、方形画框、牌匾”后，才得到干净单体雷矛。否定词要放在开头并具体到物件，不要只写“不要人物”。
- **“环”字不能稳定约束结构**：同一个“烈焰震环”分别得到火柱、金属火环、爆发火球。想和已有火环图标区分，宁可接受“爆发球”这种视觉近似，也不要让两个技能图标都变成同心圆。
- **方形图的“全身”仍会给半身**：1024×1024 写远景全身，人物容易只到腰；1344×768 宽景能稳定拿到全身，但脸会缩小或被头盔替代。要脸和全身同时成立，靠单图提示基本做不到，需拆图或后期合成。
- **模型不会执行所有装备细节**：连续两次写“左手塔盾”，结果都没有塔盾。文件名必须按实际画面命名（如 `04e-...-暗黑全身长戟`），不能按提示词命名，否则后续接入会误判。
- **批量脚本的跳过也会占间隔**：`cogview_batch.py` 遇到已存在文件会跳过，但仍等 30 秒；给已完成的批次追加 1–2 张时，另建临时 manifest，别重跑整批。
- **水印在小尺寸会消失，不等于授权干净**：23px 下“AI生成”几乎看不见，但原图仍有水印、JPEG 无 alpha；未签免责声明前只能当概念稿，不能直接进游戏资产。

## CogView 装备图标第四批：46px 才是装备格验收尺寸（0.8.63）
- **不同 UI 位置有不同验收尺寸**：技能图标是 23/19px，装备格是 **46/29px**，背包格约 46/29px；不要拿技能图标的 23px 口径验收装备图。尺寸必须从真实页面测量，本批在 1440×900、1920×993、390×844 三个视口确认。
- **同屏同类物品必须靠剪影区分**：07 紫晶戒与 08 右戒首轮都生成“紫晶 + 金边”，46px 下几乎撞脸。解决办法不是继续堆“黑曜石”提示，而是**把宝石整个删掉**，改成纯黑狼首印记戒；颜色和形状同时变，才拉开。
- **模型对“宝石”有强先验，否定词压不住**：明写“黑曜石、不要紫色”，仍连续生成紫晶。遇到这种强先验，改需求结构（无宝石、浮雕戒面）比加否定词有效。
- **“玉佩 + 无链”会被做成桌面摆件**：12b 生成了带底座的玉镜和散落紫珠。必须写“红绳悬空、无底座、无支架、无桌面、无散珠”，才能得到可佩戴的 12c。
- **“矿石 + 块”会生成方块**：14 首轮是青色发光立方体，像科幻箱。改“粗糙不规则碎块、绝非方块/立方体/箱子”后才得到 14b；但“银色矿脉”仍被替换成暗红余烬，模型不会完全执行材质细节。
- **“卷轴”容易触发卡通描边**：15c 仍是白边、亮黄纸、扁平风；强写“写实厚涂、PBR、不要描边、不要白边”后才得到 15d。纸色仍偏亮黄，说明颜色约束也不稳定。
- **道具提示里的“锁链/小锁”连续两轮不执行**：05 最终只是厚护腕。文件名要按实际画面命名（“锁腕”可以，但不能写“带锁”），后续接入不能按提示词想象。
- **补拍要按批次另建 manifest**：`cogview_batch.py` 遇到已存在文件会跳过，但仍等 30 秒；给 16 张整批追加 5 张补拍，另建 `manifest-补拍B/C/D.json` 最省时间。补拍轮次也要写进 README 与最终选用映射，避免后来者把弃用件当成品。

## 套装/品质徽记第五批：先定“形状语义”，再定画风（0.8.72）
- **套装靠轮廓，品质靠同框换色**：6 套套装必须用盾、圆、竖椭圆、六边形、心形、八角等不同外轮廓，否则缩到 32px 都像同一枚圆章；6 档品质反过来要共用同一套八芒星环，只换宝石颜色与切面，玩家才会把它读成“同一槽位的不同档位”，而不是 6 个不同道具。

- **内置 `image_gen` 请求 1024 仍可能返回 1536**：本批传 `width/height=1024`，实际全部 1536×1536；落库前必须统一 resize 到系列口径，不能只改扩展名。
- **`image_gen` 与 CogView 的授权状态不同**：本批无右下角水印，但仍是 RGB JPEG、无 alpha；不能因为“没水印”就当作可直接上线的透明图标。
- **模型会把篆刻做成伪文字**：06 帝玺印面生成抽象纹路，远看像字、近看不可读；验收时要按装饰纹接受并在文档写明，不能偷偷当文字资产。
- **环境缺 `ZHIPU_API_KEY` 时要如实切换模型**：`cogview_batch.py` 会拒绝运行；继续落在 `美术素材-CogView/` 只是在延续系列目录，不代表模型没变。文档、README、生成清单三处都要写明实际模型，避免复现命令失效。

## CogView 水印：不能只裁右下角，也不能一律 inpaint（0.8.73）
- **免费账号的 `watermark_enabled:false` 不等于无水印**：实测仍会输出“AI生成”文字，只是从深色胶囊变成灰色字。必须下载后处理，并在交付前放大右下角核对。
- **整边裁切会切掉主体**：1024 图标里武器尖端就在左下，1440 场景里石地铺满底部；统一裁掉 10%~20% 右边/底边会直接损失画面。正确做法是只处理水印外接小矩形。
- **平滑背景用边缘插值，不要 inpaint**：黑底/渐变图标用 Telea 修补会留下灰色雾块或深色矩形边框；取框外 22px 的四边像素做距离加权插值，才能无缝。
- **复杂背景只能 inpaint，并接受轻微软化**：披风、石地、烟雾这类纹理用 Telea 修补不会留水印，但会软化一小块；要彻底干净，优先在智谱后台签署“去水印管理”免责声明，或在提示词里让重要纹理避开右下角。
- **检测框要把胶囊阴影算进去**：只框文字会留下 1px 深色横线；需要外扩左侧 18px、右侧 24px、上方 10px、下方 14px，并把四边阴影一起盖住。
- **Key 只放仓库外**：`~/.config/oneknife999/zhipu.env` 权限 600，`.gitignore` 不覆盖用户目录；任何日志、清单、文档都不能打印 Key。

## 状态图标第六批：语义符号优先于“好看”（0.8.74）
- **状态图标先定“玩家一眼认什么”，再定材质**：中毒用毒液骷髅、破甲用裂盾、流血用滴血匕首，都是靠符号本身；圆形暗铁底座只负责统一系列，不能反过来让所有图标都变成“圆章 + 小图案”。
- **“致盲”不能露瞳孔**：首轮给了睁眼红瞳，完全没有盲语义；横向布带仍露瞳孔；最终用黑色皮革眼罩 + 闭眼红缝，才不误导。状态图标里“闭眼/遮目”比“眼睛 + 特效”更可靠。
- **“纯黑背景”不是强约束**：CogView 仍会在 04 生成木板铁栅、11 生成红底砖墙；提示词开头必须写“背景严格为完全纯黑色，除圆形徽章外没有任何墙面、木板、铁栅栏、光晕、场景元素”，交付前按 64px 与 16px 两级检查。
- **状态图标的验收尺寸比技能图标宽**：HUD 状态条建议 32px 设计、24px 保底；16px 只适合极简符号。本批 03/04/11 在 16px 明显偏弱，不能拿 1024 原图判断可用。
- **同类形状要靠颜色/配件双保险**：02 减速与 12 疾行都是靴子，靠冰蓝/银蓝 + 锁链/羽翼区分；05 破甲与 07 流血都偏红，靠盾/匕首区分。只靠颜色，色弱玩家会混。
- **补拍按“语义失败”而不是“画得丑”触发**：03 是语义偏弱、04 是语义错误、11 是背景污染；三类问题都值得重拍。不要因为“不够华丽”重拍，那会无限消耗 30 秒间隔。
- **预览脚本按固定编号取文件**：状态图标文件名带中文与序号，`glob` 顺序不可靠；`art_status_preview.py` 用 `ITEMS` 常量逐个匹配 `01-*.jpg`，数量不等于 1 直接报错，避免拿错补拍件做总览。

## 状态图标接入 HUD：先分清“谁的 debuff”（0.8.75）
- **玩家状态条只放玩家自身状态**：中毒、减速、眩晕、致盲属于玩家；破甲属于当前目标，必须放目标栏。混在一起会让玩家误读为“我被破甲了”。
- **不要拿普攻冷却 `attackTimer` 判断眩晕**：它同时承担正常出手冷却，每次普攻都会被写值。眩晕必须单独 `stunTimer`，否则状态条每刀闪一下。
- **状态角标口径要分类型**：中毒给层数 `×n`，减速/致盲/破甲给向上取整的剩余秒，眩晕 0.5s 不加秒只闪图标；混用秒数/层数会让玩家无法判断危险程度。
- **HUD 加一个兄弟 div 就会打坏 `span:last-child`**：`targetStatus` 插到目标栏后，原来靠 `span:last-child` 的两行规则立即失效；窄屏测试能抓到，选择器应直接锚定 `#targetHint`。
- **JPEG 状态图透明化不必上 rembg**：徽章是居中的圆形，手工正方形裁切 + 4× 超采样圆形 alpha + feather 3 就够；不下载模型、不依赖 OpenCV，5 张 128px PNG 约 152KB。前提是原图背景近黑且无复杂场景。
- **状态计时要在换图/复活清零**：否则减速、致盲会跨图残留，玩家以为中了永久 debuff；这类清理属于行为修正，要在文档写明，不要被后来的人当 bug 回退。
- **渲染回归 ≠ 真实触发**：直接写 `state.player` 只能证明显隐/角标/加载正确，证明不了蛛毒、蝙蝠减速、雾区致盲真的会写进状态条；上线前必须在真实战斗逐类触发。
- **16px 不是状态条目标**：32px 是主力，窄屏最多 28px；03 眩晕在 16px 偏暗、04 致盲在 16px 像两只红眼，不能为了“省空间”硬缩。
- **深色图标接入前必须先提亮**：03 战盔、05 破盾原图在 32/26px 下近乎黑块；`build_status_icons.py` 给 03 提亮 1.55×、05 提亮 1.5× 才可读。别直接拿 1024 概念稿判断 HUD 亮度。
- **HUD 加行不能只看 DOM 宽度**：移动端 `.side-panel` 固定 96px 且 `overflow-y:hidden`，状态条虽然在 DOM 里有宽度，实际被整行裁掉；浏览器截图和逐级 `overflow` 祖先检查都要做。第一版测试只查 `width>0`，是假通过。
- **窄屏侧栏要按画布基线反推高度**：390/360 用 140px 侧栏；320×568 只能用 127px，并把状态条上边距归零，才能同时保住 190px 画布和 32px 状态图标。先算高度，再改 CSS，别一次性全抬到 140px。
