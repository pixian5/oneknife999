# 文档与流程经验

> 来源：`docs/README.md` 的治理规则，以及各轮 `当前开发进度 / 下一步待实现 / 专项记录` 的实践。

## 文档事实源与优先级

- 冲突时按优先级：`docs/11-数值配置基线.md` → 对应系统分卷 → `docs/00-产品总纲.md` → 历史备份（仅追溯，不参与实现）。
- 规则改动必须同步改验收用例（单测或 Playwright），只改文档不改测试视为未完成。
- `docs/` 的历史文档不一定正确，尤其旧进度记录里的数值；以当前代码与最新实测为准，冲突时在新的专项记录里说明「为什么改」。

## 每轮必须同步的位置

1. `docs/年月日-时分-标题-模型.md`：本轮技术记录（问题、方案、踩坑、验证数据）。
2. `docs/年月日-时分-当前开发进度-模型.md` 与 `docs/年月日-时分-下一步待实现-模型.md`。
3. `docs/README.md`：分卷表 + 版本状态小节。
4. `文档索引.md`：文档分类与一句话摘要。
5. `README.md`：版本号、【当前开发进度】追加一段、【下一步待实现】替换为最新清单，并指向上面两份文档。
6. `设计.md`、`game/README.md`、`VERSION`、`package.json` 版本号。
7. `经验/`：把本轮可复用的结论归类沉淀，而不是复制 docs 原文。

## 版本与提交

- 每次修改版本号 +0.0.1，满十进一；`VERSION` 与 `package.json` 必须一致。
- 提交信息用中文，说明「为什么改」，不要只写「更新」。
- **配置有定义 ≠ 生效**：被动表 / 参数表只是声明，必须能指出具体读写位置（`grep 参数名` 全源码，只在定义处出现一次即为可疑项）。新增原语时同步补纯函数 + 单测，否则会长期静默失效。
- **做消融实验前先确认行为真的生效**：对死代码做 A/B 只能得到「无差别」，会被误读成「该行为无害」。
- **A/B 用同种子做配对比较**：`ONEKNIFE_PROBE_SEED` 让第 n 次运行取 `seed+n-1`，基线臂与消融臂跑同一组种子即可逐对被比（本轮第 30 关 15/10/9 → 0/2/0），比单看中位数更能排除噪声；总开关（`noabilities`）只能回答「有没有影响」，定位到具体行为要拆细粒度开关。
- **种子只锁随机数，锁不住帧时序**：同一份基线代码、同一组 seed，0.7.2 测得中位 10 死、0.7.3 测得中位 8 死（代码只加了门控，全开时原样返回）。差异来自 `dt = Math.min(delta, 0.05)` 在主循环里随负载变化。结论：**跨会话的数字不可直接比较**，四臂必须放在同一个后台任务里串行跑完。
- **先归因再补偿**：两个职业在同一关都超标、且关掉同一类行为后都归零，说明根因在这关的配置而不在职业数值；此时给「看起来更脆」的职业加血/加盾只会掩盖问题，还会让另一职业继续超标。0.7.4 法师对照就验证了这一点（中位 7 死 → 关形态 0 死）。
- **判定小调参用速率指标，不用次数**：死亡数离散且带正反馈（回城重生 → 普通怪满血重清），n=3 判不了 10%–20% 的调整；0.7.6 给探针加了 `damage100`（每百秒净承伤）、`firstDeath`、`killers`，同代码 8 次的承伤波动约 ±17%、死亡数却能 2→10。但**速率指标会被通关效率抵消**：0.7.7 把第 30 关攻击降到 0.88 倍后，死亡中位 7→3、单次通关总承伤 −25.5%，`damage100` 却只 −3.8%（战斗时间缩短 21%）。判「关卡变简单」用「每次通关的总承伤」（速率 × 耗时 / 100），死亡数只作闸门。
- **拆消融开关后必须验证「正交」**：只证明「关掉 A 维度后 A 变了」不够，还要逐只断言「B / C 维度一点没变」，否则开关顺手把别的行为也清了，归因数据全部失真（`tests/ui-ability-flags.cjs` 就是这条的落地）。
- **双远程并行开发先比提交、不要比版本号**：GitHub 与 GitCode 两条线都从 0.6.5 各自升到 0.6.6 / 0.6.7，号相同但内容不同；用 `git log --oneline HEAD..<remote>/main` 判断，合并后版本取「较大的下一号」。
- **基础设施类改动（CI / 部署 / 脚本）单独确认再合并**：对方删除 `.github/workflows/` 是用户在其会话里的指示，直接 rebase 会把本线刚修绿的 CI 一起抹掉。
- 提交前确认 `.gitignore` 未遗漏临时产物（`node_modules/`、`tests/balance-out.csv` 等按现状处理），临时复现脚本不入库。
- 推送后确认远端（GitCode / GitHub）已同步，再收尾。0.7.0 起 GitHub Actions 已整体删除，门禁改为本地 `npm run verify` + 三项浏览器回归，提交前必须全跑完。

## 云电脑（远程沙箱）环境

- **没有本地持久盘**：`/workspace` 每次会话启动都是重新 `git clone`（`git reflog` 里只有 `clone:` 与 `checkout:` 两条），`node_modules`、Playwright 浏览器、`.test-artifacts` 一律不保留。唯一事实源是**已 push 到远端的提交**；不 push 等于这一轮不存在。
- **开场固定动作**：`npm install` → `npx playwright install --with-deps chromium` → `ONEKNIFE_CHANNEL=chromium`（本机无 Chrome）→ `npm run verify` 确认基线，再开始改。
- **资源上限要按 cgroup 看**：`lscpu` 显示 3 vCPU，但 `cpu.max = 200000 100000` 只给 2 核；`memory.max = 4 GiB`、无 swap、无 GPU（无 `/dev/dri`）。浏览器任务必须串行，探针要在空闲时单独跑，否则出现假死亡数。
- **节点会变**：不同会话的宿主机名不同（实测 `all-in-one-74-zhxjn` → `all-in-one-73-lzl76`），`/root`、`/tmp`、apt 安装都不可跨会话依赖。
- **perf 只在容器基线内比较**：软件渲染约 200~240 fps，只看 p99 与 20ms+ 长帧，不能与 macOS 本机的 6000+ fps 对比。
- **perf 门禁要按执行环境分开**：真机 / 本机用 `tests/perf-probe.cjs` 默认（p99 ≤ 4ms、零 20ms+ 长帧）；共享 runner 与云电脑是软件渲染，`ci.yml` 用容器基线（`ONEKNIFE_PERF_P99_MAX=12`、20ms+ 长帧 0），是硬门禁不是 `continue-on-error`。0.8.85 实测同一 SHA 首轮 p99 12.8ms 失败、重跑 10.3ms 通过，说明单次过线要先重跑，不能直接判回归。
- CI 红了先定位**具体哪一步**：0.5.2～0.6.6 连续 9 轮 CI 全红，真因只是第 12 步帧率门禁用错了基线，前面所有功能步骤都通过。
- **测试断言要与帧率解耦**：主循环 `dt = Math.min(delta, 0.05)`，软件渲染的低帧率下固定 `sleep(650)` 期间模拟时间只推进几帧，「按住 0.65 秒就位移够」这类断言会假失败。改用「等待状态就绪 + 轮询直到条件成立或超时」；放宽的是等待时间，不是断言阈值。
- **状态变更与 UI 刷新不在同一拍**：Toast 在按键回调里同步写入，HUD 面板却走按帧刷新的签名缓存。断言「操作后面板变了」必须先轮询 DOM，不能紧接着读一次；这类假失败在快机器上永远复现不了。
- 记录环境数据时附上采集命令与日期；节点换了之后旧数值可能失效。详见 [docs/20261029-0258-云电脑会话环境与持久化-DeepSeek-V4.1-Flash.md](docs/20261029-0258-云电脑会话环境与持久化-DeepSeek-V4.1-Flash.md)。

## 协作与表达

- 用中文回复；专有名词后附中文。
- 发现能明显提升体验或与既有要求冲突的优化方向时，先告诉用户让其决策，不擅自扩大范围。

## 部署与容器增补（2026-11-18，DeepSeek-V4.1-Flash）

- **容器会整体重置，不只是 `/workspace`**：0.8.39 部署轮实测 `/opt` 下的仓库、8080 进程、`/var/log` 日志、`/opt/oneknife-start.sh` 同时消失。部署脚本与结论必须入库（`scripts/container-deploy.sh`），否则等于没部署。
- **npm 全局包要装到可写 prefix**：`npm config get prefix` 在云电脑指向 `/opt/cloud/devTools/nodejs/v22`（平台只读快照层），`npm i -g` 当次能用、下次会话消失。固定用 `npm i -g --prefix /usr/local <pkg>`，并用绝对路径调用。
- **「HTTP 200」不等于「浏览器能用」**：serveo 与 pinggy 都是 curl 四项全绿、真实 Chromium 打不开（告警页 / connection reset）；localhost.run 是 curl 与浏览器都通、但免费额度会 burst 降速。公网验收必须包含一次真实浏览器打开 + 读 `#classModal` 与 console。
- **首次冷加载超时不算缺陷**：隧道刚建立时首次 `goto` 常 60–120 s 超时，复测即通过。判「页面坏了」前先跑第二遍，并区分 goto 超时与 console error。
- **先查平台能力再选型**：本轮 `yum` 源解析失败（装不了 nginx）、DevKit 沙箱 `connect` 超时与 `APIGW.0301`，两条「看起来最正」的路都不可用——10 分钟内用最小命令验证，比反复重试省时间。
- **实例更新用公开 URL fetch**：`git fetch https://atomgit.com/... main && git reset --hard FETCH_HEAD` 免令牌，既不把带令牌 URL 写进实例 `.git/config`，也不出现在命令行历史；`serve.py` 读文件系统，更新即生效无需重启。
- **硬对齐脚本必须先查 dirty**：`container-deploy.sh` 第一版直接 `reset --hard`，把本轮的文档改动整批冲掉（untracked 文件保住、已跟踪改动丢失）。脚本要在 fetch 前 `git status --porcelain` 非空即中止，`FORCE=1` 才允许丢弃。
- **ag 登录不支持 `--force`，也别用 heredoc 传令牌**：`ag auth login --with-token --force` 直接 `unknown flag`；`cat <<EOF | ag auth login` 在交互终端里会把结尾吞掉，令牌还会粘进报错行。正确写法是 `printf '%s' "$TOKEN" | ag auth login --with-token`，登录后用 `ag auth status` / `ag repo view` 验证。容器内的 `/root/.config/ag-cli/token.json` 不持久，接手时重登即可。

## 多线并行与合并（0.8.40）

- **两个环境各改一摊时，先比对父提交再合并**：先 `git fetch` 两端 + 到另一个环境查 `git log/status`，若父提交相同、改动文件不重叠，就能干净叠加；不要用「谁覆盖谁」的方式硬推。
- **`git apply` 上下文冲突优先用 `--3way`**：同一文件两边都改过（例如版本常量已被本方先改到新号），普通 apply 会因上下文行不匹配直接失败，三方模式能正确合入且不留冲突标记。
- **二进制文件不要走 SDK 文本读取**：`Sandbox.files.read` 对 tar.gz 会按文本处理导致解压失败（"not in gzip format"）；纯文本逐个读、二进制改走 base64 或让远端直接解包。
- **平衡闸门红了先判「是不是基线过期」**：`balance-sim` 是确定性模拟（同一提交在两台机器跑出逐项相同数字），所以数值差异不可能是算力噪声；若基线 JSON 的采集版本早于关键改动（如改动攻击间隔、单刀上限），FAIL 就是基线口径过期，需重采基线而非改代码或改数字。

## 深层长跑夹具与存档隔离（0.8.85）

- **`abyssBest` 不能高于当前起始层**：`enterNextAbyss` 用 `Math.max(abyssFloor, abyssBest)+1`。夹具设 `currentMapId=abyss-F91` 但 `abyssBest=95` 时，F91 完成按 T 会直接跳到 F96，F92–F95 根本没测到。回归夹具必须让 `abyssBest` 等于当前层，`currentMapId`、`abyssFloor`、`abyssBest` 三者一致。
- **`run_abyss.py` 会覆盖正式档**：每层 `save_manual()` 写 `saves/abyss-progress.json`；长跑前必须先备份，跑完恢复，并把测试期死亡日志另存。恢复前核对备份文件的版本，`before-f91-v2.json` 可能是中间态（F91、deaths 484），不是正式档。
- **恢复后要同时恢复浏览器状态**：只改磁盘存档不够，页面 localStorage 仍指向测试档；必须重新注入恢复后的正式档并刷新，再核对 `currentMapId / deaths / marks / potion` 四项。
- **测试证据与正式档分目录**：日志、截图、快照放 `saves/abyss-runs/<日期>/`，正式档只留 `saves/abyss-progress.json`；不要把测试档提交进仓库当“最新进度”。
- **恢复 F96 时 `abyssBest` 必须 ≥ 当前层**：`state.abyssFloor = min(abyssBest, saved.abyssFloor)`；若 `abyssBest=95` 而 `currentMapId=abyss-F96`，有效层数是 95，F96 会被拒绝并回落 `ash_outskirts`。夹具要让 `abyssBest` 至少等于当前层，`abyssFloor` 也等于当前层，页面才会加载深层。
- **未完成层不会 `save_manual()`**：`run_abyss.py` 只在层完成后落盘；F99 撞墙中止时，页面在 F99、存档仍是 F98。恢复正式档必须用事先备份，不能拿“当前存档”当测试结果。

## F99/F100 深层验收与 CI（0.8.86）

- **夹具要还原“到达该层时的真实状态”**：F99 用 `currentMapId=abyss-F99`、`abyssFloor=99`、`abyssBest=99`、deaths 558、potion 0、marks 3819、玩家在营地；首次进层 +1，清完开箱 +2。只改地图 id 不改进层次数/药水，会把“清层难度”和“补给差距”混在一起。
- **F99/F100 的完成态只在页面，未完成层不落盘**：`run_abyss.py` 只在 `completed` 后 `save_manual()`；测试完成 F100 后正式档已被覆盖。跑前备份 `saves/abyss-progress.json` 与 `saves/abyss-floor-deaths.jsonl`，跑完恢复并重新注入浏览器，核对四项。
- **F100 完成瞬间 boss HP 会回到 171,435**：首领死亡后实体可能按新状态重建；判定用 `bossDefeated=true`、`completed=true` 和“本层已通关”截图，不要拿最终实体 HP 当“战斗回血”。
- **`gh` 未登录时可用 git remote 里的令牌调 GitHub API**，但不要把令牌打印到日志；`gh run list` 不支持 `--branch`，按 `head_branch` 过滤或直接查 run id。`main` 的 perf 失败可先用 `workflow_dispatch` 同 SHA 补跑，不要急着改 perf 阈值。
- **文档先写可复现事实，再写结论**：用时、死亡、药水、清层/回响分段、`completed` 标记、截图/日志链接要能对上；单样本必须写明“只有 1 次”，不能写成稳定均值。
- **Instabox 旧实例可能只是休眠，不是消失**：旧公网地址本轮较早 curl 404，随后又 200，实例实际是 0.8.85。发布前先 `curl` 首页与 `src/main.js` 版本，再决定是唤醒旧实例还是重建，不要用一次 404 判死。
- **实例更新只 `git fetch` 公开 main**：`git fetch https://github.com/pixian5/oneknife999.git main && git reset --hard FETCH_HEAD && git clean -fdq game/`；`serve.py` 读文件系统，更新后无需重启。发布后核对实例 `VERSION`、公网 `CURRENT_APP_VERSION`、`CACHE_VERSION` 三处。
- **公网 `page.goto` 首次 60s 超时是已知冷启动**：第二次 120s `domcontentloaded` 成功，标题、`#classModal`、console/pageerror 均正常。报告要写“第二次通过”，不能拿首次超时下结论。
- **CI 单项抖动不要连续 dispatch**：`main` push 的 perf 失败可在同 SHA dispatch 复跑，但可能换另一项失败（本轮 perf 通过、`ui:blind` 30 秒等待失败）；本地同一测试 PASS 就按抖动记录，第三次 dispatch 返回 HTTP 500 时停止重试。后续文档提交 `e0eff6d` 在 `main` 跑出 24/24 全绿，说明同一代码树可自愈，保留全绿 run 作证据、记录抖动即可。

## F100 第二样本与 0.8.87 发布（0.8.87）

- **无 `--save-path` 时复制脚本比改正式脚本安全**：把 `tools/run_abyss.py` 复制到 `/tmp`，只替换 `SAVE_PATH` / `DEATH_LOG_PATH` 到 `saves/abyss-runs/20261126-f99-second/`，正式档与死亡日志先备份为 `formal-before.json` / `formal-deaths-before.jsonl`，跑完恢复。临时复制能隔离，但不是长期方案；下一版必须把参数做进 `tools/run_abyss.py`。
