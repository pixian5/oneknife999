# 文档与流程经验

> 来源：`docs/README.md` 的治理规则，以及各轮 `当前开发进度 / 下一步待实现 / 专项记录` 的实践。

## 文档事实源与优先级

- 冲突时按优先级：`docs/11-数值配置基线.md` → 对应系统分卷 → `docs/00-产品总纲.md` → 历史备份（仅追溯，不参与实现）。
- 规则改动必须同步改验收用例（单测或 Playwright），只改文档不改测试视为未完成。
- `docs/` 的历史文档不一定正确，尤其旧进度记录里的数值；以当前代码与最新实测为准，冲突时在新的专项记录里说明「为什么改」。

## 每轮必须同步的位置

1. `docs/年月日-时分-标题-模型.md`：本轮技术记录（问题、方案、踩坑、验证数据）。
2. `docs/年月日-时分-当前开发进度-模型.md` 与 `docs/年月日-时分-下一步待实现-模型.md`。
3. `docs/README.md`：分卷表 + 版本状态小节。
4. `文档索引.md`：文档分类与一句话摘要。
5. `README.md`：版本号、【当前开发进度】追加一段、【下一步待实现】替换为最新清单，并指向上面两份文档。
6. `设计.md`、`game/README.md`、`VERSION`、`package.json` 版本号。
7. `经验/`：把本轮可复用的结论归类沉淀，而不是复制 docs 原文。

## 版本与提交

- 每次修改版本号 +0.0.1，满十进一；`VERSION` 与 `package.json` 必须一致。
- 提交信息用中文，说明「为什么改」，不要只写「更新」。
- 提交前确认 `.gitignore` 未遗漏临时产物（`node_modules/`、`tests/balance-out.csv` 等按现状处理），临时复现脚本不入库。
- 推送后确认 GitHub Actions（`ci.yml` / `e2e.yml`）通过再收尾。

## 云电脑（远程沙箱）环境

- **没有本地持久盘**：`/workspace` 每次会话启动都是重新 `git clone`（`git reflog` 里只有 `clone:` 与 `checkout:` 两条），`node_modules`、Playwright 浏览器、`.test-artifacts` 一律不保留。唯一事实源是**已 push 到远端的提交**；不 push 等于这一轮不存在。
- **开场固定动作**：`npm install` → `npx playwright install --with-deps chromium` → `ONEKNIFE_CHANNEL=chromium`（本机无 Chrome）→ `npm run verify` 确认基线，再开始改。
- **资源上限要按 cgroup 看**：`lscpu` 显示 3 vCPU，但 `cpu.max = 200000 100000` 只给 2 核；`memory.max = 4 GiB`、无 swap、无 GPU（无 `/dev/dri`）。浏览器任务必须串行，探针要在空闲时单独跑，否则出现假死亡数。
- **节点会变**：不同会话的宿主机名不同（实测 `all-in-one-74-zhxjn` → `all-in-one-73-lzl76`），`/root`、`/tmp`、apt 安装都不可跨会话依赖。
- **perf 只在容器基线内比较**：软件渲染约 200~240 fps，只看 p99 与 20ms+ 长帧，不能与 macOS 本机的 6000+ fps 对比。
- **perf 门禁要按执行环境分开**：真机 / 本机用 `tests/perf-probe.cjs` 默认（p99 ≤ 4ms、零 20ms+ 长帧）；共享 runner 与云电脑是软件渲染，`ci.yml` 用容器基线（p99 ≤ 20ms、长帧 ≤ 10）并 `continue-on-error`，只留 `PERF PROBE` 日志看趋势，不让跑分环境把功能回归的 CI 拖红。
- CI 红了先定位**具体哪一步**：0.5.2～0.6.6 连续 9 轮 CI 全红，真因只是第 12 步帧率门禁用错了基线，前面所有功能步骤都通过。
- 记录环境数据时附上采集命令与日期；节点换了之后旧数值可能失效。详见 [docs/20261029-0258-云电脑会话环境与持久化-DeepSeek-V4.1-Flash.md](../docs/20261029-0258-云电脑会话环境与持久化-DeepSeek-V4.1-Flash.md)。

## 协作与表达

- 用中文回复；专有名词后附中文。
- 发现能明显提升体验或与既有要求冲突的优化方向时，先告诉用户让其决策，不擅自扩大范围。
- 重大改动先备份旧数据再重构，不必兼容旧存档结构（迁移表负责迁移）。
- 「改完必须验证」是硬规则：不跑测试就停等于没完成。
