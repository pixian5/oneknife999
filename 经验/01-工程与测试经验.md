# 工程与测试经验

> 来源：`docs/` 各轮开发记录（00–20 分卷、2026-09-30 起各版本进度与专项记录）的提炼。docs 原文不一定正确，以当前代码与实测为准。

## 模块化与纯函数

- 战斗计算（`combat.js`）、掉落（`drops.js`）、技能规则（`skills.js`）、连击/指引（`feedback.js`）、地图几何（`geometry.js`）都应与 DOM 和全局状态解耦，随机数由参数注入，这样 Node 单测可以直接跑，不必启浏览器。
- `main.js` 只做「状态写回 + 视觉反馈」，凡是能写成纯函数的规则都下沉；否则每次小改都要依赖 Playwright 才能验证。
- 新增纯逻辑模块时，同步把 `node --check` 加进 `package.json` 的 `check` 脚本，避免语法错误拖到运行时才暴露。

## 渲染与性能

- HUD 按需渲染（脏检查 + 签名缓存）是帧率的主要来源；`docs/20-界面性能与倒计时修复记录.md` 记录过「每帧重建 DOM」和「倒计时读固定值」两类事故。
- 静态地图用离屏 Canvas 缓存；每帧只重绘动态层。
- `npm run perf` 观察 p95/p99 与 20ms+ 长帧数量。**启动首帧偶发 200ms+ 属正常**（模块解析与首帧编译），不要当成回归。
- 震屏只做相机平移，不能影响点击命中换算；否则移动端会出现「点了没反应」。

## 测试组合

- 提交前固定跑：`npm run verify`（check + Prettier + 单测）→ `test:ui`（三视口）→ `test:ui:levelup` → `test:ui:regression` → `perf` → `ONEKNIFE_RUNS=1 npm run test:e2e`。
- `tests/e2e-ten-clear-runs.cjs` 用 `fast=1`：玩家伤害 ×25、世界时钟仍是真实时间。**它的死亡数不能直接当作真实难度**（怪物常在前摇期间被击杀），只能当作「流程能否走通」的回归信号。
- 真实难度用 `tests/difficulty-probe.cjs`（`npm run test:difficulty`）：`page.clock` 只快进**虚拟时间**、URL 不带 `fast`，伤害与出手节奏按正式数值结算。**每关必须新建 context + page**，同页连跑会因虚拟时钟 / 自动推进 / 存档写回累积，让第 15 关死亡数从 2 次涨到 17 次。
- 探针的玩家基线要「像正常玩家」：主线等级 + 技能点均分 + 穿戴本关掉落表前 4 件装备 + 带药水。裸装会被首领打进「死亡 → 复活 → 首领满血重置」的死循环，永远打不完。
- 探针判断「半血撤退」必须用游戏侧 `snapshot().player.maxHp`（含装备生命加成），自算 `基础 + 等级×18` 会漏装备加成，撤退阈值形同虚设。
- 远程职业停在射程边缘、近战贴脸；打首领用「一刀一撤」拉开到 `radius + 70` 之外（首领约 104px）。横移 240ms 不够，必须后撤约 320ms。
- 慢脚本给每个目标设预算并定期打印进度（`PROBE FIGHT ... guard / hp / deaths`），否则卡死时看不到任何信号。
- **HUD 数值必须与结算公式同源，不能另写一套近似公式**：角色面板的攻击显示用 `hero.attack + level×4 + 装备有效战力×0.9`（与 `computeDamage` 的 `base` 一致），防御用 `playerDefense()`、生命用 `playerMaxHp()`。如果面板自己算一套（例如把装备战力直接相加、防御乘个系数当「战力」），玩家看到的数字和实际战斗不一致，改数值时也无法靠面板验证。
- **按需渲染的签名必须覆盖所有被展示的值**：`renderPlayer` 用 `panelChanged($("powerText"), signature)` 做脏检查，签名里只放「战力」时，只改防御 / 生命词缀（战力可能不变）会出现面板不刷新的 bug。新增展示项时第一件事是把它加进签名。
- `__ONEKNIFE_E2E__.snapshot()` 的字段是测试的唯一事实源，脚本按什么算就要有什么：0.3.6 补了 `player.maxHp`，0.3.7 补了敌人 `maxHp`（此前打印 `hp=152/NaN`）。新增测试断言前先确认快照字段齐全，别在测试里自算游戏内数值。
- `balance-sim.mjs` 是无快进数值模拟器，**不复现前摇 / 围攻上限 / 走位躲避**；改了承伤节奏时它不会变，必须用专项 Playwright 复现（如沙蝎王战连跑 3 次）。
- 临时复现脚本（Playwright）不入库，验证完删除；仓库只保留 `tests/` 下的常驻用例。

## 交互与面板

- 面板形态要服从既有 e2e 约束：百图回归依赖 `page.mouse.click(canvas)` 寻路且每个动作后按 `f`，所以**城镇商店做成侧栏面板而不是全屏遮罩**（遮罩会吞点击、F 会反复弹遮罩）。要改造成模态弹窗，必须先跑百图回归。
- 复用已有按键（如 `F`）扩展交互时，优先级必须显式：掉落 > 秘藏 / 场景节点 > 城镇 NPC。新增 NPC 要接着往后排，否则会出现「按 F 开了面板却拾不到东西」。
- 瞬态 UI 状态（`state.shopOpen`）不写存档，并且在换图 / 复活 / 条件失效（走出城镇）时统一复位，避免跨场景残留。
- 新增玩家字段（如 `reforgeScroll`）优先给默认值而不是升存档版本：`loadGame` 里缺省兜底即可，迁移表只用于结构变化。
- 写「注入存档」类浏览器测试时注意 `persistGame` 同时写顶层 `equipment` 与 `player.equipment`，而 `loadGame` 优先读顶层；两处都要改，否则穿戴装备不会恢复。
- 专项 UI 测试要确认玩家真的站在触发区域：`ash_outskirts` 的城镇是 y 950~1250，出生点 y 780，进城需要先向下走约 1 秒。

## 常见坑

- 遍历 `state.entities` 的新逻辑必须跳过 `friendly`（骨卫）与 `npc`（流浪武者），否则会把召唤物当怪打、把 NPC 拉进自动索敌。
- e2e 快照也要过滤 `friendly`，不然断言里的实体数量会随召唤波动。
- 存档迁移用「版本函数表」逐级升级（v2→v3→v4），不要写一次性大 if；拒绝读取更高版本存档。
- 用系统 Chrome 做 Playwright 测试（`tests/browser-options.cjs`），避免在 macOS 上反复下载浏览器。
