# 工程与测试经验

> 来源：`docs/` 各轮开发记录（00–20 分卷、2026-09-30 起各版本进度与专项记录）的提炼。docs 原文不一定正确，以当前代码与实测为准。

## 模块化与纯函数

- 战斗计算（`combat.js`）、掉落（`drops.js`）、技能规则（`skills.js`）、连击/指引（`feedback.js`）、地图几何（`geometry.js`）都应与 DOM 和全局状态解耦，随机数由参数注入，这样 Node 单测可以直接跑，不必启浏览器。
- `main.js` 只做「状态写回 + 视觉反馈」，凡是能写成纯函数的规则都下沉；否则每次小改都要依赖 Playwright 才能验证。
- 新增纯逻辑模块时，同步把 `node --check` 加进 `package.json` 的 `check` 脚本，避免语法错误拖到运行时才暴露。

## 渲染与性能

- HUD 按需渲染（脏检查 + 签名缓存）是帧率的主要来源；`docs/20-界面性能与倒计时修复记录.md` 记录过「每帧重建 DOM」和「倒计时读固定值」两类事故。
- 静态地图用离屏 Canvas 缓存；每帧只重绘动态层。
- `npm run perf` 观察 p95/p99 与 20ms+ 长帧数量。**启动首帧偶发 200ms+ 属正常**（模块解析与首帧编译），不要当成回归。
- 震屏只做相机平移，不能影响点击命中换算；否则移动端会出现「点了没反应」。

## 测试组合

- 提交前固定跑：`npm run verify`（check + Prettier + 单测）→ `test:ui`（三视口）→ `test:ui:levelup` → `test:ui:regression` → `perf` → `ONEKNIFE_RUNS=1 npm run test:e2e`。
- `tests/e2e-ten-clear-runs.cjs` 用 `fast=1`：玩家伤害 ×25、世界时钟仍是真实时间。**它的死亡数不能直接当作真实难度**（怪物常在前摇期间被击杀），只能当作「流程能否走通」的回归信号。
- `balance-sim.mjs` 是无快进数值模拟器，**不复现前摇 / 围攻上限 / 走位躲避**；改了承伤节奏时它不会变，必须用专项 Playwright 复现（如沙蝎王战连跑 3 次）。
- 临时复现脚本（Playwright）不入库，验证完删除；仓库只保留 `tests/` 下的常驻用例。

## 常见坑

- 遍历 `state.entities` 的新逻辑必须跳过 `friendly`（骨卫）与 `npc`（流浪武者），否则会把召唤物当怪打、把 NPC 拉进自动索敌。
- e2e 快照也要过滤 `friendly`，不然断言里的实体数量会随召唤波动。
- 存档迁移用「版本函数表」逐级升级（v2→v3→v4），不要写一次性大 if；拒绝读取更高版本存档。
- 用系统 Chrome 做 Playwright 测试（`tests/browser-options.cjs`），避免在 macOS 上反复下载浏览器。
