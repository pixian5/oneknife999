# 交互与真人体验经验（0.8.45 复盘）

## 点击命中

- Canvas 游戏里“立绘”和“实体坐标”常不是一回事：脚在实体点、身体向上画。点击判定只按 `radius` 会漏掉胸口/头部，玩家点了立绘却被判成走位。胶囊必须和渲染共用同一套脚底锚点，并覆盖到立绘顶部：Boss 取 100% 高度，普通怪 90%（留 10% 顶部余量）。只覆盖 62% 时首领头部仍然点空。
- 悬停必须给指针反馈（手型/描边），否则玩家不知道“这里能点”。
- 多目标重叠时的命中优先级不要写成 `Number(a.boss) - Number(b.boss)`：普通怪没有 `boss` 字段时是 `NaN`，比较器返回 `NaN` 会被当成 0，排序整段失效，首领就会被旁边的小怪抢锁。显式写 `(b.boss ? 1 : 0) - (a.boss ? 1 : 0)`，并用契约测试禁止 `Number(b.boss)` 回归。
- 不要用截图目测 HUD 坐标去反推 DOM 位置：本次试玩把装备格坐标读错 60px，误判“HUD 点不动”。要直接读 `getBoundingClientRect()`。

## 反馈

- 任何“按了没反应”都要回答三件事：最近目标是谁、距离多少、射程多少。只弹“附近没有目标”等于没回答。
- 射程要画出来：细线在火焰背景上等于不存在。填充 + 变色 + 指向目标的虚线，才能让“看着贴脸其实差 300”变得可解释。
- 目标栏只显示血条不够，距离与“是否在射程内”必须常驻。

## 引导

- 引导要求“去拾取”，就必须保证场上真有东西可拾。42% 掉落率不能承担教学职责，首杀要保底。
- 地面掉落不跨会话保存。任何“引导依赖地面物件”的设计，都要在读档时补发或直接判定完成。

## 花钱操作

- 装备槽单击直接扣金币强化 = 玩家想看装备时误扣。所有不可逆花费至少两段式确认，并显示消耗与成功率。
- 二次确认窗口不要短于 3 秒；按钮被重渲染后确认态会丢，重渲染时要么保留要么明确取消。

## 重生

- 普通怪 11–20 秒重生，会让“清剿 1/8”看起来没涨。重生间隔至少大于玩家从击杀点走到下一只怪的时间，28–45 秒是本次实测可接受区间。

## 暂停

- “暂停”必须停 update，而不是只停 render：怪物 AI、玩家伤害、掉落/重生计时、药水回复、冷却都在 update 里推进，只停渲染等于站着挨打。
- 恢复时要清空 keys / 摇杆 / pointer.down / moveTarget，并重置 `lastTime`；否则角色会沿暂停前方向继续走，暂停期间的真实时间还会被算成一帧超大 dt。
- 暂停时动作栏要整体 `pointer-events:none`，否则玩家会点攻击/药水发现没反应，误判游戏卡死。
- 打开设置、切后台都应该自动暂停；切回来不要自动恢复，给一个“点击继续”的遮罩，避免玩家没准备好就被打。
- 暂停遮罩只盖画布是合理的：右侧属性/装备面板仍可查看；但养成操作是否允许要单独决定。

## 缩放

- 镜头缩放要改 `getViewScale()` 的乘数，不要改 canvas 分辨率；`canvasPoint` 用同一个 scale 换算，鼠标/触屏才不会点歪。
- 缩放档位写入 localStorage 后，测试要断言 `viewScale` 精确按倍率变化，而不只是按钮高亮。
- 设置弹窗正文 10–11px 在 1280×960 下偏小，先把弹窗正文提到 11–12px；整体 DOM 字号缩放不要用 `zoom` 整个 app-shell，会把固定动作栏和画布一起撑出视口。

## 验证方法

- 页面级 `press_key` 不一定能驱动 Canvas 游戏的 keydown；用同一条 `KeyboardEvent` 派发验证逻辑是可行的，但要说明它不是 OS 级按键。
- 每次修完操作层，至少跑一遍“选职业 → 出营地 → 点立绘锁定 → 超射程按 X → 首杀拾取 → 点装备槽”的真人路径，再跑 `npm run verify`。
- 触屏用例偶发失败不一定是测试抖动：连续跑 10 次，每次失败都打印点击世界坐标、命中候选、当前 targetId。本次正是靠 1/3 概率的偶发失败抓到 Boss 排序 `NaN` 缺陷，产品代码必须一起修。
- 暂停回归不要只看 `paused` 布尔值：记录敌人坐标/血量、玩家血量，等 1.5 秒后逐项比较；再按一次 X 断言目标血量不变，才算时间真的冻结。
- 写触屏用例时，`page.touchscreen.tap` 收到 `Input.dispatchTouchEvent: Invalid parameters` 先查坐标是否 `NaN`/越界。本项目的相机投影字段是 `meta().viewScale`（不是 `meta().scale`），实体屏幕坐标 = 画布偏移 + `(entity - camera) * viewScale`；坐标算错时协议层只会报“参数非法”，不会告诉你字段名错了。

## 0.8.46 Service Worker 也会造成“页面半坏”
导航 network-first 只保证 HTML 新，js 若 cache-first 仍会拿到旧模块；新模块 import 新导出时整张模块图失败，表现是职业卡全空、控制台却没有报错。判断方法：HTML 有新按钮但功能没执行、js 请求 status ok、控制台只有无关 warning，就查 SW 缓存策略。代码文件必须 network-first，图片才适合 cache-first。

## 0.8.47 射程外点击要给出“会自己走过去”的确定感
只弹“正在接近，距离 N”会让玩家以为要再点一次，而且人走到了提示还停在旧距离。正确做法是把意图状态化：记录 autoAttackId，进入射程自动打一次；HUD 用“自动接近中”表达持续状态，任何手动移动/换目标/暂停都撤销意图。提示文案不要写死点击瞬间的距离。

## 0.8.48 状态文案要按最窄容器实测
新增“自动接近中”后，桌面单行正常，320px 目标栏 117px 却只显示前半句。判断文字是否被截断不能靠目测，直接比较 `scrollWidth/clientWidth` 与 `scrollHeight/clientHeight`。窄屏用两行 + line-clamp:2，390 以上保持单行，动作条高度不变。

## 0.8.49 鼠标点完按钮，hover 提示不会自己消失
桌面端用鼠标攻击时，点完普攻光标仍停在按钮上，`hover` 说明会一直挡住目标栏。只靠 CSS `:hover` 无法区分“正在看说明”和“刚点过”。正确做法是 pointerdown 加抑制类，pointerleave/pointerout 再恢复；触摸端天然无 hover，不受影响。

## 0.8.50 打首领前先告诉玩家“身边有几只小怪”
新手会一直点普攻自动锁首领，小怪没人管，连续死于包夹，日志里却显示 boss 血量只掉一点。目标卡在步骤 2 动态报出首领附近小怪数量，并提示范围技能，能把“为什么死”提前说清。计数要进任务卡刷新签名，否则小怪清完文案不会变。

## 0.8.51 生命值要显示“当前 / 最大”，不能只显示最大值
真人试玩时实际只剩 111 血，侧栏仍显示「生命 386」，玩家完全看不出危险。只画一条 76×5 的头顶血条不够，必须在玩家卡给出数值和随伤变化的条。文本刷新要进 `renderHeroPanel` 签名，否则缓存会一直停在满血。用 `classList.toggle` 时注意项目里的 `setClassName` 是整体替换、只有两个参数，条件开关要用 `setClass`；测试要同时断言满血时低血类不存在。

## 0.8.52 死亡本身也要落盘
只在击杀/升级时存档，会让“死亡后直接关浏览器”回退死亡数、金币和位置。`die()` 在回到安全营地后必须再 `persistGame()`；测试直接令 hp=0，检查 localStorage 的 deaths 与 state 一致，并确认复活坐标在 townRect 内。首领血量是否跨会话属于另一个设计问题，不要顺手混进死亡存档。

## 0.8.53 首领战不能一边打一边刷小怪
普通怪 28–45s 重生，在清怪阶段是节奏，在首领战里就是“越打越多”。清完 8/8 进首领区、好不容易把小怪清到 0，倒计时又塞回 1–2 只，目标卡在 1/2 之间跳。正确做法是首领交战（受伤或仇恨）期间冻结首领出生点附近的普通怪 respawn，首领死/脱战后恢复。测试要把 respawn 设成 0.12s，验证交战期间不复活、脱战后恢复。

## 0.8.54 提示半径必须和实际玩法半径一致
目标卡统计“首领附近小怪”用 180px，首领战冻结重生却用 260px，结果两只距首领 188/189 的卫兵明明贴身打玩家，目标卡仍说“前往首领区域”。同一个规则出现两个半径，玩家就会在提示“没有小怪”时被围杀。任何“附近/范围内”提示都应与对应玩法判定共用同一常量或同一配置；改半径时先搜索全部硬编码。

## 0.8.54 第一关首领要按“无装备开荒”验收
900 HP / 36 攻的首领，对 Lv2 无装备战士需要 38 次命中，而玩家约 11 次挨打就死；真人死亡 9 次只打到 92%。第一关是教学首领，应按“本关上限等级、无装备、2–3 瓶药”的真实路径验收。0.8.54 改成 720/30/12 后，3 瓶药就能击杀，同时保留阶段与技能压力。

## 0.8.54 首领胜利后要清场，别让杂兵补刀
首领倒下时玩家只剩 64 HP，残存小怪继续攻击，死亡数从 9 变 10；玩家已经拿到通关奖励，却看到“胜利后死亡”。首领死亡分支应清空首领区内的普通怪，且不结算经验/金币，避免刷奖励；范围外的怪保持原状。UI 回归用“近处 80px / 远处 600px”双实体验证边界。

## 0.8.54 浏览器店铺操作后先点一次画布再按技能键
云端 Browser Use 里用 DOM 点击买药、按 F 关店后，直接按 2/4 技能没有派发，怒气不变；点一次画布后同一按键正常。判断是页面焦点仍停在已移除的店铺按钮上，而不是技能冷却/怒气不足。后续真人脚本在店铺/背包操作后先点画布空白处，再发送战斗热键；若真实玩家也复现，再在 `closeShop()` 里主动把焦点还给画布。

## 0.8.55 真人试玩新增
- **出口必须只由玩家主动触发**：`movePlayer()` 里进入 exit 矩形就 `tryTravel()`，会让正常走位变成强制换图，首领战被瞬间打断且首领回满。出口只保留区域检测，换图统一交给 T 键。
- **容量判断要把「材料」和「装备」分开**：背包 12 格若按 `inventory.length` 计算，材料与魂核会把装备栏塞满；玩家站在掉落上按 F 永远拾取失败，日志只有一行“背包已满”。容量只统计非材料项，材料单独堆叠。

## 0.8.56 真人试玩新增
- **容量判断必须是一套口径、三个入口**：拾取、商店兑换、背包渲染只要有一个还在用 `inventory.length`，材料就会把装备挤成“看不见的第十三格”。容量统一走 `equipmentSlotCount()`，渲染按“装备优先、材料在后”排序，测试同时覆盖 12 材料、12 装备与空值。
- **Browser Use 后端挂死不等于游戏死**：`CELL_RUNNER_EXIT` 后新调用会卡到 900 秒安全超时，但页面 CDP 仍可正常求值。真人输入可以切到直连 CDP 桥，只发 `Input.dispatchMouseEvent/KeyEvent`，先 reload 释放渲染内存，再从存档恢复，不要盲目重开新档。

## 0.8.56 三职业全通补充
- **商店面板“存在”不等于“可见”**：`document.querySelector('[data-buy-marks]')` 在商店关闭时仍能命中隐藏 DOM，据此判断会跳过按 F 开店，随后点击空坐标、买东西全失败。必须用 `offsetWidth > 0` 判断可见性。
- **城镇坐标要走到内缩范围**：`nearTown()` 是城镇矩形内缩 28px；自动寻路若用 50px 容差，可能停在店外按 F 无反应。购买前按 20px 容差走到城镇中心。
- **低血量职业的喝药阈值必须按最大生命比例**：固定 `hp < 400` 对最大生命 334 的道士等于每轮都喝药，18 瓶药几十秒耗尽。统一改为 `hp < maxHp * 35%`。

## 0.8.57 空动作也要有反馈
- 篝火是靠近被动恢复，玩家按 F 时原先走到“附近没有可拾取物品”的兜底提示，读起来像功能坏了。F 的分支应显式覆盖“篝火/休整点”，告诉玩家无需按键，而不是复用拾取失败文案。
- 新增交互分支要维持原有优先级：掉落 → 补给箱 → 场景节点 → 城镇商店 → 篝火，避免提示抢走真实拾取与交易。
